    • 设计决策 & 落地影响

    默认显示什么
    (本次修订)    		一枚身份牌,不是一排选项。Provider 是粘性选择 —— 配好之后绝大多数会话都用同一个,把 5 枚 chip 永久摆在中间区,是给 10% 的换用场景付 100% 的视觉成本。可发现性只需要付一次(▾ + hover + 副标题),不需要每次都付。
    记忆写在哪
    (本次新增)    		写回 agent.provider,即 per-agent 记忆。PATCH /agents/:id 今天就收 provider(agents/dto.ts:24),所以记忆本身零后端改动;而且这与现有“选模型即写回 agent 默认”是同一条路,不引入第二套记忆机制。粒度选 agent 而不是全局,是因为 agent ≈ 项目,项目和 provider 的绑定本来就稳定。
    记忆必须被说出来写回是隐式副作用,不说的话下次会变成“我的模型怎么自己变了”。所以切换后的胶囊带一句 saved as orbit-web’s default(C4)。这也是我上一版“不回写”主张被化解的方式:不是不写,而是写了要说。
    当次会话怎么落地仍然走 CreateSessionDto.provider,而不是“先 PATCH agent 再 POST session” —— 后者是两个请求,中间有竞态,而且会顺带影响这个 agent 的 task run / MCP spawn。精确落地当次 + 异步写回记忆,两件事分开做。
    牌里有什么Engines 组在上,Your keys 组在下。Engines = LoginEngine 的三个:claude / codex / kimi(shared/src/dto.ts:340,DTO 层已在拒绝把 configured-provider slug 当登录引擎)。opencode 虽是第四个 AgentProvider,但不可登录,故不进列表。顺序与 mergedProviderOptions() 今天一致。
    默认选中agent 自己的 provider,其兜底就是 claude(sessions.service.ts:155 的初值)。所以“默认 Claude”和“默认跟 agent 走”在全新账号上是同一件事,不需要两套规则。有了记忆之后,这一栏读作:上次在这个 agent 下选的那个。
    钱从哪出摘要行直说:内置写 runner login(订阅额度),BYOK 写 your API key。这是两类身份唯一需要用户分清的差别,所以给它一行字,而不是给它两套视觉。
    草稿保留未发送的选择跟着现有的 per-agent 草稿键 draft:<runnerId>:<agentId> 走,离开再回来不丢;发送时才写回 agent 记忆。
    模型联动切 provider → 重新 seed 该 provider 的 defaultModel → clamp effort → Auto 模式不支持时退回 Default。全部沿用 defaultModelForProvider / normalizeEffortForProvider / supportsAuto,无新逻辑。
    后端改动只差一个入参:CreateSessionDto.provider?: string。session.provider 列已存在,分发链路 session.provider ?? agent.provider 已经就位(queue.service.ts:213、runner-api.controller.ts:2349)。服务端需校验该 slug 属于本人且 enabled,并据此写 providerBuiltin;缺省时维持今天的“继承 agent”。
    不可用态
    (有前提)    		理想是提前置灰:内置引擎没登录、或 BYOK provider 借壳的 runtime 没装在这台 runner 上,都该点不动。但控制面今天看不到 runner 的引擎状态 —— runners 表只存“正在进行的那次登录”(loginEngine / loginStatus),已装/已登录的快照没有上报。P0 先不置灰,点了之后复用已有的 RunnerSignIn / ClaudeSubscriptionCard 事后引导;要做置灰得先给心跳加 engines[]。
    会话开始后中间区随草稿消失;provider 变成 composer 左侧的静态 pill(与只读态的 Agent pill 同一套样式),中途可见不可改。
    三端一致web 与 native 已同时落地。native 的 hero 本来就是 provider 品牌色的圆形 mark + agent 名,所以那枚 mark 直接跟着 provider 走,底下补一行 provider 胶囊 —— agent 名管“在哪儿干”,provider 胶囊管“谁来干”,两个 chevron 各司其职。点开在 iOS/macOS 是 Sheet(分 Engines / Your keys 两段),不是 popover。
