Goal

让「新建 workspace」不再要求用户先手动 clone 仓库、再粘贴绝对路径。

1
Acceptance criteria
  1. 在 web 顶层点「新建 workspace」,贴一个仓库 URL、选一台机器,能建出一个可用的 workspace —— 全程不需要事先手动 clone,也不需要输入任何绝对路径。
  2. clone 期间该 workspace 以 CLONING 状态出现在 sidebar 中它所属机器的分组下,用户可以离开页面;完成后它自动带上 worktree 隔离(enableWorktree=true)和从 remote 默认分支探测到的 defaultMergeTarget,名字取自仓库名。
  3. clone 失败时该 workspace 留在列表里(不消失),失败卡片原样回显 git 的 stderr,并提供重试 / 改 URL / 换机器 / 删除四个出口。
  4. 账号下只有一台 runner 时,「选机器」这一步完全不出现。
  5. 目标机器上已存在同 remote 的 checkout 时,创建流程显式提供「复用该 checkout」和「再 clone 一份」两个选项,不自动替用户选。
  6. RunnerDetailPage 的 Add workspace 按钮和 RunnerRegisterGuide 的 Create a workspace 按钮都跳到同一个新建流程(机器一步预填),产品里只剩一份 workspace 创建 UI。
  7. CLONING 状态的 workspace 拒绝开新 session,并给出「仍在克隆」的明确原因,而不是让它看起来可用然后在 spawn 时报 ENOENT。

四个问题

1
作者原文，全宽 Markdown。ProjectsPage.tsx:633–637 的 Field label="Acceptance criteria"。这里没有任何判定信息——读完它的人不知道 acceptance 从没跑过。
2
同样 7 行 + 判定徽章，在 1.32:1 里那个 1fr 的窄列（ProjectsPage.tsx:649–652）。宽度分配反了。CSS 注释写的是「acceptance is a column of short lines and does not [need width]」——中文长句不是 short lines，每条被压成 3–4 行。
3
没人说谁是权威。两处内容一样、措辞一样、都没标注关系。用户要在半页之外自己发现「哦，下面那个才带结论」。
4
never-run 花掉两段散文。「从未跑过」是常态而不是异常，却在最窄的列里占了 5 行——而真正该抢眼的「7 条一条都没判」反而没有可扫读的图形。
成因（不是巧合）：服务端 parseCriteria 把 acceptance_criteria 的每一非空行剥掉列表符号后当作一条，于是 ② 的 criteria[] 恒等于 ① 的正文逐行切分。
唯一的信息差：① 会渲染 Markdown（粗体 / code / 链接），② 只显示纯文本源码。合并时必须把这半点差补回去。
