Providers · 把「本机登录的 Claude / Codex / Kimi」放进来

今天 /providers 只回答一个问题:我贴过哪些 API key。但 Orbit 绝大多数会话跑的是另一种身份 —— runner 机器上用订阅登录的 claude / codex / kimi CLI。它们在这一页完全不可见,于是: 新用户看到 “Anthropic (Claude)” 卡片就去申请 API key(其实订阅已经够用);引擎掉登录只能靠发消息撞错误卡才发现; runner 已经上报的订阅额度无处可看。
主张:这一页改成回答 “我的 agent 的模型从哪来”,分成两段 —— On your runners(登录来的,按机器生效,花订阅) / Your API keys(贴进来的,全账号生效,按 token 计费)。前者放上面,因为那才是新用户手里已经有的东西。

A1完整页面 — 两段式 ✓ 推荐
上段按 runner 分组(登录是按机器生效的,这是唯一诚实的分组方式),下段是今天已有的 key 表格 + 画廊,一行没动。
  • 为什么按机器分组而不是按引擎:一次 claude auth login 只写这台机器的 ~/.claude。 “Claude 已登录” 这句话单独说是假的,必须带机器名才成立 —— 分组方式必须让这件事没法说错。
  • 每行四列:身份(logo + 引擎名 + CLI 版本/默认模型)· 状态 · 订阅额度 · 动作。额度用 runner 已经上报的 planUsage,不是新数据。
  • 段落副标题各自把话说全:上段 “spends the subscription you signed into on that machine”, 下段 “on your account, usable from every runner”。用户唯一在乎的差别是在哪儿生效、谁付钱,就写这两件事。
  • 画廊卡片补一句本机提示:Anthropic / OpenAI / Kimi 三张卡在对应引擎已登录时,副标题变成蓝色的 “Already signed in on mac-studio” —— 把用户从「多花一份钱」上拦一下,但卡片依然可点(第二把 key 是合法需求)。
  • 右上角 Add provider 保持只管 key。给引擎加身份的入口是行内的 Sign in,不塞进那个按钮。
    • A2状态全谱 — 一行能落在的所有格子
    五种状态各自的措辞和动作。原则:只有探针明确报 yes 才敢说 Signed in。
  • Signed in → 绿 pill + 计划名 + 额度条 + 重置时间;动作收进 ⋯(Re-sign in / Sign out)。
  • Signed out → 琥珀 pill + 主按钮 Sign in,直接走已有的浏览器中继(RunnerSignIn),不用去那台机器开终端。
  • Not installed → 灰 pill + 主按钮 Install。这是全站唯一能主动装引擎的地方:按需安装 (ensureEngine())只发生在 register 时同意过 AutoInstallEngines 的机器上, 拒绝过的、以及在这个问题存在之前注册的老 runner(零值 = 不允许),会话会直接以 engineMissingMessage 失败,而用户在界面上无路可走。这个按钮就是那条路。
  • 为什么 Install 不并进 Sign in:① 两件事的失败原因不同 —— 装不上是网络/权限(EACCES、代理), 登不上是账号;合成一个按钮,错误就没法讲清楚是哪一步炸的。② BYOK 也要这个 CLI —— preset 的 runtime: 'claude' | 'codex' 表示它借壳跑,Gemini / DeepSeek 的 key 在没装 claude / codex 的机器上一样跑不了,而那种情况根本不需要登录。 装完这一行自动翻成 Signed out、Sign in 就在原地,两步是连着的,不会多走冤枉路。
  • Installing… → 蓝 pill,行内摊开正在跑的那条命令,给 Cancel。文案明说“可以离开这页” —— 装机是分钟级的,盯着看没意义。
  • Install failed → 红 pill,把那台机器自己的报错原样贴出来(EACCES / 代理不通之类),给 Retry, 并附上 engineSpec.installAlt 里的备选命令可复制。只写一句“失败了”等于把人扔回终端。
  • Unknown → CLI 的探针返回 authUnknown(三态里的第三态)。绝不猜成 Signed in;写 “Can't tell — run a session to find out”。
  • Runner offline → 整卡降透明度,状态显示最后一次心跳的快照并标 “as of 2h ago”,按钮全部禁用。 离线机器上的登录状态我们确实不知道,UI 不许假装知道。
    • A3登录进行中 — 中继直接在行内展开
    复用 RunnerSignIn 组件(今天只长在 Transcript 的报错卡里),两种流程两种形状。
  • claude:回调地址是 Anthropic 托管的,页面会给一串 code,所以形状是「开页 → 粘贴 → Submit」。
  • codex / kimi:device flow,一次性码显示在这里,让用户去页面上输,CLI 自己轮询批准 —— 没有可粘贴的东西, 所以这里只能等。别给一个假的输入框。
  • 两者都要预告延迟:runner 下一次心跳才接单,最坏半分钟。文案沿用现有的 “The runner picks it up on its next check-in”,不要在这里重新发明。
  • 一台 runner 同时只能有一个中继在飞(Runner.loginStatus 是单槽)。所以进行中时,同卡其它行的 Sign in 置灰, 提示 “Another sign-in is running on this machine”。
    • B备选 — 按引擎分组
    和这一页“provider 列表”的语感更一致;机器多、引擎少的时候更短。
  • 好处:和下面那段 key 列表长得像,一眼是同一页的两段。摘要行 “Signed in on 2 of 3 runners” 能一句话交代全局。
  • 坏处:把“登录是按机器的”这件事藏进折叠里 —— 恰恰是这一页最需要教会用户的一件事。默认折叠时 “Claude Code · Signed in” 会被读成账号级已就绪,而这正是今天误解的来源。
  • 结论:除非 runner 数量常年 > 5,否则不选。真到那天,直接上 C。
    • C备选 — 矩阵(机器多时的收敛形态)
    行=runner,列=引擎。6 台以上机器时 A 会太长,这个形态一屏能看完。
  • 格子点开是浮层,里面就是 A 的那一行(状态 + 额度 + 动作,含 Install),所以两个形态共用同一套行组件,不是两份实现。
  • 缺点:额度条摆不下,只剩状态词;订阅还剩多少要多点一次才看得到。
  • 建议:runner ≤ 4 用 A,更多自动切 C,不做手动切换开关 —— 这不是一个值得让用户选的选项。
    • D空态 — 一台 runner 都还没有
    这一页第一次被打开时的样子。不能上来就是空表格 + 一堆等着收钱的 logo。
  • 先给不花钱的那条路:装 runner → 用你已有的 Claude / Codex / Kimi 订阅登录。API key 是并列的第二条路,不是第一条。
  • 没有 runner 时上段只有这一块引导;有 runner 但三个引擎都没装时,卡片照常显示三行 “Not installed”, 因为那才是真话,而且 Install 按钮就在那儿,装完接着 Sign in。

    • 数据来源 — 这版设计要用的每一个字段

    引擎已装 / 版本 / 是否登录需要新增 · runner 心跳补一个 engines[]。 探针本身已经写好了:src/runner-go/doctor.go 的 checkEngine() 已经产出 {installed, path, version, auth},auth 就是 authYes|authNo|authUnknown 三态。 现在这些只打印给 orbit doctor 看,没有上报。改动 = 心跳带上 + Runner.engines Json? 一列 + GET /runners 透出。
    订阅计划 / 额度 / 重置时间已有 · Runner.planUsage(PlanUsage.claude / codex / kimi,每个是 PlanUsageSnapshot)。runner detail 页已经在渲染同一份数据,这里复用 planUsageRows()。
    默认模型已有 · Runner.runtimeDefaultModels(引擎自报的 effective default)+ modelCatalog。
    引擎安装(Install 按钮)需要新增 · 一个和登录中继同形状的安装中继: 心跳下发 “装 X”,runner 跑完把结果(成功 / stderr 尾巴)回报。要执行的东西全是现成的 —— 命令在 engineSpec.installCmd / installAlt(doctor.go:54),执行在 runInstallCmd() / ensureEngine()(engineinstall.go), 今天只是仅有“会话内按需触发”这一个入口,且被 AutoInstallEngines 一次性同意位挡着。 UI 上按下 Install 本身就是这一次的明确同意,不该再受那个开关影响。
    登录中继(A3)已有 · Runner.loginStatus / loginEngine / loginUrl / loginUserCode / loginMessage, 加 <RunnerSignIn runnerId engine />。组件不用改,换个挂载位置。
    runner 在线 / 名字 / 版本已有 · GET /runners(online、displayName、 version、lastHeartbeatAt)。
    API key 段已有 · GET /providers/mine,表格和画廊一行不改,只换段落标题和副标题。

    取舍与边界

    不做:引擎的开关引擎不是 “enabled/disabled” 的资源 —— 装了且登录了就能用。加一个开关等于凭空造一层状态。
    不做:在这页删登录“Sign out” 收在 ⋯ 里,不给独立按钮。清掉一台机器的凭据是个破坏性动作,不该和 Edit/Delete 一样显眼。
    老 runner 的兼容没上报 engines[] 的旧 runner:整卡显示一行 “This runner is on v0.1.7x — update it to see engine status”,不要拿三行 Unknown 糊过去。
    OpenCode 呢不进这一段。它是第四个 AgentProvider 但不是 LoginEngine,没有可中继的登录流程, 放进来会多出一行永远只能显示 Unknown 的东西。
    iOS / macOS本稿只画 web。原生端如果跟,建议直接跟 A 的行组件(logo + 名 + 状态 pill + 额度条), 两端的 runner 详情页已经有同款额度条,视觉不用新造。
