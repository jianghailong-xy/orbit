Task 从「我这个会话的现场」起步；codeless 任务不留空分支

设计见 docs/task-fork-from-session-design.md。① 今天和新方案对照 · ② 快照和组件 · ③ 一次 fork 的时序和 git 历史 · ④ codeless 任务 · ⑤ 待定 · 要你拍板，和落地顺序。界面文案仍是英文。

① 今天 vs 新方案

不给 agent「新 worktree / 在我的 worktree 里跑」的二选一：两个会话写同一个目录会互相覆盖，Project 契约刚把退回共享目录的路都堵上。要接着谁的工作干，就开一个从那份工作起步的独立 checkout。A（接着我的分支）和 C（接着我还没 commit 的改动）是同一个机制。

今天

会话 X 在自己的 worktree 里改了一半，调 task_create参数里没有任何关于 worktree 或起点的字段
↓
新任务从 workspace 的 workDir HEAD 分出来看不到 X 的分支，更看不到 X 没 commit 的改动
↓
绕路：X 先 commit、合进主 checkout，再建任务半成品进了主线；或者干脆不拆任务，自己做完
↓
codeless 任务照样建 worktree 和分支跑完留下一条空分支，runner 从不删分支，看着像没做完的活
拆不出「接着改」的子任务半成品被迫进主线空分支堆积

新方案

task_create { …, forkFromSession: true }只能 fork 调用者自己这个会话（D6）
↓
runner 给 X 的 checkout 拍快照 S，X 一个字节都不动临时 index：HEAD + 未 commit 的改动 + 未跟踪文件；干净时 S 就是 HEAD
↓
新任务在同一台 runner 上开自己的 worktree，从 S 起步SOURCE 钉死在 S：重试也从 S 起，找不到 S 就拒绝，不退回 workDir
↓
做完：X 自己 git merge 任务分支，记 merge_receiptcodeless 任务：独立 checkout，没改动就不建分支（B2）
A 和 C 一个机制发起会话不被打扰起点可复现不留空分支

② 快照和组件

快照在 orbit mcp 进程里同步完成：它就跑在发起会话的 runner 上，checkout 路径是确定的 worktreesDir()/<sessionId>，不需要新的 runner 指令。服务端只是在 SOURCE 表里多一行。

GIT_INDEX_FILE=tmp git add -A → write-tree → commit-tree -p HEAD = S

保活 ref 新

refs/orbit/fork/<id> → S，防 gc；没有未结束的任务引用 S 时由现有 gc 删

X 的 checkout 不动

index、暂存区、工作文件、分支、历史全不变

API server

SOURCE 表 PF 行 新

无 codebase 且 forkSha 非空 → SESSION_FORK，SHA 值，RUNNER_LOCAL 指向 X 的 runner

放置约束 新

只派到 X 的 runner；别的 runner → FORK_SOURCE_NOT_REACHABLE；绑了代码库的 Project → FORK_IN_BOUND_PROJECT

pin / 拒绝 / 理由 复用

SR12 不换基线、SR19 不回退、SR18 理由：「Forked from session … at abc1234 (includes uncommitted changes)」

runner · 新任务的会话

setupSourceWorktree 复用

在 S 上 worktree add；仓库里没有 S 就拒绝，不去 fetch

强制有分支 新

workspace 关了 worktree 也开：和 X 共用目录正是要禁的

快照覆盖什么
X 的 checkout 里进不进 S说明
已 commit进（S 的父提交就是 HEAD）干净的 checkout：S = HEAD，不新建提交
已暂存 / 未暂存的修改、删除、改名进临时 index 从工作区重新读，X 自己的暂存状态不受影响
未跟踪的新文件进add -A；P0 验证大文件和子模块
.gitignore 掉的文件（node_modules、构建产物、.env）不进和 X 自己 commit 时一样；新任务要依赖就自己装

③ 一次 fork 的时序和 git 历史

X 有未 commit 的改动时调 task_create；之后 X 继续干活，回合结束时自己 commit 了同样的改动；任务做完，X 把任务分支合回来。

会话 X（发起者）
orbit mcp（X 的 runner）
API server
任务 T 的会话（同一台 runner）
创建
1
改了 a.ts、新建 b.ts，没 commit；调 task_create {forkFromSession: true}
临时 index 拍快照 → S（父 = H0）；写 refs/orbit/fork/…
2
POST 任务，带 fork {sessionId, sha: S, baseHead: H0}
校验 X 是调用者、assignee 在同一台 runner、不在绑代码库的 Project → 建任务
运行
3
继续干活；回合结束自动 commit → C1（含 a.ts、b.ts 和后来的改动）
派发：PF 行 → SESSION_FORK，pin = S
在 S 上开 worktree，分支 orbit/T；跑，commit → K
4
T 达到 DONE；task_await 的回执带分支、S 和合并命令
合回
5
git merge --no-ff orbit/T → M；调 merge_receipt
记录：T 的工作已进 X 的分支
git 历史

S = H0 + X 当时没 commit 的改动。C1 也含同样的改动，合并时两边相同，git 不报冲突。只有 X 在 fork 之后又改了 T 也改的同一处，合并才冲突。那是真冲突，由 X 处理。

④ codeless 任务：不留空分支

任务声明 codeless（调研、核对、发布这类不产出代码的）时怎么跑。

B1 不开 worktree
  • 和「在任务里 @ 开的对话」一样传 noWorktree，直接在 workDir 里跑。
  • 改动最小：一行。
  • agent 真写了文件，就写进主 checkout，和那里正在跑的别的会话混在一起。
B2 独立 checkout，有改动才建分支 建议
  • git worktree add --detach <base>：照样隔离，但没有分支。
  • 结束时没改动：删 checkout，什么都不留。
  • 有改动：这时才建 orbit/<name>、commit、上报分支和改动文件，不丢东西。
  • 代价：服务端要接受「结束时才报上来的分支」，只对这一类会话。

另记一个现有缺口，不在本设计里改：创建时就声明 codeless、后来又写了代码的任务，今天没有任何检查拦它；task-codeless.ts 只拦「事后改成 codeless」。

⑤ 待定 · 要你拍板

每项给了建议。D1、D3 决定会不会动到发起会话的 checkout；其余可以先按建议走。

D1 未 commit 的改动怎么带过去

A：快照提交放在旁路 ref 上，X 不动 · B：先在 X 的分支上真 commit 一次

建议 A：X 可能正改到一半，或有子 agent 在写；替它 commit 会改它的 index 和历史。

D2 fork 出的任务能在哪跑

A：只在 X 的 runner · B：把 S 推到远端，别的 runner 也能跑

建议 A：B 要可写的远端，还会把半成品推出去。

D3 谁把结果合回来

A：X 自己合，task_await 回执里给命令 · B：X 空闲时 Orbit 替它合

建议 A：B 要一个在活着的 checkout 上合并的新 runner 操作，还要冲突策略。

D4 绑了代码库的 Project 里能不能 fork

A：v1 拒绝 · B：允许，但要求 S 包含 Project 线

建议 A：否则协调者没落地的改动会绕过落地进入 Project 线。先在 Project 外用起来再说。

D5 codeless 任务怎么跑

B1：不开 worktree · B2：独立 checkout，有改动才建分支

建议 B2：保住隔离，常见情况什么都不留。

D6 能 fork 哪个会话

A：只能是调用者自己 · B：本账号任意会话（按 id）

建议 A：mcp 进程只读得到自己的 checkout；B 会让一个 agent 拿走另一个的半成品。

落地（按依赖排，后一期依赖前一期）
P0 摸底

真 runner 上：临时 index 拍脏 worktree（未跟踪、忽略、暂存、改名、子模块、X 持有 index 锁）；另一个 checkout 在 S 上开 worktree；X 自己 commit 同样改动后合回。

完成：每种情况有录下的过程；合回除故意制造的重叠修改外都无冲突。

P1 服务端

列和迁移；两个创建入口的 forkFromSession；PF 行和契约章节、交集用例；放置拒绝；理由文本。

完成：pg spec 建 fork 任务、领取，看到 SESSION_FORK pin 在 S、派到对的 runner；每种拒绝一个 spec。

P2 runner

mcp 里的快照；保活 ref 和 gc；fork 任务强制有分支。

完成：真 runner 演练：X 有未 commit 改动时 fork，T 再改一个文件，X 合回后两处改动都在；fork 前后 X 的 checkout 逐字节相同。

P3 codeless 和客户端

B2（runner 和结束上报）；web、macOS/iOS、Android 的任务和会话页显示 fork 来源（英文文案）；task_await 回执。

完成：没改动的 codeless 运行不留分支，有改动的留下分支和改动文件；各客户端都显示 fork 来源。
