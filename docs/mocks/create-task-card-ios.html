落地要动的地方（按代价排，前三条客户端即可，第四条要 runner）

  • 纯改版式（客户端）：单卡分支的 OrbitAskBody(impact: [], note: prose, detail: "Done when", rows: criteria) 换成「pill + meta + 标题行 + 两个 DisclosureToggle」。ApprovalCards.swift 一处；web 的 CreateBody 同结构（宽栏可以默认展开，但引导顺序和文案一致，抄同一份字符串）。
  • 头行改计数：Create task “标题”? → Create 1 task?，标题移到正文首行。文案常量与 OrbitAskPreviewTests 一起改。
  • transcript 行：ToolDisplay 里 mcp__orbit__task_create 现在落到 default 分支， 显示 orbit · task_create + 一坨 mono kv；批卡那行是「Create tasks · 3 independent tasks」。给单卡加一条同族的 行（Create task + 标题），抬头与折叠卡就成套了。
  • pill / meta 的数据（服务端，不是 runner）：放在 POST /runner/sessions/:id/approvals 落卡的那一刻 —— toolName 是 orbit_task_create 时用同一个 previewCreateMany(ownerId, {tasks:[input]}) 算一份挂进 input.preview，best-effort（读失败就照原样落卡）。放服务端而不是 runner：runner 是个只在发版时才更新的二进制， 放它那边等于「装着的每个 runner 都还在问老问题」。客户端 batchPreview(from:) 连解析都不用重写， 拿不到就退回「没有 pill 的那版骨架」（头 + 标题 + 两折 + 动作），依然比今天短得多。
  • 不给 pill 的情况也要说清楚：orbit_project_create 是同一张卡、同一处改（goal 折进 Description， 标准列表折进 Done when），但它没有 dispatch 这回事 —— pill 那一格对项目改成什么，等定了再画。
