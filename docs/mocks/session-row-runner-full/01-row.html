会话列表 · 「Runner full」这一行怎么写

场景：你在会话「卡片高度不一致确认」里发了一条消息，可这台 runner 的 16 个位置全被占了，消息只能排队，等有空位再自动送进去（queuedReason = runner_at_capacity）。 会话列表里这一行的第二行现在只写 Runner full。Web、macOS/iOS、Android 共用一套文字（queuedLabel / SessionLine），所以不管改成哪种，三端会一起改。 下面的行是按你的截图画的；界面文字照原样用英文，会话标题和消息内容都是示例。

先看问题：现在这一行少了什么

① 现在
设置页按钮对齐2m
Running Edit SettingsView.swift…
卡片高度不一致确认just now
Runner full
1
导出 CSV 的列顺序1h
Done. The columns now follow the table's own order, and the…
诊断
  1. 你说的话被顶掉了。本来第二行显示的是 You: 请确认卡片高度…，进了排队就整个换成 Runner full。在列表里只看这一行，分不清排着的是哪一条消息。
  2. 只有原因，没说结果。“Runner full”是 runner 那边的状态，没告诉你“会自动发出去、不用管”。灰色时钟加灰字，看着更像卡死或者出错了。
  3. 看不出要等多久。满了多少、等了多久都没写。这些数其实都在：会话里的那个弹框写着 HPC is running 16 of 16 sessions…，只是列表里不显示。
  4. 右上角的 just now 是这一行最后一次有动静的时间，不是开始排队的时间，所以帮不上忙。

三个方案

A · 消息原样保留，状态缩成前缀推荐
设置页按钮对齐2m
Running Edit SettingsView.swift…
卡片高度不一致确认just now
Runner full·You: 请确认三张卡片在窄屏下的高度是否一致，截图…
导出 CSV 的列顺序1h
Done. The columns now follow the table's own order, and the…

＋ 你说的话还在（和“用户输入是视觉重心”那条裁定一致）；状态词变短，只当前缀用；“You:”这种写法和正在跑的那一行一样，少一种样式要认。
－ 窄侧栏里消息会截得更短。等待时长和占用数仍然要点进会话才看得到（用 ④ 的悬停提示补）。

B · 加上占用数
设置页按钮对齐2m
Running Edit SettingsView.swift…
卡片高度不一致确认just now
Runner full · 16/16
导出 CSV 的列顺序1h
Done. The columns now follow the table's own order, and the…

＋ 改动最小，数字服务器已经发下来了。
－ 16/16 只是把 full 又说了一遍，你最关心的“什么时候轮到”还是看不出；数字跳得快，列表会一直闪；有 6 个位是后台任务占的，这种情况下 16/16 反而容易看错。消息照样被顶掉。

C · 改成大白话，加上已等时长
设置页按钮对齐2m
Running Edit SettingsView.swift…
卡片高度不一致确认just now
Waiting for a free slot · 3 min
导出 CSV 的列顺序1h
Done. The columns now follow the table's own order, and the…

＋ 一眼看出是在等、会自己走，等多久也有了。
－ 列表得每分钟刷新一次；和会话里已经批准的“Runner full”说法对不上（Run full / Batch full 也得另想词）；消息照样被顶掉。

④ 配合 A：悬停（iOS / Android 长按）看完整原因

鼠标停在前缀上，出来的就是会话里那个弹框的原话和等待时长（capacityHeldMessageText / capacityHeldWaited），不新写一个字。iOS、Android 没有悬停，就放进行的长按菜单里，或者干脆不做（见待定 ②）。

待定 · 要你拍板

  1. 选哪个方案：A / B / C。推荐 A：列表这一行该回答的是“哪个会话、在干嘛”。标题已经说了是哪个会话，时钟说了在排队，剩下最值钱的信息是你说的那句话。等多久、满多少要点进去才看，而会话里已经有现成的弹框。
  2. 要不要加悬停 ④：推荐 Web + macOS 加（只用现成的文字），iOS / Android 先不加，点进会话就能看到弹框。
  3. 前缀规则要不要推广：A 的“状态 · 消息”写法同样适用于 Queued、Runner offline、Runner updating 这几种排队状态。推荐一起改，规则一条，不留例外；不同意就只改 Runner/Run/Batch full 三种。

落地（按代价排）

  1. Web sessionLine 的 QUEUED 分支：有 lastUserText 就拼成 前缀 · sentLine，没有就跟今天一样；颜色沿用 queued 的灰色，前缀稍微加重。
  2. OrbitKit SessionLine.make 和 Android SessionLine.kt 按同样的规则改，补上 parity 测试。
  3. （如果选了 ④）Web/macOS 行上加 tooltip，内容复用 capacityHeldMessageText。
