iOS 会话列表 — 搜索模式照 Notes 走

规则：搜索模式只在点 X 时退出。在搜索模式里滑动或点空白处，只收起键盘；搜索框留在底部、保持展开，X 也还在。这和 Notes 一样。 Apple 的规范把 Mail 和 Notes 列为"底部搜索"的范例：点开后搜索框"变成键盘上方的搜索框"。 目前（本分支 3d920986c）的做法是不让空搜索框失去焦点，结果键盘一直挡住半屏，也就是 ①。 ②–⑤ 是照 Notes 改后的样子。所有 iPhone 画面都按 393pt 宽画。

待定 · 要你拍板

1. 空搜索时，列表区显示什么

A 保持原列表推荐 点开搜索时列表不动，开始输入才换成搜索结果，也就是 ② ③ 的画法。原列表本来就按最近活动排序，点开搜索时画面不跳。
B 换成 Notes 式的搜索页 点开就换成一页"最近会话"，跨所有工作区，和 ⌘K 面板空搜索时一样。更像 Notes，但一点开整屏就换了内容，而且大多数会话本来就在原列表里。

2. 怎么实现

A 用系统搜索框，失焦后把搜索态挂回去推荐先试 继续用系统的底部搜索框。系统因"空搜索框失去焦点"而退出时，我们把搜索态重新挂回去，但不弹键盘；点 X 的那一次则放行。 改动小，样式和 VoiceOver 都由系统负责。风险是 X 和失焦这两种退出可能分不清，或者挂回去时闪一下，所以要先在模拟器上跑 UI 测试确认。
B 自己画底部搜索框和 X 开发者论坛上给出的绕法：不用系统的搜索控件，换成自己的搜索框和关闭按钮，行为完全由我们决定。 代价是玻璃样式、滑动时隐藏、键盘避让、VoiceOver 都得自己做，iOS 以后改样式也要跟着改。A 不可靠时再走这条。

落地（按代价排）

  1. 撤掉本分支"空搜索框不让失去焦点"那两处改动（Platform.swift 的点击放行、keepsEmptySearchOnScroll）。切换工作区不清空搜索词这一条保留。
  2. 按实现 A 改：用 searchable(text:isPresented:) 自己记住搜索态，失焦退出时挂回去，点 X 时放行。
  3. 在模拟器上跑一轮 UI 测试，照着 ②–⑤ 截图：滑动、点空白、进会话再返回、切换工作区、点 X。如果 A 分不清 X，就改走 B。
