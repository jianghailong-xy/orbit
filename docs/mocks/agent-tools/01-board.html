数据从哪来

  • 连接状态 / 原因：引擎自己说的。Claude：system/init 的 mcp_servers（connected / failed / pending / needs-auth）和它实际列出的 mcp__orbit__*；Codex：mcpServer/startupStatus/updated，失败带原文。其他引擎不报这个，显示 Not reported 并写明原因。
  • 工具族与不可用原因：runner 用 orbit mcp 同一个函数、同一组开关算出本进程拿到的工具；原因用 runner 现成的句子（编排关、Watch / Wiki 未开）。
  • 版本：本会话 runner 二进制里的 contract / catalogue / primer / guide 版本。
  • 指令顺序：runner 知道这次用了哪个载体（Claude --append-system-prompt；Codex 按版本是 application context / developer message / turn input），面板按实际载体写角色。
  • 用法与示例：Go 里生成一份 JSON 给 web 和 OrbitKit，同时生成 docs/agent-tools-guide.md 和 Claude / Codex 托管 skill；测试保证提交的文件和生成结果一致。

不做什么

  • 不放开关、不放配置表单：开关仍在原处（Settings → Session orchestration、工作区 Instructions），抽屉只说明并链过去。
  • skill 只放长 playbook（多步计划、批量脚本、委派、排障），primer 和工具描述不依赖它。
