Turn 结束后的建议输入 —— iPhone 为准，web 同构

turn 结束后 1–2 秒，Claude Code 会给出一句「你接下来大概会打的话」（--prompt-suggestions，本机 2.1.293 实测）。 Orbit 把它放进空着的输入框：灰字加行尾一个 Use。点一下，文字填进输入框，不会直接发出；自己打字时它就让开。没有建议时界面和现在完全一样。 数据用 composer-card 那套：你的会话、Opus 5.5 · Max · Auto。虚线框和红点是标注，不是界面的一部分。

什么时候出现（全部满足）

  1. 有当前建议：最后一条 prompt_suggestion 之后，没有新的 user，也没有新的 turn_end
  2. 会话在 Open、可以发送（Completed、Trash 不出）
  3. 没有在跑的 turn（⑤）
  4. 没有待处理的审批或提问（⑥）
  5. 输入框空、没附件、没在回复某条（④）
  6. 上一轮没失败（API 错误、登录失效、限额各有自己的卡片）

什么时候消失

  • 开始打字（删空会回来）；任何一台设备发出消息；下一个 turn 开始
  • 不加 ✕：它不挡东西，不想要就去设置里关

为什么不放在对话末尾（虚线气泡）

  • 建议比 turn_end 晚 1–2 秒，那时插一行，正在读的内容会被往上顶；虚线气泡也容易被看成已发出的消息

建议从哪来

  • Claude Code 自带 --prompt-suggestions：result 之后 fork 一次请求（同模型、命中缓存、禁用工具），只要「你正要打的那句」：2–12 个词，跟随你的语言；拿不准、上一条出错、plan 模式、有待批权限时不给；第一轮不给
  • 实测（2.1.293，haiku）：用示例数据测试一下这段代码 +1.68 s；用一个含空值的示例 CSV 测试一下 +1.20 s；抢答时不出；--resume 后照常
  • 代价：每轮多一次整段上下文的缓存读，约等于 agent 多走一步，记在会话的 Claude 账号上
  • 范围：只开 Claude 引擎（Anthropic 账号）；手动会话 + 协调会话；任务列表自动跑的会话、Wiki 维护不开；设置里一个开关
  • 其他引擎（Codex、Kimi…）没有原生能力：二期可选，用服务端已有的 DeepSeek 补

要改的

  • runner：带版本门（≥ 2.1.293）加参数；建议帧记到刚结束的 turn 上，有在途 turn 就丢
  • shared / apiserver：新事件 prompt_suggestion（持久化，无迁移）；领取载荷 promptSuggestions；不推进 lastTurnAt，不进搜索、预览、推送
  • 客户端：ComposerView.swift（iPhone、iPad、Mac 同一份）、WorkspaceView.tsx 的 .composer-box、Android SessionComposer.kt；派生只有三行：收到 prompt_suggestion 记下，收到 user / turn_end 清掉
