④ 怎么跑起来：大部分是现有零件

新增改动现有，直接复用
1 找 workspace按当前目录找本机包含它的 workspace，和 session import 按 cwd 找的是同一段逻辑。
2 建会话用本机 runner 凭据建会话（import 已经这样建）；新增一个 终端占用 标记：租约 + 心跳。
3 前台起 Claudeclaude --session-id <uuid>，带 Orbit MCP、ORBIT_SESSION_ID，以及会话记录的 CLAUDE_CONFIG_DIR。
4 实时同步tail <uuid>.jsonl → parseImportTranscript 的增量版 → 现有的事件上报通道。
5 退出交还补发最后的记录，释放占用；排队的消息照常派给本机 runner，用 claude --resume 接着跑。
三个风险，落地时要先验证：
① 账号目录：runner 可能把 Claude 会话跑在某个账号自己的 CLAUDE_CONFIG_DIR 里。终端必须用同一个目录启动，否则 runner 之后 --resume 找不到 jsonl。
② 两个进程同时写：终端占着会话时，服务端绝不能把可执行的 turn 租给 runner。终端被 kill 掉时，占用要靠租约过期自动释放。
③ 同步保真：import 会拒绝回放对不上的转录，实时同步要逐批做同样的校验；Claude 压缩对话（compact）之后要整体重新同步一次。

附带收益：orbit resume <id> 也用同样的占用和同步，在恢复的终端里聊的内容不再从 Orbit 里消失。

落地（按代价排）

  1. CLI：TTY 里敲 orbit → 找 workspace → 用 runner 凭据建会话 → 前台起 claude --session-id。先不做实时同步，退出时走 import 路径一次性补全转录。

  3. 实时同步：tail jsonl，增量上报事件；orbit resume 也接上。
  4. D3 从"拒绝"升级为"终端里直接建 workspace"。
  5. 其他引擎：Codex（codex resume + rollout 文件），然后是 Kimi、OpenCode；DeepSeek Harness 和 Cursor 仍然拒绝，和 orbit resume 一致。
