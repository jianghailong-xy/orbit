Kimi Code 多账号 · web Providers 页：和 Claude Code / Codex / Antigravity 一样「+ Add account」，加账号时先选 kimi.com / kimi.ai

可以做：Kimi Code 的整个登录都在 KIMI_CODE_HOME 一个目录里（凭据只存文件，没有钥匙串），和 Codex 的 CODEX_HOME、Claude Code 的 CLAUDE_CONFIG_DIR 一样能一个账号一个目录；runner 的账号槽、登录中继和各端页面都是按同一份引擎名单（ACCOUNT_ENGINES）做的，Kimi 只是还没进名单。下面每张都是真实 web 控制台截图（同一套组件和样式，接口数据是造的）；「改后」是把提案写进组件后的原型截图（prototype.patch，只含 web 部分）。

说明

  • 为什么可以（2026-10-08 在 HPC 上核实，Kimi Code 2.1.1）

  • a登录整个在一个目录里。Kimi 把登录写进 <KIMI_CODE_HOME>/config.toml（managed:kimi-code provider 和模型列表）和 credentials/<key>.json。凭据存储只有文件一种：CLI 里只有 FileTokenStorage，配置里虽有 keyring 选项但没有实现。所以 macOS runner 也能分开——不像 Claude Code 在 Mac 上那份全机共用的钥匙串。
  • b实测：两个目录，两个登录。空的 KIMI_CODE_HOME 里 kimi provider list --json 是 {"providers": {}}，同一台机器的 ~/.kimi-code 是 kimi.ai 的登录；在临时目录里跑 kimi login --region … 也只写那个目录。
  • crunner 已经按目录跑 Kimi 会话。每个 Kimi 会话在自己的 overlay 里跑，overlay 借用的是会话环境里 KIMI_CODE_HOME 指的目录（kimi_home.go / kimi_acp.go）。所以把账号目录交给会话，就是 CODEX_HOME / CLAUDE_CONFIG_DIR 那一套。
  • d是没接，不是接不了。账号槽（account_slot.go）、登录中继（login.go）、移除、控制面和各端都看同一份引擎名单；代码注释原话是「Kimi, OpenCode today simply has no accounts」，Claude Code 多账号那次提交也写了「Not in this change: Kimi slots」。

  • Kimi 和另外三个不一样的地方

  • e站点。每个账号各属 kimi.com 或 kimi.ai：加账号先选站点（图 ③），每行写站点（⑦⑧），重新登录时 Current 是这个账号的站点（⑩）。
  • f没有额度。Orbit 现在不读 Kimi 的额度（单账号也是 No quota reported），所以 Automatic 排不出先后：新会话从 Default 开始，Default 掉线或暂停了才用下一个。
  • g对话存在账号目录里。Kimi 的会话记录在账号目录的 sessions/ 下（Antigravity 的在会话自己的目录里，所以它换账号什么都不用搬）。一个已经说过话的会话换到另一个 Kimi 账号，要把对话搬过去，像 Codex / Claude 各自做的那样。

  • 要改的地方（链路）

  • 1runner：新增 kimi_account_slot.go——账号就是一个 KIMI_CODE_HOME，Default 是 ~/.kimi-code，新加的在 <orbit home>/kimi-accounts/<id>；声明 kimi-account-login/v1、kimi-account-remove/v1。登录状态（kimi acp authenticate）和站点（kimi provider list --json）按账号目录各问一次，账号上报带 kimiRegion；会话 meta 记下账号目录（有会话在用时拒绝移除）；新账号目录先建好 sessions/，否则对话只落在会话的临时 overlay 里，进程一退就没了；模型列表像 Antigravity 那样读 Default（Default 没登录就读第一个已登录的账号）；orbit resume 的 Kimi 分支带上账号目录。
  • 2apiserver：migration 加 workspace.kimi_account、session.kimi_account / kimi_account_pinned；ACCOUNT_CHOICE / ACCOUNT_PINNED 和登录、移除、换账号三张 capability 表各加 kimi；心跳 sanitizer 保留账号的 kimiRegion；几处「only Codex, Claude or Antigravity」的报错文案。
  • 3shared：ACCOUNT_ENGINES 加 kimi，ACCOUNT_DIR_VAR.kimi = KIMI_CODE_HOME，RunnerEngineAccount.kimiRegion；accountOfEnv 认出 Kimi 自带凭据的会话（不占任何账号）。
  • 4web：这张图的原型就是改动本身（prototype.patch，约 30 行）：Add account 跟着 kimi-account-login/v1 出现；账号行写站点；Kimi 的加账号面板不自动开始；Current 取账号自己的站点；设备码提示写站点。工作区和输入框的账号选择器跟着名单自动带上 Kimi。
  • 5iOS / macOS / Android：keepsAccounts / canAddAccount 加 Kimi（看 capability），加账号表单接上已有的 Kimi 站点选择。规则同上，动手前另出 iOS 图。
