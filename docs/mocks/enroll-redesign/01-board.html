待定 · 要你拍板

下面两项会动服务端或 CLI，其余改动都只在 web。

1. 加不加 Deny（拒绝）

今天的页面只能批准。orbit login 的审批页已经有 Approve 和 Deny 两个按钮。

A加 Deny推荐

服务端：DeviceEnrollment.status 增加 DENIED，新增 POST /runners/device/:code/deny，轮询返回 denied。CLI：收到后打印 “registration was denied in the browser” 并以非 0 退出。两张审批页的行为一致；遇到别人发来的链接，也有一个明确的动作可以拒绝。

B不加，只改页面

改动只在 web。不是你发起的请求只能关掉页面，10 分钟后自动过期，终端一直等到超时。效果图里的 Deny 按钮和 “Request denied” 页去掉。

2. 要不要显示请求来源 IP

验证码防得住“开错了链接”，防不住“设备码钓鱼”：别人在自己机器上跑 orbit register，再把链接发给你。他发来的链接里，验证码和页面上显示的永远一致。真正能防住的是“这个请求从哪里来”。

A这次不做，单独开一个任务推荐

这次只重做页面。来源 IP 牵涉服务端怎么取到真实 IP（反向代理的 X-Forwarded-For）、IPv6 显示，以及这类信息展示多少合适，单独做更稳。
