原生端

iOS / macOS：Settings › Sessions 页加 Translation 分组（macOS 在 ⌘, 的 Settings 表单同位置）。语言行点进去是单选列表。

Android：Settings › Sessions 同位置一个分组，语言行点开 bottom sheet 单选。

会话里三端一致：气泡下 “Translated · Show original”，进行中 chip，失败行 Retry / Send as written。

翻译在服务器做，客户端只读字段并画切换——所以三端差别只在 UI。

⑪ 怎么跑（服务器侧，三端共用）

环节做法
你的消息发消息时 apiserver 看到 Translation 开着：先用 DeepSeek 把中文译成英文，turn 存两份——prompt（引擎拿到的英文）+ displayPrompt（你写的中文）。译完才排给 runner；排队、steer、编辑排队消息都走同一处。
Agent 回复每个 assistant 文本块落库后（流式结束），后台队列（同 recap 的 AsyncWorkQueue 套路）译成中文，写一条 translation 事件 { of: seq, text, lang }，实时推给在看的客户端；刷新时随事件页一起回放。
不翻tool_use / tool_result / thinking / 命令输出 / 代码块与行内代码 / 文件路径。Prompt 里要求模型原样保留 code 与 markdown 结构。
成本一条消息一次 DeepSeek 调用；回复按文本块计。服务器 key 付费，不占会话自己的额度。
会话标题、recap标题按你的原文（中文）起名，不变；recap 已按会话语言写，不变。

要动的文件（大致）

shared：dto.ts UserPreferences + turn/事件字段，enums.ts RunEventType.TRANSLATION · apiserver：prisma 迁移（user 三列 + conversation_turn.display_prompt），新 sessions/translation.ts（复用 deepSeekCall），turn 入队处、事件 ingest 处 · web：SettingsPage.tsx、Transcript 气泡脚注、Composer 标记 · iOS/macOS：OrbitKit SessionSettings、会话气泡 · Android：SettingsScreen、会话气泡；三端 copy parity 测试。

⑫ 待你定（每项推荐 A）

  1. 你的消息翻译失败时（J）
    A 不发，标红 “Couldn't translate, so it wasn't sent · Retry · Send as written”　/　B 直接发中文原文，脚注标 “Sent untranslated”
  2. 回复还在流式输出时（H）
    A 先灰显英文实时滚动，结束后换成中文　/　B 隐藏，只显示 “Translating…” 直到中文出来
  3. Agent 的提问卡片与选项、权限审批的说明、Suggested replies
    A 一起翻（你点中文选项，引擎收到英文）　/　B 保持英文
  4. 翻你的消息时等多久（G）
    A 发出后气泡显示 “Translating…”，通常 1–3 秒，超时 20 秒按失败处理（同第 1 项）　/　B 发出前在 composer 里先给你看英文预览，再点一次发送
  5. 语言列表（B）
    A Your language 给常用几种（Chinese Simplified / Traditional、Japanese、Korean、Spanish、French、German），Agents work in 固定 English 不给选　/　B 两边都自由选　/　C 只做 中文↔English
  6. Composer 标记的写法（D）
    A “Chinese → English”（纯英文 copy）　/　B “中文 → English”（语言自称，需给 copyLanguage.test 加白名单）　/　C 不加标记
