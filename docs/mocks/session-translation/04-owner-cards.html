怎么做（服务器为主，三端只读字段）

环节做法
翻什么每种卡片列出它的“Agent 写的字段”（第 2 部分），一个共用函数照会话提问卡的 translateCard：整张卡全成功才算，失败就记 { failed: true }，卡片照原文画。代码、命令、链接、路径照旧不翻。
存哪每张卡自己的行加一列 translation（jsonb，带 lang）：project_open_item、owner_request、证据、确认审查、标准提案、crossing。会话里的 Orbit 卡已有 approval.translation，只是扩大要翻的字段。
什么时候翻卡片提交后在后台队列翻（和回复同一个 DeepSeek 队列），翻完写列、发一次刷新事件，客户端原地换成中文。见待定 ①。
你的回答每个能打字的门（回答问题、Owner request Done/Decline、Not yet、任务确认、Send back）都先把你的话译成 Agent 的语言再交付；翻不了返回 TRANSLATION_FAILED，什么都不记录。你的中文原话也存着，卡片上照常显示。
三端Web、iOS/macOS、Android：有译文就画译文 + Translated · Show original；没有就画原文。文案三端逐字一致，进现有的 copy parity 测试。
测试服务器：每种卡一个 spec（翻好 / 翻失败 / 翻译关）、每个回答门一个 spec（译成英文 / 失败拒收 / Send as written）。三端各一组卡片渲染测试。

  1. 什么时候翻
    A 提交时翻；另外，读到一张还开着、却没有你当前语言译文的卡（翻译是后来才开的、或换了语言），就补翻一次 · B 只在提交时翻，开翻译之前的卡保持英文 · C 每次打开时现翻（慢 1–3 秒，费用高）
  2. 你的回答翻不了时
    A 不发，显示 Couldn't translate, so it wasn't sent · Retry · Send as written（与会话提问卡一致）· B 直接发中文，加注 “Sent untranslated”
  3. 推送和飞书
    A 推送最多等译文 20 秒（翻译的超时），拿到就推中文，拿不到推原文 · B 立即推原文，不等 · C 先推原文，译好后再更新飞书卡片（推送不能改）
  4. 开了 “Show both languages” 时
    A 卡片仍只显示一种语言，用 Show original 切换（卡片要短，选项逐条配英文太长）· B 和对话一样每段下面附原文
  5. Handover 说明没有客户端画
    A 另开一个任务先把它画出来，不放进这次 · B 并入这次
