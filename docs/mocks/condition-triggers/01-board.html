待定 · 要你拍板
P1 探针能跑什么：A（建议） 卡上批准的那一条命令原文，声明只读，用工作区已有的权限跑；B 只能从 Orbit 内置的几种探针里选（磁盘、HTTP、命令退出码）。A 才接得住 Ceph 这类任意系统，代价是你要看一眼命令。
P2 放在哪：A（建议） Scheduled 页里多一组 “Waiting for a condition”（④）；B 单独一页。A 不增加入口，“以后会自己开始的事”都在一处。
P3 一次性条件一直不成立：A（建议） 30 天后问你一次“还等吗”；B 一直等，只在列表里显示。
P4 探针失败几次算“读不到”：A（建议） 连续 3 次（默认间隔下约 15 分钟）通知一次；B 第一次失败就通知。

落地（按代价排）

  1. Runner 探针：按间隔执行已批准的命令，带超时，随心跳上报采样。
  2. 服务端条件：模型、越线 / 持续 / 重新待命 / 未知的判定，采样历史。
  3. 定时任务 When 规则：和 Daily / Weekly 同级；执行、发现、信封、预算全部复用。
  4. Task Starts when：和 runAt 同级，走同一趟派发扫描；30 天提醒。
  5. Agent 工具：schedule_create 和 task_create 接受条件；创建前先跑一遍探针作为 Today。
  6. 客户端：创建卡的 When / Starts when 行、Scheduled 页的分组和读数、详情里的 Condition 块。先 iOS，再 Web、macOS、Android。
  7. 之后：外部事件入口；是否开放“信封内直接执行”。

1–3 做完，Ceph 90% 的例子就能用；4 做完，“等第三个 OSD”的例子就能用。
