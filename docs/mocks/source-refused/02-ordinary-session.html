普通会话「没跑起来」：同一张卡，原因全是机器侧的

补 01 那张图缺的一格：没有任务、没有项目的普通会话。它的「起跑被拒」不可能来自项目线， 只会来自机器 —— 这台 runner 跑不了这个引擎（没装 / 没登录 / runner 太旧）、runner 掉线、引擎起来就死。 好消息是这些原因每一句都已经在仓库里（runner-provider-support.ts 的四条升级句、 Transcript.tsx 的 repair 卡、reaper 的 runner offline）； 缺的不是句库，是这句话要落在一条从未开口的会话上：今天这条路径上页面只有 Starting。

三类原因、三种动作、今天各自的处境：

原因句子（现成）用户的动作今天
runner 太旧，跑不了这个引擎Waiting for a newer runner + runner 版本句 什么都不用按：runner 空闲时自更新，这次运行随后自己开始只有 antigravity/dsh 的 transcript 卡
引擎没装 / 没登录… isn’t installed on <machine> / … needs authentication Install / Sign in（Providers、runner 登录）同上，且只在被 claim 门挡下的会话上
runner 掉线 / 引擎起来就死Disconnected — runner went offline / 引擎自己的 stderr Send it again（掉线的会自动重试）词有了；0 轮猝死没有卡

普通会话与任务会话的差别只有两点：原因集合（这里全是机器侧，没有「线不存在」这一类）； 恢复语义（任务会话的 Start it again 要新建一次运行，普通会话直接重发即可 —— 会话本身可续，所以按钮是 Send it again）。 相同的两点：同一张卡（同一个事实）；同样依赖「拒绝/失败时把这次运行收尾」， 否则会话永远挂在 run_claimed_at 上，卡片和 Retrying 状态都画不出来。
