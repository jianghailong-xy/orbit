协调者停着时，证据卡不再找你，排队等它回来

截图那一屏（10-09 20:02）：项目的协调者 18:08 在 claude 上撞了周额度，run 落成 FAILED，会话还开着。19:59 一个任务交了证据，平台去投递时把「停着」当成了「结束」，直接拒收，于是这一版从交上来那一刻起就成了你的卡。之后你把协调者换到 DeepSeek，它已经跑起来了，卡还留在你面前：协调者回来时，没有任何东西会再把它投过去。20:03 你按了 Confirm done。

任务名、项目名、判据和缺口是示意文本，长度和结构照截图；时间是真实的。

为什么：代码里的四处
  1. 投递把停着当结束。bindQueuedDelivery 用 sessionHasEnded 判断，而它把 run FAILED 也算作结束。停着 = 拒收。
  2. 拒收就直接归你。没有投递记录的版本，readPendingEvidenceJudgments 直接放进你的 pending：那张卡、Needs you、Waiting for approval 都来自这里。
  3. 投出去以后再停，也一样。coordinatorHolds 同样用 sessionHasEnded，协调者一停，持有就作废。更糟的是：失败时排着的消息会被直接标成已答，协调者其实没读到；它若 2 小时内被救回，卡又从你面前消失，结果谁都没在判。
  4. 回来也不补投。证据只在「提交」和「任务换项目」两个时刻投递。

对照：异常待办早就分清了「停着」和「结束」（conversationIsDown）。协调者停着时，待办仍归它，等它一轮跑完时补投（契约 §4.4 X-D4 3）。证据没走这条路。

近 7 天，Automatic 项目一共交了 385 版证据：协调者判了 333 版，你判了 31 版。

建议：停着不算结束。卡排队等它，回来就投给它；你想自己判，随时可以

待定 · 要你拍板

1. 协调者停着时，这张卡在你那边是什么样。你那句「可以加入队列」，可以是平台自己排，也可以是卡上加个按钮、由你来排。平台自己排的话，排着的卡还有两种画法。三种并排放在下面，每张底下标着在手机上占多高。

推荐 A
  • 停机时你要知道的是「有东西在等它」，不需要再读一遍整张卡。A 一张灰卡约 230 pt；B 和 C 都在 780 pt 以上，比截图里对话区能看到的高度（约 408 pt）还高，看上去和今天差不多。
  • A 用的是现成的样子：收起态加 View details 弹出页（协调者提问卡），状态行加「You can still …」那句（任务确认复核时的 Under review）。
  • Automatic 项目近 7 天的 385 版证据里，协调者判了 333 版。由它判是常态，停机只是让它晚一点判。
B、C 的好处
  • B 少点一次：判据和缺口不用点开就能看到。任务确认在复核期间就是这样，整张照画，可以按，但不算你的；不过那张卡本来就短。
  • C 每张都过你的眼，由你决定等不等。代价是每次停机你都得一张一张按，和 10-08 你定的「协调者拿着的事由它自己办完」相反（契约修订 13）。

2. 停着期间要不要设等待上限。停机能有多长：账号轮换只要 33 秒（10-09 有一个任务会话自己换了账号接着跑）；5 小时额度是几个小时；周额度要好几天。下面是截图那一晚的真实时间。

推荐 A：不设上限
  • 停机的解法是让协调者回来（换模型、换账号、等重置），而不是让你替它判。排着的卡和停机原因你都看得到；觉得等不了，换模型也只是一次操作，截图那次你就是这么做的。
  • 设了上限，周额度这种一停好几天的情况，卡照样会全推给你，又回到了今天。
B 的好处
  • 有兜底：你几天不看手机，任务也不会一直卡着。异常待办今天就是这样（契约 §4.6 X-E1：协调者停着也照样计时，到点变成 Escalated to you）。上限可以沿用项目的 exceptionEscalationSeconds（默认 2 小时），也可以单独定成 24 小时。

落地（按代价排）

  1. 服务端：停着不算结束，回来补投，读接口多一组服务端
    持有和投递改用 conversationIsOver；停着时不往它那儿写 turn；补投挂在每一轮结束的钩子上和换协调者的地方；投递那一轮没读到的（被失败清掉、deliveredAt 为空），回来时补投一次；readPendingEvidenceJudgments 多一组 waitingOnCoordinator。只做这一步的话：停机时卡不再来找你，回来后自动投给它；但客户端还不认识新的那一组，停机期间对话里只看得到额度提示，看不到排着的卡。
  2. iOS / macOS：灰卡、弹出页、胶囊iOS / Mac
    灰卡用待办的收起样式，弹出页直接复用今天的 EvidenceDecisionCard。新文案和 Web 共用一份，沿用现有的 copy parity 测试。
  3. Web：同上Web
  4. Android：同上Android
  5. 可选 · 异常待办也改成停着不计时服务端 + 契约修订 14
    今天待办在协调者停着时照样走 2 小时的表，到点变成 Escalated to you。要和证据一致，就改 §4.6 X-E1。
  6. 可选 · 另外两处「停着当结束」服务端
    任务确认复核：投递时协调者停着，就直接记成没复核，而且不可逆。「项目看起来做完了」：投递被拒，连 Record as done… 都不会出现。按同一条规则改。

建议先做 1 和 2（一个服务端任务、一个 iOS 任务），3 和 4 跟上；5 和 6 等你说要再做。
