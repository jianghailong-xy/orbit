怎么认出这一轮（不改 agent 读到的字）

  • 派发任务时，apiserver 在 user 事件的 payload 里另存一份 taskStart 快照（任务 id、标题、项目、描述、验收标准、判据与命令、来源），做法照搬 withOpenItemDelivery。text 一个字不动，引擎续跑还要重放它。
  • 客户端只认 payload，不按「请开始执行任务「」这个前缀去猜，这是 open-item 卡定下的规矩。没有 payload 的历史事件照旧画成气泡；要不要回填历史另议，那要改生产库的 run_event。
  • 卡上画的是派发那一刻的快照，跟 agent 读到的一致；任务后来改了描述，看最新版请点 Open the task。

顺带要一起改的

  • sticky 条：从「↑ Your question · 请开始执行任务「…」」改成「↑ Task started · runner + web：配额按账户归属」（StickySummary.of 加一支）。
  • 同一任务在老会话里重跑，派发 prompt 会作为新一轮进来，也画成这张卡，不只管第一条。
  • web 和 macOS 用同一张卡，文案放 OrbitKit，由 copy-parity 测试对齐 web。
  • UI 文案用英文（按现有约定），任务内容保持原文。
