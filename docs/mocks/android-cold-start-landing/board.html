待定 1：这一页要不要整页跟 iOS

A 整页跟 iOS（推荐）。就是第 1 张的 b、c。打开后第一眼就是这一页，样例里一屏能看到 8 条而不是 4 条；你两台手机看到的是同一个东西。项目目标也写了“业务页面结构尽量与 iOS 一致”，这页当年没做到，同数据双端对照也一直留着缺口。代价是改动大，见下面第 4、5 条。

B 只改打开时的行为。落点、存行、只读 Open、去掉状态字和灰按钮都照做，页面保持左边这样：搜索框、两排按钮、⋮ 不动。改动小很多，以后再对齐也不白做。

第一版的四项，现在都按 iOS 定了

  • 落到哪：上次用的，没有就第一个。每台手机、每个账号各记各的，退出登录就清掉。
  • 第一屏：手机存一份工作区和 Open 列表，离开前台时写一次。代价：刚打开时行可能是旧的（比如已结束的还写 Running），读完就换掉；iOS 也一样。
  • 读取中：什么都不显示。第一版推荐的右上角转圈撤掉。
  • New session：不灰，新建页也不等目录读完。行的菜单同样不等；操作被服务器拒绝时走现有的提示。

落地（按代价排）

  1. 状态和灰按钮：DirectoryStatus、NewSessionComposer、DirectoryActions；抽屉加 Can't reach Orbit 行。
  2. 落点：MainActivity 记住上次工作区；名字页删掉，只留“还没有工作区”和转圈。orbit://active 也改到落点。
  3. 只读 Open、存一份：RealtimeRest、RealtimeCache，解码挪出主线程，账号主题也存进去（iOS 首帧用对主题靠这个）。SessionProjectPage、DrawerProjects 不能再假设内存里有 Completed。
  4. 页面（只有 A）：DirectoryScreen 重写：顶栏、底部搜索、紧凑行、长按、下拉刷新、列表页胶囊。
  5. 测试：23 个测试文件靠点名字页进工作区，12 个靠 ⋮；设备旅程按 API 29–36 重跑，TalkBack 要重走一遍（长按已带读屏动作，没验过）。

还没验证

  • 全部是模拟器上的 debug 包，没上过你的手机。启动到列表画完 2.62–3.33 秒（6 次，主机负载 10–15）；项目的门槛是真机 release 3 秒。
  • 只读 Open 之后一次读取要几秒没量过。今天的 7–10 秒是 11-02 在你手机上量的，大头是 Completed（18.3 MB）；要上真机才知道。
  • iOS 那张是 10-21 的探针图（11-01 的探针图结构相同），数据和右边不同，没有做同数据对照。
