Web · 建议输入：去掉「Use Tab」胶囊，把 Tab 提示写进灰字里

你说「Web 不需要展示 Use Tab 这个，如果要提示 Tab，是否可以展示在提示文字的输入框里」。可以：胶囊整个去掉，灰字后面紧跟一个小小的 Tab 键帽，就是左栏搜索框里 Ctrl K（Mac 上是 ⌘K）的那种键帽。 下面每一张都是真实会话页的截图（vite + 仓库里 ui-migration 的会话 fixture，加一条 prompt_suggestion 事件）：「现在」取自 main bc790273c，「改后」是同一份代码按方案改了 WorkspaceView.tsx 和 index.css 跑出来的，不是画的（这两个文件在最新 main 870e33a1f 上没有变化）。虚线和编号是标注。只改 Web；iPhone、Android、Mac App 不动。

桌面 Web有键盘：1280 宽窗口，光标在输入框里
现在① 行尾一个「Use [Tab]」胶囊
①去掉

灰字后面空出一大段，行尾是蓝色的 Use 按钮，按钮里再套一个 Tab 键帽。窗口越宽，它离那句话越远，看上去像另一个控件，而且是整个输入框里最显眼的东西。

改后② 灰字后面紧跟一个 Tab 键帽 推荐
②Tab 键帽

胶囊去掉了。键帽紧跟在建议后面，和左栏 Ctrl K 同一种画法：细边框、无底色、灰字。它和灰字一样不接收点击：点这一行的任何地方，都只是把光标放进输入框，自己打字。按 Tab 填入、不发送，跟现在一样。

桌面 Web细节
状态③ 光标不在输入框：只有灰字，没有键帽

比如刚从左边列表点开这个会话。这时按 Tab 是在页面上切换焦点，不会填入，所以这时不提示 Tab。点进输入框（或用 Tab 走到它）键帽就出现，变成 ②。

状态④ 按 Tab 之后（和现在一样）

建议填进输入框，光标停在末尾，发送键变蓝；不发送，可以接着改。键帽随灰字一起消失；删空后建议又回来，跟 placeholder 一样。

状态⑤ 长建议：灰字省略，键帽留在最后
⑤

建议最长约 100 个字。放不下时灰字在末尾省略，键帽不会被挤掉。

状态⑥ 深色

键帽只用主题的边框色和灰字色，深色下自动跟着变。

手机网页⑦ 触屏没有 Tab 键（手机浏览器、没接键盘的 iPad）
甲 · 保留 Use 推荐
⑦
乙 · Use 也去掉

甲和现在逐像素相同（现在的触屏本来就只有 Use、没有键帽），也和 iPhone App 一样。乙更干净，但手机上没有 Tab，就没有任何办法一下填入，建议只能看。

备选别的写法（都试过，不推荐）
⑧ 键帽放行尾 占的正是原来胶囊的位置，离那句话远，看着像没改。
⑨ 写成文字「· Tab to use」 和建议同色同字号，读起来像建议的一部分。
⑩ 不提示 最干净，但没人知道按 Tab 能填入。

② 用的键帽就是左栏这一个（.session-search-kbd）：同样的边框、圆角、字号，没有发明新样式。

规则改了什么、没改什么
情况现在改后
