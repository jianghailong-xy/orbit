⑤ 规则、文案、改哪里，以及要你拍板的一件事

什么时候算「更新」，什么时候算「停止」

runner 心跳今天建议
draining，phase = draining / restarting（真的在等装 0.1.x）Runner updating不变：Runner updating · updating to 0.1.x · Later ▾ · Update Now…
draining，没有 phase（已是最新版，进程在停）Runner updating，无版本号，只有 Later ▾Runner stopping，无按钮 ← 你截图里的情况
draining，phase = available / postponed（有新版在等，但这次 drain 是因为进程在停）Runner updating + Later ▾ + Update Now…Runner stopping，无按钮（这时按 Update Now 也没用：进程正在退出）

怎么区分（只改服务端一处判断 + 四端读一个字段）

服务端：心跳 draining 但 self_update.phase 不是 draining / restarting，就是「停止」。session 行的 queuedRunnerUpdate 和 runner 的 drainWaiting 各加一个 stopping: true；queuedReason 仍是 runner_updating，所以还没升级的 iOS / Mac / Android 老版本照旧显示今天的样子，不会出错。runner 不用发新版本。

待定 · 要你拍板

方案代价
A（推荐）叫 Runner stopping。runner 只知道自己收到了停止信号，不知道会不会被重新拉起（systemctl restart 和 stop 发的是同一个信号）。说「停」永远是真的，后面那句「once HPC is back」把「要等它回来」说清楚。你在 HPC 上 restart 的时候，看到的是「stopping」而不是「restarting」，稍显冷。
B叫 Runner restarting，更贴近最常见的情况（重启服务、发新版）。如果是真停（stop 或关机），这句话就是错的，而且 session 会一直等。
