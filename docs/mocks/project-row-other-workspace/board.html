Web：项目条目在别的 Workspace 里，不再把你带走

一个项目在每个有它的会话的 Workspace 里都有一行。这一行在 coordinator 所在的 Workspace 里代表 coordinator；在别的 Workspace 里，它收的只是那个 Workspace 自己的会话。今天方向键和「从侧栏进来时默认打开哪条」仍把它当 coordinator，于是在 orbit-prod 里会被带去 orbit-develop。每张图都是真实 Web 控制台的截图（vite 加假数据：今天 = main 0868a3f21，建议 = 同一棵树打上 prototype.patch）；会话名和项目名是示例，红色虚线和数字是标注。

① 今天在 orbit-prod 里按 ↓，到了 orbit-develop

→↓
  • orbit-prod 里的这一行，收的是项目放在 orbit-prod 的两个会话（生产只读核查、生产部署）。22m ago、不转圈，都只算这两个；coordinator 不在 orbit-prod。
  • 按 ↓，方向键把这一行当成 coordinator：打开的是 coordinator 的会话，列表跟着它换成 orbit-develop 的，侧栏亮到 ⌘1。
  • 右栏是 coordinator 的对话，带 Coordinator 标。
  • 同一个项目在 orbit-develop 的那一行：1m ago、在转圈，算的是 orbit-develop 自己的会话（coordinator 和一个在跑的执行任务）。
  • 再按 ↑，在 orbit-develop 的列表里往上走，到了 Google 项目的 coordinator，回不到「证书轮换脚本」。
  • 换个时刻：这个项目在 orbit-prod 刚有动静，它那一行排第一。点侧栏的 orbit-prod，默认打开列表第一行，也就是这个 coordinator，结果还在 orbit-develop。只有这个标签页里在 orbit-prod 打开过别的会话，才会回到那一条。
  • 点这一行本身不会跳：10-05 起，点击进项目会话页（见 ②）。还按旧规则把它当 coordinator 的，只剩方向键和默认打开的那一条。

② 建议在别的 Workspace 里，这一行像文件夹行一样

方向键跨过它，默认也不打开它；点击照旧进项目会话页。在 coordinator 所在的 Workspace 里一切照旧。下面四张图是打了补丁的真实页面。

  • 按 ↓ 跨过项目这一行。文件夹行今天就不在方向键的路线上，这里同样处理。
  • 停在下一行「复查会话列表的设计」。
  • 还在 orbit-prod，侧栏不动；再按 ↑ 就回到「证书轮换脚本」。
  • 项目这一行排第一时，默认也不打开它……
  • ……打开 orbit-prod 自己的第一条会话。
  • 要找 coordinator：点这一行进项目会话页，它在 Coordinator 一节，点开照常切到 orbit-develop——这是你点的，不是被带过去的。
  • 在 coordinator 所在的 orbit-develop，这一行仍代表 coordinator：按 ↓ 到它就打开 coordinator。
  • 右栏是 coordinator 的对话，和今天一样。

coordinator 所在的 Workspace（orbit-develop）别的 Workspace（orbit-prod）

↑ / ↓打开 coordinator（不变）跨过（改）

第 2 行、进度小标签整个项目（不变）整个项目（不变）

待定 · 要你拍板在 orbit-prod 里按 ↓ 到这一行，做什么

推荐方案 A · 跨过（② 里的图）

和文件夹行一个规矩，列表永远是你看着的这个 Workspace 的。

改动最小：两处映射，+14 −4。

用键盘到不了这一行，要点它。

方案 B · 打开这个 Workspace 里最新的成员（左图）

键盘能到这一行，列表也不动；① 这一行跟着高亮。

② 右栏打开的是「生产只读核查」，和这一行的标题对不上；成员不止一个时，只到得了最新那个。

不推荐方案 C · 照旧打开 coordinator，但列表留在 orbit-prod

要让会话地址记住列表来自哪个 Workspace（多一个参数）；左边 orbit-prod 的列表，右边 orbit-develop 的对话。

这一行还是被当成 coordinator，和点击（进项目会话页）不是一回事。
