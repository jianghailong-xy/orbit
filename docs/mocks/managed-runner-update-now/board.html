1 · How Orbit Cloud images work

An image is a frozen copy of the machine's software. Nothing inside it updates itself, so the only way to a newer runner or newer CLIs is a new container made from a newer image, on the same disk.

6 · What happens on Update Now

  1. Idle (its own fresh report says nothing runs, and Orbit's records show no work): the drain sleep already uses — no new work, it agrees to stop, it exits by itself — then it wakes at once on the current image. Nothing is interrupted.
  2. Busy, after the red button: the request and the sessions it interrupts are recorded in Activity; Orbit asks Docker to stop the container (SIGTERM, then the stop grace). The runner's ordinary shutdown stops its turns.
  3. Docker reports the container exited — the proof that nothing writes to your disk any more. Only then is the next generation made, from the current image, on the same disk and the same runner identity.
  4. The new runner comes online and the interrupted turns continue with "interrupted — Orbit Cloud updated" in their transcript. (To verify in the server task on a real container; if they don't resume by themselves, the server re-queues the turns it recorded.)
  5. Works on your Nov 16 runner as it is: nothing in steps 2–4 needs the old image to know about this feature.

7 · Rules and what is still open

RuleDetail
When the card showsOnly while the container was made from an older image than the current one. A sleeping runner shows nothing: it wakes on the current image anyway.
Who can press itThe account owner. A disabled account, a failed or provisioning runner, or one already current is refused.
Busy runnerConfirm, then interrupt (decision 1, as on your own machines). Activity names every interrupted session.
New work arrivingNever cancels an Update Now you pressed. It does still cancel an automatic idle roll, as today.
Idle rolls on DockerAdded (decision 2): after a release, a runner that goes quiet moves by itself, as on Kubernetes.
Your dataThe disk, sign-ins, workspaces and runner identity stay. Background jobs and services stop with the old container.
KubernetesNo forced stop there: a busy runner's Update Now waits for it to be idle, and the card says so. No Kubernetes deployment exists today.
Open: build datesThe card names builds by date. The current build's date comes from the image's revision label, which the Docker channel starts reporting; without it, the card says "A newer build is available".
