运行器页 · 每个引擎只登录一个账号时，行上都只挂一条额度

在方案 3 的基础上统一到所有引擎：Claude Code、Codex、Antigravity 只有一个账号时，引擎行上都只挂最接近上限的那一条（有用完的先挂用完的，否则挂剩得最少的——composer 额度小圆点选的同一条），完整的额度都在点进去的引擎页。两个以上账号的行、引擎页、web Providers 页都和现在一样。示例机器上每个引擎各一个账号，数据为示意。

现在每个引擎各一个账号

A Claude Code 挂两条，Codex 两条，Antigravity 四条：一个账号挂几条，取决于这个 CLI 报了几个窗口，三行高矮不一。

改后每行一条

① Claude Code：5 小时窗口用了 85%，比周额度（38%）更接近上限，挂它。② Codex：周额度已用完，用完的先挂，橙色并写明哪天恢复。③ Antigravity：3p-weekly 剩 98%，是四条里最少的。三行差不多高，一眼看完。

规则改完后三个引擎一致
情况运行器页的引擎行点进去：引擎页
一个账号只挂最接近上限的那一条（这次的改动，三个引擎都一样）这个账号的全部额度
两个以上账号写「N accounts signed in」，不挂额度（三个引擎现在已经一致）每个账号各自的全部额度
有账号掉线写「Signed out」+ Sign In（已经一致）掉线的账号行上有 Sign In
  • 1百分比的意思不变：Claude、Codex 照旧写用了多少（85%），Antigravity 照旧写还剩多少（98% remaining），和引擎页里同一条一字不差。
  • 2web 运行器页同一规则：每个引擎一行一条；多账号时「Next: 某账号」下面也只挂那个账号的一条。web Providers 页是管理账号的地方，照旧列全部。
  • 3macOS 是同一套页面，改法相同。
