今天为什么这样

first-workspace-in-conversation（10-31）定的：发消息时把 workspace、会话、第一条消息放在一个事务里建（POST /sessions 带 newWorkspace），所以「Nothing is created until you send」。好处是没发消息就不会留下空 workspace；代价就是这里这一步的落差。

其他走法怎么接

  • 先登录、后选文件夹（第 2 步最后完成）：选好文件夹点按钮 → 同上直接跳。
  • 先选文件夹、后登录（第 1 步先完成）：文件夹折成完成行；登录成功那一刻页脚出现 Open new session 按钮，不自动跳（见待定 A）。
  • 没设完就先发了消息：今天的「消息先等着」保留；两步完成后照旧一起建 workspace + 会话，直接跳到那个会话，不是空的新会话页。
  • 建失败（机器离线、目录已被占）：留在卡上，按钮下一行红字，按钮恢复可点。

规则

  1. 确认按钮是设置的终点：两步都完成时，点它就建 workspace 并进入它的新会话页。
  2. 建出来的 workspace 和 10-31 的规则一致：名字取文件夹名、重名加「 2」、隔离关、新文件夹 autoCreateWorkDir。
  3. 引擎/凭据沿用卡上已选的，带到新会话页的草稿。
  4. 已有等待中的消息时，不建空 workspace，直接按今天的路建 workspace + 会话。
  5. 失败不跳页、不留半个 workspace（服务端一个请求一个事务）。
  6. 「Nothing is created until you send」这句删掉；SETUP_LEAD、setupReady 换成新文案。

问题方案 A方案 B推荐
A. 先选文件夹、后登录时，登录成功要不要自动跳？不自动跳；页脚出 Open new session 按钮，用户点了才建、才跳。「确认才建」一条规则贯穿。登录成功就自动建 + 跳。少点一次，但登录回调常在另一个标签/页面完成，回来时页面已变，容易迷路。A推荐
B. 确认后、还没发消息就离开，空 workspace 留不留？留着。它就是一个普通 workspace（和机器页表单建的一样），下次打开直接用。没发过消息的 workspace 在离开时删掉，回到「没发就不建」。逻辑复杂，还会让侧边栏闪一下又消失。A推荐
C. 重名时按钮/页脚显示什么名？页脚写文件夹名；真正的名字（可能是「my-app 2」）以服务端结果为准，在新会话页提示行里说出来。先问服务端预取名再显示。多一次请求，名字可能被并发抢走。A推荐
D. 原生端一起上吗？web 先上，iOS/macOS/Android 跟一个任务。四端同一批落地。A推荐
