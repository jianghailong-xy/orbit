macOS and iPad (regular width)

  • The toolbar's Chat button opens a third column next to the inspector.
  • Open or closed is remembered per device (UserDefaults), and it never opens by itself.
  • When an iPad narrows to compact width, the column becomes the iPhone sheet.
  • The same chat, cards, change lines and Undo as on the web. The history lists the account's Scheduled chats.

Decisions (owner 11-26: A on all six) and what gets built

Revision 2 of the plan takes in Fable 5.2's review. What v1 leaves out is listed on the right.

D1–D3

D1 Entry point
A · Chat button in the header CHOSENBottom right holds the quick-add line. A deliberate departure from the Wiki's FAB.
B · the Wiki's round FAB
D2 Inspector and chat together
A · three columns, width bands of part 2 CHOSEN
B · the chat replaces the inspector while open
D3 Open by default
A · no, open on a press, remembered per device CHOSEN
B · open by default on wide windows, like the Wiki

D4–D6

D4 Session kind
A · listed, tagged From Scheduled CHOSENA marker column, as Wiki chats have. No new run source, and nothing for old clients to decode.
B · hidden like Change…A new run source and about 17 filter sites.
D5 Change… and quick-add
A · unchanged in v1 CHOSENWhile the panel is open, the quick-add line sends into it.
B · move both into the panel now
D6 Run now from the chat
A · a Run now button you press CHOSENOwner channel, no budget.
B · the agent presses it as a session

What gets built (by cost)

  1. Server: Session.scheduleChatAt; POST/GET /api/schedules/chat; the turn's optional context (filter, selected schedule); the <orbit_schedules> note (counts and the selection, titles escaped as data); resolveActor → USER with that turn's words; the From Scheduled tag.
  2. Web: ScheduledChatPanel on the shared conversation and composer; header button and its states; chip; row flash; Run now button; width bands; quick-add into the chat.
  3. macOS + iOS.
  4. Android (follows iOS).

Not in v1

  • One grouped Undo for several changes in a turn
  • Creating in another workspace from one chat
  • Managing tasks that wait on a condition (questions only)
  • Splitting the Wiki chat panel into a generic frame
  • A revision check on in-envelope edits (they're last-writer-wins today)
