Run a queued message now, over the runner's limit

The message waits because HPC is running 16 of 16 sessions. "Run now" lets the owner start this one message straight away as the 17th, a one-time pass for this turn only. The limit itself does not change. Drawn with the web console's light tokens and its real classes (chat-runner-updating, runner-updating-pop), the same way the "Runner updating" popover already offers "Update now".

F. Queue fairnessThe overflow turn counts as active. Messages already waiting still start only when the count drops below 16, so nobody behind is moved further back.—
Under the hood (for the build): the server's claim gate and the runner's pool (session_pool.go: turn permits and resident engines, both capped at max) each enforce the 16. The pass is a field on the queued turn, overCapacity, that the claim SQL accepts while active < limit + burst. The runner admits a claimed overflow turn past p.max, up to max + burst, and never evicts another session's running turn for it. Older runners that do not support this keep queueing, and the button says so.
