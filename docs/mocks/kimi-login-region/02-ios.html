Kimi 登录 · iOS 引擎页：同一个选择，同一套文案

iOS 和 macOS 的登录卡是同一个 RunnerSignInView.swift，从运行器页点 Kimi Code 进引擎页、按 Sign In 出现。改法和 web（01-web）一一对应：开始时选站点、设备码写明站点并能一键换、登录后看得到站点、Sign In Again 换站点。

现在按下 Sign In 之后

A 一个「Sign in to Kimi Code」，站点由 runner 上的 CLI 自己定（Orbit 装的 = kimi.com）。

改后先选站点

1 两个按钮上下排，手机上整行好点；按哪个就在那个站点开始登录。下面一句说明两个站点账号不通。

改后设备码（kimi.ai）

2 按钮和提示写明 kimi.ai（读自登录 URL 的域名）。3 「Use kimi.com instead」取消并在另一站点重来。代码仍是点一下复制。

改后已登录 kimi.com，按 Sign In Again

4 账号行下面写站点（kimi.com），运行器页的引擎行也是 2.1.1 · kimi.com · Signed in。5 Sign In Again 打开同一个选择，当前站点标 Current，点 kimi.ai 就换过去。

  • a文案和 web 逐字一致（Which Kimi account are you signing in with? / kimi.com · Mainland China / kimi.ai · International / Use kimi.com instead），放进 OrbitKit 的 copy 常量，沿用现有的 web ↔ Swift 文案一致性测试（CodexSignInCopyParityTests 那一类）。
  • bRunnerSignInModel.begin(region:) 把站点带进 POST /runners/:id/login；设备码状态里的站点从 model.url 的域名读，和 web 同一条规则。
  • c旧 runner（没声明 kimi-login-region/v1）：kimi.ai 按钮 disabled，说明换成「This runner signs in on kimi.com only. Update it to sign in with a kimi.ai account.」——和 web 第 7 点一样。
  • dAndroid 没有 runner 登录卡，不涉及。
