Kimi 登录 · 分开 kimi.com 和 kimi.ai：开始登录时先选站点

kimi.com（中国大陆）和 kimi.ai（海外）是两套账号，登录页、API、订阅都不通。Kimi Code 2.1.1 已经支持 kimi login --region mainland-cn|global，但 Orbit 跑的是不带参数的 kimi login：首次登录由 CLI 按安装脚本写下的 ~/.kimi-code/region 决定站点，而 Orbit 用的是 code.kimi.com 的安装脚本，所以永远去 kimi.com——kimi.ai 的账号在 Orbit 里登不上，登错了也换不回来。下面每张都是真实 web 控制台截图（同一套组件和样式，接口数据是造的）；「改后」是把提案写进组件后的原型截图。

① 开始登录：Providers 页 → Kimi Code → Sign in
现在只有一个按钮
A

A 点「Sign in to Kimi Code」→ runner 跑 kimi login，去哪个站点由 CLI 自己定：这台机器从没登过就看安装渠道（code.kimi.com = kimi.com），登过就沿用上一次。用户没有任何地方能说「我是 kimi.ai 的账号」。

改后先问用哪个 Kimi 账号

1 两个选项各写域名和地区，点哪个就直接在那个站点开始登录（kimi login --region mainland-cn / global）。点击次数和现在一样（Sign in → 选站点）。不预选：选错的代价是到了登录页才发现账号不在，所以让用户自己点。

现在不说是哪个站点

改后写明站点，选错一键换
2 3

2 按钮和提示都带上站点：「Open the kimi.ai sign-in page」「Sign in with your kimi.ai account there」。站点从 CLI 打印出来的登录 URL 的域名读（auth.kimi.ai / auth.kimi.com），显示的就是用户马上要打开的页面，不会和实际不符。
3 「Use kimi.com instead」：取消这次登录，在另一个站点重新开始——不用退回上一步。

说明

  • 为什么做在「选站点」这一步，而不是别处

  • a不默认、不记忆。站点是账号的属性，不是偏好：猜错一次，用户就要在别人的登录页里白跑一趟。kimi.com 和 kimi.ai 两个选项并排，和 Kimi 自己的登录对话框一样（「Sign in with your kimi.com account」/「… kimi.ai account」）。
  • b放在面板里，不放在行上的 Sign in。行上的按钮不变；面板原本那个「Sign in to Kimi Code」换成两个选项，点击数不变，Claude / Codex / Antigravity 完全不受影响。
  • c不选的备选方案：① 默认 kimi.com、设备码页给「切到 kimi.ai」——每个 kimi.ai 用户都要先白等一次 runner 心跳（最长一分钟）；② 在 Providers 页给 Kimi 加一个全局「地区」设置——地区是每台 runner 上那个登录的事，同一个人可能两台机器登两个站点；③ 用 kimi.ai 的安装脚本重装——只影响「第一次登录」，登过一次就不再看它。
  • diOS / macOS 共用 RunnerSignInView.swift，同样改（见 02-ios）。orbit doctor 的终端登录也要先问站点，再跑 kimi login --region …。

  • 要改的地方（链路）

  • 1shared dto.ts：KimiRegion = 'mainland-cn' | 'global'；POST /runners/:id/login 的 body 加 region（仅 kimi）；RunnerEngineHealth.kimiRegion（第 4、6 点读它）。
  • 2apiserver：runner 行加 login_region（migration 0397），随 LoginCommand 下发；engine ≠ kimi 带 region 直接 400；runner 没声明 kimi-login-region/v1 时，下一次心跳把这次登录标为失败并说明要升级 runner，不降级成裸登录。
  • 3runner login.go / kimi_region.go：kimi login --region <region>；先用 kimi login --help 确认 CLI 认识 --region（同 Codex 的 --device-auth 探测）。太旧的 Kimi 选 kimi.ai 直接失败并提示更新引擎，选 kimi.com 退回裸 kimi login。设备码 URL 的正则本来就不限域名，不用改。
  • 4runner 上报站点：从 kimi provider list --json（CLI 自己读的 config.toml）里取 managed:kimi-code——oauthHost = auth.kimi.ai 是 global，key 为 oauth/kimi-code 是 mainland-cn，再看 API 地址；没登过就不报（不读安装标记，免得把「从没登过」说成 kimi.com）。换了站点也会让 runner 重读模型列表。
  • 5不用改：登录状态探测（kimi acp authenticate）、模型列表（kimi provider list --json）、会话里的 KIMI_CODE_HOME overlay 都跟着 CLI 自己的 config.toml 走，登到哪个站点就用哪个站点的 API。
