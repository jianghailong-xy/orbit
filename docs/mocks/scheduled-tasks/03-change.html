定时任务 · Change…（修改）

今天三个客户端的 Change… 都是离开 Scheduled 页，跳到该工作区的新会话输入框（Web 预填 "Codex stable check: "，iOS / macOS / Android 什么都不填）。设计文档 §8.2 说的「带上这个定时任务」并没有做：agent 只能按标题去 schedule_list 里猜是哪一个；改完的结果（变更行、Allow 卡）留在那个会话里，人得自己回 Scheduled 页确认。
提议：Change… 进入一个绑定了这个任务的会话，agent 先发第一句——说清它现在是什么、哪些能直接改、哪些要你 Allow——然后你回复。结果（变更行 + Undo、信封卡）用会话里现有的组件。没有表单，信封规则（§4）不变。iOS 为准，Web / macOS / Android 跟随。

普通对话，没有新组件。agent 只该问人才能定的（哪天、多久一次），和创建时一样（§8.1）。
规则
入口Change…（详情面板、行左滑、长按菜单、macOS 右键）打开这个会话。在任意会话里直接说「把 Codex 检查改成 8 点」照旧可用。
开场POST /api/schedules/:id/change 在任务的工作区、用任务的 agent 建会话，写入第一条消息（agent 角色，Orbit 生成），不启动引擎。
绑定会话记住 scheduleId：绑定条、导航标题都从它来；你第一次回复时，发给 agent 的提示带上任务 id、revision、read-back。
结果沿用会话里现有的变更行 + Undo、信封卡（GET /api/sessions/:id/schedule-cards）。
放弃打开了却一句没说就离开：会话不留下，任务不变。
