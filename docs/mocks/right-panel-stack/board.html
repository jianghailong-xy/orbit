Right side: one panel that drills in (Project › Task), not two panels side by side

Today, opening a task from the project panel adds a second panel to the right. The conversation, which is the main pane, shrinks to about the width of each panel beside it, and two panels show the same status. Proposed: the right side holds one panel. Clicking a task in the project panel replaces the panel's content with the task and adds a back link (‹ Project), so the conversation keeps its width. Same window width (2000 px) in every frame.

The rules
  1. The right side shows at most one panel.
  2. From the project panel, a task row opens inside the panel; the header becomes "‹ Project name". ‹ returns to the project, scrolled to where you were.
  3. From anywhere else (the conversation's "Task ›" chip, the Tasks page, a link), the task opens on its own; a breadcrumb names its project and drills out to it.
  4. ✕ closes the panel at any depth. Esc goes back one level, then closes.
  5. ⤢ (expand) still opens the task as a full page.
  6. A run row under Needs you opens the run in the conversation. Any session of a project other than its coordinator has "‹ Coordinator name" at the start of its header: one click back to the coordinator, from any depth, panel untouched.

  • The main pane is the widest again.
  • One status to read, not two that repeat each other.
  • Parent and child look like parent and child (a breadcrumb), not peers.
  • You can't see the project's Needs you list while reading a task; ‹ brings it back in one click.
Open questions
  • Should very wide windows (≥ 2400 px) offer an explicit "pin side by side"? Proposed: not now; add it only if coordinators ask for it.
  • The ‹ link goes to the coordinator, not to the previous page: Run 3 → Run 6 → Run 5 is still one click back. No browser-history walk.
  • Does the panel remember its depth per conversation (come back and still see the task), or reset to the project? Proposed: remember it.
  • ④, the superseded-run banner, and taking failed runs of a landed task out of Needs you are separate changes; they're shown here because they appear on the same screen.
