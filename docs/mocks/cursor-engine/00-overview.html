Cursor CLI 原生接入 · T0 设计总览：Web 与 iOS 各一套（明暗两版），今天 vs 提议、规则表、要改的文件、待你定的 6 项

Cursor CLI 作为第 7 个 engine（内部名 cursor）进入每一处列 engine 的地方；它的三种凭据（runner 上登录的账号、同一台 runner 上的多个账号、存在 Orbit 里的 Cursor API key）都只跑 Cursor CLI，按 Cursor 套餐计费。和其他 engine 不一样的地方都来自 P0a 契约：不能轮中插话（轮中再发会取消当前轮，Orbit 改为排队）、没有上下文读数、做不到「编辑前要问」（Default 模式）、Free 套餐的请求上限读不到、登录链接约 27 分钟失效、跨账号续聊还没验证。Web 的每一帧都是真实页面截图（vite + 仓库自带的 ui-migration 假 API，「改后」是同一页面加上 prototype.patch 里的原型）；iOS 是按现有 SwiftUI 画的 393×852 手机。Android 跟 iOS 稿，不另出图。界面文案全部英文。

② 待你定 · 显示名与图标（契约 D3 建议「Cursor CLI」）
A「Cursor CLI」+ Cursor 立方体标（板上按此画）
CLI 自己就叫 Cursor CLI（agent about 的标题「About Cursor CLI」），和「Kimi Code」「Antigravity CLI」一样是 CLI 的产品名；和厂商名「Cursor」（画廊卡片、API keys 组名）分开，也不会被当成 Cursor 编辑器。标取自 LobeHub icons（MIT，和其他厂商标同一来源），黑底白标。
B「Cursor」+ 同一个标
更短；但 engine 名和厂商名重名（新会话里的「Cursor」和画廊里的「Cursor」是两种东西），也容易被理解成 Cursor 编辑器本身。
C「Cursor CLI」+ 中性字母标「C」
不用 Cursor 的商标图形，和 OpenCode 的灰色「O」一样。代价：和其他六个 engine 都用品牌标不一致，列表里不好认。

暗色下黑底标加一圈 1px 的白色描边（同 Antigravity 的做法）；菜单标题里 glyph 按品牌色上色的地方，Cursor 改用正文色，否则暗色下看不见（Web 5 ①）。

③ 待你定 · D1、D2、D4、D5、D6（事实引自契约；推荐项绿框）

D1代码库索引默认开还是关（契约 §14.3、§16.7）

  • 索引只在 Cursor 账号的隐私模式为 4 时运行，每 5 分钟把完整文件内容上传到 Cursor（repo42.cursor.sh）；所有者的账号是模式 3，实测上传 0 字节。
  • --disable-indexing 只关这条上传，不关 worker、不关 LSP，对功能没有可见影响。worker 另会 npx -y typescript-language-server（从 npm 下载运行），那是另一件事，交 P3 / P5c。
  • 界面上没有开关（首版不做），只体现在 runner 的启动参数里。
A默认关（加 --disable-indexing）
任何隐私模式的账号都不上传完整文件。将来真需要，再给账号加一个开关。
B沿用 Cursor 的默认（隐私模式 4 的账号会上传）
和直接用 Cursor CLI 的行为一致；代价是代码出境与否取决于每个账号自己的隐私设置，Orbit 不管。

D2Cursor 提交时加不加它自己的署名（契约 §14.4）

  • Cursor 默认在 agent 的提交里加一个 trailer（文本由服务端定，还没实测到原文，P8 冒烟时核对）。能按账号关掉：账号的 cli-config.json 写 attribution.attributeCommitsToAgent=false（PR 同理）。
A沿用 Cursor 默认（加署名）
契约的建议；和其他 engine 在提交里写自己的署名是一类事。
B关掉
提交里不出现 Cursor 的 trailer；Orbit 在建账号目录时写好这项配置。

D4多个账号怎么彼此隔离（契约 §8.4）

  • 只有 HOME 能挪走 Cursor 对 ~/.cursor 的读写（agent-cli-state.json、按账号下发的 skills、AI 代码追踪库，以及读 ~/.cursor/mcp.json、hooks、rules）；而 agent 跑的命令继承 CLI 的全部环境。
  • 方案 A：CLI 用账号自己的 HOME，命令经一个 SHELL 包装拿回真 HOME——待 P0c 用一次 prompt 补验（上次的包装名不含 bash，CLI 没用它）。A 成立就用 A，界面无变化。
B真 HOME，接受副作用
多账号照常（板上画的就是这种界面）；代价：runner 用户自己的 ~/.cursor 配置（含 mcp.json 里的服务器）会进入 Orbit 的 Cursor 会话，各账号共享这些文件，不满足项目判据 4「不写 runner 用户真实的 Cursor 配置」。
D这类机器只支持 Default 账号
机器卡片 / 引擎页上不出现 Add account，Accounts 标题回到「Sign-In」（同今天 Kimi 在旧 runner 上）；其余界面不变。只在 A 不成立时二选一。

D5说过话的会话能不能换账号或换 key（契约 §13）

  • 会话库 acp-sessions/<id>/ 拷到另一个配置目录后能 load 并续聊——只在同一身份下实测过；跨账号、跨团队没测。会话本身不记账号。
A验证前：只有没说过话的会话能换（板上按此画）
说过话的会话在 Provider 菜单里列出其他账号和 key，但灰掉，写「Cursor CLI can’t carry a conversation to another account or key yet. Start a new session to use one of these.」；P6b 用两个真实账号验证后，runner 声明 cursor-account-move/v1，自动变成能换（Web 6 ②、iOS 6）。
B先放开，出错再说
不推荐：服务端是否因账号不同拒绝续聊不得而知，失败时会话卡在半路。

D6Default 权限模式（契约 §5.4、§16.5；P1 已先按「拒绝 default」实现）

  • Cursor 在 ACP 下写工作区文件从不发权限请求，也没有开关能让它问——「编辑前要问」做不到。Plan 只挡写文件（命令和 MCP 由 Orbit 拒绝），Cursor 的 ask 模式不用。
ACursor 不提供 Default；新会话默认 Accept Edits
Default 在下拉框里灰掉并写原因；账号默认是 Default 时，Cursor 会话落到 Accept Edits。同一个词在所有 engine 上意思一致。
BDefault 作为 Accept Edits 的别名
可选，写明「Runs as Accept Edits — file edits don’t ask」。省一步，但「Default」在 Cursor 上不再问编辑，和其他 engine 不同。
