图 01 · 任务链接在哪里点，就在哪里打开

真实页面截图：左右两套构建（今天的 main 与原型），同一份示例数据。会话里一条回复引用了项目任务 “Capture browser baselines”。

今天：点会话里的任务链接，被带离会话

  • 1会话回复里的任务引用（/tasks/<id>）。
  • 2地址变成项目页 /projects/…/tasks/…：会话不见了，侧栏高亮跳到 Projects。
  • 3点 ✕ 关掉面板后，停在项目页，要自己再找回刚才的会话。

改后：面板盖在会话上，✕ / 返回 回到会话原处

面板就是项目页上那个任务面板，原样复用，不新造外观；地址只在会话后面加 ?task=<id>。

  • 1同一个链接，点下去不跳页。
  • 2任务面板盖在会话右侧，会话还在背后，地址 /sessions/…?task=…，可复制、可刷新。
  • 3面板顶部的项目名本来就是链接：想去项目页，点它。
  • 4✕ 或浏览器返回：回到会话原处（滚动位置不变）。

改后 · 窄屏（≤960px）：任务占满屏幕，返回手势回到会话

规则

在哪里点今天改后
会话（引用、任务卡、开工卡、消息卡、watch 行…）
Waiting on you、Wiki、设置等其它页面		项目任务 → 项目页；非项目任务 → Tasks 页原地打开：面板盖在当前页上
项目页里点它自己的任务盖在项目页上不变
Tasks 页 / 某个清单里盖在清单上不变
⌘/Ctrl/中键点击新标签页打开任务地址不变（新标签页仍是任务自己的地址）
粘贴的 /tasks/<id> 地址、推送通知点进来项目任务 → 项目页见下方待定 A

待定 · 要你拍板

问题方案 A（推荐）方案 B
A. 直接打开任务地址（粘贴链接、通知）保持今天：项目任务进项目页、盖在项目页上。没有“原处”可回，项目页是它的家。进 Tasks 页、盖在“项目外任务”清单上（9 月改之前的做法，✕ 落到一个它不在的清单）。

  2. 网页：少数不是链接、而是代码里直接跳转的入口，逐个改成同一个“盖在本页”的打开方式。
