发消息跟到任务当前那一轮 · macOS / OrbitKit

一个任务同时只有一轮在跑（session_task_execution_claim_idx）。 上一轮失败后平台两秒内重派，手里这个会话就不再是任务当前那一轮 —— 但屏幕上什么都没变。 发出去的下一句话撞上一条写给程序看的 409，一个字都没投出去。

左边是现在，右边是改后。所有文案与 web 端同一份常量 （src/web/src/lib/taskRunHandoff.ts），由 TaskRunHandoffCopyParityTests 钉住。

虚线框 = 这次改动的地方

1 · 在已被接手的旧 run 里发消息

服务端已经把消息投给了持 claim 的那一轮，并在回答里写上 routedToSessionId（契约 §2.1）。客户端要做的是跟过去。

2 · 投不过去的三种情况，各自说各自的话；不认识的仍然照抄原文

按 code 分支，不按句子。TASK_ALREADY_RUNNING 一个 code 覆盖两种处境，靠 conflictingSessionEnding 这个字段分开 —— 光看 conflictingSessionStatus 两边都是 RUNNING。

3 · 失败卡上的 Retry 撞到 409

Retry 是这张卡自己的按钮。答案只在别处闪一下，卡片原封不动 —— 和「按下去什么也没发生」分不出来。

4 · composer 换 provider：说清什么时候生效；要停掉在跑那轮时明着问

一个 run 的 provider 在它生命周期内固定。换 provider 只能是 「停掉这一轮 + 用新 provider 起新一轮」—— 而停掉一轮在跑的活是破坏性的，必须有一次显式确认。

5 · 任务列表 / 任务详情的入口

入口读的是会话行（running/queued/ sessions[].status），不是 status 这个会滞后的标签 —— 出事那次就是：任务失败、两秒后被重派，行上还写着 FAILED。
