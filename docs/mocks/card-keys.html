卡片快捷键：Enter 确认，⌘ + Enter 交给主输入框

「这类卡片」＝ web 上成对出现 第一动作 / Chat about this 的四张：证据判定卡、owner 确认卡、开工确认卡、项目结算卡。它们本来就共用一个发送动作（OWNER_SEND_BACK_ACTION），现在共用一对键。

审批卡（ApprovalPanel）早就吃 Enter＝Approve、⌘/Ctrl + Enter＝Always allow；这次把四张卡也接到同一个判定上（web CardHotkey.ts），而不是各写一份——两条规则会漂，一条不会。macOS/iOS 这次没动。

两张（或更多）同时在问时，四张卡都不带键位、Enter 也不响应：回车得在两问之间挑一个，而按错门的键比没有键更糟。读者照旧点他正在看的那颗按钮。只剩一张卡在问时，键位自己回来——包括另一张卡被答掉、走 stale、或它自己那一下正在飞的时候。

键位落在哪 四张卡 + 审批卡共用同一段判定

操作结果
Enter第一动作：Confirm done / Start the project / Confirm the criteria / 审批卡的 Approve。
⌘ + Enter（非 Mac 是 Ctrl + Enter）第二动作：Chat about this——接管底部主输入框，下一次发送就是理由；审批卡上是 Always allow。
光标在输入框里（底部主输入框、任何 textarea/input）两颗键都不响：打字的地方归打字。
焦点在按钮上 + Enter让给那颗按钮自己的回车（焦点在哪颗就按哪颗）；⌘ + Enter 仍然归卡片。
按钮 disabled（走 stale、按下正在飞、已记录）那颗按钮的键跟着死，另一颗不受影响。
