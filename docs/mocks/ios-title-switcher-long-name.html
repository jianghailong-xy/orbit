iOS 会话列表 — 长 workspace 名把标题挤到左边

标题槽是 workspace 切换器（WorkspaceTitleSwitcher，b205f199a）。它在 .principal 上，是个自定义 title view： 系统按 ideal 宽度给它位置——放得进中间槽就居中，放不进就整组夹到汉堡按钮右边（不截断）。 实拍同一台 393pt 机（1179px @3x）：orbit 那个工作区组中心 195.7pt（屏幕中心 196.5，居中）； wikova-develop 那个组 72.3–217pt，起点正是汉堡右缘 60.3 + 12。 右边那个双按钮玻璃胶囊实测 107pt 宽，系统按宽的一侧两边各留（≈123pt/边）——留完中间只剩 ≈147pt 可以居中，名字一过线就掉到兜底分支。 

// A 案的做法 —— 画在这里留档，最终没有采用（选定的是 B）
// WorkspaceTitleSwitcher：名字限宽、箭头固定宽（原注释里「名字过长时截断，箭头不被挤走」这版才真的成立）
Text(name)
    .font(.headline).foregroundStyle(.primary)
    .lineLimit(1).truncationMode(.tail)
    .frame(maxWidth: maxNameWidth)          // ← 新增：给 ideal 宽度封顶，系统于是永远能居中

// 调用处（列表页 AgentPanes / 新会话草稿页各一处）：从列宽算预算
// 132/边 = 右侧玻璃胶囊 107 + 外边距 16 + 8pt 余量（实测能居中的上限 ≈147，取 129 组宽留档）。
// 18 = HStack 的 6 + chevron 的 12。
static func nameBudget(columnWidth: CGFloat, chrome: CGFloat = 132) -> CGFloat {
    min(max(columnWidth - 2 * chrome - 18, 0), 240)
}   // 393pt 机 → 111pt：约 12–13 个西文字符；超出的尾巴截掉，整组仍在正中

落在哪：只有列表页这一处动（AgentsView.swift 的 AgentPanes toolbar）——标题槽被两个尾随按钮挤掉的是它。 新建会话草稿页（AgentsView.swift:980）共用同一个 WorkspaceTitleSwitcher，但那页右边没有那两个按钮， 中间槽从来放得下，没有兜底分支可躲，所以它继续用 .principal（居中）。要两页一模一样，说一声，一起挪。
上机要量的两件事：leading 项与汉堡的先后（这一版靠「声明在高层的先排」推断）、iOS 26 会不会把两者并进同一块玻璃。 仓库里的 .ios-probe/ + client.yml -f probe=true 是量这个的现成路子。
