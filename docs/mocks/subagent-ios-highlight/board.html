折叠行的三行分工

  1. 第一行不变：✦ SubAgent + description + 状态。
  2. 第二行 = 谁、在哪：引擎 chip（引擎小标 + 短模型名，按引擎着色）。和父会话引擎不同时，前面加灰字 Claude →；相同就不加（第三个块）。后面是灰字档位和类型，Background 放在类型的位置。只读的 run 加 🔒 Read-only，派到别的机器的加 on orbit-macos。
  3. 第三行 = 做成了什么：结束后，会写文件的显示 N files changed +a −d，只读的显示交回结果的第一句；运行中显示斜体的当前步骤（今天的 live line）。用时和花费从第二行挪到这一行的右端，运行中换成计时和步数。

展开

  • 顺序：Why → 步骤 → Changed files（新增，标明 not committed）→ 结果。
  • 跨 workspace 的 run 在这里显示 runner 附的 Discarded changes，不画 Changed files。

要服务端补的字段

SubagentRunView 加 engine（选中的引擎）、readonly、changedFiles（带行数）、运行中的 steps。subagent_run 表已经有 changed_files 和 decision.engine，只是没下发；行数要 runner 回报时多带。父会话的引擎客户端本来就有。

顺带修：今天 iOS 第二行漏了 on <workspace>（web 有，设计 §10.3 要求）。

组头

  • 3 SubAgents + 进度 2 of 3 done；进度条绿 = 已结束，紫 = 在跑，红 = 失败。
  • 第二行：用到的引擎（和父会话不同的才列，前面同样加 Claude →）、几台机器、累计花费。

成员

  • 两行：状态 + description；引擎 chip + 只读 / 机器 + 用时花费。比单个块省掉一行，三个成员的高度和今天差不多，但信息多了引擎和机器。
  • 点成员在组内展开，内容同 ① 的展开；一次只开一个成员，组本身不跟着展开或收起。
  • 后台成员结束时唤醒父会话，组的进度就地更新，不在消息流底部再插一个块。

不做的

不跨回复合组（隔着正文的两次派出各自成块）；引擎自带的 Agent 卡不进组。
