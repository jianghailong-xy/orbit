iOS 会话列表：状态图标按 Web 列表来画

两张截图里的毛病是同一个：iPhone 列表只给“在动”的状态画图标。排队（“Runner full”）和只挂着 service 的后台进程，右侧都是空的。Web 列表的每一行都有图标。

① 今天 iPhone 会话列表 · 示例数据 · 黄底 = 状态在动却没图标
1排队（Runner full / Queued）：会话在等 runner 空位，什么都没画。Web 画的是灰色时钟。
2后台只有 service（dev server、watcher）：文字写着 “Background process running…”，却没有图标。Web 画的是静止的终端。有 job 时 iPhone 才画呼吸的终端。
3等你回复 / 已结束 / 成功：iPhone 都不画。Web 分别画对话气泡、灰色勾、绿色实心勾。
原因：iPhone 行和抽屉 Recents 用的是 SessionLiveIndicator，它是 SessionStatusGlyph 的“精简版”：只留 spinner、眼睛、审核时钟、呼吸终端、琥珀点、红点，其余落进 default: EmptyView()。
Web 的 StatusIcon 和 macOS 宽行的 StatusGlyphView 用的是完整版，每种状态都有图标。三端吃的是同一份 SessionStatusGlyph，iPhone 只是没把它画全。

② 两种改法

图标位置不变：标题右侧、时间前面，也就是今天 spinner 所在的位置。绿底 = 比今天多出图标的行。iPhone 已有的灰色 spinner、琥珀点、红点保持不变。

方案 A · 和 Web 一样，每行都有 推荐
方案 B · 只补“还有事在进行”的两种

③ 逐个状态对照

同一个会话状态，Web、iPhone 今天、方案 A、方案 B 各画什么。绿底 = 要改的格子。

④ 待定 · 要你拍板

方案 A：完全按 Web 画 推荐

每一行都有图标，形状和 Web、macOS 一样。一眼扫过去就能分出排队、后台、等你、结束、成功。图标都是灰色，只有成功是绿色，所以不会比今天吵太多。代价是列表右侧不再有“空”的行，“没图标 = 没事”这层含义没了，改成看图标形状。

方案 B：只补排队和后台进程

只给“还有事在进行、但 Agent 不在生成”的两种状态补图标：排队 → 时钟，service → 静止终端。等你回复、结束、成功这些“已经停下”的行还是空的，靠文字说明。列表更轻，但和 Web 仍然不完全一样。

Android：SessionLiveMark 是照着 iPhone 做的，问题一样。默认跟 iOS 用同一个方案，你也可以只改 iOS。

落地（按代价排）

  1. iOS：SessionLiveIndicator 的 default: EmptyView() 换成画 glyph 自己的 SF Symbol（灰色，成功为绿色）。方案 A 就是这一处。方案 B 只放行 clock 和 terminal。抽屉 Recents 共用这个视图，一起生效。SessionStatusGlyph 和 OrbitKit 测试都不用动。
  2. Android：SessionLiveMark 补同样的分支，复用 ic_clock / ic_terminal。方案 A 还要补消息、勾两个 drawable。每个分支补一个 Compose 测试标签。
  3. Web、macOS、服务端：不用改。
