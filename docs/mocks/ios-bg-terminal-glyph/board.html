iOS 会话列表：后台进程的终端图标

你截图里三行都写着 “Background process running…”，但只有一行有终端图标。问题在于图标只给 job 画，service 什么都不画。

① 今天 iPhone 会话列表 · 示例数据
1有图标的行：后台有一个 job（bg_run 跑的、会结束的命令，比如测试、构建）。终端图标在呼吸（透明度 1 → 0.42 → 1，2.4 s 一次）。
2没图标的行：后台只有 service（dev server、watcher 这类常驻进程）。文字照样写 “Background process running…”，右侧却什么都没有。字和图标对不上，看起来像漏画了。
原因：SessionLiveIndicator（iPhone 紧凑行和抽屉 Recents 共用）只在 glyph.pulse 为真时画终端；pulse 只对 job 为真。service 掉进 default: EmptyView()。
同一个 glyph 在 Web 和 macOS 宽行（StatusGlyphView）里，service 是静止的终端，job 是呼吸的终端。只有 iPhone（以及照着它做的 Android）把 service 这一半去掉了。

② 建议：凡是写着 “Background process running” 的行，都画终端图标

图标的形状和颜色不变（灰色终端，不是 spinner）。job 呼吸、service 静止，和 Web、macOS 用的是同一条规则。不新造外观。

建议 绿底 = 有终端图标的行
1job：不变，还是呼吸的终端（图中橙色 ≈ 表示在动）。
2service：新增一个静止的终端，和 job 同样的形状和灰色，只是不动。文字说有进程在跑，图标也这么说。“动”只留给真正在干活的 job，所以常驻的 dev server 不会让这行看起来很忙。
优先级不变：等你批准的琥珀点、审核中的时钟、spinner（Agent 在生成或子 Agent 在跑）、watch 的眼睛，都还排在终端前面。终端只在会话停下来、后台还有进程的时候出现。
VoiceOver 不变：行的 accessibilityValue 已经读出 “Background process running”。

④ 待定 · 要你拍板

方案 A：service 静止、job 呼吸 推荐

和 Web、macOS 完全一致，共用的 SessionStatusGlyph 一行都不用改。“在动”仍然只表示有会结束的活在跑。如果一个会话常年挂着 dev server，这行就一直有个静止的终端，安静、不抢眼。

方案 B：只要有后台进程就呼吸

手机上更醒目，但长期挂着 service 的会话会一直在动，和真正在跑测试的会话没法区分。而且会和 Web、macOS 不一样，要么三端一起改，要么 iPhone 单独一套。

Android：默认跟 iOS 走同一个方案（SessionLiveMark 加 service 分支，复用 ic_terminal，不加动画）。你也可以只改 iOS。

落地（按代价排）

  1. iOS：SessionLiveIndicator 加一个分支：.symbol("terminal") 且不呼吸时画静止的 Image(systemName: "terminal")，次要色。约 3 行，抽屉 Recents 一起生效。
  2. Android：SessionLiveMark 在 isRunningJob 下面加 “parked 且 runningBgCount > 0” → 静止的 ic_terminal，补一个 Compose 测试（session-mark-services）。
  3. OrbitKit / Web / 服务端都不用动：glyph 已经给了 service 一个 terminal，只是 iPhone 的视图没画。
