iPad 侧边右滑 —— 和 iPhone 同一个规则

iPhone 上从屏幕左边缘往右滑，有两种结果：在列表页拉出抽屉，在推进来的页面返回上一页。iPad 今天两样都靠不住： 系统自带的「右滑拉出侧栏」只在空白处起手才灵，手指落在会话行上，这一下就成了这一行自己的右滑（完成 · 置顶），滑到底直接执行； 栏里带「‹ 返回」的页面（文件夹、项目的会话页、Runner 的引擎页、项目下的任务）右滑从来不返回，只会拉出侧栏；侧栏上左滑也收不起来。 改成：哪一栏左上角有 ‹，从这一栏左边缘右滑就是返回；最左一栏没有 ‹ 时，从屏幕左边缘右滑拉出侧栏；在侧栏上左滑收起。 和点 / ‹ 是同一个动作。图全是 iPad Pro 13 英寸模拟器（iOS 26.5）上的真实界面，「今天」一栏是同一个手势在现在的版本上实际滑出来的结果；数据是编的，红色手指、色条、编号是标注。

待定 · 要你拍板

① 起手区

  1. A. 只认栏左边缘约 20pt（推荐）：和系统返回手势同一个位置；行的右滑（完成 · 置顶）从行中间起手照旧，两者不打架。
  2. B. 栏里任意位置右滑都算（iOS 26 的 iPhone 推进页就是这样）：好够，但在会话行上右滑分不清是「返回 / 拉侧栏」还是「完成」，满滑还会直接把会话完成。

② 跟不跟手

  1. A. 松手决定，动画和点按钮一样（推荐）：侧栏是系统分栏，只有开 / 关两态；栏里的返回页下面也没有「上一页」可以露出来。
  2. B. 跟手：侧栏随手指拉出、页面随手指滑走。侧栏要接管系统私有的分栏手势；返回要把列表栏、详情栏改成真的导航栈（推翻文件夹设计 §3.3「中间栏没有自己的导航栈」），代价大。

变与不变

  • 只改 iPad 宽屏（三栏）的手势； 和 ‹ 按钮照旧都在
  • 右滑 = 点 ‹ / 点 ，没有新动作、新页面
  • iPhone、窄窗口 iPad、Mac 不变
  • 行中间起手的右滑（完成 · 置顶）、竖向滚动、点按不变
  • 空白处起手的右滑，系统照样拉出侧栏（今天就这样）

落地（按代价排）

  1. 栏边缘手势小：一个 iOS 专用的小部件，挂在三栏各自的导航视图上；只接左边缘 20pt 起手、横向为主的拖动，接手时让行的滑动和列表滚动等它，不接手时什么都不碰。
  2. 侧栏小：MainView 里最左一栏边缘右滑 → columnVisibility = .all，侧栏上左滑 → 收起；和 写的是同一个状态，「上次开着还是关着」照旧记住。
  3. 四个 ‹ 页小：文件夹页、项目的会话页、引擎页 / 名称页、项目下的任务页，在已有的 ‹ 旁边挂同一个动作（leaveFolder / leaveProjectSessions / nav.pop()），各 1–2 行。
  4. 验证中：这次拍图的 iPad 探针改成改前 / 改后两组，横屏竖屏各滑一遍，带上「行中间右滑仍是完成 · 置顶」；OrbitKit swift test；iPhone 抽屉和系统返回回归。
