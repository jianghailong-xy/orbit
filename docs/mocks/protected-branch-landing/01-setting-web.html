Landing setting — web

Workspace settings gain one way to choose how finished work reaches the target branch. “main” stands for the workspace’s target branch, whatever it is called. Source: docs/design/protected-branch-landing.md §11.1.

Recommendation: A. Both choices stay visible with what each costs, so the owner sees “faster” and “needs the right to push” side by side. B hides the trade-off behind a menu; C reads as a feature switch and loses the default’s explanation.

How finished work reaches main on GitHub.
Pull requestDefault
Orbit pushes to main when GitHub allows it. When main requires a pull request, Orbit opens one and merges it once the branch’s rules pass: required checks, and a review if one is required.
Push as meFaster
Orbit pushes to main with your GitHub account, so a landing doesn’t wait for a pull request where you may push past main’s rules. Needs the right to push to main. If GitHub refuses, Orbit opens a pull request instead.

Label

The design doc asks the board to settle the name of the default. Pull request mode now pushes directly when GitHub accepts the push, so a label that promises a pull request every time would be wrong.

Recommendation: keep “Pull request” with the Default badge. The description right under it says Orbit pushes when GitHub allows it. Alternatives: “Follow branch rules” (accurate, but says nothing to someone who has never met branch protection) or “Pull request if required” (accurate, long).
