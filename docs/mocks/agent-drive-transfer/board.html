Agent 上传 / 下载 Files：显示进度和速度

现状：Agent 调 drive_put 把 15 个文件放进 Files 时，对话里只有一行 “Thought for 1s, used 6 tools” 和 Agent 自己写的路径列表，看不出传了多少、多快、还要多久、哪个失败。 提议：一轮里连续的 drive_put / drive_get 调用不再折进 steps 行，而是合成一张传输卡——总进度条 + 速度 + 剩余时间 + 每个文件一行；传完自动收成一行，可点开、可直达文件夹。条和文案沿用 Files 页上传托盘（FilesUploadTray）。卡上 UI 文案为英文，注释为中文。

部分内容从哪里来
哪些调用合成一张卡同一轮里、中间只隔着思考的连续 drive_put（或连续 drive_get）；中间夹了别的工具就另起一张。卡和其他“自成一卡”的调用一样，结束它前面的 steps 行（isGroupableTool 排除它们）。现有 transcript 节点
“of 15”卡知道的文件数 = 已发出的调用数。Agent 是一个一个发的，所以分母会长；分母还没稳定时只写 “Uploading 7th file”，不写 “of N”。并行发出的一批调用一次就知道全数。tool_use 节点
字节和速度Runner 在每个 8 MB 块发出后（以及块内按读取字节）上报 sentBytes / size；速度取最近 3 秒滑动平均；剩余时间只在知道总大小时显示，说法同托盘（“under a minute left” / “about 3 min left”）。新：runner 在 putDriveFile / getDriveFile 里每 ≤ 500 ms 发一条进度事件到会话流；不进 transcript 存档，只活在直播里
完成后全部成功 → 收成一行（② b），点开见 ② c；有失败 → 卡不收起（③ a）。刷新页面后从工具结果重建完成态（大小来自结果的 sizeBytes，用时来自调用起止时间），不依赖进度事件。现有工具结果
卡住≥ 20 s 无新字节 → 黄色 “No progress for N s”进度事件的时间戳
文件名相对目标文件夹显示，按子文件夹分组；完成的行链到 orbit-drive:<id>工具入参 path + 结果 link
