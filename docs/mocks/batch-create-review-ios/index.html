批量建任务确认页「Create 3 tasks?」：先看结论，再看任务，任务能点开

截图里这张 sheet 有三个硬伤：右上角 ✕ 被画成了蓝色主按钮，和「Create them」抢着当确认键； 标题说了两遍（外加 new tasks 徽标），真正要你判断的后果却塞在一颗像按钮的蓝药丸里； 三个任务标题是等宽灰字，挤成一坨、分不清边界，而且点不开 —— 每个任务的描述和验收标准明明就在卡片的 input 里。 下面 ② ③ 用的就是这三个任务的真实标题、验收标准和描述（项目「Google 账号登录与开放注册」，10-07 00:40 建的那批）；④ 是同一套样式遇到有依赖的批次时的样子（示例数据）。

落到代码上（只动 iOS/macOS 的 SwiftUI 层，服务端和数据不变）

  1. ✕：ApprovalReview.swift 的关闭按钮从 .confirmationAction 换到 .topBarTrailing（macOS 保持原样）—— ShareSheet 已经这么分过平台。
  2. 不重复标题：sheet 里（inApprovalReview）批卡的 details 不再画 ApprovalHeader；对话里那张紧凑卡照旧有卡头。
  3. 后果卡：ImpactPill → 带图标的行；batchImpactLines 的字符串不变，按「 — 」拆粗体 / 灰字。单任务卡也用这颗药丸，跟着一起换，两张卡仍是一家。
  4. 孤立的「·」：清单名、边数、形状三段先过滤空串再用 " · " 连接（现在 shapeSuffix 无条件带前缀）。
  5. 任务列表：OrbitAskBody 的 mono 树行换成按层分组的列表（分层算法从 Web 的 batchGraph.ts 搬到 OrbitKit，替掉 batchTreeRows），比例字 + 序号 + 「Waits on」；每行 NavigationLink 推入任务页，读 approval.input["tasks"][i]。
  6. 底色：review 模式的 ScrollView 用分组底色，内容放白卡片。
  7. 按钮文案：「Create them」→「Create N tasks」，Web 的 ApprovalPanel.tsx 同一个按钮一起改，两端说法一致。

刻意没改的

  • 后果文案本身：「3 need a manual start — nothing will trigger them」两端共用、有测试锁着，这里只改排版。
  • sheet 高度：仍是 .large。所有审批共用这个 sheet，有的很长；按内容自适应高度会在展开 / 收起时跳，收益不值。
  • 按钮高度：34pt 是 ApprovalMetrics 注释里定下来的，这次不碰。
  • 每个任务单独标「马上开跑 / 等待」：服务端预览只给总数，不给逐条结果；要做得先改预览接口，不在这次范围里。
