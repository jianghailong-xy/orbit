项目会话页 · 第三版：从第一性原理出发

一个项目是这样一条链：目标 → 任务 → agent 去执行（会话）→ 成果落地（合入分支）→ 判据验收。干活的是 agent，你的角色是定方向、回答问题、做判断，你最稀缺的是注意力。会话只是 agent 干活的载体，是实现细节，你心里想的是任务：哪个任务在动、到了哪一步、卡没卡在你这里。所以这一页的单位应该是任务，而不是会话。落地也不是另外一件事，它就是任务的最后两个阶段。

① 你打开这一页时要回答的问题，按优先级排

每个问题下面写它在这一页上怎么回答。答不了这五个问题的东西不放；只有答得了的才放，而且按这个顺序从上往下排。

Q1 · 注意力
有没有事等我？
审批、提问、证据裁决、阻塞。等我的事比任何别的都重要，而且唯一需要我动手的就是它们。
Needs You 节置顶；一句话状态变琥珀色
Q2 · 健康
项目在动吗？
在动、卡在我这、出错了、还是停着。「在跑」不等于「健康」：一个 agent 40 分钟没有输出，比它在跑本身更值得注意。
一句话状态 + 每个任务的最近活动时间，太久没动静就标出来
Q3 · 现在
谁在干什么、到哪一步了？
每个活着的任务在做什么，以及它在执行 → 验收 → 落地 → main 这条线上走到哪了。
Active 节：一个任务一行 + 一条四段的阶段条
Q4 · 方向
接下来是什么？还剩多少？
下一个轮到哪个任务、它在等谁，还剩几个任务。
Up next 节 + 进度条
Q5 · 抵达
我要看某个 agent 的过程
一下点进那个会话：看它在干什么、插话、停掉它。历史会话按需去找。
点任务行直接进它当前的会话；Done ›、All sessions › 放历史
这一页 · 现场：变化快的东西。现在谁在动、卡在哪、我点哪里进去。每 4 秒刷新一次。
项目页 · 计划：变化慢的东西。目标、判据、任务图、落地设置、历史。改计划、看全貌去那里，这一页只链接过去。
Coordinator 对话 · 指挥：决定和指示都在对话里下，回答也只在对话里的卡片上。这一页只告诉你它现在在做什么。
现状按会话、按时间排

  • 只答了半个 Q2（1 running）；Q1、Q3 的「到哪一步」、Q4 都答不了。

和前两版的区别，以及要你定的事

项第三版的选择为什么 / 代价
单位任务，不是会话。会话、落地、验收都只是任务的阶段。第一、二版还在「会话列表」上修修补补，第二版的落地还单独占一行。以任务为单位后，一个任务只出现在一个地方。
页名 / 入口副标题改成 14 tasks · 24 sessions；列表里进度小标签长按菜单的 Sessions 是否改名为 Work，待你定。页面已经不只是列会话了，名字跟着变才不误导。
阶段条四段：执行 → 验收 → 落地 → main。项目直接合进 main（没有项目分支）时只有三段。数据现成：任务状态加上项目的 buckets（running / awaitingVerification / integrating / onIntegrationLine / onUpstream），再加 integration.inFlight。新增：这一页要拉项目的任务列表和依赖图。建议服务端提供一个「项目现场」接口，一次返回这些东西，不让客户端拼三个请求。
安静太久运行中超过 N 分钟没有任何输出就提示。N 建议 20。待你定：要不要做、阈值多少。依据是会话的最后活动时间（lastTurnAt 和事件流）。
不放的判据、任务图、落地设置、改计划：都在项目页。回答按钮：只在对话里。这一页只回答五个问题，不和项目页抢活。
Web同一套规则。确认 iOS 版之后再画 Web 的会话栏版本。设计文档 §5 要整节重写。
