iOS 项目会话页 · 第二版：一进来先看到「项目现在在做什么」

页面最上面是一张 Now 卡。第一行用一句话说项目现在的状态，下面一行一件正在发生的事：哪个任务在跑、跑到哪一步、哪个分支在落地、coordinator 在等什么，最后一行是接下来会发生什么。没有事在发生时，卡片说明为什么停着。会话列表退到卡片下面，作为「Recent」。

三部手机是同一个项目的三种状态：在干活、卡在你这里、停着。第一部的数据来自这个项目 9:57 的实际状态（落地 P3b 那一行是示意）。

现状你截的图
  • 能看出「10/14 done · 1 running」，但看不出在跑的是哪个任务、跑到哪了，只能在下面 24 行会话里一行行找转圈图标。
  • coordinator 在等什么、哪个分支在落地、下一个轮到哪个任务，这一页都没有。
  • 停着的时候也说不清为什么停：是等你、出了错，还是项目被暂停了。

Now 卡每一行的来源

行什么时候出现、写什么数据
一句话状态按顺序取第一个成立的：Waiting for you → Working on <任务> → Landing <任务> → Paused / Waiting on <依赖> → Done。由下面几行推出来，客户端纯函数，放进 OrbitKit 加单测。
等你执行会话或 coordinator 在等你，琥珀色，排第一。现成的 SessionLine（approval tone）。
在跑的任务每个在跑的任务一行：任务名、蓝字写此刻在做什么、已跑多久；重跑过的加 Run N。成员会话里状态是转圈的那些，文案是现成的 SessionLine；任务名建议服务端在 projectMembership 里加 taskTitle。
落地有落地作业在跑或排队时出现：阶段 + 计时；失败时变红，写失败的检查。项目详情的 integration.inFlight，项目页已经在用（integrationPhaseWords、landingClock）。这一页需要多拉一次项目详情，也可以让 /projects/sidebar 带上它。
Coordinator一直出现，写它在等什么或在处理什么（Watching… / Checks failed… / 最后一句话）。coordinator 会话的 SessionLine 和 attention.coordinatorItems，都是现成的。
Up next / 停的原因下一个能开始的任务和它在等谁；没在跑时写停的原因（暂停、预算、依赖、全部完成）。新增数据：任务依赖图 + pausedAt / blockers.open。项目页已经在拉依赖图，可以复用同一个接口。
Recent其余会话按任务合并、按时间排，一个任务一行（见第一版）；Judgments 收成一行。同第一版。
