#方案 A方案 B推荐
D1 项目页入口coordinator 卡片 Workspace 行加 Move…，打开同一个 Move 对话框；Rebind 只留给对话已坏的情况。不加入口，只能从会话列表 / 会话页 ⋯ 里的 Move… 搬。A：在项目页找 coordinator 是最自然的地方，零新界面。
D2 引擎搬不动时和普通会话一样置灰写原因（比如 Codex 换不了机器），就此为止。额外给一个 Start a new coordinator there：在目标 Workspace 开新的 coordinator，旧对话留着只读（就是今天的“换一个新 coordinator”，只是可以选地方）。A：先不加。B 等于开新对话，今天 ⌄ 菜单里已有“开下一个 coordinator”，需要时再把选地方加进去。
D3 已换下的旧 coordinator当普通会话处理：能搬，不碰项目（项目的指针早已指向新的那个）。照旧拒绝（A project's coordinator stays …）。A：它已经不协调任何东西，没理由锁住。
D4 目标 Workspace 是另一个仓库不拦，确认框里照常写“改动留在原 Workspace 的分支上”。检测到仓库不同时额外加一句提醒，或直接拦。A：项目代码在项目分支、任务各自的 Workspace 里，coordinator 不依赖自己的工作目录；B 需要新数据才能判断。
