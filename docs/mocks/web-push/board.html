④ 通知长什么样、点了去哪

系统通知中心里的一条，跟 YouTube 一样。标题和正文就是手机上那条，一字不改（服务器同一份内容）。

O
Google Chrome · orbitd.io · now
Approval needed · Fix login redirect
Claude wants to run: npm run test:pg
Settings ▾
O
Google Chrome · orbitd.io · 2m ago
Session finished · Translate owner cards
All 3 tasks are done. Review the changes.

示例文字，非真实数据。macOS 上的 Chrome；Windows 和 Firefox 外观各自不同，内容相同。

  • 点通知：已有 Orbit 标签页就切过去并跳到那个会话 / 项目 / 任务；没有就新开一个。跳转地址跟飞书卡片的「Open in Orbit」同一套规则。
  • 同一会话的新提醒顶掉旧的：同一个会话等审批，只留最新一条，跟手机一样。
  • 在手机上批了：浏览器里那条审批通知自动消失（服务器本来就发「清掉这些会话」的同步，浏览器也收）。
  • 浏览器全关了：收不到；推送服务保留 1 天，下次打开浏览器时送达。
  • Orbit 标签页正在前台：见 D3。

⑤ 架构：多一个出口，上游一行不改

哪些事提醒、什么时候提醒、两个开关、退出登录就停推，全在 deliver() 之前，已经对三个平台一致。浏览器只是第三种设备。

提醒的来源审批、完成、Agent 找你、Owner item…
→
PushService判断要不要响、开关、去重
→
deliver()owner 的每一台在线设备
→
ios → APNs
android → FCM
web → WebPushTransport（新）加密 + VAPID 签名，POST 到浏览器厂商的推送服务
→
浏览器的 sw.js（新）显示通知 · 点击跳转 · 清掉已处理的
改哪里内容
数据库device_tokens 加一列 web_keys（浏览器订阅的两把公钥）。token 存订阅的 endpoint，platform = 'web'。
服务器新 web-push-transport.ts（用 web-push 库），GET /api/push/web-config 给公钥，register 收 platform: 'web'。endpoint 只认浏览器厂商的推送域名，防止被拿来请求任意地址。推送服务回 404/410 就删掉这条登记。
Webpublic/sw.js，Settings 新卡片，退出登录时退订。nginx 给 /sw.js 加 no-cache。
部署生产 .env 加 WEB_PUSH_PUBLIC_KEY / WEB_PUSH_PRIVATE_KEY（一次性生成，之后不能换，换了所有浏览器要重新订阅）。不配置就整个功能关闭，开关不显示。

待定 · 要你拍板

方案 A方案 B建议
D1 在哪打开只在 Settings → Notifications 的开关打开。再加一条登录后出现一次的提示条「Get notified in this browser」，可关掉。A：不打扰；先看用得怎样再说提示条。
D2 收哪些跟手机完全一样，受同样两个开关管。只收「需要你」的：审批、Agent 找你、Owner item。A：一套规则，不出现「手机响了浏览器没响」。
D3 Orbit 标签页正在前台不弹系统通知，页面本身已经显示了。照样弹。A：人就在页面上，再弹一次是重复。

落地（按代价排）

  1. 服务器：迁移、WebPushTransport、web-config、register/unregister 支持 web，带测试（内容转换、域名白名单、410 删登记、退出登录不推）。
  2. Web：sw.js、Settings 卡片和四种状态、退出登录退订、nginx，带测试。
  3. 生产：生成 VAPID 密钥写进生产 .env，部署；所有 Orbit 标签页关掉的情况下，在 Chrome 里实测一条审批通知。
  4. 第二期：自建部署 10.66.82.117，需要先有 HTTPS（域名 + 证书）和到浏览器推送服务的外网。

限制：iPhone / iPad 上的 Safari 只有把 Orbit 加到主屏幕（iOS 16.4+）才能收；有 Orbit App 的话不需要。
