④ 撤销与容量

流是长连接：开着的时候权限可能没了；匿名长连接也更容易被耗。

什么时候断流

事件断哪些
访客被移除 / 自己离开该访客在该会话的流
公开链接撤销 / 过期 / 改成不含会话该链接的所有流
会话进回收站 / 被删该会话的所有访客流与公开流
建议 A：写路径提交后发 viewer.revoked，经现有 NOTIFY 桥到每台 apiserver，当场发 gone 并关流；每次 ping（~20 s）再复查一次（一条主键查询），兜住信号丢失和过期到点。
B：只靠 ping 复查，撤销后最多还能看 20 s。

上限（超了回 429 → 客户端退回轮询）

维度建议值
同一 IP + token 同时开的流4
同一链接同时开的流200
每台 apiserver 观众流总数2000（环境变量可调）
重连退避1 s 起翻倍到 30 s，加抖动
一条流的成本：hub 上一个进程内过滤订阅；同一会话的观众共用一个 runner-link 订阅。没有额外 DB 轮询，只有 ping 时一条权限复查和 head 的偶发重读。标签页隐藏时 Web 关流，回来带 sinceSeq 重开。
