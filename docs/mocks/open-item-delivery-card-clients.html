An exception item’s delivery to the coordinator — clients

The control plane already records the item as fields beside the turn’s echo (openItemDelivery, written by b14b2b604; the web draws it as OpenItemDeliveryCard.tsx). iOS and macOS decode the same payload and draw the same card — every fact the web card shows, in the native card language (BackgroundWakeCardView): amber card, glyph + Exception item + kind chip, the title, the task it is about, why it is here, the landing the platform already knew, the doors, and the paragraph the agent read folded at the foot rather than dropped.

Both shells share this source (src/macos/OrbitKit + src/macos/OrbitApp): iOS draws the same card with the iOS half of the type ramp, which is what the second and third figures differ by. A delivery carrying no openItemDelivery (every event stored before the payload existed) is untouched — it stays the bubble on the left.

What this is, and what it is not
  • The card reads the payload only. Identifying a delivery by the shape of its text is the road the web already backed out of (lib/deliveredMessage.ts); a client that did it would draw half a card for a paragraph it half-recognises.
  • Half a card is never drawn. A payload missing itemId, kind or title — or an openItemDelivery that is not an object — decodes to nothing, and the turn keeps the reading it has today (figure 1).
  • The prose is kept, folded. “What the coordinator was told” opens the paragraph verbatim, exactly as the web’s <details> does.
  • The existing note path keeps its job. AttachedNoteView is untouched: it still draws whatever delivery appended to a message (controlPlaneNote) in the bubble. On a delivery turn the card takes the turn itself — the delivery is the control plane’s, not the reader’s — and anything the same turn carried in its note rides inside the card, the way BackgroundWakeCardView already handles it.
  • English copy, held to the web’s. Every string (“Exception item”, the kind labels, the landing sentences, the door names, “a notification, not an interruption”) is the web card’s wording, and a copy-parity test reads the TSX to keep the two ends together.
