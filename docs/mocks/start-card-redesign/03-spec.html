其他状态

这一版画的是“协调者请求了，建议 Automatic 关”。

  • 协调者建议 Automatic 关：开关仍默认开，How it runs 的说明里加一句 (the coordinator suggested off)；它的理由在页头它的原话里。
  • 没人请求，自己点 Start…：页头只写 Nobody asked yet，没有协调者引用；Automatic 本来就默认开（defaultSettings）。有协调者时 Chat 照常。
  • 项目还没有协调者，Automatic 开：卡片写明开始时会建一个、建在哪（任务所在的 workspace，规则同 project_ensure_coordinator）。按下后先确认建得出来；建不出来（比如 runner 都离线）就整次不写，底栏上方说原因。建好后它的第一条消息就是“项目已开始”。没有协调者时不显示 Chat。Automatic 关时不建。
  • 合并检查为空：正常状态。那一行写 None 和 Work lands once it rebases cleanly.，不变色，也不拒绝请求；Automatic 那句改成 “merges into main by itself”。
  • 请求失效（计划或标准变了）：底栏按钮变灰，按钮上方一行沿用 requestGone 的句子。
  • 还在读取：按钮变灰，各节显示占位，不画半张卡。
  • 计划太大（依赖图折叠了）：Plan 只写 “N tasks” 和 View tasks。
  • 按下没成功：错误句子显示在底栏按钮上方，卡片不动。

数据和要改的东西

建议分两步：第一步只改客户端，第二步改服务端。

  • 第一步 · 客户端：新结构；Automatic 默认开（协调者建议关时只加那句说明）；不再画 request.warnings 和 Orbit checked；固定底栏和 Chat；按层的 Plan；编号规则多认 P1a。清单先写开关和落地线能确定的几行。
  • 第二步 · 服务端：
    1. 就绪检查的提醒只给协调者：project_request_start 的返回照旧带 warnings，START_REQUEST 的 payload 不再存。
    2. POST /projects/:id/start：Automatic 开而项目没有协调者时，确保建出一个（复用 ensureCoordinator 的规则，建在任务所在的 workspace）。先确认能建，建不出来就整次拒绝（409，说原因）；响应里带上新协调者的 sessionId。卡片要提前写“建在哪”，所以项目的读接口加一个预览：会建在哪个 workspace、哪台 runner 上。
    3. project_request_start 的 automatic 改成可选、默认开；工具说明写“默认开，你认为该关就在 why 里说”。合并检查为空不拒绝，START_NO_MERGE_CHECK 只作为提醒留在协调者那边。
    4. START_REQUEST 带上每个任务的完成方式（readStartPlan 已经读了 completionCriterion），清单里的 P10 和 Plan 里的 You 才有数据。
    5. 可选：codeless 启发式只看 OWNER_CONFIRMED。没有命令的 EVIDENCE_JUDGMENT 是写代码任务的常态，这次 11 个全是误判，协调者那边也少一些噪音。
  • iOS / macOS：ApprovalCards.swift 的 StartProjectCard 重排（含“没有协调者”和“合并检查为空”两种状态，mergeCheckMissing 的琥珀色去掉）；项目页的两个 sheet（RequestedStartProjectSheet、OwnerStartProjectSheet）改成导航栏标题 + 固定底栏 + Chat；协调会话里的预览卡不变，点开的审阅页用同一个布局。草稿的开关从请求里取改成默认开（StartSettingsDraft）。
  • OrbitKit：StartProject.swift（新文案、会找你的事、按层、底栏那行，删掉 warningLines 的用处）、ProjectRunSettings.swift（开关的两句）。
  • Web：StartProjectCard.tsx、lib/projectStart.ts 同步。
  • 测试：StartProjectTests、StartProjectCardCopyParityTests、StartProjectWiringTests、StartProjectCard.test.tsx；第二步加 project-start-request 的 pg spec。
  • 不变：按下仍是一次写入（POST /projects/:id/start），请求和失效的规则不变；开始后的回执照旧标出“和协调者建议不同”的设置。
