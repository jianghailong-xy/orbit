Start 卡片重新设计：从“按下 Start 到底改变了什么”出发（第 2 版）

上一版只修了黄字。这一版从头问：owner 在这张卡上要做什么决定？页面的每一部分都要回答其中一个决定需要的问题；回答不了的，挪走或压成一行。

依据是代码里 Start 的实际行为（POST /projects/:id/start、Automatic 对证据审核和问题分派的影响）和产品文档里写下的理念，出处都标在下面。

第 2 版按 owner 10-07 的决定改过：① Automatic 默认开；② 卡片上不放 owner 不关心的提醒，刚建好的项目不该一打开就有警告；③ 合并检查可以为空；④ 项目还没有协调者时，按下 Start 顺手建一个。

第一性原理：按下 Start，实际发生三件事

一次写入：标准的 seal、四项设置、它回答的那份请求。

1 · 只有你能做

确认“做完”的定义

7 条验收标准被封存（seal）。之后项目是不是 done，只从这 7 条推出来：每条都满足、都落到 main，而且你确认的是当前这一版。改标准、确认标准，是产品里只能由你做的两件事（HUMAN_ONLY）。

2 · 默认放手

决定放多少手

Automatic 默认开：任务做没做完、路上的冲突和检查失败、分支进不进 main，都由协调者处理；会找你的只剩 P10 的确认、标准变更、它 2 小时内解决不了的问题。关掉是你的选择，关掉后 11 次证据审核都会找你。项目还没有协调者时，开始时顺手建一个，Automatic 才有人跑。

3 · 开始花资源

让工作开始

P1a 马上开工，其余 11 个按依赖接着跑，最多 3 个同时跑。协调者开始用 runner 和模型额度。

其余设置（落到哪条线、并发数、合并检查）开始以后都能在项目页的 How it runs 里改，落地线在第一次落地前也能改。所以它们不必在这里展开讲。

所以这一页只回答三个问题

按决定排，不按数据类型排。结果在前，过程在后。第四个问题“有没有要先处理的”，不该在这张卡上问你。

你要回答的问题新页面的一节现在的卡片
① 做完是什么样？Done when：放在第一位，不折叠；下面一句写明 done 只从这几条推出。有，但和计划、设置、提醒一样分量，排在中间。
② 放多少手？以后什么会找我？How it runs：Automatic 默认开，下面直接列出“会找你的事”，开关一拨清单就变；其余设置一项一行。开关跟着协调者的建议（这次是关），加一段 6 行说明，看不出后果；四项设置平铺。
③ 打算怎么做？Plan：按层列出 12 个任务，P1a 标 Now，P10 标 You。一行顺序字符串，编号认错，读不出先后。
④ 有没有要先处理的？不在这张卡上：协调者能修的，在请求前修好（检查直接拒绝请求）；只跟协调者有关的，只告诉协调者。到你面前的卡片默认没有警告。✓ 是底部一行小字；⚠ 是 6 段橙色原句，插在计划中间。这次 6 条全是误判。
→ 开始Start 固定在底部，下面一行写明按下等于什么；右上角 Chat 用来先改点什么。在 2,650 pt 长卡的最底下，要滑三屏多才能按到；项目页打开的 sheet 里没有 Chat。

产品理念 → 这一页的设计决定

每条理念都摘自仓库里的文档或代码注释。

理念这一页怎么做
Mission control：监督、可见、能干预，不承诺全自动docs/project-maturity.md默认放手（Automatic 开），但“会找你的事”写成清单，干预点一眼看得到；Start 下面写明按下等于什么。
标准和不可逆的事归你Automatic 的说明 · docs/human-only-authority.md标准放第一位；要你确认的 P10 在“会找你的事”和计划里都标出来。
任务完成是过程，验收是结果docs/ux/project-acceptance-consolidation.html结果（Done when）在前，过程（Plan）在后；计划只给大概，细节去 View tasks。
既不什么都不问，也不什么都问：给你一个拨盘docs/product-intro.md拨盘默认在 Automatic；两档各会找你几件事，按下之前就能看到。协调者建议关时只在说明里提一句。
平静、精确、对边界诚实docs/project-maturity.md卡片上只放你要决定、能决定的东西：不放内部词，不放你做不了什么的检查结果，刚建好的项目不带警告。
在手机上批docs/product-intro.mdStart 固定在底部；开始后还能改的设置压成一行一项。
折叠的清单等于请人不读就签ApprovalCards.swift 的 criteriaList 注释标准不折叠，仍是每条两行加 Read all。
被请求才出现；一次按下，一次写入StartProject.swift 文件头保留：仍由协调者请求，Start 仍是一次写入，计划变了请求就作废。
