Today — one amber edge around a blue card

The shipped rule: .approval-card.coordinator-question { border: 1.5px solid var(--warning-solid) } — nothing else on the card changed.

  • The line itself is right: 1.5px, solid, full-strength orange — the 2026-11-13 pick (Q2) and the same stroke native's emphasized draws.
  • Everything it wraps is still --brand: tinted head, head rule, FROM COORDINATOR mark, action rule and the Send answer button.
  • Native draws the whole card orange — ApprovalReviewLayout(tone: open ? .orange : .blue, emphasized: open) with an orange icon chip. Web is the only client that shipped the outline alone.
  • Orbit's toned cards put surface, rule, mark and edge in one tone. The owner open-item card does it with --warning-bg + --warning-border; this card puts a stray amber outline on a blue object.
  • It is the only 1.5px card edge in index.css. Every other 1.5px border there is a status dot or a spinner.

The line conforms; the card it draws does not. Width and hue match the approved pick, but it is the only amber thing on a blue card — so it reads as a warning frame dropped over somebody else's card, the exact confusion the Q2 board flagged.

Redesign A — the whole card is amber Recommended

Keep the owner's heavier edge; give it a card that agrees with it. This is the same chrome the owner's open-item card already wears.

  • Edge: 1.5px solid --warning-solid — unchanged, the 2026-11-13 pick.
  • Surface: --warning-bg; head rule and action rule --warning-border; FROM COORDINATOR drops .prov-brand for its default amber mark.
  • Action stays blue: --brand is the one pressable colour — the open-item card pairs an amber surface with blue presses the same way.
  • Now web agrees with native and the Q2 board: one orange card, and two cards waiting on the same person agree too.

Conforms: every toned surface, rule and mark comes from the warning family, and the heavier edge is the one documented exception.

B

Redesign B — amber, every line on the hairline

Same amber card, but the edge returns to the system's 1px border role.

  • Edge: 1px solid --warning-border — the border role the status family defines, and the hairline every other card uses.
  • Nothing leaves the token roles (fg / solid dot / tint bg / border), and there is no 1.5px exception left to explain.
  • The amber surface and the amber mark still carry the “waiting on you” reading; the edge is just quieter.
  • Trade-off: in a long open-items list the card stands out less than A, which is the only reason A keeps the heavier edge.

Conforms strictly: pick this if the 1.5px width is itself the objection.
