Coordinator question card — a scheme from the product's own palette

Same card, three tones, every value already a token in index.css. The card is drawn with the real component classes; only this board's frame and captions are drawn. Question: which colour should an open question wear, so it reads as “somebody is being asked” and not as “something went wrong”?

Scheme 1 — brand blue, solid heavier edge Recommended

The card keeps the tone it already has everywhere; only the edge is emphasised while the question is open.

  • Surface, head rule, mark and action stay --brand — nothing new is introduced, and the answered card drops back to the 1px edge.
  • This is the product's own “asked of you” colour. The web strip that points at what waits marks it with a blue dot (decision-strip-dot, #3b82f6).
  • The card's own comment says so: “the mark is in the brand colour rather than the warning one — nothing is wrong, somebody is being asked” (index.css:14726).
  • It was Q1, the option the 2026-11-13 board itself recommended; only one value changes.

Matches the product: blue is “someone is asking you”, and the thicker solid edge is the emphasis — no warning tone borrowed.

2

Scheme 2 — brand blue, hairline edge

The card as it was before 2026-11-13: the plain approval chrome, no emphasis beyond its own tint.

  • No new tone and no thicker line — the most conservative scheme; the card is exactly the approval card.
  • The pointing is left to the strip and the project page: the “1 open question below” line scrolls to it.
  • Weakest in a list: in a transcript of several cards, a plain 1px blue card does not say “answer me” before reading.

Matches the product — but it gives up the thing the 2026-11-13 pick was for: being visible before it is read.

3

Scheme 3 — amber card

The exception-card language: the same amber surface the owner's open-item cards wear, plus the heavier edge.

  • Amber is a product colour for “this is yours to act on” — but it is the exception language: conflicts, failed checks, escalations (.project-open-item-card.is-owner, index.css:26545).
  • Amber also means warning / criteria change in the card language; the Q2 board itself warned that the two will be confused.
  • It paints a question — a normal, healthy thing a coordinator does — as a fault, and it is the only card whose surface leaves its own family.

Product-adjacent, not product-matching: it is the exception tone applied to something that is not an exception.

What Scheme 1 changes

One value

/* was: border: 1.5px solid var(--warning-solid); */
.approval-card.coordinator-question {
  border: 1.5px solid var(--brand);
}
/* nothing else moves: surface, head rule, mark,
   action rule and button were brand already */

Why blue and not amber

  • The card is an ask, not a fault: the product's calm reader-facing ask is brand.
  • The web's own “something waits for you” mark is a blue dot (decision-strip-dot).
  • Amber stays available for real exceptions and criteria changes, so the two never read alike.
