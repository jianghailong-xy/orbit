账号掉线、重新登录：网上其他产品怎么做

查了五类做法，都是按它们公开的文档重画的示意图，不是截图，来源附在本图最下面。最有用的是 Claude Code 自己：登录到期前 3 天就会提醒续期，读的是登录文件里的到期时间，这个时间 runner 能读到。

Claude Code官方文档 + 2.1.292 本体
⚠ Your login expires in 3 days · run /login to renew
───────────── /status
Login   Expired — log in again
───────────── /login
Paste code here if prompted >

登录到期前 3 天，启动时提醒续期，但不拦着你用。过期以后 /status 写「Expired — log in again」。浏览器跳不回本机时（SSH、容器里常见），让你把网页上的码贴回来。

→ 我们：快过期就提前提醒（①）。贴码这一步省不掉，那就做成点一下（⑤）。

iPhone 设置Apple ID 要重新登录时
Update Apple ID Settings1
Some account services will not be available until you sign in again.

问题顶在设置页最上面，带红色角标。用一句话说后果：重新登录之前，有些服务用不了。点进去就开始登录。

→ 我们：掉线的账号也用一句话说后果：会话用不了这个账号（②）。

ZapierApp Connections
Notion · alex@example.com⚠ ExpiredReconnect
Expired connections: 1 — the number of connections that require reauthorization

过期的连接，Reconnect 按钮就在过期标记旁边。重连的还是原来那个连接，用到它的流程全部恢复，不会多出一个新连接。

→ 我们：按钮挨着状态，只在要处理时出现。登回的是同一个账号目录，我们本来就是这样（③）。

苹果的粘贴按钮UIPasteControl / SwiftUI PasteButton
Paste
iOS 16 起，程序去读剪贴板会弹「允许粘贴」；用这个系统按钮不会弹。

系统自带的粘贴按钮，用户点一下就把剪贴板里的内容交给 App，不经过权限弹框。

→ 我们：贴码那一步换成它，粘贴完直接提交（⑤）。

拿来的五件事
  1. 快过期先提醒，别等会话失败才发现（Claude Code）
  2. 掉线时说后果，一句话就够（iPhone 设置）
  3. 按钮挨着状态，只在要处理时出现（Zapier）
  4. 复制码和打开网页合成一下（VS Code / GitHub CLI）
  5. 粘贴一下就提交（苹果的粘贴按钮）

改后 · 引擎页：快过期先提醒，掉线时说后果

左边是上一版（两个按钮已经去掉、暂停改成左滑），右边在它的基础上加了两行。第二个账号的登录还剩 3 天，第三个已经掉线。

上一版按钮去掉以后

快过期的账号看不出任何异样，等过期了、会话失败了才知道。掉线的只写 Signed out，看不出影响多大。

这一版加两行

两行都只在出事时出现，平时的账号行还是那么短。

  • 1快过期先提醒：登录剩 3 天以内，这一行多一行橙字「Login expires in 3 days」，右边一个 Renew。点了走和 Sign In 一样的登录，登回同一个账号，到期时间续上。不点也照常能用，和 Claude Code 自己的提醒一样。Orbit 上的会话大多没人盯着，等它过期再发现，会话已经停了。
  • 2掉线时说后果：Signed out 下面一句「Sessions can’t use this account until you sign in again.」。如果这个引擎只有这一个账号，就改成「Sessions on this runner can’t use Claude Code until you sign in again.」。
  • 3按钮挨着状态：Renew 和 Sign In 只在要处理时出现，平时的账号行没有按钮，和上一版去掉按钮的方向一致。
  • i只有 Claude Code 有到期时间：runner 已经在读每个账号的 .credentials.json，里面的 refreshTokenExpiresAt 就是 Claude Code 自己用来提醒的那个字段。这台机器上三个登录都有这个字段，还剩 23 到 24 天。Codex 和 Antigravity 没有这个日期，只做 ②③。

改后 · 点 Sign In 或 Renew 之后

登录卡片的样子和现有文案都不变，改的是：哪一下开始、哪个按钮关、怎么贴、主按钮跟着下一步走、什么时候收起。Claude Code 要把码贴回来，从现在约 10 下减到 6 下（都算上 Safari 里的两下和切回 Orbit）。

每一处在做什么

  • 4点了就开始，只留 Cancel：不再先出一张只有「Sign in to Claude Code」的卡片，Add Account 早就是这样。进行中只有 Cancel，点了取消这次登录，卡片收起。现在的 Close 只把卡片藏起来，登录还挂在 runner 上，和 Cancel 放一起分不清。
  • 5粘贴一下就提交：框空着的时候，Submit 换成系统的 Paste 按钮，不弹「允许粘贴」，贴进来就提交。手打的话，框里有字时变回 Submit。贴错了 runner 会拒，橙字提示，再贴一次就行。
  • 6主按钮跟着下一步走：去网页之前，Open the sign-in page 是蓝色主按钮。从网页回到 Orbit 后，Paste 变成蓝色，Open 退成一行链接，以防要重开。
  • 7登好了自己收起：「Signed in — this runner is ready.」停一两秒，卡片收起，这一行变回 Signed in 和额度。
  • 8设备码先亮出来：码放大放在最上面，一个按钮「Copy Code & Open Sign-In Page」同时复制码、打开网页，到网页上直接粘贴（VS Code 的做法）。

落地（按代价排）

  • 小④ 开卡片传 autoStart: true（Add Account 现成的参数）；RunnerSignInView 加 onCancel（web 的 Add Account 卡片就是这么接的）。
  • 小⑤⑥ PasteBackForm：框空时用 PasteButton，拿到字直接 submitCode()。点过 Open、App 回到前台时，把 Paste 换成主按钮。
  • 小⑦ 页面看到这个账号变成 Signed in，等一两秒收起卡片。
  • 小② 掉线那一行加一句后果，是新文案，web 的同一行也加上。
  • 小⑧ 设备码卡片换顺序、换按钮文案。web 的同一张卡要一起改，两边有文案对照测试。
  • 中① runner 从 .credentials.json 读出 refreshTokenExpiresAt，随账号状态一起上报；服务端带过去，客户端在剩 3 天内显示。只有 Claude Code 有。

考虑过、没采用

  • 否在 App 里直接打开登录页（ASWebAuthenticationSession）：看上去能省掉切回 Orbit 那一下。但 Anthropic 的回调页不会跳回 Orbit，看完码只能点左上角 Cancel 关掉，意思是反的；而且打开前还要多点一个系统确认框，算下来一步没省。
  • 否自动读剪贴板：回到 App 时直接读剪贴板，iOS 会弹「允许粘贴」，比点一下 Paste 更烦。
