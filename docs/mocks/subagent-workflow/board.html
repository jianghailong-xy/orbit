Workflow · 父会话交一段脚本，Orbit 按脚本把一批 SubAgent 跑完，只唤醒一次

父模型调用 workflow，交一段 JavaScript（接口与 Claude Workflow 相同：agent / parallel / pipeline / phase / log）。脚本在父会话的 runner 上执行，每次 agent() 就是一次 SubAgent：路由、换候选、跨 workspace、审批、花费全部沿用。设计：docs/subagent-workflow-design.md。

今天 vs Workflow
① 今天后台 delegate × N，靠唤醒逐轮推进

能用

父模型派 4 个后台 SubAgent，结束一轮；每个结束都唤醒父会话，父模型看结果再派下一批

↓

控制流在模型脑子里

同样的输入两次扇出不同；12 个 SubAgent = 12 轮父模型，上下文越滚越长；返回值是自由文本；runner 重启后父模型凭记忆重派，常常重复或漏掉

② Workflow脚本决定控制流

确定、可复现

循环、条件、pipeline 无屏障的流水线都写在脚本里；整个 workflow 结束只唤醒父会话一次

↓

schema 校验的返回值

子 Agent 的 orbit mcp 多一个 return_result 工具，inputSchema 就是这次的 schema；所有引擎同一条路

↓

服务端日志，可重放

每次调用记进 subagent_run；resumeFrom 时没变的前缀直接取结果、花费 0

项决定
D1 脚本形态JavaScript，接口与 Claude Workflow 相同（runner 内嵌 goja）；不做声明式 JSON DAG
D2 谁能发起开了 SubAgents 和 Workflows 的会话都能发起，不发确认卡，与 delegate 一致
D3 并发与 SubAgent 共用 subagentsMaxRunning，默认从 4 改成 8
D4 花费上限没有默认值；maxCostUsd 可选，给了才生效；设置里不加
D5 隔离调用的补丁只交回，由脚本 applyPatch 或父模型决定，不自动应用

P1 编排

workflow 工具、goja 沙箱、agent / parallel / pipeline / phase / log、后台 + 一次唤醒、可选上限、并发默认 8

P2 schema 与重放

return_result（各引擎）、服务端日志、resumeFrom

P3 隔离

isolation: 'worktree'、补丁、applyPatch 与冲突列表
