04 · 手机端顶栏："Handing over"

交接进行中（coordinatorHandoff.state 为 WRITING 或 HANDING_OVER）时，iPhone 和 Android 顶栏中间显示 "Handing over"，和 web / Mac 头部（02-2）用同一个词。其他状态不显示，顶栏和现在一样。手绘示意，控件按现有代码画：iOS 是 ConsoleView 的 .principal，Android 是 SessionReader 里 PageBar.Bind 的 center。

iOS 1在末尾（今天中间是空的）
iOS 2不在末尾：替换问题胶囊（建议 A）
Android 1在末尾
Android 2不在末尾（建议 A）

3待你决定：不在末尾时，中间那一格给谁？

A · 建议 交接期间 "Handing over" 一直占着中间

B 不在末尾时问题胶囊 / 等待胶囊照旧，"Handing over" 只在末尾出现

  • 1在末尾：今天中间是空的（问题胶囊只在不在末尾时出现），这里放一个不可点的胶囊，灰色字 "Handing over"，玻璃底和问题胶囊一样高。不加转圈，和 web / Mac 的头部一致；转圈和计时留在对话里的 "Writing the handoff note" 那一行。输入框占位文字仍是 "Handing over to a new coordinator…"。
  • 2不在末尾：建议 A，"Handing over" 优先于问题胶囊和等待胶囊（needs-you）。理由：交接改变了输入框能不能用，而这个会话里的等待正要转到新会话，往上跳到旧卡片意义不大；回到末尾仍可以点右下角的跳到最新按钮。
  • 3B 的代价：人往上翻历史时，顶栏看不出正在交接，只能靠输入框的占位文字。
  • ·出现与消失：只在 WRITING / HANDING_OVER 时出现（iOS 判断用 CoordinatorContextActions.locksComposer，Android 用 CoordinatorHandoff.outgoing(detail)?.locksComposer，文字用 CoordinatorHandoffCopy 里的 badge 文案）。交接完成、失败或取消后立刻消失，中间恢复今天的规则。输入框收起导航栏时（打字中）跟着一起收起。
