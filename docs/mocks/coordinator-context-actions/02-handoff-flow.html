  • 1确认弹窗列出实际会发生的两件事：写交接说明，以及具体转移哪几个等待（数量和名称都从后端读，没有等待时这一行不显示）。按钮写 Hand over，不写 OK。旧会话不删除，沿用现有替换流程的说法。
  • 2平台在旧会话里发一轮固定提示，让它写交接说明（四个固定小节：现状 / 和 owner 的约定 / 在等什么 / 下一步）。这条提示属于平台消息，不显示成用户发言，界面上只有这条状态提示加计时。期间输入框禁用。Skip the note = 不带说明直接替换；Cancel handover = 什么都不改，会话恢复原样。
  • 3交接说明在新会话里显示为一张卡片，同时拼进开场消息；开场指令仍然要求先读 project_get 和 task_list，说明和项目状态冲突时以项目状态为准。卡片里的链接指向旧会话。
  • 4等待的转移：把旧会话名下所有 ACTIVE 状态的等待改到新会话名下，和 coordinator 指针切换放在同一个事务里，这样不会出现两边都收到或者两边都收不到。新会话里显示一枚提示，点开列出具体是哪些。
  • 5旧会话完成后，输入框的位置换成一条横幅，带链接跳到新会话，避免用户回到旧会话后继续在里面发消息。
  • 6失败（这一轮报错、超时、被用户停掉）时，什么都不改（旧 coordinator 继续有效，等待也不转移），给出三个出口。上下文满到连交接说明都写不出来时，引擎会自己先压缩，压缩期间显示 "Compacting…"，计时继续走。
