29 · Wiki 首页（web 桌面）布局优化：铺满右侧整块区域，随宽度重排

真实 WikiPage 组件 + 落地后的 index.css 渲染，数据仿 10-06 截图。左：现状；右：优化后。均为 1920×1080 窗口。手机端（≤960px）单列顺序不变，iOS 板不受影响。

现状1040px 定宽居中，主列短、右栏挤、目录撑高整页

改满宽流式，目录独立滚动，等你处理的放最上面

①去掉 1040px 上限，首页铺满右侧整块区域（Mintlify / GitBook 的 wide 模式）。首页是看板不是正文；文章页仍保持阅读宽度，不动。
②左侧目录 sticky + 独立滚动（高度 = 视口）。35 篇目录不再决定页面高度，主内容下面不再出现大片空白（Docusaurus / Mintlify 做法）。
③"等你处理"条：Review 与 Plan 并排置顶，横跨主区。Review 有待办时用浅琥珀底强调（Slab 的"待验证"色）。这是 Orbit 首页最该先看到的东西——owner 审 agent 的提案、确认 plan。
④主列 = 知识本身：Recent decisions 拿到宽列，标题不再截断；Recently changed 每次维护运行一行：谁 · 改了几条 · 分级计数 · View run / Revert run · 时间（DeepWiki"Last indexed"式的新鲜度）。
⑤右栏 = Agents used the wiki（Orbit 独有的"被 agent 消费"指标），从顶到底。Principles 留在主区、待办条下方横跨两列——DOM 不变（手机单列与 iOS 的顺序由它钉住），布局全由 CSS grid + display: contents 完成。
⑥按主区宽度重排（container query）：主区 ≥1500px 时 Recent decisions 与 Recently changed 并排成三列（下方 2560 图）；更窄时两者叠在 Review/Plan 下方；侧栏宽 clamp(280px, 24%, 380px)，始终贴右从顶到底。
