没有 workspace 的机器 · 规则、改动清单、分期、待你定

01–03 是样子，这一张是规则。原则只有两条：只问人才能答的事（文件夹是 agent 能读写的范围，登录是凭据），其余都推导； 不在沉默中卡住（什么都跑不了的机器要被说出来，路径错了当场就说）。

  • orbit register 的目录只当建议，不当默认。
  • 「最近用 Claude Code / Codex 工作过的目录」先不扫：runner 今天刻意不普查目录（claude_history.go），放到 P2 再定。

#场景规则为什么
1什么时候出卡机器在线，这个账号在它上面 0 个 workspace，打开它的新会话页时。离线：卡上写离线，两步都不能做。没有文件夹就开不了会话；与其让人去设置页，不如在开始的地方把它问掉。
2文件夹建议orbit register 的目录：存在、而且不是 ~ 或 / 才列出来；是 git 仓库时默认选中，否则默认选「新文件夹」。安装脚本在用户当前目录里跑 register，那通常就是 ~。把整个家目录当默认，等于替人做了授权决定。
3新文件夹建在机器的 Repos Folder 下（orbit@austin 上是 ~/orbit-repos/），名字必填。第一次会话前由 runner mkdir -p，只对 Orbit 自己要建的目录这样做。今天目录不存在时会话直接起不来（working directory … does not exist）。代码不在这台机器上的人，第一条消息里让 agent 去 clone。
4别的文件夹输入就在机器上检查：不存在的不能选；不是 git 仓库的能选，但写明会共享目录、不隔离；是 git 仓库的显示分支。今天写错路径要到会话失败才会暴露。
5登录跟随输入框选的引擎，嵌入现有的 RunnerSignIn。机器上装了的其他引擎给 Use X instead；账号有能用的 key 时给 Use an API key。凭据只能由人给。用同一个组件，机器页、会话里、设置卡三处一模一样。
6先发的消息留在卡下面，状态写 Waiting for <machine> — sends once both steps are done，可以撤回。两步做完自动发出，不用再按一次。先说要做什么，不被配置打断。和今天「排队的消息」是同一种说法。
7发送时建什么一次请求建三样：workspace、会话、第一条消息。workspace 名取文件夹名，重名加序号；隔离沿用今天的默认；合并目标自动检测；repoUrl 由探测回填。任何一步失败都不留半成品。用户只按了「发送」，不该留下一个空的 workspace。
8建完告诉人对话第一行写 Created workspace <name> on <machine> · <path>，带 Rename 和 Settings。说清楚建了什么，才可以不额外再问一遍。
9侧边栏和抽屉在线、0 个 workspace 的机器显示 Set up <machine>，排在所有 workspace 后面；离线的不列。离线的机器在 Machines & models 里已经算 needs you。
10提醒机器上装了的登录型 CLI 一个都没登录 → 一条 No coding CLI is signed in，不管有没有 workspace；Settings 里也算 needs you。只要有一个登录了，其他没用到的引擎照旧不报。什么都跑不了的机器要被说出来；但不要为没人用的引擎吵。
11打开 Orbit 落在哪一个 workspace 都没有的账号 → 第一台在线机器的新会话页；所有机器都离线 → Machines & models。落在能直接开始的地方，而不是一页引擎列表。
12入口批准页（/enroll）、Add a runner 页、机器页的空状态，都用同一句下一步和同一个按钮：Start a session。今天三处说法不一样：一处说先登录，一处说先建 workspace，原生端说去 web。
13以后的 workspace（P2）在已有的会话里说「也在 ~/code/api 开一个」，agent 调 agent_create，和 task_create 一样先出确认卡。它决定 agent 能碰哪些目录，今天却不经确认。

待你定蓝框是推荐。

1. P0 先单独上吗？

A 先上 P0推荐改动小、三端都是规则和文案，马上不再沉默。代价是入口先指向机器页，等 P1 上了再改指新会话页。
B 等 P1 一起上少改一次入口；但 P1 落地之前，没 workspace 的机器继续不出声。

2. 新文件夹建在哪？

A 机器的 Repos Folder：~/orbit-repos/<name>推荐和托管 runner 的 Default（…/orbit-repos/default）同一个约定，Orbit 建的东西都在一处。
B 家目录下：~/<name>更像人自己建的，但会和用户自己的目录混在一起。

3. 这样建出来的 workspace，隔离默认开不开？

A 沿用今天的默认：关推荐第一次使用不需要先懂 worktree；需要时在会话里一键打开（今天已有）。
B git 仓库默认开并行会话更安全，但第一次就多一个分支和合并的概念。

4. 原生端什么节奏？

A web 先上，iOS/macOS 和 Android 随后（P1b）推荐服务端和 runner 的改动先在 web 上验证，再接原生端。
B 四端同时上手机上的死路关得最快，但一次要改的面最大，copy parity 测试一起动。
