① 新工具 browser_request_sign_in（Orbit 的 MCP，CLI 同名 orbit browser request-sign-in）：说清哪个站、为什么。只有 Orbit Cloud runner 上、开关打开时才有。② agent 的这一轮停在“等你”；浏览器租约暂时放开，免得你登录时它还在点（已定 Q1、Q2 = A）。 ③ 卡上直说：密码你自己输、Orbit 看不到；登录留在这台 runner，所有 agent 都能用（P2 = B）。④ Open browser = 打开浏览器标签页（方案 C），已在接管，页面就停在 agent 遇到的登录页。Not now = 告诉 agent 你现在不登，它自己决定下一步。 ⑤ 标签页顶上一条请求横幅；I’m signed in 把结果交回 agent，它接着做。只按 Done 不算回答，卡还在。

② 工具面（orbit mcp 与 CLI 同一套）

工具 / 命令做什么谁能用要不要你确认
browser_status
orbit browser status		开关、是否在跑、哪个会话占着、几个人在看、有没有保存的登录（只说有没有，不列站点）本账户的任何会话不用（只读）
browser_open
orbit browser open [--url]		启动浏览器（没在跑就启动），返回标签页地址；给 url 时先打开那一页。CLI 在本机直接打开本账户的任何会话不用
browser_request_sign_in
orbit browser request-sign-in		①：发卡请你登录，等结果（I’m signed in / Not now）Orbit Cloud runner 上的会话就是那张卡
browser_clear_logins
orbit browser clear-logins		停浏览器、删掉保存的登录本账户的任何会话要：确认卡，和 Settings 的 Clear saved logins 一样

开关关着：四个工具都不出现（不是报错），和“关 = 不存在”一致。只有 runner 主人的会话能用（P4 = A）。

不做的

✕从别的 runner 操作这个浏览器（DevTools 或点击走链路）。保存的登录会变成全账户任何 runner、任何 agent 都能用，超出 P2 定的“这台 runner 上的 agent”。要用登录态的活，放到 Orbit Cloud runner 上跑。
✕CLI 里看画面（终端 VNC）：标签页够了。
✕列出保存了哪些站点：cookie 名单本身就是隐私，status 只说有没有。
✕租约排队：status 够 agent 自己等、重试；排队以后再说。

已定（owner 2026-11-19）：Q1–Q4 全部 A

#问题A（已定）B
Q1agent 等你登录时这一轮停住等（像现在的问题卡），你回答后它接着做立刻返回，agent 自己轮询 status
Q2等的时候浏览器租约放开，你登录时它不会同时点；回答后它重新拿留着，别的会话也用不了
Q3browser_status / open 给谁本账户任何会话（只读、只开给你看，不碰登录）只给 Orbit Cloud runner 上的会话
Q4卡出现在哪和其他“等你”的卡一样：网页、手机通知、Mac只在网页
已定：都选 A。Q1：卡住等最不容易出错，和现有的问题卡一个模式。Q2：你在里面登录时 agent 还在点会互相打架。Q3：状态和打开不碰登录态，限制没意义。Q4：要你登录就是要你知道。
