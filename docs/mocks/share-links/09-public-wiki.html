Question
一个 session 从创建到结束是怎么跑的，断了以后怎么恢复？
Written for
  • 第一次读 runner 代码的人
  • 排查会话卡住、重复执行的人
Covers
  • turn 的投递与领取
  • 心跳、超时与恢复
Not covered
  • 事件怎么推到客户端 → 3.2
  • 消息在会话之间怎么路由 → 3.3

1总览

Orbit 中的 session 是一个 agent runtime 与 runner 绑定的可恢复多轮会话。 所有交互遵循「先存后投」：用户的 turn 先落库，runner 再通过出站 long-poll 领取。 runner 不需要任何入站端口。

2turn 投递与 inbox 领取

Runner 每次只领取一条 turn，并在同一个事务里把它标成已领取。 领取失败的 turn 留在队列里，下一次长轮询会再拿到它。

GET /api/runner/runs/:id/inbox?wait=25

心跳每 15 秒一次；连续 3 次没有心跳，服务器把会话标成可恢复，交给下一个领取它的 runner。
