2 · 一个模型：分享链接 = 一个根对象 + 勾选的层

会话、任务、项目共用一套：同一个对话框、同一个公开页外壳、同一份管理清单。一个链接只读地打开「根 + 勾选的层」这一块。范围之外的东西，在公开页上既不显示，也不能点。

新 范围 = 根对象往下，按层裁剪（以项目链接为例）
▣ 项目 · Claude 账号池：按订阅配额均衡派发 Overview总是包含
Goal · Work overview · Task graph · Acceptance criteria · Tasks（标题 + 状态）
☐ 12 个任务页 Task pages默认开
每个任务：Description · Acceptance · Dependencies（本项目内）· Runs 列表。关掉后，图和列表里的任务只剩标题和状态，不能点开。
✎ 评论与附件 Comments & files默认关
Comments（29 条）· Inputs 附件 · 进度说明。这些是 agent 和人写的自由文本。
▤ 对话记录 Conversations默认关
每次 Run 的完整记录，再加协调会话。可能含命令输出、文件内容、路径。

任务链接就是从「任务页」这一层开始的同一棵树；会话链接是一棵只有「对话记录」的树。

对话框里每一层都写出数量（「14 transcripts」），让所有者按「会暴露多少」来决定，而不是按抽象的开关名。

新 生命周期：对象怎么变，链接就怎么变
发生了什么链接的反应
Access 改成 Only you立即 404。再打开会发一个新 token，旧链接永远不会复活（沿用现在的做法）。
到期自动撤销。清单里标「Expired」，一键「Share again」生成新链接。
会话进回收站暂停，和撤销显示同一张 404 页，不透露对象还在。Restore 后恢复。这一点写进删除确认框和清单（Paused · in Trash）。
永久删除会话 / 删任务 / 删项目链接随之删除（外键级联；项目和任务本来就是硬删除）。
任务被 Superseded / Abandoned页面照常，显示「Superseded by …」。后继任务在范围内才能点。
项目 Completed / Cancelled页面照常，显示终态。Live 在这之后等同于 Snapshot。
公开内容里的 Orbit 引用orbit-task / orbit-session / 「Open the task ↗」：在范围内就跳到对应的公开页，在范围外就只显示文字。一律不指向要登录的 app。
红线 勾什么都不会公开的
  • 账号：owner、邮箱、user id
  • 机器：runner 名、workDir、路径根
  • 代码：仓库地址、分支、SHA、合并检查命令
  • 算力：provider、模型、账号、费用、token 用量
  • Instructions（写给 agent 的）
  • Open items、Blockers、Run queue
  • Coordinator 卡：Workspace、Wake-ups、Self-started
  • Crossings、Attribution、Followed by
  • 派发、收敛、验证的内部状态
  • 评论 @ 投递记录
  • 跨项目依赖的标题（只写「另有 1 个前置在别的项目」）
  • 所有者自己的操作：Delete、Run、Resolve…

实现上不复用所有者的 DTO（GET /tasks/:id 会把整行展开返回），每种公开页各写一个显式 select，再配一条否定断言的 spec：公开响应里一个上面的字段名都不能出现。providers 的「全文不含 sk-ant」断言就是这么写的。

新 地址形状（旧的 /s/<token> 全部继续有效）
/s/<token>根对象的公开页：项目、任务或会话，由链接的类型决定。 /s/<token>/t/<taskId>项目链接内的任务页。前提是勾了 Task pages，并且这个任务属于该项目。 /s/<token>/c/<sessionId>范围内的一段对话记录，要勾 Conversations。会话必须是范围内任务的 Run，或者是本项目的协调会话。
