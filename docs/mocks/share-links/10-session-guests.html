谁能做什么 · 数据与接口

访客的话会驱动跑在所有者机器上、带着所有者仓库和凭据的 agent，这是本方案最大的风险。边界照飞书 §8.3 的七条对齐。

谁能做什么
动作所有者访客说明
看对话（含工具输出）✓✓访客看到的 = 公开投影 + 工具输出
发文字消息、Steer / 撤回自己排的✓✓每人每会话每天 50 条
会话结束后接着发✓✓D5；沿用原模式 / 模型
附件 / 图片✓✕D4，本期只文字
! shell（kind: shell）✓✕访客的门不收 kind
改模式 / 模型 / effort / provider✓✕resume 也不收覆盖字段
审批、回答 agent 的提问✓✕只推给所有者
Interrupt / End / Merge / 删除 / 移动✓✕
邀请 / 移除别人✓✕所有者通道，PAT 和 agent 也不行
Leave—✓访客自己退出

agent 每收到一句访客消息，正文后面都接一段前言：这句话来自主人邀请的人、不是主人，也不是主人对任何事的批准（约 61 token，单测钉在 80 以内）。

数据与接口
东西形状
新表 session_guestsession_id（CASCADE）、owner_id、user_id（CASCADE）、added_at、removed_at、removed_reason REMOVED | LEFT；部分唯一 (session_id, user_id) WHERE removed_at IS NULL
turn 署名复用 0502 的 external_sender_source / _id / _name，CHECK 放宽到 FEISHU | ORBIT_GUEST；无新列
会话行lastUserFromExternal: {source: 'ORBIT_GUEST', name}；访客 userId 不进任何客户端读口
所有者接口GET · POST {email} /sessions/:id/guests、DELETE …/guests/:userId
访客接口GET /guest-sessions、GET /guest-sessions/:id、…/events?before=|after=、POST …/turns {clientTurnId, content}、自己的 turn 的 DELETE / steer、POST …/leave；没有有效邀请一律 404
投影复用 /shared 的显式 select，同一组否定断言 spec 跑两扇门
activity每条访客消息一行 session.guest.turn（credential_kind GUEST）

旧客户端缺口：已装的 iOS / Android / macOS 只认 FEISHU，会把访客的话画成所有者自己的（You:）。三端的署名必须和服务端同一版发。

待定 · 要你拍板

绿色格是推荐。全部照推荐，就是前四张图画的样子。

AB为什么推荐
D1 谁能被邀请本 Orbit 上已注册的账号，按邮箱点名拿到链接、登录了的任何人A：每个能驱动你 agent 的人都是你点名的
D2 访客在哪回话独立访客页 /g/<id> + 侧栏 Shared with me，不依赖公开链接在公开页 /s/<token> 上给登录的被邀请者加输入框A：关公开链接不该连带赶走访客，反过来也一样
D3 权限模式沿用会话当前模式；Auto / Don’t ask / Bypass 下首次邀请多勾一次只有 Default / Plan / Accept edits 的会话能邀请A：和飞书「主人选模式」一致；B 会让大多数 Bypass 会话没法邀请。模式是整条会话一个值，没法只让访客那句换模式
D4 附件本期只文字可带图片A：先把署名和边界做稳，图片下一期
D5 会话已结束时访客的消息照常 resume只在会话没结束时能回A：「接着讨论」多半发生在会话结束之后
D6 通知访客发言不推给所有者，会话行显示 From <name>；审批照常推每条访客消息都推给所有者A：别人讨论得热闹时不刷你的屏

落地（按代价排）

  1. G1 服务端：迁移（session_guest、CHECK 放宽）、所有者三接口、访客门与投影、每日上限、移除时撤回排队消息、activity。pg spec 覆盖：跨账号 404；shell、附件、覆盖字段被拒；移除即刻生效；否定断言。
  2. G2 runner：ORBIT_GUEST 的前言和 token 预算测试。
  3. G3 Web：分享框 People 段、From <name> 署名和会话行、Shared with me、访客页（复用 SharedSessionPage 外壳 + 纯文字的 Composer）。
  4. G4 iOS / macOS 与 Android：署名和会话行必须与 G1 同一版发；分享面板 People 段；Shared with me 与访客页可以晚一版。

不做（本期）：匿名访客；访客用自己的 runner / 额度；访客审批；任务、项目级邀请；访客之间互相可见的成员列表；访客推送。
