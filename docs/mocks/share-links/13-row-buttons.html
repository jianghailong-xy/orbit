今天提议为什么
1 开着的链接[Copy] [Settings] 两个带框按钮，再加红字 Turn off点整行打开 Share 对话框（原来的 Settings），行尾有 ›；露在外面的只剩一个无框复制图标（停上去提示 “Copy link”，复制后的 toast 不变）；⋯ 里是 Copy link、Settings…、分隔线、红字 Turn off…来这一页，最常做的是复制链接和改设置：复制一下就够，改设置点整行就到。Turn off 是关掉别人的访问，放进 ⋯ 的最后，并且照旧要确认
2 已结束的链接过期的显示 [Share again]不变：[Share again] 还是带框按钮，露在外面这是把东西找回来的操作，跟 Account pools 的 Resume Now 一样，不收进 ⋯
暂停的链接红字 Turn off只有一个 ⋯，里面是 Turn off…；整行点不动，也没有 ›在回收站里的会话不能改分享设置（设计文档 §3），点行打不开任何东西
3 ⋯ 菜单—无框图标按钮，跟 API keys / Account pools 用同一个组件（Dropdown + EllipsisOutlined）；Turn off… 选中后弹出现在这个确认框（Turn off this link? / Anyone who has it loses access right away.）三处 Settings 页面长得一样
4 操作列宽度236px约 92px，多出来的宽度给标题标题是这一行最该被看见的东西

改到的文件：src/web/src/pages/SharedLinksPage.tsx（行可点、复制图标、⋯ 菜单）、index.css（.shared-link-row 的列宽和悬停样式）、SharedLinksPage.test.tsx（行操作的断言）。只改 Web；iOS / macOS 的 Shared links 本来就是列表 + 滑动 / 菜单。

待你定
1. 点整行打开 Share 对话框（推荐，和 API keys 点行打开编辑页一致），还是打开被分享的东西本身（会话 / 任务 / 项目）？
2. 复制图标要不要露在外面？推荐露：这一页最常做的就是复制链接。不露的话，复制也收进 ⋯，每行只剩 ⋯ 和 ›。
