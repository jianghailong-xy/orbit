从 GitHub 建 workspace · 03 规则、改动清单、分期、界面细节

01 和 02 画的是界面长什么样，这一张写规则。设计文档：docs/github-workspace-design.md。原则有两条： 凭据由 Orbit 负责，但只交给 runner 自己用（不进 agent 的 shell，不落盘）；clone 是 workspace 的一个状态，不是会话里的一次操作（看得到进度、失败可以重试、不会留下半成品）。
已按推荐定下（2026-11-11，你回的「按推荐」）
  • 用 GitHub App，不做 PAT 粘贴后备。
  • agent 不能直接拿 token push，改动经 Orbit 落地推回 GitHub。
  • 托管和自托管 runner 都支持；自托管 runner 优先用机器自己的 git 凭据。
  • v1 就支持私有仓库。
规则web、iOS/macOS、Android 同一套
#场景规则为什么
1什么时候有 From GitHub部署配好了 App（管理员打开开关，并且 ID 和密钥核对通过）。没配时完全不显示，界面和今天一样。自建部署没有 App 就做不了这件事，显示一个点了也用不了的选项只会让人困惑。
2能选哪些仓库只有装了 App、并且当前用户有权限的仓库，用 user token 现查。建 workspace 时服务端再查一遍。不允许拿别人的 repoId 来建；用户在 GitHub 上收回授权后马上生效。
3clone 到哪<reposRoot>/<folder>，folder 默认是仓库名，规则和 newFolder 一样。目标必须不存在；先 clone 到临时目录，再 rename 到目标。和 newFolder 的路径校验相同；中途失败不会留下半个仓库。
4什么时候 clone建 workspace 时就把 cloneState 设为 PENDING，心跳把任务下发给 runner。会话已经建好，但在 READY 之前不派发。clone 可能要几分钟，不能占着会话的 claim；失败要能单独重试。
5凭据顺序先问机器上的凭据助手；没有答复，或认证失败，再向 apiserver 要 installation token 试一次。用了哪种凭据要上报。自托管机器上已有的设置不能被 Orbit 抢掉；托管机器上只有 Orbit 的 token 可用。
6token 的范围只对一个仓库，权限 contents:write 和 metadata:read，1 小时过期，只缓存在内存。只签给拥有这个 workspace 的那台 runner。泄露时影响最小。
7agent 自己的 gitcheckout 的 .git/config 和 remote URL 里都不写 token，引擎的环境变量里也没有。系统提示里告诉 agent：要推送，就走落地。已定的第 2 项。agent 和 runner 是同一个 OS 用户，Orbit 只能承诺做得到的事。
8workspace 建好以后仓库绑定（repoId、ref）v1 不能改。repoUrl 在建的时候就写好。删除连接不会删 workspace。不能改，就不需要 workspace write card；项目的 Codebase 绑定马上能读到 repoUrl。
9失败写成用户能处理的英文原因，带 Retry。会话在队列里显示 WORKSPACE_CLONE_FAILED。token 先脱敏再写日志（ghs_ 前缀已经能识别）。今天 clone 失败只能看到 agent 在对话里报错。
10文案所有界面文案都用英文，写在 machineSetupCopy.ts 和新的 githubCopy.ts 里；原生端从同一处复制。CLAUDE.md §5、copyLanguage 测试。

界面细节2026-11-11 所有者定：四项都按推荐（A），01 和 02 画的就是 A

1. From GitHub 放在哪

A. 放在「A new folder」和「Another folder」之间推荐和「新文件夹」挨着，因为两者都是"在 reposRoot 下建一个新目录"；位置固定，连没连接都一样。
B. 已连接时排第一连了 GitHub 的人多半就是为了用它，但选项顺序会随状态变化。

2. 分支怎么选

A. 默认分支，点 Other branch 才展开推荐大多数情况不用选；会话本来就在自己的 worktree 分支上工作。
B. 总是显示分支下拉一眼可见，但多一个要看的控件。

3. clone 进度怎么显示

A. 进度条加百分比推荐大仓库要几分钟，看到数字在动，用户就知道没卡住。大约 30 秒更新一次。
B. 只显示 Cloning… 和转圈实现更简单，但大仓库时看不出是不是卡住了。

4. Settings 的 "Workspaces from GitHub" 列表

A. 要，并写明每个用哪种凭据推荐断开连接之前，能看到哪些 workspace 会受影响。
B. 不要页面更短；凭据信息放到各自的 workspace 设置里。
