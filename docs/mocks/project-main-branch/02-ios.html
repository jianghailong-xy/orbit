项目的主分支 · iOS / macOS：开始卡片和 How it runs 多一行 Main branch，记住上次的选择，文案叫它的名字

iOS 和 macOS 是同一批 SwiftUI 视图：开始卡片 StartProjectCard（ApprovalCards.swift；对话里的卡在 iPhone 上点开是一张审阅页，项目页的 Start… 是 OwnerStartProjectSheet，同一张卡），项目页的 How it runs 是 ProjectsView.runSettingsSection，字都在 OrbitKit 的 StartProject.swift / ProjectRunSettings.swift，由对照测试和 Web 逐字比。这里只画 iPhone（浅色），规则和每一句英文照 Web 那张（01-board.png）和已经落在项目分支上的 Web 实现（MainBranchSelect.tsx、lib/projectStart.ts）。「现在」按项目分支 7217e3402 上的代码画，「改后」是提案。例子和 Web 一样：仓库 acme/payments-api 的主分支是 master，协调工作区 payments-api 报上来的本地分支是 develop / master / release/2.4。灰色字母标现在的问题，橙色数字标改动。主分支是 main 的项目，除了多出 Main branch 这一行、锁定说明多半句，其它字一字不差。Android 跟这同一份图：每一段下面一行写 Android 的对应位置，最后的说明里有细节和文案总表。

① 开始卡片 Start this project?（对话里的卡，在 iPhone 上点 View details & act 打开的审阅页；项目页的 Start… 是同一张卡）
现在卡上没有主分支这一项

A 协调者在卡片顶上那段话里说了「这个仓库的主分支是 master」，Automatic 这句却写 merges into main。B Tasks land on 和 Merge check 之间没有地方选主分支：按下 Start，项目绑到 refs/heads/main，这个仓库没有 main，任务一启动就报 BASE_REF_NOT_FOUND，只能去终端 orbit project update --upstream-ref。

改后多一行 Main branch

1 Tasks land on 下面多一行 Main branch：两项是同一个决定，也一起锁。值是协调者在开始请求里建议的 master（它读了 origin/HEAD）。分支名用等宽字，右边是 ›：点开是一个选择页，不是菜单（见待定 ①）。2 卡上所有说「合进哪里」的句子都跟着叫 master。按 Start 时连同 upstreamRef: refs/heads/master 一起写入，这一下也记成「你给 acme/payments-api 选的」。

过程点 Main branch：选择页

3 半屏的选择页，和会话里选合并目标的 Merge into 同一个样子（WorktreeBar.swift 的 MergeTargetPickerSheet）：小标题 Branches in payments-api，列出 runner 给协调工作区报上来的本地分支（和会话 Merge 菜单同一份，去掉 orbit/*），当前的值打 ✓，点一个就选中并收起。4 最下面一句说这一项决定什么。

过程列表里没有：直接输入

5 远端才有、runner 还没报上来的分支，在搜索框里直接输入：列表跟着过滤，输入的不在列表里、又像个分支名时，多出一行 Use “release/3.0”，点它就用这个名字。带空格、..、~^:?*[ 的不出现 Use。runner 一个分支都没报时，列表里只剩当前的值，照样能输入（小标题换成 Type a branch name）。

Androidprojects/StartProjectCard.kt 的 LineRow 下面加 MainBranchRow（这张卡也用在 ProjectSettings.kt 的 OwnerStartSheet / RequestedStartSheet 和对话里的 CoordinatorStartCard）；值是一个 TextButton，点开的选择界面照 reader/WorktreeBar.kt 的 MergeTargetPicker（Dialog：Cancel + 输入框 + 分支列表，当前的打 ✓），加上 Use “…” 和底部那一句。

② 同一个仓库的下一个项目：直接带上你上次选的
改后第二个项目，主分支已经是 master

6 两天前你给 acme/payments-api 的第一个项目选了 master。这次协调者没建议（仓库已经记住了就不用建议），卡上直接是 master，下面一行小字 Your last choice for acme/payments-api 说它从哪来。改成别的，这行字就不显示；按 Start 后，新选的就是这个仓库新的「上次」。

改后选择页里标出上次选的

7 上次选的分支后面标 last chosen，和 Web 的下拉、会话 Merge 菜单在当前目标后面标 selected 是同一个做法；当前的值照旧打 ✓。

边界这一行的几种样子

卡片失效（计划变了，请求作废）或正在开始时，这一行和别的设置一样变灰、点不动。没有仓库的项目（工作区没记录远端）没有这一行：没有分支可合，其余和现在一样。

初始值从哪来（和 Web 同一个顺序）

取第一个有的：这个项目自己已经选过的 → 你上次给同一个仓库选的（标 6）→ 协调者建议的（标 1）→ main。你自己的选择排在协调者的建议前面。

什么算一次选择：开始卡片上按 Start（卡上显示的那个就算）、How it runs 里选中（iPhone / Mac 上选中就写入，见标 8）、终端 orbit project update --upstream-ref、API。

记在哪：服务端，按「账号 + 仓库」记。iPhone、Mac、Web、Android 看到的都一样，换台机器、换个工作区也一样。

对话里的卡要多读一次 GET /projects/:id/integration（仓库、分支列表、上次的选择）。现在对话只在合并卡卡住时才读它；读回来之前不画这张卡（和 Web 的对话卡一样），免得先画出 main 再跳成 master。读失败时不显示这一行，开始时保留项目原有的主分支。

Android同一个 MainBranchRow 下面用 Note 多一行 Your last choice for …；Dialog 里上次选的分支后面标 last chosen。初始值的顺序写在 StartProjectCopy 里，和 iOS、Web 同一个。

③ 项目页的 How it runs（项目已开始）和标题下的集成行
现在主分支已改成 master，页面还写 main

C 这个项目的主分支已经在终端改成了 master，How it runs 里却写 Directly into main、Every merge into main asks you；D Automatic 那段写 merges the branch into main。主分支在这一页既看不到也改不了。

改后多一行 Main branch，文案叫 master

8 Tasks land on 下面多一行 Main branch，点开是同一个选择页（标 3、5、7）。iPhone 的 How it runs 没有 Save，每一行改了就写（Tasks land on 也是这样），所以选中即写入：PATCH /projects/:id/integration 的 upstreamRef；门拒绝时照旧弹 Couldn't do that。下面一句说明：这也是 acme/payments-api 以后新项目的默认值。9 两个选项、Automatic、Merge check、Pause 的说明都叫 master。

状态开始集成以后：和线一起锁住

10 集成一开始，线和主分支一起锁住（服务端 409 INTEGRATION_LINE_LOCKED）。两行都只读，值前面一把锁，和现在锁住的 Tasks land on 一个样子；原来写在 Tasks land on 下面的说明挪到 Main branch 下面，多半句 and its main branch，并且叫 master。没有仓库的项目还是左下 a 的样子。

现在 / 改后锁定说明和标题下的集成行

E→11 标题下的集成行（ProjectPage.integrationFacts）：ahead of main、synced with main 改叫项目的主分支名。直接合进主分支的项目，这一行第一项本来就是主分支名，不变。

Androidprojects/ProjectSettings.kt 的 RunSettingsSection：LineSetting（72–89）下面加 MainBranchSetting，选中就 PATCH /projects/:id/integration（照 lineWrite，没有 Save）；锁住时写「🔒 master」，lineLocked 那句挪到它下面换成新句子。标题下的集成行是 ProjectsScreen.kt 的 Header（611–619），读 ProjectPage.integrationFacts。
