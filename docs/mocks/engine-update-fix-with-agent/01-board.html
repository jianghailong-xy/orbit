需要你定的 3 件事（蓝框为推荐）

1. 一次失败几个按钮
（一轮里可能有多个引擎失败）
推荐A. 整个框一个按钮新增一类 engineUpdateFailed（按机器算，不按引擎）。首条消息列出所有红行。多个引擎往往是同一个原因（网络、代理、npm 前缀），一个 Agent 一起修。
B. 每条红行一个按钮复用按引擎算的 engineNotUpdating。但超时这种失败机器未必会报成引擎警告，服务端会以 “no longer reports that warning” 拒绝；而且几个 Agent 会争同一个全局 npm 前缀。
2. 同一引擎在 Needs attention 卡片上已有 Agent 在修
推荐A. 两边各算各的规则最简单：框里的按钮只看自己这一类。重复的概率低（卡片要报警 30 分钟以上才会出现），真撞上了，第二个 Agent 一看就知道问题已经修好了。
B. 框里显示那张卡片的 “An agent is fixing…”不会多起一个会话，但两类要互相查对方，规则和测试都要跟着加。
3. 修完怎么收尾
推荐A. Agent 自己通过 Orbit 重跑 Update engines跟 Install failed 的收尾一样。结果由机器上报，新报告替换红框。
B. Agent 只汇报，你再按 Update engines多一步，但每一次更新都由你亲手按下。

落地（按代价排）

1. shared：RunnerAttentionFixKind 加 engineUpdateFailed（不带引擎）。
2. apiserver（attention-fix.ts）：判断“机器还报着这个警告” = 引擎中转槽 mode=update、状态 done/failed、消息里有红行；首条消息用这些红行和命令拼成。pg spec 补一个用例，覆盖起会话、去重、离线/已退出登录被拒、Dismiss 之后被拒。
3. web（MachineSettingsPage.tsx）：Dismiss 那一行换成 AgentFixButton + AgentFixLine，代码直接复用；单测覆盖 4 个状态。
4. iOS/Android：这个报告框目前只有 web 有，不在本次范围。
