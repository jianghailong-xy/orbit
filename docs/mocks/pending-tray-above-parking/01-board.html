未读的消息挪到停车条上面

Web 会话页，输入框上方那一组。你说「消息排队在停车条上面」：现在还没被读的消息（托盘）压在输入框上沿后面， 停车条（Watching、Background processes、Tasks、分支条）在它上面；改后托盘排到这一组最上面，紧接对话，停车条贴着输入框。
已定（2026-10-28）：按推荐落地，② 独立卡片，Web、iOS / macOS、Android 一起改。

① 托盘压在输入框上沿后面：左右各收进 18px，只有上面两个圆角，底边藏进输入框 22px，和输入框读成一叠。停车条在它上面，离对话更近。

② 托盘排到最上面，紧接对话，从上往下就是时间顺序：对话 → 你刚发、模型还没读的话 → 这个会话在跑的东西（后台进程、建的任务、分支）→ 输入框。 托盘不再压在输入框后面，改成一张独立卡片：和停车条同宽，白底（同现在），12px 圆角，下面隔 8px。iOS / macOS 的托盘本来就是这样一张独立卡片（12pt 圆角，下面隔 8pt）。 行一点没变：↳、文字、Waiting to be read、Steer、撤回。

规则改了什么，没改什么

现在改后
位置输入框上方这一组的最下面，压在输入框后面 这一组的最上面，紧接对话。停车条和其他提示（托管 runner 的状态、回复谁、任务运行交接、provider 说明）之间的顺序不变
样子左右收进 18px（手机 12px），只有上圆角 16px，底边藏进输入框 22px 独立卡片：和停车条同宽，白底，1px 边，12px 圆角，下面隔 8px
行↳ 插进当前回合 / ≡ 排到下一轮；文字一行，点开看全文；状态；Steer；撤回（文字回到输入框）；Cursor 会话的说明。不变
好几条按发出的顺序往下排，最新的在最下面；超过 4 行在托盘里滚动。不变
App 打字时停车条收起，托盘不收，所以打字时托盘贴着输入框。不变
  • Web：WorkspaceView.tsx 把 <PendingTray> 挪成 .workspace-composer 的第一个；index.css 的 .pending-tray 去掉负 margin、上圆角和 22px 垫底，改成独立卡片，删掉手机的 12px 内缩。上面的效果图就是这两处渲染出来的。
  • iOS / macOS：ConsoleView 里把 PendingTrayView 挪成 ComposerBand 的第一个；样子不用改。
  • Android：PendingTrayCard 现在画在 SessionComposer 里、输入框正上方；挪到 SessionReader 的停车条上面，去掉 24dp 内缩，和停车条同宽。
