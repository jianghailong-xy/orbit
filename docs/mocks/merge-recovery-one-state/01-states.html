  1. 顶栏的 “Working…”：服务端有一个 pending 任务，但卡上看不出它在做什么、什么时候开始的、有没有卡住。“Checked 50m ago” 让人以为它卡了 50 分钟。
  2. “Checking…” 是假的：busy 把三件事合成了一个，包括“会话这一轮在跑”。只要会话在跑，检查按钮就显示 Checking…，其实什么都没在检查。
  3. 两个主按钮（顶栏一个、卡里一个）同时灰着，都没说为什么。
  4. 一次 fast-forward 推 1 个 commit，却摆出了 candidate diff、merge check 配置、linear history、repair branch 路径这么一整份“审查”。
改版 五种状态，每种只有一个主动作

① 可直接合并 fast-forward，本地 main 跟 origin 一致，没有别人的 commit

⎇ orbit/session-coordinator-workspace-… +50 −12 · 8 files · 1 commit Merge into main

截图里就是这种情况：不弹恢复面板，跟普通合并一样只有一个按钮。点下去，服务端先重新 preview 再 apply，跟上次 preview 一致就直接完成，不让人再“审”一遍。

② 会话正在跑一轮 以前这里显示假的 “Checking…”

⎇ orbit/session-coordinator-workspace-… +50 −12 · 8 files · 1 commit Merge when this turn ends

按钮不灰，直接告诉你在等什么，点了就排队。点之后变成下面 ③ 那一行，状态写 “Queued — merges when this turn ends”，旁边带 Cancel。
如果服务端暂时做不了排队，退一步：按钮灰掉，tooltip 写 “Waiting for this session’s turn to end”。

进行中的时候，顶栏和卡里都不放动作按钮，只有这一行：在做什么、从什么时候开始、在哪台 runner 上。超过阈值（比如 5 分钟）变成琥珀色，并给出 Cancel / Retry。这一条要配合后端给 pending 加超时和开始时间。
