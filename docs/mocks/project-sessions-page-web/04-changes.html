④ 对齐清单：iOS 怎么做，Web 现在怎么做，改成什么样

“整体”的范围我先按项目会话页这一整页来理解，下面是全部 15 项。如果你说的整体还包括别的页面（比如项目页 /projects/:id），告诉我范围再补。红字是现在就和 iOS 行为不一致的 bug，蓝底是新加的东西。

页头与进入

#项iOS（参照）Web 现在Web 方案
1页头的操作右边一个 ⊞，打开项目页⋯ 菜单：Open Project、Open Coordinator换成一个 ⊞ 按钮（title “Open project”）。Open Coordinator 去掉，协调者那一行就在下面。
2手机顶栏一层两层：全局 “☰ Orbit” 加项目页头项目页只留页头，规则和打开会话时一样（复用现有的 :has(.show-conversation) 写法）。
3从侧栏进项目iPad：只换列表栏，右边的对话保留整个地址换掉，右边的对话被关掉只换会话栏（加 ?project=），保留右边正在看的对话。
4加载中也先写 “Project · 0 sessions”（这次一起改）先写 “Project · 0 sessions”会话还没读到时只写 Project，不写 0 sessions；iOS 同步改。

进度卡、启动、落地

#项iOS（参照）Web 现在Web 方案
5进度的形态列表里第一张灰卡，随列表滚动；进度条 66pt；没有链接钉在列表上方的横带，带底线；进度条 32px；↗ 打开项目页同 iOS：灰底圆角卡（#f2f3f5，圆角 10），放进滚动区，进度条 66px，去掉 ↗。
6没有计数时写项目状态只剩一个 ↗写项目状态（Open / Done …）。
7没启动Not started · N tasks，下面是启动行（本次 iOS 已实现）“0/N done · 0 running”，没有入口同 iOS。判断用 projectStart.ts 里和项目页同一条规则；数据用 sidebar 新加的 startedAt，没启动时再读 open items（这次服务端已加）。
8点启动起始卡以 sheet 盖在本页上—桌面：现有的 ProjectStartDialog；已请求时换成请求的那一版。手机：底部面板（图 ③）。
9有任务在落地卡里一行：Landing · 状态 · 时长 · 任务，每秒走，点开项目页没有（只在工作区列表的项目行第二行出现）同 iOS，复用 Web 现成的 LandingRow 和 landingLine()。

合入卡与时间线

#项iOS（参照）Web 现在Web 方案
10合入卡的位置进度卡下面，随列表滚动钉在列表上方，占着位置不走挪进滚动区，放在进度卡下面。
11询问时的内容图标块、分隔线、判据进度（“1 of 5 met on this branch …”）没有图标、分隔线和判据那一行补齐这三样。判据数取项目的判据里已满足的条数，和 iOS 的 criteriaMet 一样。Details 保留。
12受阻时去协调者打开协调会话，项目页留在下面链接丢掉 ?project=：会话栏被换掉，没有滑动动画和页头原来的 Open Coordinator 一样，带着 ?project= 推进去。
13已合入那一行绿圆里是合入箭头绿圆里是 ✓换成合入箭头。

行操作与空状态

#项iOS（参照）Web 现在Web 方案
14手机上的行操作左滑的 Move 只有协调者有；长按出菜单每一行左滑都有 Move（菜单里却只给协调者）；手机上没有长按Move 只给协调者。长按出和桌面 ⋯ 一样的菜单（会影响所有会话列表，不只这一页；iOS 菜单里的 Rename… 和 Tags… 这次不加）。
15空和出错中间写 No sessions，或 Couldn’t load sessions 加原因；可以下拉刷新列表底部一行小字，没有重试中间写清楚，出错时加 Retry（图 ②）。

不变的

Coordinator 分区协调者固定排第一，下面按时间分组（Today / Yesterday …），已合入的记录夹在会话中间。两端已经一样。
会话行行的样子、悬停 ⋯、选中后右边打开对话（桌面）或推入（手机）、上下键切换，都不动。
轮询Web 有 SSE 时 60 秒、没有时 4 秒，比 iOS 固定 4 秒更省，不改。

数据来源：这次已经补上的 sidebar startedAt，以及现有的 projectOpenItemsQuery、projectIntegrationQuery、projectPromotionQuery。不需要新接口。
