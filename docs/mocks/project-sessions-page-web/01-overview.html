① Web 项目会话页：照 iOS 的交互整体对齐

Web 的项目会话页和 iOS 的同一页，骨架已经一样：页头、进度、合入卡、Coordinator、按时间分组的会话。但交互上有好几处不同：页头用 ⋯ 菜单；进度是一条钉在列表上方的横带，还带 ↗；没有启动入口，也没有落地行；合入卡不随列表滚动；手机上叠着两层顶栏。
方案：以 iOS 的项目会话页（SessionProjectPage）为准，逐项对齐。完整对照见图 ④ 的 15 项清单。图里的数据是截图中那个项目的真实状态：5 个任务，还没启动，协调者还没请求启动。每一帧都截自真实的 Web 控制台（vite + 固定数据），方案部分用控制台自己的样式画进页面；红色虚线和数字是标注。

现在桌面：会话栏换成项目页，右边是协调会话
  • ⋯ 菜单里只有两项：Open Project 和 Open Coordinator。
  • 进度是一条钉在列表上方的横带：“0/5 done · 0 running” 加一个 ↗ 链接。没启动的项目也这么写，看不出它在等启动；这一页也没有启动入口，得去项目页的 Open items 里找 Start…。

方案同一页，照 iOS 的交互
  • 页头右边换成一个 ⊞ 按钮，打开项目页，和 iOS 工具栏一样。Open Coordinator 去掉，因为协调者那一行就在下面。
  • 进度改成一张灰底圆角卡，放在列表最前面，跟着列表一起滚动；进度条从 32px 加长到 66px；↗ 去掉（页头的 ⊞ 就是入口）。没启动时写 Not started · 5 tasks。
  • 卡里加启动行，规则和 iOS 一样：协调者还没请求时是灰点加 The coordinator hasn’t asked yet；请求了是橙点加 Ready to start（见图 ②）。
  • Start… 打开现有的起始卡弹窗（下图），在里面看判据、计划和跑法，按 Start the project 才真正启动。启动后这一行收起。
方案点 Start… 之后：起始卡弹窗
  • 弹窗用现有组件 ProjectStartDialog / StartProjectCard，就是项目页 Open items 里 Start… 打开的那个，不新做。
  • 还没请求：设置按默认规则填。任务互相依赖，所以是项目分支；并发取项目现在的 3；Automatic 开。这个项目没配 merge check，所以那一行是琥珀色提醒。
  • 已请求：内容换成协调者请求的那一版（和协调会话里 SessionStartProjectCard 一样）：协调者建议的设置、它给的理由、“Orbit checked the plan”。Start the project 回答这份请求。
  • 计划这一行用的是修好后的编号规则：P1 starts now · P2, P3 after P1 · …。修之前，“P1 Web：…”这类标题认不出编号，每个标题会被截成 23 个字再拼起来。
  • 点右上角 ✕、按 Esc 或点遮罩关掉：回到本页，什么都没写。启动被拒（比如别处已经启动了，或判据变了）时，弹窗不关，按钮上方用红字写出服务器的原话（现有行为）。
  • 这里不放 Chat about this，和 iOS 一样：想先改再启动，就去协调者那一行（它就在弹窗下面），会话里的那张卡上有这个按钮。
