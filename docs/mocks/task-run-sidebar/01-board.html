1
盖住了对话。面板占窗口 56%，会话每一行都被截断（截图左侧 "…fail"、表格、FAILED 那句）。人是在看 agent 说了什么时点开任务的，盖住正好挡住了他要对照的东西。
2
首屏是配置单。Done means 全文 + Brief + Runs with 五个芯片，都是建任务时就写好的；在任务自己的会话里，Brief 已经是对话的第一条消息，重复了。
3
「为什么 Failed」埋在 Activity 最底的评论里。状态 pill 只写 Failed；验收命令哪次 exit 1、和 agent 自己那次 exit 0 有何不同，要读完一段长评论才知道。
4
分支状态完全不在面板上。分支还剩几个提交、比 main 领先/落后、为什么不落地——这些只在会话正文里，面板里看不到。
A
停靠，不覆盖。宽度 ≥ 1280 时侧栏固定 380px 推开会话；更窄时退回今天的覆盖方式。⤢ 打开完整任务页（今天的全部内容都还在那里）。
B
判定放第一块，带下一步。pill 写明「check exited 1」；卡片并排两次检查结果、最新一条说明的一句摘要，以及三个按钮：Re-run the check（只重跑验收，不重跑 agent）/ Retry the task / Close as not needed。
C
Branch 一块。分支名、相对 main 的 ahead/behind、剩下的提交、Landing 一句话状态。数据来自今天已有的 integration / landing 记录，不新造。
D
Done means 变成检查清单。每条标准一行、带 ✓/✕；全文和 Brief 折叠成一行。Runs 列出每次运行，标出「this conversation」；Runs with 与 Activity 各压成一行。

各状态的第一块

Running：沿用今天的 Now（task_progress_report 步骤条），去掉「Run started…」等会话里已有的行。

Needs you：要你做的事和按钮放第一块，与 iOS 已批准的规则一致（一个主按钮，随状态换字）。

Done：今天的 Delivered 缩成两行；证据详情点进去。

Failed：见 1/2 ②。原因优先取「验收结果」本身，其次取最新一条评论的首句。

待定 · 要你拍板

D1 · 什么时候是侧栏

A 只在「任务自己的运行会话」里停靠；从别处的链接打开仍是今天的覆盖面板。
B 所有会话页里打开任务都停靠（窗口够宽时）。

建议 A：先解决你截图这一处，别处的覆盖面板是 task-link-in-place 刚定下的。

D2 · 侧栏是否常驻

A 点了才出现，记住开/关（按会话）。
B 任务会话默认就开着侧栏，可收起。

建议 B：任务会话里，这一列就是「这次运行的结果」，默认可见才有用。

D3 · Failed 的「Re-run the check」

A 新增：只在同一棵树上重跑验收命令，不起新 run。
B 不加，只给 Retry the task。

建议 A：你截图这次就是负载导致的误判，重跑验收几十秒、零 agent 成本。需要服务端新接口。
