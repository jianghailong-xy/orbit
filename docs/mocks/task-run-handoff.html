发消息跟到任务当前那一轮 · web

一个任务同时只有一轮在跑。旧的那轮失败后平台会在几秒内重派，用户手里的会话就不再是任务当前那一轮 —— 他再发消息，撞到的是一句写给程序看的英文，而消息一个字都没投出去。 下面每组左边是现状，右边是改后；虚线框是改动处。

虚线框 = 本单改动的地方

1 · 在已被接手的旧 run 里发消息

服务端已经把消息投给当前那一轮并回一个 routedToSessionId（契约 2.1）。 web 要做两件事：别在原会话里乐观画出这条气泡，以及把用户带过去。

2 · 投不过去的两种情况，各自说各自的话

带附件的消息不路由（附件按会话锚定，契约 2.4），落回 TASK_ALREADY_RUNNING； 而那一轮正在收尾时（conflictingSessionEnding）等一下就通了。 今天这两种、外加 TASK_RUN_PIN_CONFLICT，弹的是同一种红条。

3 · 失败卡上的 Retry

配额/接口失败卡的 Retry 也走同一条发送路径。撞上 409 时今天只弹一个红条，卡片本身毫无变化 —— 看上去像「按了没反应」。

4 · composer 换 provider：说清什么时候生效，要停的时候明着问

一个 run 的 provider 在它生命周期内固定。所以换 provider 只能是停掉这一轮 + 用新 provider 起新一轮， 而停掉一个在跑的 run 是破坏性的，必须用户明着点头。

5 · 任务行 / 任务详情的入口

status 是会话维护的标签、会滞后；running/queued 每次读都从 session 行算出来。出事的正是这个缝：任务失败了，平台 2 秒后重派，行里还写着 FAILED。
