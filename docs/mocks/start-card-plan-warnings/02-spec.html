规则

②③ 的细节。

  • 合并：按 code 合成一行。同一 code 的多条（每条标准一条）合起来，行的先后按服务端给的顺序。
  • 数字：任务数按 taskId 去重。标准号升序压成区间，写作 “1–5 and 7”、“1, 3 and 4”、“2”。
  • 任务名：用 Plan 一行里的编号（planTaskLabel）。超过 12 个时写前 12 个，再加 “and N more”。
  • 颜色：只有三角图标是琥珀色。标题主色 15pt（subheadline，medium），第二行次要色 13pt。展开后的说明 13pt 次要色，Criteria / Tasks 的值用主色。
  • 交互：整行是一个按钮，点一下展开或收起，箭头上下翻。VoiceOver 读“标题，第二行，按钮，已收起”。展开状态只在这张卡上，下次打开是收起的。
  • 不变的：服务端的检查和原句（协调者照旧收到）、Start 按钮、Merge check 行里的提醒、底部 “Orbit checked the plan” 那一行。
  • 两处入口一样：协调会话里的卡片，和项目页 Start… 打开的 sheet（截图这张）。
  • ④（可选）：服务端在 finding 上带回协调者的说明。有说明的行不用琥珀色，第二行引用原话，点开内容同 ③。

顺带修：Plan 一行的编号

编号规则只认“大写字母 + 1–2 位数字”，P1a 这种带小写字母的认不出，整个标题被截到 23 个字符拼进来。

现在 /^([A-Z]\d{1,2})(?:[.):：]|\s)/u P1 ✓ D12 ✓ P1a ✗
方案 /^([A-Z]\d{1,2}[a-z]?)(?:[.):：]|\s)/u P1 ✓ D12 ✓ P1a ✓ P12c ✓
现在 P1a · wiki-worker 服务骨架与… starts now · P1b · wiki_job 作业表与模型请求… after P1a · wiki-worker 服务骨架与… · P2, P3 after …
方案 P1a starts now · P1b after P1a · P2, P3 after P1b · P4, P5, P6, P7 after P1b and P2 · …

Web 是 projectStart.ts 里这条正则；iOS 的 StartProject.leadingCode 是同一规则手写的版本，同样多认一个小写字母。
