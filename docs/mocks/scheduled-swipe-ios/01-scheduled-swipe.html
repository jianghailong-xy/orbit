Scheduled · iOS 行的左滑、右滑和长按：先定规则

App 里已经有一套左右滑的规矩（会话列表 SessionRowActions.swift、任务列表 TasksView.swift）：右滑放正向、可撤回的操作，只有它能一滑到底；左滑放删除和次要操作，删除在最外侧、红色、不能一滑到底、点了先问；长按菜单是全集，左右滑有的长按里都有（VoiceOver 和 Mac 右键也靠它）。Scheduled 页照这套规矩配，按行的种类各给一组。

行的种类（这一页有六种）右滑 · 从外到内左滑 · 从外到内长按菜单点一下
A 计划行（Today / Tomorrow / Later 里，还没跑） Pause 一滑到底即暂停 · Run now Delete 先问 · Change… Run Now · Pause · Change… · Open Last Run · ─ · Delete…打开详情
B 暂停 / 被挂起的行（Paused 组） Resume 一滑到底即恢复 · Run now（挂起的没有，服务端会拒） Delete · Change… Run Now · Resume · Change… · Open Last Run · ─ · Delete…打开详情
C 正在跑的一次（Queued / Running） Open run Stop 先问 Open Run · Open Schedule · ─ · Stop Run…打开详情
D 跑完的一次（打开 Show past runs 才有） Open run 无 Open Run · Open Schedule打开详情
E 草稿（等你允许的创建卡） 无（Allow 是放权，要看完卡片再按） Not now Open Conversation · ─ · Not Now打开草稿
F 等条件的任务（When… 组里的任务行） 无无Open Task打开任务
  • 1一滑到底只给 Pause / Resume：可撤回，历史里有记录，可以 Undo。Run now 不给：误触会花掉这周的一次额度，还会真去跑。
  • 2Delete 和 Stop 都先问：Delete 用详情页 ⋯ 里那句现成的问话；Stop 问「Stop this run?」。都染红色但不用系统的 destructive 角色，否则行会在你回答之前先被动画删掉（今天落地的 Delete 就是这么做的）。
  • 3「一次」的行不再能 Delete 整个计划：今天落地的版本里，正在跑 / 跑完的那一行左滑也是 Delete，删的却是整个计划，看不出来。改成 Stop（正在跑）或者没有（跑完）；要删计划，用计划行或长按里的 Open Schedule。
  • 4Change… 打开对话，和详情页的 Change… 一样（agent-first：改计划是跟 agent 说，不是表单）。

待你定，以及落地

待定 1 · 右滑一滑到底做什么？

A 推荐：Pause / Resume（上面画的）。B：什么都不做，两边都只能点。会话列表右滑一滑到底是 Complete，A 和它一致。

待定 2 · 按钮画成什么样？

A 推荐：圆形，和会话列表一样（circleSwipeActions，上面画的）。B：系统自带的。iOS 26 按行高画，这一页的行约 62pt，会被压成扁胶囊——会话列表就是因为这个才自己画圆。

待定 3 · 范围

A 推荐：这次只做 iPhone / iPad；Mac 只加同一份右键菜单（Mac 没有左右滑习惯）。Android 和 Web 另起一张图跟进。B：四端一起做。

落地（按代价排）

  • 小一份动作表：每种行一张 RowSwipeAction 列表，左滑、右滑、长按都从它画，不会三处对不上（RowSwipeActions.swift 已经有这个类型）。
  • 小按下去：ScheduledModel 已有 runNow / pause / resume / stop / delete；Change… 走 openChangeConversation；草稿的 Not now 走卡片现成的决定。
