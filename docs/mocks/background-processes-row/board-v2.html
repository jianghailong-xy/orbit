为什么这样画：三栏（v2）

iOS 习惯

  • 轮播 = 一个位置轮流显示几件事：主屏的 Smart Stack 就是这样自动轮换；变化用向上推的 .push，不用横向跑马灯（跑马灯要读者追着读，在 30pt 的行里还和截断冲突）。
  • 3 秒、0.3 秒：露出的约 20 个字符一眼能读完；切换比 band 展开用的 0.12 秒慢一点，看得出是换了一条。band 里以前没有定时轮换，这两个数是新的，写成常量放进共享 fixture（E1 请你确认）。
  • 可访问性先于动画：减弱动态效果 → 淡入淡出；VoiceOver 不读轮播内容，读全称 + 计数；App 在后台不跑定时器。
  • 短标签 + 完整读屏标签：系统控件常见做法（可见文字短、accessibilityLabel 完整）。

Orbit 一致

  • 「Background」不是新词：后台 sub-agent 的标签三端都写「Background」。点开后的头部仍是全称「Background processes」，和今天一样。
  • 计数句只用已有的词：「3 running」（FoldedBand.processes）、「2 running · 1 failed」（Tasks 卡 createdTasksCountLine，failed 红色同 .ct-failed）。
  • 颜色/图标不新增：名字 tint 同 Tasks 单条名字；转圈 / ✓ / ✕ 是列表行今天的。
  • 「你发了消息」用的是对话里已有的东西：你的消息本来就是事件流里的用户消息，三端都画成你的气泡；比较它的时间就够，不加「已读」状态。agent 自己开的唤醒轮不算你看过。
  • bg_run 任务画成和 Bash 后台命令一样的行；列表、展开输出不改。

协调

  • 一份规则、三端同步：显示条件（有在跑的，或结束晚于你最后一条消息）、点名/计数、轮播顺序与时长、失败钉住——全写进 src/shared 的新 fixture，web / OrbitKit / Android 各一组 parity 测试读它。
  • 服务端（D3）：getBackgroundShells 加上 runner 托管的 bg_run 任务（id、label、command、开始/结束时间、结果），三端拿同一份；先做这步，否则新规则下这一行很少出现。
  • Android 是新建：今天没有这一行，按 iOS 在 band 里 Watching 与 Tasks 之间新加，直接按 v2 规则做。
  • 假 running：会话不在线时 web 已用 sessionLive 收掉；iOS 核对，Android 新做时带上——否则轮播会永远转。
  • 折起的 pill（FoldedBand.processes）：没有该画的就不出标记。文案英文（CLAUDE.md §5）。
