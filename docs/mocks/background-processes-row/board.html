为什么这样画：三栏

iOS 习惯

  • 没有事就不占地方：系统的「正在进行」类信号（灵动岛、Live Activity、来电条）只在事情进行中出现，结束后自己走——不留「历史计数」。
  • 状态用系统控件：在跑 = ProgressView 小转圈，结束 = checkmark/xmark.circle.fill，正是 BackgroundRow.statusIcon 今天用的那几个 SF Symbol。
  • 截断：description 是一句话，按 iOS 文本惯例尾部截断；只有退回到命令时才中间截断（像 Finder/Files 的长路径），保住开头的程序名和结尾的参数。
  • 出现/消失不推 composer：只在一轮之间变化（开始/结束），沿用 band 已有的 .easeOut(0.12)；打字时整个 band 本来就会被 TypingFold 折起。
  • 点击区域整行 30pt，和兄弟卡一致（低于 44pt 是 band 既有的取舍，不在这次改）。

Orbit 一致

  • 一个点名、几个计数：Tasks 卡（single → .ct-one 蓝色名字 + 状态）和 Watching 条（一个目标点名）已经这样做；Background processes 照抄，不另立规则。
  • 没有新词：「Background processes」「N running · N total」、名字 description ?? command、「Agent / Workflow」小标，全是现有文案；不加「+N more」「finished」之类。
  • 没有新颜色：名字用 Tasks 卡单条名字的 tint；失败的红 ✕ 是列表行现有的；不把整行染红（stall 板 11-16 的做法：只有状态图标带颜色）。
  • 隐藏规则跟 Watching 走，不跟 Tasks 走：Watching「Hidden when there are none」（过程），Tasks「Once something is, the row stays」（产出）。后台进程是过程。
  • 折起的 pill（FoldedBand.processes）同步：没在跑就不出这个标记，而不是写总数。

协调

  • 三端同一条规则：web BackgroundShellsTray.tsx:56、iOS/macOS WorktreeBar.swift:1094（BackgroundTrayView）+ FoldedBand.swift——同一次改、同一个 fixture（参照 watch-strip.fixture.json：显示/隐藏、单条名字、计数句三组用例）。Android 今天没有这一行（只有会话列表里的 bgRunning「Background process running」），按「Android 跟 iOS」的约定新加，直接按新规则做。
  • 「在跑」要可信：会话不在线时，web 推导时带 sessionLive；iOS 需确认 console.state.background 有没有同样处理，Android 新做时带上——否则一个假 running 会让这行永远不消失。
  • bg_run（D3）要动服务端：getBackgroundShells 加上 runner 托管的任务，三端拿到同一份列表；不做的话这行在 95% 的场景里不会出现。
  • 顺序不变：Watching → Background processes → Tasks → 分支条，web 与 iOS 一一对应（iOS 多的 Agents 行不受影响）。
  • 文案仍是英文（CLAUDE.md §5），这块板只有标注是中文。
