Q1　请求存在哪里？

A　owner 请求 PROJECT_REOPEN推荐和 settings_propose 的 SETTINGS_CHANGE 一样。任何会话都能发，结束通过现有 owner 请求投递回到提问者；项目页读它画一行。
B　项目 open item REOPEN_REQUEST和 project_request_done 一样挂在项目上。项目页天然有，但 open item 只投递给协调者，非协调者提问要新写一套路由。

Q2　几个会话问同一个项目，几张卡？

A　一个项目一张推荐后来的提问者并入，卡上写 “Also asked by …”；你答一次，所有提问者都收到结果。
B　每个会话一张每张有自己的理由；按下第一张 Reopen 后其余自动结束。卡多、信息全。

        409 PROJECT_ALREADY_OPEN · 409 REOPEN_REQUEST_DECLINED · else OwnerRequest{PROJECT_REOPEN, PENDING}
owner ─Reopen─▶ POST /owner-requests/:id/reopen-project  (owner 登录专用；带会话头 403，PAT 拒绝)
        一个事务：status OPEN + reopenRecordOfPress + 该项目所有 PENDING 卡 → DONE
        之后：结果送回每个提问者 · tellCoordinatorProjectReopened（协调者不是提问者时）
owner ─Chat about this─▶ DECLINED + 理由 → 同一会话不能再提
