Toast 通知系统 · ① 分级与样式

现在三端只有一种样子：iOS / macOS 是一张全宽卡，web 是一张 360px 的卡。从 Link copied 到 Merge into main failed 都长一个样。新系统按它要你做什么分级：只是告诉你成功了 → 胶囊；你可能要撤销或打开 → 卡片；失败了或者要你批准 → 着色卡片，不会自己走，也不会被别的挤掉。另外加一个「进行中」状态：一个操作从头到尾只用一个 toast。

1现在的问题三端近 300 处调用的盘点（web ≈ 240，iOS / macOS ≈ 50）

1一种样子画所有事

iOS 一个词也占一整张全宽卡；web 的两层（Message / 会话卡）是刻意画成同一张卡的。看不出轻重，重要的反而不显眼。

2文案没有语法

只有动词没有对象：Decided、Saved、Recorded。web 122 处错误里九十多处只放服务器原话（e.message），不说是哪一步失败。

3出得晚

等写入 + 刷新都跑完才弹，常常落在已经切过去的页面上，跟刚才的操作对不上（Wiki 的 Decided）。

4会丢，或者会堆

iOS / macOS 只有一个槽：没读完的错误会被后来的 Link copied 直接顶掉。web 相反：错误一直叠下去，要逐个点 ×。

5进行中没有状态

Merging… 4 秒就走，结果再弹一张新的；合并慢的时候，中间什么都没有。

2两种形状，四种用途

Link copied

胶囊 = 一句话。不带按钮，宽度随内容，居中。用于 ① 确认、进行中，以及 ③ 缩起来以后的样子。可以有第二行写对象；能点的（回到会话、展开错误）末尾带 ›。

Session completed会话间消息参数与回复设计Undo

卡片 = 要你看或要你动手。带按钮或带原因，和内容同宽。用于 ② 结果、③ 需要处理。tone 只决定图标颜色；只有 ③ 会给整张卡着色（红 = 失败，橙 = 等你批准）。

① 确认 胶囊

你刚做的事成功了，不用再做什么。

  • 宽度随内容，最宽 300pt
  • 一行；结果落在具体对象上时，第二行写对象
  • 3 秒 · 不拦点击 · 上滑可以提前关掉
  • 例：Link copied、Schedule saved、Accepted

进行中 胶囊 + 转圈

要花一会儿的操作。一个操作从开始到结束只有一个 toast。

  • 不计时，直到完成
  • 完成后原地变成结果：成功 → ①；失败 → 展开成 ③
  • 离开了发起的页面，第二行写对象，结果带 › 可点回去
  • 发起的地方已经在显示进度（如分支条）就不弹

② 结果 卡片

结果落在一个对象上，你可能想撤销或打开它。

  • 和内容同宽（iPhone 361pt，桌面 360px）
  • 最多 1 个按钮：Undo 或 View
  • 点卡片打开那个对象（会话、任务、条目）
  • 6 秒；手指按住 / 鼠标悬停时暂停

③ 需要处理 着色卡片

失败了，或者要你批准、要你决定。

  • 红 = 失败，橙 = 等你批准
  • 标题说哪一步失败；服务器原话单独一块，可选中复制
  • 最多 2 个按钮 + ✕
  • 不会自己消失，也不会被后来的顶掉
  • iPhone 上 6 秒后缩成顶部胶囊，点开恢复；桌面保持展开
  • 在别处处理掉了（另一台设备批准了）自动收走
