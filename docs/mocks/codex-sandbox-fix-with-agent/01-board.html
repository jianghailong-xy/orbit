需要你定的 3 件事（蓝框为推荐）

1. 按钮放在哪
推荐A. 条目下方单独一行这句诊断有两句正文加一个链接，按钮挤在句末会截断正文；放在下方也是机器页那两处已有的位置。
B. 行内，句子末尾更紧凑，一屏里占的高度小；窄屏上按钮会掉到下一行，读起来像句子的结尾。
2. 修复会话结束后，这条历史怎么画
（会话记录是历史，不会像机器页的红框那样自己消失）
推荐A. 留住链接，不再给按钮显示 “Fixed by an agent in X · Open session”。这一条已经处理过；下一次 Codex 再报会是新的一行、带新的按钮。服务端在 runner 上记“最近一次修复会话”，关掉也还读得到。
B. 按钮一直留着实现最简单（只看“现在有没有 Agent 在修”）；但对一条已修好的旧警告再按，会再起一个 Agent 去检查。
3. 这条提醒的语气
推荐A. 琥珀色 WARNCodex 明说会用自带的 bubblewrap，回合没有失败；把它画成可恢复的诊断，和模型目录、MCP 那些非致命诊断一致。
B. 保持红色 ERROR像截图一样更醒目；但会继续把一条非致命日志读成回合失败，而且会让人以为要马上处理。
