Agent 提问卡（AskUserQuestion）：答完以后，卡上写「问了什么 + 你怎么答的」

截图那一屏：agent 问了一个问题，你选了第一项。答完后对话里留下的这张卡占了三分之二屏：问题被排成 17pt 粗体，选项是一串圆点，哪项是你选的看不出来；底下 OUTPUT 又把整个问题用等宽字抄一遍，你的答案在它最后一句，被输入框挡住了。这张卡上最该看到的那一句，这一屏上恰好没有。

建议：卡上写「问了什么 + 你怎么答的」，点开原样回放问题和每个选项

和昨天定的协调者提问卡同一个写法：卡上写问题开头两行，再写你的回答；点开看全文和全部选项，你选的那项打勾。仍然是对话里的一张工具卡（紫色竖条、Question），只换卡里画什么。

其余几种答法

同一张卡，只有回答那一行和点开后的选项区不同。上面一张是收起时，下面一张是点开后（节选）。

待定 · 要你拍板

① 点开以后，全文在哪看。左边是建议：在原地展开（上面画的）。右边是协调者提问卡的做法：对话里放一张蓝色的 Answered 卡，点 View details 弹出详情页。

推荐 A
  • 这是 agent 对话里的一次调用，和 Plan、Bash、Edit 是一家：它们都在原地展开，问题卡也这样，不多一种操作。
  • B 让对话里出现两种「问答记录」：协调者问的是蓝卡，agent 问的也是蓝卡，但前者是项目里的待办，后者只是这次对话的一步，混在一起反而难分。
  • A 只改卡里画什么；B 还要给工具卡加一个能弹详情页的入口，Mac 和 Web 也要各配一个。
B 的好处
  • 问题长、选项多时，整页详情比在对话里展开好读，展开也不会把对话往下推。
  • 和提问时的那张卡（也是点开一页）前后一致。

② Web 怎么跟。

推荐 A · Web 也换成同一张卡
  • 收起时同样是问题开头 + 你的回答，点开是全文和选项；OUTPUT 不显示；回话不再是红色。三端字句一致（有测试盯着不许走样），回看时在手机和电脑上看到的是同一种卡。
  • Web 本来就在用同一段结果文字打勾，只是改成按问题切开，顺便把自己打的字和回话也认出来。
B · Web 只修两处
  • Web 的对话栏宽，问题和选项默认全展开也放得下，所以只去掉重复的 OUTPUT、把回话改成不是红色，其余照旧。
  • 代价：同一个问题，手机上是两行记录，网页上是一整张卡，两边看起来不是同一个东西。

落地（按代价排）

  1. OrbitKit：把结果文字按问题切开只改客户端
    拿问题原文去结果里找 "<问题>"="…"，得到每个问题选中的选项和自己打的字；多选按逗号认选项名（选项名里本身带逗号也认得出）。错误结果里，<tool_use_error> 开头的、runner 自己写的几句（approval poll failed、denied by the user）是真失败，照旧红色；其余的是你在对话里回的话。格式认不出时一律退回今天的样子。Linux 上就能跑单测。
  2. iOS / macOS：卡片按第 2、3 部分改只改客户端
    收起时问题开头 + 回答；点开问题全文 + 选项行（沿用协调者提问卡详情页的选项行）；OUTPUT 只在切不开时显示；回话的行尾不再是红叉。用 macOS 26 的 CI 模拟器出改前、改后截图，各种答法都拍到。
  3. Web：同一张卡Web（按「待定 ②」，选 B 就只去 OUTPUT、改回话颜色）
    现有的 Questions 组件改成同样两种状态；用同一套切法。新加的几句英文（Replied in chat、Your answer）两端共用，各有测试对着对方的源码。
  4. 顺带 · iOS 上 Plan 卡、Agent 卡里的 Markdown 也是 17pt一行
    和第 1 处是同一个原因：工具卡里的 Markdown 没按 16pt aside 排。要不要一起改小一号，你定；不改也不影响这张问题卡。
  5. 另起一件事 · 选项的小样（preview）另起任务
    agent 可以给每个选项附一段小样（文字画的界面、代码片段），本意是让你对照着选。今天三端提问时都不显示，答完也看不到。这比答完后的记录更影响你做决定，建议单独排。
  6. 以后 · Android另起任务
    Android 对话里还没有逐个工具画的卡，先要有这一层，问题卡才能接上。

建议 1–3 一起做，一个任务、一次落地；4 你说要就带上；5、6 另起。
