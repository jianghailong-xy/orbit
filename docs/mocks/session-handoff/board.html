D2 任务运行

B任务运行上不提供。

D3 提示方式

A只在上下文面板约 60% 起加一行。推荐
B对话里也弹横幅。

D4 bg_run 服务

A同 worktree 交接时服务继续跑（dev server 不断）。推荐
B服务停掉，和今天会话结束一样。

落地（5 个任务）

  1. 服务端：把交接从 /projects/:id/coordinator/handoff 泛化到 /sessions/:id/handoff，协调者走同一服务；换人事务搬 watch/唤醒/循环/排队消息/任务 run；keep-work 信号和网关规则推广到任何交接过的会话。
  2. Runner（需发版）：worktree 交给新引擎；任务、服务、watch、SubAgent 跨交接继续；属主变了的 worktree 不回收。
  3. 便条与开场：五段提示词、首条提示原文、状态摘要（大会话 ≤16k 字符的 spec）。
  4. 客户端（web / iOS·macOS / Android）：面板动作与 60% 提示、带种类（含 SERVICE）的确认弹窗、新会话便条卡、旧会话横条。
  5. 生产验收：先查 runner 引擎；带未提交改动 + bg_run 服务和任务 + Codex SubAgent + 唤醒的普通会话交接，新会话看到同样的 diff、服务仍可访问、所有唤醒送达、量首轮 token；再在一个任务 run 上做一遍。
