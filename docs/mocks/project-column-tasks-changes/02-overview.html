项目栏第 2 版：首页是“概览”，每类资源点进去看全部（代替标签）

第 1 版用“Tasks | Changes”两个标签；你指出标签装不下更多种资源。项目产出的东西至少有四类：任务、代码改动、文件（截图 / 测试报告 / 文件包，Orbit Files 已按任务记录）、合入记录，以后可能还有更多。
建议：项目栏首页是一张概览，每类资源一段（摘要 + 最重要的几条 + “全部 →”）；点“全部 →”在栏内推进到这类资源的完整页，左上角返回。加一类资源 = 多一段，不受标签数限制。这也是 Codex 任务侧栏的做法：计划、来源、产物、摘要上下排成段，而不是标签。数据为样例，界面文字为将上线的英文。

待定 · 要你拍板

  • 导航方式：A 概览 + 下钻推荐 / B 图标栏 / C 下拉切换。
  • 概览里放哪几类：Tasks、Changes、Files、Landings 四类推荐；以后可加 Docs（设计稿 / 文档）、Deploys（上线记录）。
  • Files 默认分组：按任务推荐 / 按类型。

落地（按代价排）

  • Web 概览 + Tasks 下钻：用现有数据（任务、会话、分支统计），即第 1 版方案 A。
  • Landings 段：现有合入记录，搬进概览。
  • Files 段：Orbit Files 已按任务、会话记录文件，加一个“按项目列文件”的读接口即可。
  • Changes 段：新增“项目分支相对 main 的文件差异”接口（第 1 版方案 B）。
  • iOS / Android：同一结构，用系统列表的分组和推进页。
