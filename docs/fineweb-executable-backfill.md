# FineWeb shard `EXECUTABLE` backfill

Migration `0187_fineweb_executable_backfill` is the N19 operator migration for project
`34C0tJjDOprFHYQ38s69w` (`FineWeb × Common Crawl → RocksDB 语料库`). Applying the schema migration
only installs a strict classifier, an audit ledger, and bounded operator functions. It does not
update a task until an operator explicitly calls the prepare and step functions.

## Hard gate

Do not prepare or run a batch until N17 has proved the production path end to end: the exact
declared shell command must be dequeued and executed, its actual exit code must be recorded, and
that fact must derive the task status. Save the task id, session id, command, expected and actual
exit codes, raw output, and derived status with the N19 evidence.

The backfill itself never writes `task.status`. A change in any status count, especially `DONE`, is
a stop condition.

## Strict classes and command templates

The classifier accepts a row only when both its title and its complete acceptance prose match the
reviewed template. A recognized prefix with prose drift is unclassified; the migration does not
guess.

| Class | Strict title | Mechanical command | Expected exit |
| --- | --- | --- | --- |
| `FINEWEB` | `[FineWeb][DUMP] SHARD.parquet` | Python checks the exact declared byte size, reads the Parquet footer/schema, validates the manifest object and unique `warcs[]` entries (`path`, `size_bytes`, `etag`), and reads the per-shard status JSON. | `0` |
| `WARC` | `[WARC][DUMP] SHARD 的 WARC 依赖` | Runs the existing `warc_inventory.py --dump DUMP --shard SHARD`, requires exit 0 and `齐全，可直接 merge`, then reconciles manifest and status counts/bytes. | `0` |
| `MERGE` | `[Merge][DUMP] SHARD → RocksDB` | Requires the published RocksDB and absence of build/`.incoming`; checks `missing_rate <= 0.05`; opens the DB read-only with rocksdict, requires `default/text/html/warc_index`, deterministically samples 20 Parquet rows, checks all three main CFs and byte-exact text, and requires nonempty `warc_index`. | `0` |
| `VERIFY` | `[校验][DUMP] SHARD.rocksdb` | Requires the final Parquet location and no working copy; opens all four CFs read-only; reports CF counts, difference/rate, size properties and SST count; validates 200 complete readbacks and 20 metadata comparisons; validates five `warc_index` ranges as complete response records whose URL/date reproduce the key; runs the guarded reclaim script in `--dry-run` mode to obtain non-mutating accounting. | `0` |

The full, versioned shell bodies are generated by
`n19_fineweb_executable_classify` in the migration. Random-looking samples are deterministic per
dump/shard so replay evaluates the same rows.

`[校验]` is intentionally included. The only expected unclassified row in the production
snapshot is the project root `_v+ project0`, which has neither a recognized prefix nor acceptance
criteria and therefore remains `HUMAN_SIGNOFF` with no command.

## Bounded, idempotent execution

Prepare one immutable snapshot and use a unique operator key:

```sql
SELECT n19_fineweb_executable_prepare(
  '01a02d83-7c58-708c-8d7c-103d15523d70',
  'n19-production-20260827-v1',
  250
);
```

The receipt fixes the upper task id, source/candidate/unclassified counts, class counts, pre-status
counts, command version, and batch size. Reusing the key with identical inputs returns that receipt;
different inputs are refused.

Call one step per transaction until `finished=true`:

```sql
SELECT * FROM n19_fineweb_executable_backfill_step('BATCH_UUID');
```

One call locks and updates at most 250 eligible rows. It snapshots each row's old declaration in
the ledger, stores the installed command digest, changes only `completion_criterion`,
`acceptance_command`, `acceptance_expected_exit_code`, and `updated_at`, then commits. A replay after
completion returns zero rows changed. Scope drift aborts instead of silently claiming completion.

## Verification and rollback

After the final batch, compare the saved before counts with both `pre_status_counts` and
`post_status_counts`, then query the live tasks. `DONE` must be unchanged. Sample every class and
compare the stored command to a fresh classifier result byte for byte. List every unclassified row
and confirm it still has `HUMAN_SIGNOFF`, a null command, and a null expected exit code.

Rollback is also one bounded transaction per call:

```sql
SELECT * FROM n19_fineweb_executable_rollback_step('BATCH_UUID');
```

It restores the exact previous declaration from the ledger, never status. Before restoring a row it
requires status to equal the captured status and the current installed declaration digest/exit code
to equal the migration's values. Any later status or declaration change raises
`N19_ROLLBACK_DRIFT`; investigate that row instead of overwriting it. Continue until
`finished=true`. Replaying a completed rollback returns zero.
