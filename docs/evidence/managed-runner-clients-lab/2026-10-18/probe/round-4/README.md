`replay.py` serves one scene at a time on 127.0.0.1:8765, on the scene's clock:

- a GET gets the latest recorded answer to the same request at or before the clock (the session list's `since`
  cursor is the one wildcard); the two event streams replay their events at their recorded times;
- a request read only every 15 s or 30 s (`sampledEvery`) gets its next recorded answer once the clock is within
  that time of it, never past a write the app has not sent: its change happened somewhere in that time. Added after
  the first run (39103921488), where a workspace refresh got the new workspace list with the provider list from
  before the key, a pair the server never answered, and the draft kept Claude Code's model;
- an app's write must be the scene's next recorded action, same method and path, same key fields; the clock holds
  just before an action until the app sends it, and moves to it when it does;
- every timestamp in an answer is shifted by one constant, so ages and due times read as they did live; nothing else
  in an answer is changed;
- any request the scene does not hold, a write whose key fields differ, or an action never sent fails the test
  (`GET /__violations`).

`ReplayTests` (generated by `gen_tests.py` from `scenes/`) has one test per scene: load it, launch the app where the
scene says (a workspace's New Session draft, or a session), and play the scene's steps — wait for the shared
display's words, take a picture, type and send, press Retry, see words go. The report job pushes pictures, notes,
replay logs, verdicts and build tails to `probe/t07-managed-runner-replay-results`. The same push runs client.yml's
compile gates (OrbitKit `swift test`, OrbitApp `swift build`, the iOS app).

Every answer is a test server's: test accounts and a fake-model key only (fake-model.py, not a model).
