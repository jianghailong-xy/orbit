# Orbit 0.1.261-beta.106

## Summary

This release is mostly what a session list row looks like, and one runner-link change behind it. On web, macOS, iOS and Android a row now draws its state as icons: the chips come down to "Needs you" alone, Failed, Retrying, On hold, Background and Will resume join the row's title line, and Interrupted, Finished and Ended are no longer drawn. An idle row draws no circle beside its time. On web, a run claimed while its runner has no free slot now reads as the runner-full queued card instead of "Getting the session ready", and Stop no longer stands in for Send while a message is on its way. On the link, the gateway keeps a runner process's heartbeat facts across reconnects and nodes, and permessage-deflate is negotiated without context takeover.

## Upgrade impact

- **Migrations:** none in this range. `git diff --stat v0.1.261-beta.105 origin/main -- src/apiserver/prisma/migrations/` is empty, so the schema is exactly beta.105's, and `1750_runner_presence_last_heard_at` from beta.105 is still the last migration a deployment from beta.105 applies.
- **Backfill:** none.
- **Configuration:** none added or changed. permessage-deflate is negotiated per handshake with a fixed 512-byte threshold and no context takeover; nothing ports, sizes or switches it.
- **Server:** every heartbeat answer now names `capacityClaims`; `GET sessions/claim` takes a full scope, and return-slot takes the reason `runner_full` (fenced to this runner, a lease owner that is this process or none, and no recorded drain). Background-job holders count in full toward a runner's capacity, with the claiming session's own jobs left out, and the displayed queued counts and Run now's overflow gate leave that own job out too (no more 5/4). `waiting_for_slot` is a named engine phase, and a row in it carries `slotWait` — a shared `SessionSlotWait` on `ControlSessionSummary`, now with the runner's count beside its limit. An `ALREADY_MERGED` integration receipt records the main sync its landing pushed as `target_sha_after` instead of NULL.
- **Gateway:** the link gateway must be rebuilt for its half — it keeps heartbeat facts for runner + process for 15 minutes past the last connection, says so in `Welcome.process_facts` (new field 11), asks the other gateway nodes over NATS for a digest it lacks before falling back to `want_facts`, and negotiates permessage-deflate. Compatibility holds in both directions: an older gateway still gets every fact whole, and old runners and old gateways still connect uncompressed.
- **Runners:** the runner served at `/dl` is built from this tag. A runner at or past `maxConcurrent` now names a full scope so the control plane hands it only the holders' own messages plus Run now, and gives back a claim that lands anyway through return-slot with reason `runner_full`, withdrawing it and claiming the session again once a slot frees. A claim that rests on the main sync now pushes that sync and reports it as `landedSha`. With `Welcome.process_facts` the runner keeps one record per process instead of per connection, so its first beat after a reconnect is a steady beat's size (16.3 KB to 1.7 KB measured); facts a beat lost with its connection go whole again. An older runner sends every fact whole, asks for claims without a full scope and returns none, which is the parking these runner and server commits describe as the pre-fix behavior.
- **Clients:** web arrives with the deploy of this commit; the macOS beta-channel DMG, the iOS TestFlight build and the Android APK come from this tag. Everything the server adds to a payload is an addition — `Welcome.process_facts`, `capacityClaims`, `slotWait` — so an older client reads what it already did and draws the old chips and circle until it updates.

## Security fixes

None in this release. No commit in this range names a security issue or a fix for one.

## Known limitations

- A `runner_full` claim the control plane will not take back — a message already leased, or another process of the runner holding the lease — keeps the slot and, while no engine has spoken, leaves the session in `waiting_for_slot`. An older control plane likewise keeps that phase for a claim it will not take back.
- The runner-full card is web-only in this range. The macOS and Android clients get the row's icons but not the queued runner-full reading; they still show the pre-fix state word for such a run.
- A web Stop whose own request outlives 20 s ends with "Couldn't stop the session". The commit does not say whether the stop still lands on the server after that.
- A full runner's claim is requeued behind `runner_at_capacity`; nothing in this range bounds how long a runner full of long background jobs keeps a turn waiting beyond the job ending.

## Rollback

The previous tag is v0.1.261-beta.105 (release commit `b0d3312702a778795d92fe3af8eb5afd5e3a9fb1`, whose source is `4f926c7dcb12d37ba0e811da3234a27490940144`), and its GitHub Release published the macOS DMG, the Android APK, the runner binaries and the appcast for it.

Application-only rollback is **schema-safe**: this range adds no migration, so an earlier server reads and writes exactly the columns beta.105's schema has. No down-migration or backup/restore step is needed; deploy the previous commit for the server, web and gateway together.

Rolling the runner back to beta.105's binary loses this range's returned-claim, `landedSha` and per-process digest halves: it asks for claims without a full scope and sends every fact whole, so a full runner can again be handed a claim it cannot start — the behavior these commit messages describe as pre-fix. A gateway left un-rebuilt still works with the new runner, and a reconnecting runner then sends every fact whole; permessage-deflate simply is not negotiated.

Client rollback is to v0.1.261-beta.105's DMG, `orbit-android-0.1.261-beta.105.apk` and TestFlight build. A beta.105 client keeps working against this release's server — every payload it reads keeps its shape, and the fields this release adds are ignored — but it loses the row's icons, the runner-full queued card and the Stop change.
