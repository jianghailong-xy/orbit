# Orbit 0.1.261-beta.10

## Summary

The work merged since [0.1.261-beta.9](0.1.261-beta.9.md), on the beta channel. beta.9 reached TestFlight
only: its Android job timed out while signing, so its GitHub Release, the macOS beta update and the Android
APK were never published. For macOS and Android this release therefore also carries everything listed in the
beta.9 notes (recovery contract, ~30 translation languages, managed runners in Machines & models, SubAgents
on another agent's machine).

- **Scheduled tasks.** Schedules that start agent runs on a timetable: a Scheduled page with its timeline and
  run panel on web, iOS and macOS; schedule cards in conversations and Waiting on you; a weekly run budget;
  and CHECK_ONLY checks that read the checkout without writing (Claude Code asks before shell commands, Codex
  runs in its read-only sandbox, and each other engine in its nearest mode that is not wider; see
  `docs/scheduled-tasks-engine-modes.md`).
- **Prompt optimizer.** An account switch, a composer button and a suggestion card on web, iOS, macOS and
  Android: DeepSeek rewrites a draft in the account's agent language, and the owner chooses whether to use it.
- **Show both languages.** An account preference that draws translated messages in both languages.
- **Translation fixes.** Your own message's Show original appears on hover on web, with the time at the row's
  end; a message sent while the agent is working keeps what you wrote once the agent reads it (iOS and macOS;
  it already reached TestFlight in beta.9).
- **SubAgents:** a SubAgent's finished turn is a line in the agent's stream on iOS, macOS and Android, as on web.
- **Smaller changes:** what starts waiting on you is noticed once, as a toast (iOS and Android); no NEW badge
  beside Prompt optimizer in Apple Settings; the iOS composer takes focus outside the SwiftUI update, never in
  a background scene; the Android release job gets 60 minutes instead of 40.

## Upgrade impact

- **Database migrations.** Three since beta.9, all safe while the previous apiserver still runs:
  `0830_schedule_run_start` (two nullable columns, an index, and `SCHEDULE` added to the allowed session
  openers), `0840_schedule_attention` (four schedule kinds added to owner requests, four nullable columns, an
  index) and `0860_schedule_check_only_asks` (a nullable column and a boolean column defaulting to false,
  filled for existing runs). The apiserver applies them on start. Over beta.8 there is also
  `0645_create_request_receipt` (see beta.9).
- **Server first.** The new clients call the scheduled-task, prompt-optimizer and bilingual-display routes, so
  the server is deployed at this release's commit before the tag.
- **Runners.** Runners on the beta channel move to 0.1.261-beta.10. The runner changes are the scheduled-run
  argv and tool rules for CHECK_ONLY checks, and filling a cloned checkout's index stat data before it is hashed, plus beta.9's delegate loading and recovery reports.
- **Configuration.** No changes required. The prompt optimizer and translation use the server's existing
  `DEEPSEEK_API_KEY`.
- **Clients.** macOS users who enabled "Receive beta updates" get this build. iOS ships to TestFlight
  (marketing version 0.1.261, build number = commit count). Android offers the APK to every install via
  `android-update.json`.

## Security fixes

None in this release.

## Known limitations

- Android has no Scheduled page yet; schedules are created and read on web, iOS and macOS.
- The known limitations of [0.1.261-beta.9](0.1.261-beta.9.md) still apply.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.10` and tag `v0.1.261-beta.10`. This tag publishes the
macOS DMG and Sparkle payload (beta channel), the iOS TestFlight build, the runner binaries, and
`orbit-android-0.1.261-beta.10.apk` with its `.sha256` and `android-update.json` on the same GitHub Release.

The features were checked in their own landings. On HPC, the Android unit tests and lint passed on main at
362a49170 (the translation-languages merge), and the release workflow tests passed (124/124) with the new
60-minute limit. Client CI (macOS + iOS) ran on main before the tag.

## Rollback

Roll back to 0.1.261-beta.8, the last release whose macOS and Android builds were published. The migrations
since then only add tables, columns, an index and allowed values that beta.8 does not read, so an
application-only rollback is schema-safe. Runners do not move back by themselves: roll them back with the
`/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
