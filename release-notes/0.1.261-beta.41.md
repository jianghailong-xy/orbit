# Orbit 0.1.261-beta.41

## Summary

This release is the owner-card translation pass: with Settings › Translation on, every owner card — the coordinator's question and its record, start and done requests, owner requests, confirmations, evidence, criteria proposals and crossings — and Orbit's own create, batch, project, blocker and DAG-change approval cards draw in the owner's language on web, Apple (macOS and iOS) and Android, the owner's typed answers reach the agent in the agent language, and a card that cannot be translated is refused whole rather than sent in the wrong language. It also carries the whole beta.40 range, because beta.40 was tagged but never published: its release run failed the Android lint job (`ProduceStateDoesNotAssignValue` at `EvidenceFilesViews.kt:233`, from cffdf80cb), so no GitHub Release was created and neither macOS nor Android received it. bbd9e0444c suppresses that check on `producePicture` alone — the value is assigned by `producer`, run as `scope.producer()` inside `withContext`, where the check cannot see it — and records `lintDebug: 0 errors`. This release therefore publishes beta.40's notification, Withdraw, runner-full row, "Orbit attached" and server-escalation changes as well, and its range is v0.1.261-beta.39..origin/main. It adds two database migrations, both additive.

- **Owner cards draw in the owner's language (web, Apple and Android).** With Settings › Translation on, a card draws the server's `translation` when it is in the owner's current language, with one "Translated · Show original" ↔ "Original · Show translation" foot per card that flips the whole card; no, failed or stale-language translation draws the original. OrbitKit's `OwnerCardTranslation` and `EvidenceTranslation` decode the optional `translation` served on open items (coordinator question, start and done requests), answered questions, owner requests, confirmation reviews and PROBLEMS records, the report's run-event translation, evidence rows, criteria proposals and crossings. Android now draws an owner card's translation only in the owner's current language, as web and iOS do, and the Waiting-on-you row of an owner request draws its translated title. Doors and bindings are the card's own, so options still answer by index. An answer refused with 422 `TRANSLATION_FAILED` shows "Couldn't translate, so it wasn't sent · Retry · Send as written" on the question, Not yet…, owner request done/decline, owner confirmation and evidence send-back, and Send as written posts `sendAsWritten: true`; the refused-answer line uses the same "·" separators on every client, and OrbitKit's `TranslationCopyParityTests` and Android's `OwnerCardTranslationCopyParityTest` hold each client's flip and refusal lines to web's.
- **Orbit's own approval cards are translated too (web, Apple and Android).** `approval.translation` gains title, acceptanceCriteria, tasks[], goal, instructions, acceptanceCriteriaItems[], reason and note (index-aligned and additive), read only on the translated Orbit cards, whole card or `failed: true`. The cards draw them under the same one-foot flip, and the task-create description the web dropped and Apple ignored is now drawn; the decline subject the agent reads stays the original title.
- **The owner's typed answers reach the agent in the agent language (server).** With Settings › Translation on, the owner's own words on an owner card are translated before anything is written — the open-item answer and done-request decline, an owner request's done text and decline reason, an owner confirmation SEND_BACK reason and the text of its CONFIRM answers, evidence SEND_BACK from the app, and Feishu direct replies. A translation that cannot be made is refused whole with the approval answers' 422 `TRANSLATION_FAILED` before anything is written, and `sendAsWritten: true` delivers the words as typed; options still go by index, and a session's note is never translated.
- **Pushes and Feishu alerts quote the translated card (server).** Coordinator-question, owner-request and crossing pushes and their Feishu cards wait up to 20 s for the card's translation when the owner's translation is on, and quote it when ready, otherwise the original. A FULL Feishu approval card waits the same way and draws `approval.translation`'s questions. Nothing waits with translation off.
- **The project page's open-item rows and the hand-over note are translated (web, Apple and Android).** The open-items read serves `translation.title` and `translation.detailLine` (the question's "If you don't answer" line built from the translated `ifUnanswered`) beside a whole translation in the owner's language; the list row draws them while a usable translation exists, with Orbit's English "Coordinator asks: " kept, and falls back to `row.title` / `row.detailLine` otherwise; the card keeps its own flip. `open_item_hand_over` now clears the item's stored translation and queues a new one that includes `handoverNote`, on items of any kind, served as `translation.handoverNote` and stored only while it is still the same note. The who-fixes card draws it in the coordinator row under "Why the coordinator handed it over", translated with its own "Translated · Show original" flip, as written otherwise, and not at all when there is no note; the status sentence no longer quotes the note, so it appears once. The caption is held to web's `HANDOVER_NOTE_CAPTION` by the OrbitKit and Android copy-parity tests.
- **iPhone owner-card text rules (board `owner-card-ios-text`, D1–D3 = A).** iPhone only; the Mac and Android cards are unchanged. Settled exception cards directly above an open one fold into one row ("✓ 2 sent back to the coordinator · Show") that expands in place, and the fold names how each item ended; a card redrawn when its fold opens reads the console's copy, because the receipt is recorded by the door's own call before the read that drops the item. Details shows the check's failing lines (✖ / not ok, at most 3) in a small mono box, then "Full output (N lines)" (a sheet) and Open landing. The heading is one line with a small "⚠ Escalated to you" label and the clock on its right, then the cause, with FROM ORBIT at the card's foot; the subline is one line with a tail ellipsis and the full task title leads Details; the check command is one line with "Copy command"; doors are left-aligned controls, link doors blue rather than centred grey words; captions are 12pt; and the coordinator row's sentence is two lines at most. The old card's required-action sentence is no longer a bold block on iOS, facts stack their label above the value at accessibility text sizes, the kind label's mark is inline at the label's size, and Details' label column fits "Came to you" on one line.
- **A two-stage deploy keeps the last three releases' images (operator).** Every release pulled its own apiserver and web image onto the target and nothing removed them: on 2026-11-18 production had kept 77 releases' images, 137 GB, with 6.6 GB of disk left. After each deploy, `deploy/two-stage/deploy-stage.sh` removes the registry's `orbit-apiserver`, `orbit-web` and `orbit-link-gateway` images except those of the last 3 releases in `.upgrade/history`; Docker still refuses any image a container uses, and a rollback past them pulls the image again. It runs on every deploy, `--prune` or not.
- **Notifications name the wait (iOS and Android).** A notice for a wait the server names a kind for (a confirmation, a project ready to close, and so on) said the tool call's "Needs your reply"; it now says what the session's row says for that kind, and only a blocked tool call keeps "Needs your reply". An owner request stops no turn, so every wake while the session waited re-announced the same request, worded as a tool approval and keyed by the session's last turn; a wait the server names a kind for is now keyed by that kind, the request's notice says "Waiting on you", and a press opens the session's oldest pending request in the Waiting on you inbox, as the request's push does (the inbox alone when this device has not read the request yet).
- **Withdraw hands back the words the reader wrote (web, Apple and Android).** With Settings › Translation on, withdrawing a message from the tray put the English delivered to the engine back in the composer, though the row showed what the reader typed. Withdraw now restores the original on every client: Apple's `cancelQueued` and `withdrawSteer` (`ComposerLogic.withdrawnText`, nil wherever `restorableText` is), Android's row restores, and web's `cancelQueued` and steer withdrawals. Put back for an undelivered message and the Stop fold are unchanged.
- **A session a full runner holds reads "Waiting for a free slot" (web, macOS and Android; the copy is in the OrbitKit row code iOS shares).** The list row said only "Runner full", which did not say the message goes out on its own; the owner's pick C on the `session-row-runner-full` board keeps plain words and no clock, since the row's own time already counts the wait from `lastTurnAt`. Run full and Batch full read the same. Web and macOS rows carry a tooltip with the gate's name, the popover's sentence and the wait; the conversation header, foot tag and popover keep their words.
- **The "Orbit attached" line is drawn nowhere (web, Apple and Android).** The owner decided on 2026-11-18 (option 3 on the attached-where board) that the "⊕ Orbit attached: <kind>" line, and the rows or fold it opened, are no longer drawn in a transcript — not under the owner's bubble, not in a session message's foot, not at the bottom of Orbit's own cards. This supersedes 2026-10-27 (`docs/mocks/attached-context-note`). What delivery appended is still recorded and still kept out of the person's words; only its rendering goes. The clients drop the line, its renderers (background-job rows, referenced-task cards, wiki-context rows), the props and model fields that only fed them, their CSS, and the parsers left with no reader; `SessionMessageCard.splitNote` becomes `narrowerLine`, the one part still drawn, and tests that pinned the line now pin its absence.
- **No dangling dot before the translation foot (Apple).** A delivered translation's foot ("Sent to the agent in English", "Show original") was always preceded by "·", so a message with no timestamp, or one a runner holds (its tag drawn instead of the time), read "📄 · Sent to the agent in English". The dot now goes only with something drawn in the state-or-time slot, as web's separator needs `node.ts`.
- **An owner item reaches the owner when its coordinator cannot take the turn (server).** Since 3810329b60 an undelivered coordinator item had no deadline and was hidden from the owner. A coordinator FAILED with no auto-retry never takes the turn, so such an item stayed silent for ever; on production an `INTEGRATION_CONFLICT` opened while its coordinator was already down held its lane by M2 and left a `LAND_TASK` QUEUED for 98 hours, with nobody told. The no-deadline wait now holds only while the coordinator can still take the turn (`openItemCoordinatorCanTake`: live, or FAILED with `retry_at` set). Otherwise the item is visible and escalates one window after it opened.
- **Newer runner engines.** The managed-runner image and the apiserver image move to Codex 0.169.1 (from 0.169.0), OpenCode 1.19.6 (from 1.19.5) and Kimi Code 2.6.3 (from 2.6.2); platform layouts are unchanged. The managed-runner image also moves to Claude Code 2.1.327 (from 2.1.326); Antigravity CLI 1.5.10 is current, and Cursor CLI is unchanged.
- **Also.** The Dependency audit job's 11 high findings all trace to picomatch GHSA-fc5q-39xc-vjpf, which every release up to 4.0.7 carries and no patched release fixes; `scripts/npm-audit-gate.mjs` now fails on every high or critical advisory except the dated entries in `scripts/npm-audit-allowlist.json` (one, picomatch, expiring 2026-12-18, as the account owner chose), with `test/npm-audit-gate.test.mjs` pinning those rules under `test:supply-chain`, and basic-ftp goes to 6.2.4 (dev). A second commit raises minimatch to 11.0.1 under `@nestjs/cli` for GHSA-g3hv-75wg-m249 (dev). Four pg specs are corrected on the test side for 1060's `condition_ended_with_task` trigger counts and for its task objects in the landing-observation frontier compare. An Android evidence test failure is fixed by keeping the tile thumbnail and viewer producers on `Dispatchers.Main.immediate`; on a device the effect dispatcher already resumes on main, so that was test-only. The session-handoff design and board, and the queued-row board, are docs only and not user-facing; the iPhone probe harness for the owner-card text rules is kept as a record only.

## Upgrade impact

- **Database migrations: two, both additive.** The diff of `src/apiserver/prisma/migrations/` between v0.1.261-beta.39 and this release adds `1070_owner_card_translation` and `1080_owner_card_translation_more`, 178 lines of SQL with no deletion or alteration of anything already there. **1070** adds a nullable JSONB `translation` column to `project_open_item` and to `owner_request`. **1080** adds a nullable JSONB `translation` column to `task_completion_evidence`, `task_owner_confirmation_review_record` and `project_handoff_approval`, and creates one new table, `project_criteria_change_translation`, holding one row per translated criteria proposal: `intent_id` (UUID, primary key), `owner_id` (UUID), a NOT NULL JSONB `translation`, `updated_at` (timestamptz(3), default `CURRENT_TIMESTAMP`), and a foreign key from `intent_id` to `project_ratified_action_intent(id)` with `ON DELETE CASCADE ON UPDATE CASCADE`. Every `ALTER` is `ADD COLUMN IF NOT EXISTS` with no default, which is a catalogue change and rewrites no table, and is wrapped in a `lock_timeout` retry loop — 2 s of lock timeout, 1 s apart, up to 60 tries — per table; the table is `CREATE TABLE IF NOT EXISTS`. Nothing is backfilled, no constraint, function or trigger is added to an existing table, and no row is inserted, updated or deleted. Both migrations are additive and neither is destructive; the apiserver applies them on boot, so no manual step is needed.
- **Server:** owner-card translation is an apiserver change, so the apiserver must be deployed from this commit or later for any of the translation features above. Until then it serves no `translation` field, and every client draws the original card, push and Feishu alert as written. The web client ships with the same deploy.
- **Runner:** this range changes no `src/runner-go` source, and the runner served at `/dl` is built from this tag. The managed-runner image and the apiserver image carry the newer engine versions named above; no runner capability or wire change is named by any commit, so a runner from an earlier tag keeps working.
- **Configuration:** no variable is added or changed, and `docker-compose.yml` is untouched. `scripts/npm-audit-allowlist.json` is CI tooling, not deployment configuration; the two-stage deploy change is operator tooling in `deploy/two-stage/deploy-stage.sh`, not a running service's configuration.
- **Clients:** macOS beta users get the DMG on the beta channel, TestFlight gets marketing version 0.1.261 with the build number as the commit count, and Android gets `android-update.json` from this tag. A client from this tag talking to a server older than this commit draws the original card text, since the translation is optional everywhere it is read. No minimum native client version above the previous release is set by this range.

## Security fixes

None in this release. Nothing in this range fixes a product security issue, and no advisory or CVE is named for a shipped component. The dependency-audit commits are tooling only: basic-ftp 6.2.4 and minimatch 11.0.1 are dev dependencies, `npm audit --omit=dev` finds nothing, and picomatch's advisory carries a dated CI exemption because no patched release exists.

## Known limitations

None known. The picomatch advisory (GHSA-fc5q-39xc-vjpf) is unpatched upstream and reaches only build and test tooling (vite, vitest, tinyglobby, `@nestjs/cli` via `@angular-devkit`); its CI exemption expires 2026-12-18 and it is part of no shipped artifact. A card filed while translation is on is translated in the background; a card read before that translation is stored is drawn as the agent wrote it — that read queues the translation (decision 1A) — so its first view can be the original.

## Rollback

The previous published tag is v0.1.261-beta.39, commit 61d26fa4486fb8fd32bf8d8c9b77882daf4f2acb (its tag object is 9d3db7b4420). Both migrations in this range are additive: 1070 adds nullable JSONB `translation` columns to `project_open_item` and `owner_request`, and 1080 adds them to `task_completion_evidence`, `task_owner_confirmation_review_record` and `project_handoff_approval` and creates `project_criteria_change_translation`. An application-only rollback to that tag is therefore schema-safe: the older server ignores the new columns and table, which stay in place unused, nothing needs undoing and no data is affected. Rolling back restores the older behaviour: every owner card, notification, push and Feishu alert is drawn or quoted as the agent wrote it, the owner's typed answers are delivered untranslated, and the iPhone owner cards draw the old layout. It also undoes beta.40's changes: notices name the tool call again and an owner request can be re-announced on each wake, Withdraw restores the translation instead of the reader's words, a full runner's row reads "Runner full", the "Orbit attached" line is drawn again, and an owner item whose coordinator is FAILED with no retry is hidden again. The clients from this tag would then talk to an older server, which serves no `translation`; every client change in this range draws the original when it is absent, so the cards fall back to the agent's words. See [Release process](../docs/release-process.md#rollback-decision-and-procedure).
