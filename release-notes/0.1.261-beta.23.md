# Orbit 0.1.261-beta.23

## Summary

- **Mac, iOS and Android: a machine with no workspace shows one card that makes its workspace.** The card reads
  "New workspace on <machine>" and asks two things: a folder name in the machine's home (used if it exists,
  created if it doesn't) and the workspace's name, which follows the folder's until you change it. Create
  workspace makes it and opens the new workspace's new-session page. This matches the web.
- The card no longer asks you to sign in a coding CLI, has no "Use This Folder" step, and no longer holds a first
  message under it that created the workspace on send. Signing in is asked by the new workspace's sessions, or done
  from the machine's page.
- Web: when the machine can't check a folder, the line under Folder now says why, instead of calling it a new
  folder.

## Upgrade impact

- **Database migrations.** None.
- **Runners.** No runner changes in this release. A machine still on a runner from before 0.1.261-beta.18 keeps
  `~/orbit-repos/` as the folder prefix until it updates itself.
- **Server.** No server changes: the card uses the existing `POST /workspaces` with a name and `workDir` or
  `newFolder`. The web fix ships with the next server deploy after this tag.
- **Configuration.** No changes required.
- **Clients.** Each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261, build
  number = commit count) and Android via `android-update.json` are offered it.

## Security fixes

None in this release.

## Known limitations

- A new workspace on a machine whose coding CLI isn't signed in shows the sign-in card only once its first session
  starts; there is no hint before the first message yet.
- Android's prompt-optimizer copy parity test fails on main (an iOS change dropped `OPTIMIZE_HELP` from
  `PromptOptimizer.swift`); it is a test-only mismatch and is not fixed in this release.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.23` and tag `v0.1.261-beta.23`. This tag publishes the macOS
DMG and Sparkle payload (beta channel), the iOS TestFlight build, the runner binaries, and
`orbit-android-0.1.261-beta.23.apk` with its `.sha256` and `android-update.json` on the same GitHub Release.
Before this tag the change was built and tested on a Mac (OrbitKit `swift build` and `swift test`, OrbitApp
`swift build`, iOS Simulator `xcodebuild`, with no compile errors; the setup-card tests passed, and the four OrbitKit
failures were the host's time-zone and quarantine-attribute ones, identical on the parent commit), on Android
(`compileDebugKotlin`, `compileDebugAndroidTestKotlin`, and the setup-card, first-workspace and copy-parity unit
tests) and on the web (typecheck and the setup-card suites).

## Rollback

rollback is schema-safe. A client rolled back shows the previous setup card (sign-in step and send-to-create) again.
