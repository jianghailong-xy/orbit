# Orbit 0.1.261-beta.24

## Summary

- **Workspaces from GitHub.** An administrator registers a GitHub App in Admin → Integrations → GitHub, and each
  user connects their GitHub account in Settings → Integrations. On a machine with no workspace, the "New workspace
  on <machine>" card then offers **From GitHub** under the folder and name fields on the web, Mac, iPhone and
  Android. Pick a repository (private ones included) and optionally another branch, and Create workspace clones it
  into `~/orbit-repos/<name>` before the first session starts. The conversation's first line shows the clone
  waiting, cloning with a percentage, created, or failed with Retry, Install on GitHub or Reconnect GitHub.
  Settings → GitHub lists your connection, installations and workspaces from GitHub.
- The clone, the runner's fetches and landing pushes sign in with a short-lived installation token scoped to that
  one repository. Orbit hands it only to the runner's own git commands, never to the agent's shell, the
  workspace's `.git/config`, a remote URL or a log.
- **The managed runner is Orbit Cloud** on the web, Mac, iPhone and Android, with a readable version line and no
  self-update card, and a managed runner no longer gets a Default workspace of its own.
- Schedules keep the read-back of the rule they were created with, and push notification collapse ids fit APNs's
  64-byte limit.

## Upgrade impact

- **Database migrations** (applied by the apiserver on boot):
  - `0820_github_app_connection`: new tables for the GitHub App setting and each account's connection. Additive.
  - `0920_workspace_clone_credential`: a nullable `workspace.clone_credential` column. Additive.
  - `0930_managed_runner_no_default_workspace`: `managed_runner.default_workspace_id` becomes nullable, and a
    managed runner's Default workspace that has never had a session, task or project membership is released and
    soft-deleted. Workspaces in use are kept.
  - `0950_schedule_read_back`: a nullable `schedule.read_back` column, backfilled from each schedule's approved
    create request.
- **Runners.** This tag's runner declares `clone-workdir/v1` and carries Orbit's GitHub credential path. From
  GitHub needs a machine on this runner or newer: an older runner is never asked to clone. Runners update
  themselves.
- **Configuration.** From GitHub stays hidden until an administrator registers a GitHub App (App ID, slug, client
  ID and secret, private key) in Admin → Integrations → GitHub. The App needs Contents read/write and Metadata
  read, and its user-authorization callback must point at this deployment's GitHub callback URL, which the admin
  page shows. Nothing else is required.
- **Clients.** Each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261, build
  number = commit count) and Android via `android-update.json` are offered it. From GitHub on a client needs the
  server deployed from this release or later: an older server hides it.

## Security fixes

None in this release. The new GitHub path is designed so the agent never sees a token. Installation tokens are
minted only for a workspace's own repository and only for the runner that owns the workspace, and a cloning or
failed workspace's sessions are not dispatched.

## Known limitations

- Clones go to `~/orbit-repos/<name>`, while new folders now go in the machine's home. Moving clones to home is a
  later change.
- From GitHub is offered only on the card of a machine with no workspace yet, not from Add workspace on a machine
  that already has one.
- On a phone, the picked line `owner/repo → ~/orbit-repos/<name>` is truncated in the middle.
- A clone on a real managed runner against production GitHub has not run yet. Clone, session and landing were
  walked end to end on a QA stack with a test GitHub App and a self-hosted runner.

landing push were walked on the QA stack against a real private repository.

## Rollback

Roll back to 0.1.261-beta.23 (830d3deb694b08c62f6e6e094b8549eea8cc07ee). The four migrations are additive or make a
column nullable, so an application-only rollback is schema-safe. Rolling back hides From GitHub. Workspaces already
cloned stay usable as ordinary folders, but their runner can no longer fetch or push through Orbit's GitHub App.
The unused Default workspaces that `0930` soft-deleted are not restored by a rollback. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
