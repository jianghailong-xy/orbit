# Orbit 0.1.261-beta.102

## Summary

Each added Codex account now carries its own rate-limit reset: a reset card per GPT account in Plan usage on web, a reset block and reset operation per account on the server, and a Go runner that reads, consumes and refreshes a reset in that account's own slot. The session list follows one shared contract on web, macOS, iOS and Android, and the server reaches deploy D3 of the `session.status` retirement.

- **Web: a reset credit card for each GPT account in Plan usage (ab0e894568, 5613f5ba2a).** The session's account comes first, then every other account with credits, each with its usage and the same card; confirmation, polling and the remembered `clientRequestId` are per runner and account, and the confirmation names the account. `GET /runners/:id/codex-rate-limit-reset` takes an optional `accountFingerprint` and answers that account's active and latest operation; without the parameter the answer is unchanged, for older clients.

- **Server, runner and contracts: a reset block and a reset operation per added Codex account (390072af38, ffd8b567a3, a995265715, c3d59627ec; migration 1669).** Contract v2 (§12) gives every added Codex slot its own `rateLimitReset` block, ordered on its own; the sanitizer keeps a well-formed block on each Codex accounts entry, and the heartbeat merge never lets an older read overwrite a newer one. A workspace or session on an added account is no longer refused `ACCOUNT_OVERRIDE`: the create route resolves the slot from the request, else the workspace's pick, else the slot whose stored block holds the confirmed fingerprint, and judges that slot's block. The Go runner reads, consumes and refreshes in that slot's `CODEX_HOME`, refuses a slot that is gone without a read anywhere, acts on version 2 commands, answers in the command's version and declares `codex-rate-limit-reset-v2`.

- **Web, macOS, iOS and Android: the session list follows one shared contract (d9d77a7b69, f8f3d82e2f, 41618af10a, b727487f42).** Rows are dated and ordered by `listedAt`, so a row no longer says "just now" under one saying "1h ago". A turn that parks `AWAITING_INPUT` now moves `listedAt` on the server, so a wake-up's or another session's new reply lifts its row. A tag filter drops only Pinned, Trash lists by `listedAt` with no pin, and a session whose background job or SubAgent is running is Working. Android had read Working from the legacy status, kept Needs you and Working nowhere under a tag filter, and ordered Trash and project entries by `lastTurnAt`; Android and Apple now place and order project timeline rows by `listedAt` too, as web's project page already did.

- **Server and clients: a session waiting on its armed retry is PENDING (175b82e2c0; migration 1670).** The owner ruled on 2026-11-26 that waiting for a retry is PENDING, replacing that day's earlier ruling (1667) that read a released one RUNNING. `deriveSessionPhase` and the stored phase read an armed retry with nothing executing as PENDING, waiting on WAKE; a held quota parked at `AWAITING_INPUT` read IDLE. Web, iOS and Android keep reading a retry's PENDING as parked or failed rather than a queued turn, and their guest views follow it at the waiting pace, since a quota reset can be hours out.

- **Web, macOS, iOS and Android: an answered crossing card says what happened (a3c9d464a9, 442e7dacfd, 6bd1268e68, 0d95eb9e7f).** An answered take-out card gets a past-tense heading and summary (the web summary no longer reads "1 task to take out of …"), drops the "Confirming…" line and the per-row state its receipt already gives, labels the quoted reason as the requesting agent's, says "Written by Orbit", and hugs its content instead of a fixed 760px sheet. Android had no take-out card at all — a move with no target read "Move this task here?" with Approve and Refuse — and now has the web's and iOS's question, route, buttons and consequence. A translated review keeps the batch's `inTarget`, and the web's copy-parity test now reads the project page's take-out wording with "as soon as you answer".

- **Web: a task opened from its session sits beside it as a column (50b35b78ad).** The owner chose option A on `docs/mocks/session-task-column`: Task › used to open the task over the conversation, hiding the reply and the header's controls. On a window wide enough for both it is now a 420px column that narrows the conversation; Task › toggles it, it and session settings close each other, and the task's run row names this conversation instead of linking to it.

- **Web: a phone's session header is one row (cf20f688d0, 2352324c08).** The phone header had a status line under the title (Follow, the run state, the time and the tag count) and, once the reader left the tail, a third row for the "back to your own question" capsule; it grew 42 pt on every scroll up. It is now the title's row alone, the capsule takes that row while it shows, and the title comes back at the tail — one row in both states, so nothing grows and nothing jumps. Follow… is a ⋯ item on every width, and the run state and time are in the session's settings. A revealed waiting card now comes to rest 16px below the scroller's top instead of 48, and below 600px the branch row drops the pending tag and the latest subject so the branch, count, stat and Commit stay whole.

- **Web: tables, tabs, checkboxes and switches take the menu style's frame (51d78dedb2, 2d8609234c, 87a36987f7, f0aec87241).** A table is now a card with a hairline edge and 12px corners all round, where it had only 8px top corners and no edge. Page tab bars are 12px with 10px tabs, the segmented control 10/8px (small 6/4px), the wiki review switcher 10/8px and the commits rail's tabs 8px. A checkbox's corners are 5px and a switch's knob takes a soft neutral shadow in place of the old green-tinted one; the partly-checked box's inner 8px square has 2px corners. Cells, header, hover, sizes and spacing are unchanged.

- **Web: tooltip group A is finished and group C's cut-off labels take the app Tooltip (7483cef977, 5a08c866c4, 87ec76dca0).** Group A's last 20 labelled buttons move to the app Tooltip, with a span for the three whose tip says why they are disabled and cut-off mode where the tip is the label; a new image-unavailable chip on main gets the same. Group C and earlier leftovers (about 80 sites) move to the Tooltip's cut-off mode, which opens only while the label or a child overflows, is 360px wide and can take a monospace font for paths and branches; tips that were not the label's own words became plain hints, and menu items' tips show beside the menu. The export-only file chip and Markdown link titles keep the browser's title.

- **Android: a reopened session catches up with one page (c9d12bb0de).** A following reader used to jump forward once per catch-up page (up to five, then a resync). `catchUp` now reads one page: a gap that fits lands in one publish, and a wider one re-seeds from the tail at once, so the window changes once. A failed read still leaves the retry to the stream.

- **Server: retrying a baseline fix's landing no longer answers 500 (11f9bbf184).** A task filed to fix an OPEN baseline item gets no held generation, so retrying that task's own baseline-red landing found no QUEUED row and `findFirstOrThrow` threw P2025. The baseline branch now queues the next generation itself when none is held, then closes the item RETRIED. A second press while the retry is in flight now answers 409 `INTEGRATION_RETRY_IN_FLIGHT` (checked before the owner-item check), not 403.

- **Server: the D3 step of the `session.status` retirement (f7d814b40c, db71fe1ffb, 3fe06733d3, d601a54729, 189e19ef2e, cbedca5f87, 0b6ffd740c, d2010a6691, 341d408fd4, 7f64600e0f, ea98d9ce85; migration 1671).** From this deploy no server code reads or writes `session.status`: the 25 writers write `turn_state`, `finished_at` and the facts beside them, and the field and the Prisma `RunStatus` leave the model. The column stays until D4, and migration 1671 keeps it equal to the word the facts give, for deploy-2 code alone should the release be rolled back; `scripts/session-status-from-facts-down.sql` is the migration's rollback. The PG suite writes facts and reads the word through the projector, and the trigger inventory now reads `CREATE OR REPLACE TRIGGER` and keeps the migration that installed a restated trigger as its `since`.

- **Docs and CI.** T17a's rehearsal of D2 to D3 alone is recorded on the HPC seeded copy (b0e8fb696b): 1671 took 21 ms with no lock wait during the hand-over, the censuses after D3, the rollback and the second forward found 0 disagreements, and the walk's claims, slots and dispatch matched D2's; it also records what the run could not show. Contract v2's §3, §8, §12, §12.4 and §12.6 and the refusal table are updated (c93b3646da, d32d6602ac, 76dd40fec5), and the release skill records that the Cloud runner prepull can take far longer than a minute (5bdcb54af2). The boards behind this range are in `docs/mocks`: the session-task column, the Main checkout bar's unpushed-commit list, the one-time browser-notification offer, a Task badge in the iOS and Android session bar, tooltip group C, and Plan usage's per-account reset card (8606e4a14f, c2884ab2dd, 928a924874, 3a7fcccb3d, 2b50bb4f4a, aaae1d6786, 5b7c95c288, 79f946398b). The API reference is regenerated for the Codex reset account query (36c7d880bc, 1adb2f8492), and main's reds on the web query census, the OrbitKit copy-parity tests and the Android `ShareDeliveryTest` are corrected (613fd52e12, 14508dadc4, 2b4172aef9). The task run sidebar and wiki run-failure designs are recorded (414ee1629d, 301ada3b8d, e8eee8c19f).

## Upgrade impact

- **Migrations:** three, applied by the apiserver on boot.
  - `1669_codex_reset_operation_account_slot` — **additive:** it adds `account_slot TEXT NOT NULL DEFAULT 'default'` to `codex_rate_limit_reset_operation` with a CHECK (`default` or an 8-hex slot) and restates the table's guard with `account_slot` among the immutable columns. A constant default is a catalog-only change in PostgreSQL 11+, so nothing is rewritten; every row written before this column existed is Default's, and an apiserver that predates it still writes Default's operations only. Re-runnable (`IF NOT EXISTS`, the constraint inside a `duplicate_object` guard, the function replaced in place).
  - `1670_session_phase_retry_pending` — **additive:** no DDL on `session`; it restates `session_phase_of` (the six-argument form) so an armed retry with nothing executing reads PENDING, then rewrites the `phase` of the armed rows whose value the new rule reads differently. It changes a derived column only, writes no user data and drops nothing; it takes row locks on the armed rows, and a second run finds nothing left.
  - `1671_session_status_from_facts` — **additive:** no row is written and no column is added or dropped. It adds the eight-argument `session_legacy_status` and a new `session_aa_status_from_facts` trigger that keeps the stored `status` equal to the word the facts give, restates the nine-argument form and `session_held_turn_state`, and adds `turn_state`/`finished_at` to the listed triggers' column lists. `status` stays in every list and in the table until D4. It drops only the trigger and function it replaces; `scripts/session-status-from-facts-down.sql` restores them. All trigger changes are in one `DO` block, one transaction, with the lock taken in 2 s tries, 1 s apart, up to 45.
- **Backfill:** not a separate step. 1670 and 1671 rewrite their derived columns inside the migration; 1669 writes no row.
- **Configuration:** none added or changed. Added-account Codex resets use the accounts and slots already configured on the runner; no new environment variable is recorded.
- **Server:** `GET /runners/:id/codex-rate-limit-reset` takes an optional `accountFingerprint` (without it the answer is unchanged); a workspace or session on an added Codex account is no longer refused `ACCOUNT_OVERRIDE`; the heartbeat dispatches v2 CONSUME/REFRESH naming the slot, one command per heartbeat. `listedAt` now moves on any turn that parks `AWAITING_INPUT`. Retrying a baseline fix's landing queues its next generation instead of answering 500, and a second in-flight retry answers 409. Deploy D3 no longer reads or writes `session.status`. No other route, field or payload changes shape or name.
- **Runners:** the runner served at `/dl` is built from this tag. This range changes the runner: it reads, consumes and refreshes Codex resets in each added slot, acts on version 2 commands and declares `codex-rate-limit-reset-v2` (c3d59627ec). A runner older than this release does not declare the capability, so added-account resets need a runner from this release or newer; a Default-account operation is unchanged.
- **Clients:** web arrives with the deploy of this commit; macOS (beta-channel DMG), iOS (TestFlight) and Android (APK) come from this tag. An older client than this release does not draw the per-account reset cards, keeps the old session-list order and row time, keeps the answered crossing card asking its question, and lacks the phone header, task column and the new table, tab, checkbox and switch corners.

## Security fixes

None in this release.

## Known limitations

- Added-account Codex resets need a runner from this release or newer; a runner older than this release does not declare `codex-rate-limit-reset-v2`, so the added-slot reset waits for a matching runner.
- Deploy D3 leaves `session.status` in the database until the D4 deploy drops it; D3 code neither reads nor writes it, and 1671 keeps it equal to the facts' word for a rollback to D2 code only.
- For the released kinds C1–C8 of the session-status plan, 1671 stores a word that differs from the one deploy 2 stored; the owner accepted this difference.

## Rollback

Previous tag v0.1.261-beta.101 (`c1e5e0b16ac27fc4568b7b894b8ad6078b610c8f`). Application-only rollback is **schema-safe for this release**:

- 1669 only adds a defaulted column with a guard that old code satisfies (it writes `default`); an older apiserver neither reads nor writes `account_slot`, so leave it in place.
- 1670 only restates `session_phase_of` and rewrites the derived `phase` of armed rows; an older apiserver reads that column and writes none of the facts it derives from differently. No commit in this range records a down script for it.
- 1671 rolls back to **D2 code only**, not to D1: D2 code reads only the facts and the projected word and writes both, so an application rollback to v0.1.261-beta.101 is free with the migration in place. `scripts/session-status-from-facts-down.sql` restores 1611's trigger, 1641's `session_held_turn_state`, 1621's nine-argument function and the nine trigger definitions without the added columns.

Client rollback is to v0.1.261-beta.101's DMG, TestFlight build and `orbit-android-0.1.261-beta.101.apk`; a beta.101 client keeps working against this release's server, since no payload it reads changes shape, and it lacks the new cards and copy.
