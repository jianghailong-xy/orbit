# Orbit 0.1.261-beta.57

## Summary

This release **opens the Feishu bot to the people the app is available to**: the owner chooses Only you (the
default, as before) or everyone Feishu makes the app available to, and a direct message or group mention from
someone in that scope starts a session in the owner's open workspace, under per-person and total limits. **Set as
default for Claude Code accounts** arrives on every client: an added account's ⋯ menu swaps its login with the one
in `~/.claude` on the machine, with the waiting line, the rollback and the machine's reason when it fails. **A
session's worktree bar now counts the branch's commits** instead of files, with a commit drawer behind it, and the
composer band gains a **Background row** drawn by one shared rule on web, macOS/iOS and Android. **Settings ›
General sets how many tasks a session may file without a card** (8 when the account never set it, 0 to 50). Two
fixes an operator will notice: **an open item's Files and Declared rows fold to five paths** with "Show N more",
and **a session's changed-file base is measured against the branch it merges into**, so main merges taken into a
project line no longer count as the task's undeclared files. Seven migration files change — five new, two
renumbered — every one additive.

## Upgrade impact

- **Database migrations: seven files, five new and two renumbered, all additive.** None drops a column or table,
  none rewrites a row, and every statement can run twice.
  - `1000_claude_account_swap` adds six columns to `runner` (five nullable, `claude_account_swap_waiting` a
    `UUID[]` defaulting to `{}`); its header states an older apiserver neither reads nor writes them.
  - `1120_evidence_send_back_translation` adds two nullable `TEXT` columns to `task_evidence_decision`.
  - `1140_feishu_open_access` adds seven columns to `feishu_app` (one with a foreign key to `workspace`, SET
    NULL, plus three CHECKs), four to `feishu_chat_route` (with two CHECKs added or widened), and one to
    `feishu_thread` with a partial index. Column adds are catalog-only; each constraint is added NOT VALID and
    then validated, which scans a small table and writes nothing.
  - `1150_feishu_show_orbit` adds `feishu_app.show_orbit`, `BOOLEAN NOT NULL DEFAULT true`.
  - `1213_session_branch_commits` adds nullable `session.branch_commits` (`JSONB`), null until a runner that
    reads commits reports.
  - `0511_project_done_task_epochs` and `0512_open_list_renewal_not_a_change` are **renumbered, not new**: the
    two files beta.56 carried under the opposite numbers (`0512_project_done_task_epochs`,
    `0511_open_list_renewal_not_a_change`) now hold unique numbers. The first adds nullable
    `project.done_task_epochs` with an `IF NOT EXISTS` guard and writes no row; the second only replaces the
    `open_list_bump_owner` function with `CREATE OR REPLACE`, so no table is locked. Each file's header says an
    environment that applied it under the earlier number replays it safely, so an instance upgraded from
    beta.56 applies both again as no-ops.
  - The apiserver applies all of them on boot, in order, in one Prisma transaction per migration; no
    `CONCURRENTLY` is used.
- **Configuration: none.** `docker-compose.yml` and the environment files do not change in this range, no new
  `ORBIT_*` variable is read, and no setting must be filled in before the upgrade.
- **Runner:** `src/runner-go/` changes in this range are the changed-file base (`7b6e305259`), the
  `claude-account-swap/v1` implementation and its macOS process scan and Keychain writes (`f9cdab7590`,
  `65d27d5c17`, `ffe4402a9d`), the `branchCommits` report and the Orbit-Saved trailer (`455945cff9`), and primer
  1.4.3 (`90454daed6`). **The runner served at `/dl` is built from this tag**, so a runner fetched from it
  declares `claude-account-swap/v1` and the Set as default menu is offered on its accounts; an older runner keeps
  its accounts without the menu item, and a runner without the commits report keeps the file bar. No
  managed-runner image or engine version changes in this range.
- **Server:** the Feishu open mode and Show Orbit switch, the Claude account swap's endpoint, relay and record
  moves, the session commit list, the background list's `job` kind and `endedAt`, and the card-free create
  preference are apiserver changes; each reaches an instance only when it is upgraded from this source — tagging
  does not deploy the server. The web changes (the Feishu settings cards, Settings › General's new row, the commit
  bar and drawer, the Background row, the calmer open-item cards, the Workflow card) reach browser users when the
  deployment's web is rebuilt from this source.
- **Clients:** macOS beta users get the DMG and Sparkle appcast from this tag on the beta channel, with the app
  and its release files still named Orbitd as in beta.56; TestFlight gets marketing version 0.1.261, with the
  build number as the commit count; Android gets `versionName` 0.1.261-beta.57 and `android-update.json` from this
  tag. No one-time step is required on a Mac, iPhone or Android device, and no account, workspace or Feishu app
  has to be reconfigured — an app that never opened the bot reads OWNER_ONLY and Show Orbit on, as before.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE, and the root
`package.json` and `package-lock.json` do not change in this range at all — the release commit writes only their
version lines. The Feishu availability check (`6263885a9e`) and the Keychain write fix (`ffe4402a9d`) change
access control and credential handling; their commits record them as a feature and a correctness fix, not as
security fixes.

## Known limitations

- **Only web gets the calmer open-item cards.** `a6949223eb` keeps the literals OrbitKit's parity tests pin
  exported until the native cards follow, so macOS/iOS and Android still draw the previous card.
- **An older runner keeps the file bar.** `455945cff9`: a runner that reports no `branchCommits` leaves the
  session on the previous "+/− files" bar.
- **A commit's file diff is the file's whole change on the branch.** Patches are per branch, so the drawer's
  All-changes view of one commit is not a per-commit patch; the commit says the drawer says so when that differs.
- **Feishu open mode answers some requests with one sentence and writes nothing.** External groups, switched-off
  implicit routes, requests over a limit, and every sender outside the app's availability scope get that answer;
  over a limit the bot also writes only the inbox and one activity row (`880ba6cb22`, `0d3828ad50`).
- **A group session on a model that cannot run Auto opens in Default.** The confirm page preselects Auto, and
  dispatch narrows it when the model cannot run Auto (`3b7aa1eabf`); the commit names no other fallback.

## Rollback

The previous tag is v0.1.261-beta.56, commit `702b423c0c18c8593f6e714bbcebddcf74748c49` (its tag object is
`c260663d9f73525dbf64a911b32c8ed903d9ddf3`), tagged on 2026-11-19 (UTC). Rolling back removes the Feishu open mode
and its settings card (the bot returns to Only you), the Show Orbit switch, the Claude account swap on every
client and the runner, the former-Default email naming, the commit bar (the worktree bar counts files again), the
Background row, Settings › General's card-free-task row (creates are carded as before), the calmer open-item
cards and the five-path fold, the Workflow card, Android's new-session hero and focus behaviour, and the
changed-file base fix — a runner from beta.56 counts a project line's main merges as the task's undeclared files
again.

An application-only rollback to beta.56 is schema-safe. Every migration this release applies is additive: nullable
columns, constant-default columns, indexes, and a function replaced in place; none drops or rewrites a row, and
beta.56 neither reads nor needs them, so they may stay. The two renumbered files replay safely under either
number, and the card-free create and Feishu settings are values in existing tables' columns. No backup or restore
step is needed. See [Release process](../docs/release-process.md#rollback-decision-and-procedure).
