# Orbit 0.1.261-beta.35

## Summary

Guests and public-link viewers now follow a session live over a server-sent-events stream instead of polling every
4 s (30 s while the session waits), so they see the agent's reply as it is typed, as the owner does. Polling stays as
the fallback. A guest's own message also shows the moment they press send, on web, macOS/iOS and Android.

- **Viewer streams.** Three new routes: `GET /api/guest-sessions/:id/stream` for a signed-in guest, and
  `GET /api/shared/:token/stream` and `GET /api/shared/:token/sessions/:sessionId/stream` for a public link.
  Each is a projection of the owner's live source. Durable events pass the same predicate as the paged reads.
  Live-only events come from an allow-list: text and thinking deltas, plus tool output only when the link includes it.
  Approvals, the queue, translations, task progress and tombstones never reach a viewer. Status changes arrive as
  `head` frames (title, status, activity and, for a guest, whether the session waits on the owner).
- **Access ends at once.** Removing a guest, a guest leaving, revoking a link, a link expiring or no longer
  including the session, or moving the session to the Trash ends an open stream with a `gone` frame. A permission
  recheck at every ~20 s ping catches a missed signal.
- **Anonymous caps.** At most 4 streams per IP and link, 200 per link and 2000 per apiserver
  (`VIEWER_STREAMS_MAX`). A stream over a cap is refused 429, and the page falls back to polling.
- **Clients.** The web public page (including sessions inside project and task links) and guest page, the OrbitKit
  guest view shared by macOS and iOS, and the Android guest view open the stream. They reconnect from the last
  sequence, close it while hidden or in the background, and poll when the stream is unavailable.
- **Draw on send.** A guest's message is drawn as soon as it is sent, instead of when the next poll brings its
  echo back (up to 4 s later).
- Also: a SubAgent `delegate` call may name a workspace of another repository.

## Upgrade impact

- **Database migrations:** none. The diff between v0.1.261-beta.34 and this tag under
  `src/apiserver/prisma/migrations/` is empty.
- **Configuration:** optional `VIEWER_STREAMS_MAX` (default 2000) caps viewer streams per apiserver.
- **Server:** the apiserver serves the new stream routes. Deployments with several apiservers get new gateway
  locations in `gateway/several-apiservers/` that route the guest stream by session and the public streams by link.
  Production already runs this commit (6b6dec729, deployed 2026-11-17).
- **Runner:** one small change in `src/runner-go/subagent.go` (the cross-repository `delegate`).
- **Clients:** web from the deployment; macOS beta users, TestFlight (marketing version 0.1.261, build number =
  commit count) and Android via `android-update.json` from this tag. An older client keeps polling, and a new client
  against a server without the routes gets a 404 and polls.

## Security fixes

None in this release. The viewer projection is built so that a stream never carries more than the matching paged
read: one predicate for durable events, and an allow-list for live-only ones, so a new live event type stays out
of viewer streams until it is added on purpose.

## Known limitations

- Anonymous viewers over a cap (4 per IP and link, 200 per link, 2000 per apiserver) follow by polling, at the
  old 4 s / 30 s cadence.
- Public links open only in a browser; the native clients have the guest view only.
- The limitations v0.1.261-beta.33 named still stand: help is web-only on all clients, and Ask runs on Claude
  only, on a machine whose runner declares `help-ask/v1`.

## Artifacts and verification

The tag is v0.1.261-beta.35, and this file is in the release commit's tree. The release publishes the macOS DMG
and Sparkle appcast (beta channel), an iOS TestFlight build and the Android APK with its `.sha256` and
`android-update.json` on the same GitHub Release, all from this tag.

The project branch's merge into main passed the merge check: build, shared and apiserver unit suites, the full web
suite (615 files, 8,416 tests) and `go test ./...` in `src/runner-go`. Postgres specs cover the stream projection
against the paged reads and the end of a stream for each way access ends. An end-to-end drill ran a real runner,
two apiservers behind the gateway and Chromium pages, 25 replies each. From runner write to on-screen text, the p95
was 126 ms for both the guest and the public page, against 27 s on polling. A removed guest's page ended in 21 ms
and a revoked link's in 20 ms, and a fifth page over the cap fell back to polling. OrbitKit tests ran in
`swift:6.1`, Android `:core:test` passed, and a `client.yml` run compiled OrbitApp for macOS and iOS.

## Rollback

The previous tag is v0.1.261-beta.34, commit aaa5f1dce. This release adds no migration, so an application-only
rollback to v0.1.261-beta.34 is schema-safe. Rolling the server back removes the stream routes, and clients then
get a 404 and poll as before. Rolling the clients back restores polling and drawing a guest's message on its echo.
See [Release process](../docs/release-process.md#rollback-decision-and-procedure).
