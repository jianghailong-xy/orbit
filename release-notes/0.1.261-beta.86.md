# Orbit 0.1.261-beta.86

## Summary

- **Agents stop applying `file_upload`'s 25 MiB cap to Orbit Files.** An agent that read `file_upload`'s 25 MiB limit applied it to the drive as well and skipped larger files. The drive was never capped: `drive_put` sends a file in 8 MiB chunks and the server sets no total size. Its MCP tool description and `orbit drive put --help` now say so, so an agent copies a large file to the drive instead of giving up on it. The transfer itself is unchanged; only the two texts an agent reads are. The generated `docs/operation-catalog.md` was re-rendered, so its content hash changed.

- **Android session-list tests match the order key.** The Android unit-test fixtures for the session list now carry `listedAt`, the field the Open list and a row's time read since 11-23 (falling back to `createdAt`); the tests had set only `lastTurnAt`, so both failed in any time zone and at any hour, not only when the local date was ahead of UTC. New cases fix the clock and the zone and cover the day sections and the row time in Asia/Shanghai and UTC. This is test-only: the Android app itself is unchanged.

## Upgrade impact

- **Migrations:** none. No migration is added or changed in this release.
- **Server:** no change.
- **Runners:** only `drive_put`'s MCP description and `orbit drive put --help` change. A self-hosted runner gets them by updating to the runner served at `/dl`, which is built from this tag. Orbit Cloud runners get them from the `orbit-cloud-runner:0.1.261-beta.86` image, which is built from this tag. Until a runner is updated, its agents keep reading the old text and may still apply the 25 MiB cap to the drive.
- **Clients:** no client step is needed. The web, macOS, iOS and Android builds change only in their version; the Android change is test-only.

The Orbit Cloud runner image is published from this tag on the build host.

None of the three commits in this release records a check being run: the runner change edits two description strings, and the two Android commits are test changes whose messages describe the defect they fix but record no test result.

No release build had run when these notes were written.

## Rollback

Previous tag v0.1.261-beta.85 (`a7a68fa7a1`). No schema change, so rolling back the application is schema-safe. Clients roll back by installing beta.85's builds. A deploy of a commit before this tag points Orbit Cloud runners back at the beta.85 image, and each moves to it once idle.
