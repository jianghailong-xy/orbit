# Orbit 0.1.261-beta.94

## Summary

Documents reaches the iPhone, the iPad and Android; an agent refused on a settled project can now ask its owner to reopen it; and the web session header gets a fixed-height menu with a searchable Tags level. Operators will also notice readable project branch names and, for OpenAI-compatible provider keys that only serve `POST /chat/completions`, Claude Code as a runnable engine.

- **iOS: the Documents pages.** The iPhone (and the iPad's column) gains a Documents row under the Wiki, shown unless the server turns it off, per board `docs/mocks/documents/01-ios.html`: pages on the section's stack for folders, a file's preview with who last wrote it and its earlier versions, the Move sheet, the share-link sheet with the secret warning, Trash and Storage, uploads from Files and Photos (files and folders, staged so they resume) with a background task, Download through the share sheet, the uploads sheet with agent syncs, the composer's From Documents picker and reply links drawn as the drive file. Follow-up commits put Trash's empty state in the content rather than an overlay on an emptied scroll, count a deleted folder in its group's row, give the list rows one unconditional `ForEach` each, read the writer label from the main-actor model, and drop container identifiers that would have overwritten their rows' for UI tests. OrbitKit holds the phone's Documents wording, the drawer row, the picker path and the `orbit-document:` link.

- **Android: Documents.** Per board `docs/mocks/documents/04-android.html`: a drawer row after Wiki gated on `documents.enabled`, folders with who last wrote each file, picture and Markdown previews, upload of files, photos and folders through the system pickers with one ongoing WorkManager notification (Pause, Show), download, Send a copy, rename, move, new folder, Move to Trash with Undo, the share link with the secret warning, Trash, Storage, the uploads sheet with agents' syncs and their details, and From Documents in the composer. `:core` gains ports of OrbitKit's Documents models, `DocumentsLogic` and `DocumentsUploads`, with the Android board's own copy, and an `ApiRequest` can carry headers (chunk sha256, Range) and a longer call timeout for 8 MiB chunks. Follow-up commits make a failed sync's row open its details, leave empty weeks out of Storage, make the device journey walk into Datasets before moving into its new folder, and make the syncs poll wait on wall-clock time so sheets open fully expanded.

- **Server, web, macOS and Android: agents ask the owner to reopen a settled project (`PROJECT_REOPEN`).** A session whose write is refused on a DONE or CANCELLED project could only say so in prose. `POST /runner/projects/:id/reopen-requests` now files one `PROJECT_REOPEN` owner request per project, and later askers join it; `POST /owner-requests/:id/reopen-project` is the owner's Reopen press, the project page's press and a delete settle waiting cards, and the four settled-project refusals name `project_request_reopen` (design `docs/project-reopen-request-design.md` §4, §7, §8; migration 1573). Web, macOS and Android draw it as an owner-request card — title, DONE/Cancelled since with a project link, the agent's reason, Planned work, Reopen / Chat about this — which folds to one line once answered and shows as one row on the project page whose Review opens the same card. On Android the two buttons are full-width as on iOS, a row that arrives above the header no longer leaves the page scrolled past it, and an unknown kind no longer falls to the generic card whose Confirm posted `/done` and settled the request without reopening anything. A board is in `docs/mocks/project-reopen-request`.

- **Runner: `project_request_reopen`.** The new tool, and `orbit project request-reopen` on the CLI, posts to `/runner/projects/:id/reopen-requests` as the calling session; it is in the operation catalog, its doc and the regenerated agent tools guide, and the project-tool and capability tables count it.

- **Web: the session header and ⋯ menu.** The tag library no longer sits inline in the ⋯ menu, where with ~40 tags Complete, Share and Delete fell off screen. The menu now leads with the lifecycle move and keeps 13 rows; tags move to a searchable level with Create, the session's tags show in the header, a failed agent-tools connection shows by the title, and a new session's subtitle no longer repeats its title. A board is in `docs/mocks/session-header-menu`.

- **Server: auto-tagging only picks tags the owner already has.** Every auto-tagged session used to mint the tags it lacked, so the library grew to dozens of one-off labels; only a person (or an agent they ask) adds tags now.

- **Server and clients: readable project branch names.** The default project branch was `refs/heads/project/<22-char public id>`. It is now built from the project title (lowercase ASCII words, capped at 40 characters on a word boundary) plus the first 8 characters of the id, or the 8 characters alone when the title has no ASCII word, and an accented letter keeps its base letter (`Ünïcode Café v2` → `project/unicode-cafe-v2-<id>`). A binding that already stores an `integrationRef` keeps it, and promotion's landing title reads the stored ref instead of rebuilding one. The server now says the default itself — `defaultProjectBranch` in integration settings and `defaultProjectBranchName` on every read of a start request — and web, macOS and Android read it, keeping `project/<id>` only for an older server.

- **Server: a done request is refused while task landings are deferred.** The same P-M1 predicate as the settled-project and promotion guards now also refuses a project done request when a DONE task's landing waits for its work session to finish, naming the affected tasks (`DONE_LANDING_DEFERRED`); web, macOS and Android draw the finding as "Landings waiting for work sessions to finish: {n}".

- **Server: Claude Code on OpenAI-compatible keys through Chat Completions.** Many third-party gateways serve only `POST /chat/completions`, so such a key could never run Claude Code. The anthropic gateway now routes that key's turns to `{baseUrl}/chat/completions` through a request/stream converter, with the same tokens, host rule, failure table and usage records as the Responses path, and the engine table offers Claude Code for it when the gateway may call its endpoint. A refused compatible key's log line now names the endpoint rather than OpenAI. Design `docs/claude-engine-openai-gateway-design.md` §10 records the routing, both mappings and what Chat Completions cannot carry.

- **Runner: an Antigravity sign-in says why it failed, and its page stays open.** A Google sign-in that agy accepted but whose `/usage` check failed was reported as "could not be verified by /usage" with agy's own reason dropped (for example an account whose region Antigravity does not serve), and one 10 s probe decided it; the reason now reaches the owner and the runner log, and `/usage` is asked again for up to a minute (30 s per try). On an Orbit Cloud runner, three failed sign-ins left their tabs open but the browser stopped 25 minutes later for being idle and came back with no tabs, so the page saying what went wrong was gone; a failed sign-in now holds the browser until the owner closes its tab, a later engine sign-in succeeds, or the browser stops anyway.

- **Orbit Cloud runners: Google sign-ins in the runner's browser survive restarts.** Debian's Chromium cannot complete its browser-level Google sign-in, and while it was on, Google signed out the web login at the browser's next start. The runner image now turns it off with a managed policy (`BrowserSignin=0`) for every runner and every new profile, including one made by Clear saved logins.

- **Runner: worktrees.** Both reclaim paths now recognize detached reads of published history through a named ref while retaining checkouts that hold recoverable work, and a finalizing session reports its branch and identifies a detached HEAD on the wire, keeping off-branch commits reachable and protecting their checkout from reclamation so an ended session can recover its edits.

- **Web: the conversation's cards.** The settlement (project start) receipt and the answered criteria-decision receipt now stop at the conversation's 720px card width like every other card. The transfer card says Documents rather than Files, and a path the agent wrote as `~/Documents/a` or `/home/orbit/Documents/a` is read as the drive's `/a` as the runner and the Documents page read it. A `documents_sync` call's `syncId` is read from the runner's receipt under `entity`, where the card had not looked, so the call is drawn as its sync's card again.

## Upgrade impact

- **Migrations:** one, `1573_owner_request_project_reopen`. It is **additive**: it restates `owner_request`'s kind CHECK with `PROJECT_REOPEN` added, restates the payload CHECK under the neutral name `owner_request_payload_chk` so it admits `SETTINGS_CHANGE` and `PROJECT_REOPEN` alike, adds a CHECK that a `PROJECT_REOPEN` names its project, and creates a partial unique index `owner_request_project_reopen_pending_key` on `("project_id") WHERE "kind" = 'PROJECT_REOPEN' AND "state" = 'PENDING'`. Two constraint swaps, one CHECK and one partial unique index over no rows: every stored row passes, no row is written, no trigger or function is named, and every statement can run twice. It is applied by the apiserver on boot.
- **Configuration:** no new or changed environment variable is recorded in this release. Documents on the phone and on Android follows the existing `documents.enabled` capability.
- **Server:** nothing beyond the new apiserver and its migration. There is no backfill and no one-time database step.
- **Runners:** the runner served at `/dl` is built from this tag. It adds `project_request_reopen`, the Antigravity sign-in reason and `/usage` retry, the browser hold for a failed sign-in's open tab, and the worktree reclaim and finalize changes. A runner older than this release keeps working against the new server, but it has no `project_request_reopen` tool, so an agent refused on a settled project can only report the refusal in prose, and it keeps the old sign-in messages. Orbit Cloud runners get the change from the `orbit-cloud-runner:0.1.261-beta.94` image, built from this tag.
- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. macOS takes the reopen card, the readable project branch names and the done-request finding; iOS takes the Documents pages; Android takes Documents, the reopen card, the readable project branch names and the done-request finding. No one-time step on a Mac, iPhone or Android device.

## Security fixes

None in this release.

## Known limitations

- The reopen request needs this release's runner: a runner from before it has no `project_request_reopen` tool, so an agent refused on a settled project can only say so in prose.
- The `PROJECT_REOPEN` card is drawn on web, macOS and Android. The iPhone's OrbitKit decodes the kind and sends the Reopen press, but no phone view draws an owner-request card in this release.

## Rollback

Previous tag v0.1.261-beta.93 (`493da80958`). Application-only rollback is **schema-safe**: migration 1573 only admits a new `owner_request` kind, widens the payload CHECK and adds a partial unique index, so the previous release's queries and writes still pass its constraints and there is nothing to undo. Any `PROJECT_REOPEN` request still PENDING at rollback stays in `owner_request`; the previous release has no card for that kind, so it is not drawn and cannot be answered until a release that has it runs again. The rollback path itself had not been exercised when these notes were written.

Client rollback is to the last published builds, v0.1.261-beta.93's DMG, TestFlight build and `orbit-android-0.1.261-beta.93.apk`; an iPhone or Android phone from v0.1.261-beta.93 has no Documents screen, and no client from it draws the `PROJECT_REOPEN` card.
