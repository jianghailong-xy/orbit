# Orbit 0.1.261-beta.80

## Summary

**Run now admits a message past a full runner.** When a message waits because the runner, a run or a batch holds
every slot, its owner can press Run now: the session's oldest queued turn gets a pass and the claim takes it past all
three slot gates while turns plus job-held slots stay under Max Concurrent plus the runner's new Extra sessions on
demand (default 2). The runner never stops a running turn to make room — it waits for an idle engine to be evicted
(`e4d349c0cf`, `f2183db509`). The runner advertises this to the server, which shows Run now only for runners that
declare over-capacity/v1; the web shows the server's refusal beside the disabled action and marks the overflow turn in
the transcript (`d70b033d8f`), and runner settings let the owner edit that allowance, including zero to turn Run now
off (`e9c7fc2d09`).

**Orbit Files arrives, with the web Files page.** The account's drive gets its owner page under Wiki — folder tree,
list with who last wrote each file, preview, resumable upload, download, rename/move, grouped Trash with per-item
restore, earlier versions, and one-file share links that scan the file for credentials — and Storage moves into Files
with the drive's bytes counted once (`45878216e0`, `2645cae173`, `137eb9a652`, `5f3087ec2f`, `34cb70618b`,
`6e945e1d1a`, `55b52cfcf4`).

**The drive is new on the server and the runner too.** The name layer (entries, versions, Trash groups, commits, change
feed), a runner drive door, resumable upload and ranged download, `DRIVE_FILE` share links, a `files` token scope, a
one-item Trash restore and a signed download URL (`a583d50525`, `b070830559`, `ee4adeb57c`, `8f9894ff55`, `b2cd7e7ee5`,
`5f3087ec2f`). Agents reach the drive through `drive_put`/`get`/`list`/`move`/`delete` and `orbit drive put|get|ls|mv|rm`
on every runner (`96f9bb5e40`); on Orbit Cloud the drive is a FUSE mount at `/run/orbit-files` behind a new CSI node
plugin, and `~/Files` links to it (`cfa00c7bcb`, `90f56f33b9`, `a440a82633`, `03446cc8b9`). Files gains orphan and
byte verification with a weekly report-only scrub, and the backup sidecar can mirror the bucket off-host (`496e75a8c8`,
`834b4cc5a1`).

**Fixes:** Codex Auto on an Orbit Cloud runner runs with its sandbox off where bwrap cannot start (`unshare` is
refused), with a truthful transcript notice and permission semantics that say so (`c5b295407f`, `ecc210a093`); a
managed runner's sleep drains only on an idle report sent after the request (`3754a9e64a`); and the drive mount no
longer treats a slow answer as an outage, nor mounts a new daemon after the dead one instead of over it (`4be3af14ac`,
`620e20aa23`, `aae782c316`).

**Native clients:** iOS, iPadOS, macOS and Android skip share-link rows of a kind they cannot draw, so a `DRIVE_FILE`
share link (created on the web) never fails or pollutes Shared links, and `orbit-drive:` links stay plain text
(`d53e7596db`).

## Upgrade impact

- **Database migrations:** eleven since beta.79, all additive — none drops a table or column or rewrites existing rows.
  `1283_drive_chunk_store` adds the drive staging, staging-chunk and version-chunk tables; `1327_drive_name_layer`
  adds `drive_entry`, `drive_version`, `drive_trash_group`, `drive_commit` and `drive_change` with their foreign keys;
  `1339_drive_mount_credential` adds `drive_mount_credential`; `1340_share_link_drive_file` adds nullable
  `drive_entry_id` and `drive_version_id` to `share_link` and widens `share_link_one_root_chk` to allow a drive root;
  `1438_drive_removed_entry` adds `drive_removed_entry`; `1439_drive_entry_name_trgm` adds a partial `pg_trgm` index
  on `drive_entry.name`; `1440_drive_trash_group_marking` adds `drive_trash_group.marking`; `1448_drive_purge_fk_indexes`
  adds three foreign-key indexes; `1450_session_codex_sandbox_unavailable` adds `session.codex_sandbox_unavailable`
  (default false); `1455_managed_runner_sleep_requested_at` adds nullable `managed_runner.sleep_requested_at`; and
  `1465_session_run_now_over_capacity` adds `runner.burst_concurrent` (default 2) and `session.over_capacity_turn_id`.
- **Configuration:** none required. Operators who want the bucket mirror set `ORBIT_FILES_S3_MIRROR=1`
  (`902637b866`). A managed-runner cluster gains the Files drive only when its profile's optional files section names
  the `orbit-files-mount` CSI plugin and `deploy/managed-runner/files-csi` is installed (`a440a82633`, `90f56f33b9`).
- **Runner** (`src/runner-go`): changed in this release. It leads with Run now: the runner now admits a turn its owner
  started over the machine's limit with Run now, up to the runner's "Extra sessions on demand" (default 2), and never
  stops a running turn to make room; it advertises this to the server, which shows Run now only for runners on this
  version or later (migration `1465_session_run_now_over_capacity` adds `runner.burst_concurrent` and
  `session.over_capacity_turn_id`, additive). It also gains the drive tools and `orbit drive` CLI, the `~/Files` symlink
  where `/run/orbit-files` is mounted, Plan-mode drive-write refusal, the Codex sandbox probe on Orbit Cloud, and the
  sleep hold on unflushed drive writes (`96f9bb5e40`, `03446cc8b9`, `01dacb1281`, `c5b295407f`, `05bde1bd55`). The
  runner binaries served at `/dl` are built from this tag.
- **Clients:** the only native-client change in this range is the share-link row skip (`d53e7596db`); the Files owner
  page ships on the web. macOS (beta channel), iOS (TestFlight) and Android get that fix, Android `versionName`
  `0.1.261-beta.80`.

## Security fixes

None in this release. The new Files surface is gated rather than a fixed issue: a token reaches `/drive/*` only with
the explicit `files` scope, terminal credentials are refused the owner's drive routes, a drive path in an evidence
citation is refused, and a shared file is scanned for credentials with the owner shown a warning (`b2cd7e7ee5`,
`842c3978a2`, `b070830559`, `8f9894ff55`).

## Known limitations

- The Files drive's mount and the `~/Files` link are for Orbit Cloud (managed) runners whose cluster runs the
  `files.orbit.dev` CSI plugin; on a self-registered runner an agent reaches the drive through the `drive_*` tools and
  `orbit drive` CLI instead (`cfa00c7bcb`, `90f56f33b9`, `03446cc8b9`, `96f9bb5e40`).
- A drive file cannot be executable by group or others, writable by them, or setuid; `cp -p`, `rsync -a` and
  `install -m755` of an executable copy its bytes and then fail, and a file created executable is kept `0644` (GNU tar
  never chmods what it extracts) (`fdf7c67fd8`, `84dd4f1b33`).
- Run now is refused at the door for a runner that is offline, updating, Keep Free, cloning or under a worktree fence,
  and appears only for a runner that declares over-capacity/v1 (`e4d349c0cf`).

## Rollback

The previous tag is v0.1.261-beta.79 (source `1b949f21d8aa2d972d8a7977d6bbe794989c42c4`). Every migration this release
adds is additive — new tables, new nullable or defaulted columns, new indexes, and a widened `share_link_one_root_chk`
— and none drops a table or column or rewrites existing rows, so rolling the apiserver back to beta.79's code is safe
without reverting the schema; the older code leaves the new tables and columns unused. Client rollback means
installing beta.79's builds, which lose the share-link row skip. The Files page is web-only and served by the
apiserver, so an apiserver rollback past this release removes it.
