# Orbit 0.1.257

## Summary

The first stable release under the single-version rule: the version in the root `package.json` is the
version of record, the tag is that version with `v`, and the GitHub Release, macOS and Android artifacts,
TestFlight build, runner binaries, `/dl/version.json`, Sparkle appcast and `android-update.json` all name it.
It replaces the untagged `0.1.257-beta.1` that `/dl` served briefly, and carries everything merged since the
previous tag `v0.1.2-beta.246` (package 0.1.256): the main checkout's Commit, Push, Move to worktree and Save
& clean; forked tasks (`--fork-from-session`); sessions with no worktree; a faster startup reclaim; and
fixes across the runner, web and clients.

It also fixes the model shown on a machine whose Claude Code is signed out. The runner no longer drops its
Claude or Codex model list (and its last good one) when a probe fails while signed out: the failure is logged
and the last list kept, and a signed-out Claude's fast-lane answer is reported as unknown rather than "none".
Web, macOS/iOS and Android name a Claude model the runner's list has no row for the way Claude Code does
("Opus 5.5", not `claude-opus-5-5`); Android's model chip now shows the list's name on every engine.

## Upgrade impact

- **Runners update themselves.** `0.1.257` orders above `0.1.256` for every runner, old ones included, so
  runners self-update from `/dl` as usual (a busy runner waits until it is idle). The one-time reinstall the
  `0.1.257-beta.1` notes asked for is not needed for this release. A runner that did take `0.1.257-beta.1`
  also moves to `0.1.257`.
- **Six additive database migrations** since `v0.1.2-beta.246`, applied by the apiserver on boot:
  `0534_main_checkout_request`, `0615_task_session_fork`, `0616_task_session_fork_checks`,
  `0617_task_fork_changed_files`, `0618_email_outbox_session_invite` and
  `0641_open_list_epoch_session_waits`. They add a table, nullable or defaulted columns, indexes, widened
  checks and triggers; none drops a column or rewrites existing rows.
- **Deployment.** No configuration changes are required. Two-stage deployments (build on one host, pull and
  bring up on another) are new under `deploy/two-stage/`; this release's gateway configuration gains the
  handover include, so the gateway is recreated once and later releases hand apiserver and web over without
  a gap. Pin the deployment to the tag `v0.1.257`.
- **Clients.** macOS ships on the stable channel to every user; iOS ships marketing version `0.1.257` to
  TestFlight; installed Android apps are offered `0.1.257`.

## Security fixes

None in this release. The dependency-alert remediation tracked in
[Project maturity](../docs/project-maturity.md) is not part of this release; do not take this section as
evidence that it landed.

## Known limitations

- Orbit remains pre-1.0 and only the newest published release is supported (see
  [SECURITY.md](../SECURITY.md)).
- The runner fix makes a failed model-list probe on a signed-out Claude visible in the runner log
  (`claude model catalog refresh failed: …`); it does not remove the failure's cause, which is not yet known.
- CI on `main` was red when this release was cut, from changes outside it: OrbitKit copy-parity tests that
  read web strings the Settings rewrite removed, and `test/upgrade-runner-link.test.mjs` after the link rate
  limit was raised. The release workflow builds the clients without running those tests.

## Artifacts and verification

The tag is `v0.1.257`; the full source SHA is that tag's commit. The release workflow publishes
`Orbit-v0.1.257-arm64.dmg`, its Sparkle payload `Orbit-v0.1.257-arm64.zip`, `orbit-android-0.1.257.apk` with
its `.sha256` and `android-update.json`, a TestFlight build of `0.1.257`, and runner binaries whose
`/dl/version.json` names `0.1.257`. Before the tag was cut, `node scripts/release-identity.mjs check-tag
v0.1.257` checked that all of these derive from the package version and that these notes carry every required
section; the release workflow runs the same check before it builds anything. The runner, web, OrbitKit and
Android changes for the signed-out model name were tested on their own branch (runner Go model-catalog
tests, web vitest and tsc, OrbitKit `AgentDefaultsTests` in swift:6.1, Android composer unit tests). Record
the workflow run URL and the asset digests in the Release once the run finishes.

## Rollback

The rollback target is the previous published release,
[`v0.1.2-beta.246`](https://github.com/jianghailong-xy/orbit/releases/tag/v0.1.2-beta.246) (its `package.json`
names 0.1.256). Record its image IDs and the source SHA you are running before upgrading. The six migrations
above are additive, so the previous application can start against the upgraded schema; rows written after
the upgrade with new kinds (a `SESSION_FORK` session source, a `SESSION_INVITE` email) are values that
release does not create, so review them before an application-only rollback, and restore to a pre-upgrade
point in time if they are not acceptable. Runners do not move back by themselves: roll them back with the
`/api/runner/release` pointer. Keep PostgreSQL and its archive running, and reinstall the previous DMG or
select the previous TestFlight build only after confirming server compatibility. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
