# Orbit 0.1.261-beta.36

## Summary

A coordinator that hands over to a new coordinator no longer kills the work it left running. Its `delegate`
(SubAgent) runs and `bg_run` jobs keep running to their end. Their result then reaches the successor through the
wake forwarding that shipped with coordinator handoff v2.

- **Kept on a handoff only.** A handoff completes the outgoing coordinator with a signal that keeps its background
  work: `keepBackgroundWork` on the session's end turn, and `keepWorkSessionIds` on the runner heartbeat. The runner
  then leaves that session's local SubAgent runs, jobs and watches running, each holding its worktree until it
  ends, and reports their end so the wake is owed. Services are still stopped. Every other ending (stop, delete,
  failure, an ordinary Complete) stops the work as before.
- **Remote runs** on another workspace were never stopped by a parent ending, and still are not.
- Also: a translated message in the tray shows the words the reader wrote; two pg specs follow main's trigger
  count; the two-stage deploy times a container's stop on the monotonic clock.

## Upgrade impact

- **Database migrations:** none. The diff between v0.1.261-beta.35 and this tag under
  `src/apiserver/prisma/migrations/` is empty.
- **Configuration:** none.
- **Server:** the apiserver sends the keep signal when a handoff completes a coordinator. It needs a deploy of this
  commit or later; until then a handoff stops the outgoing coordinator's SubAgents as before.
- **Runner:** the runner reads the signal (`src/runner-go`). Runners pick it up when they update to this release.
  An older runner ignores the signal and stops the work as before. A newer runner against an older server never
  sees the signal and also behaves as before.
- **Clients:** macOS beta users, TestFlight (marketing version 0.1.261, build number = commit count) and Android
  via `android-update.json` from this tag.

## Security fixes

None in this release.

## Known limitations

- A kept SubAgent run can no longer call Orbit tools itself once its parent has ended, since the session's tool
  socket goes with it. Its result is still reported.
- A kept `bg_run` job wakes the successor only when it exits. Output and stall wakes stop once the parent has ended.
- A runner stop or self-update while a kept run is going interrupts it (its wake is still owed) or kills a kept job,
  rather than handing it on.
- If a handoff's replacement fails after the outgoing coordinator was completed, kept runs continue and their wake
  is dropped.

## Artifacts and verification

The tag is v0.1.261-beta.36, and this file is in the release commit's tree. The release publishes the macOS DMG
and Sparkle appcast (beta channel), an iOS TestFlight build and the Android APK with its `.sha256` and
`android-update.json` on the same GitHub Release, all from this tag.

The fix's evidence: new runner-go tests for a kept SubAgent through either signal, an ordinary end still stopping
it, a remote run untouched, and kept jobs and watches woken while services are killed. The apiserver unit suite
passed 7,068/7,068, and `coordinator-handoff.pg.spec.ts` 11/11 against PostgreSQL 16. The project branch's merge
into main passed the merge check (build, apiserver unit and web suites). A production walkthrough of a real handoff
found the defect this release fixes, and is to be repeated on this release.

## Rollback

The previous tag is v0.1.261-beta.35, commit c4fbeb1b3b. This release adds no migration, so an application-only
rollback to v0.1.261-beta.35 is schema-safe. Rolling back restores the old behaviour: a handoff stops the outgoing
coordinator's SubAgent runs and jobs. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
