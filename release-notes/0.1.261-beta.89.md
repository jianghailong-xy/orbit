# Orbit 0.1.261-beta.89

## Summary

- **An agent can propose a runner's Max Concurrent, and the owner applies it with one press (server, runner, web, macOS, iOS and Android).** Owner requests gain the kind CHANGE: the card shows the runner's live Max Concurrent, an editable requested number, the running count, "Was N when asked." and a consequence line that follows the direction, and posts Apply to `POST /owner-requests/:id/apply` (RUNNER_CONTROL). The request stores `change_spec` (`{ runnerId, field, requested, before }`), and one pending change per runner setting is kept by a partial unique index: a newer filing withdraws the older one in the same transaction. Applying locks the request and then the runner, writes the value through the runner page's rules, and ends the request DONE with `{ applied, actualBefore }`, which the resolution turn carries as `change`. The runner's `request_owner_action` and `orbit owner-request` take `kind: CHANGE` with a `change` parameter, refused on any other kind, and both build the body through `ownerRequestBody`. Web keeps the card's English in `CHANGE_COPY` for the native clients' parity tests; macOS draws a native stepper and iPhone a −/+ stepper; Android draws the setting as a tinted panel with round −/+ buttons. Migration 1538.

- **Web Files: text, code, HTML and PDF preview in the details pane.** The pane previewed only pictures and Markdown, so most files showed nothing. Text and code show as written (first 1 MB, with a note when cut), HTML renders in a `srcdoc` frame with every sandbox permission off, and a PDF opens in the browser's own viewer inline (the owner chose option A on board `docs/mocks/files-preview-web`, no source toggle). The page's CSP gains `frame-src 'self' blob:`, which Chromium needs to frame the PDF's object URL.

- **Web: a session folder's page keeps the list's scope menu, tag filter and a scoped ⌘K.** A folder's page had replaced the list's scope menu with Rename/Delete, so it could not be switched between Open and Completed or narrowed by a tag, and ⌘K searched everything. The page now keeps the scope menu (Trash leaves to the workspace's Trash), tags narrow the folder and reset on Back, and ⌘K opens scoped to the folder with a removable chip. The server narrows session search with `folderId` where hits are scored and for the recents, so the total is the folder's.

- **A held queued run reads "On hold" on web, Apple and Android, and Needs you reads the session facts.** Task list rows now carry `queuedOnHold`, computed by the same `sessionIsHeld` rule behind `waitingOn` HOLD — no second copy of the rule and no extra query — and the Tasks list pill and the web Now card say On hold only when the server sends it. The Needs you grouping takes its failure part from the session facts, so an end the runner never confirmed no longer sits under Needs you while reading Ended; older servers keep the legacy status rule. A task's `sessions[]` now carries the same session facts every other payload uses (and the contract lists a `taskRun` kind), so the task detail's runs say On hold (Android also Queued in the task panel), and a session whose status word the client does not know reads its phase: a held session still reads held, a RUNNING phase with no activity or TURN reads Running, and a parked session whose engine runs its own turn (activity TURN) stays parked, as web does.

- **The Orbit Cloud runner image now installs `fonts-noto-core`, so the built-in browser draws Tamil, Thai, Devanagari, Arabic and other non-CJK scripts instead of empty boxes.** The image had shipped only CJK and emoji fonts; the gap was seen on Google's language footer. The font set is pinned in `deploy/managed-runner/image/pins.json` and checked in the image's build like the others.

- **Server and runner.** New route: `POST /owner-requests/:id/apply`. Session search takes `folderId`; task list rows add `queuedOnHold`; a task's `sessions[]` carries `phase`, `released`, `lastTurnOutcome`, `waitingOn`, `endReason` and `workFinished`, and `contracts/session-state.contract.json` lists the `taskRun` kind. The runner declares the CHANGE kind on both owner-request doors, and the operation catalog doc is regenerated for it.

## Upgrade impact

- **Migrations:** one, additive — none drops or renames a table or column, none adds a `NOT NULL` column without a default, and none rewrites a stored row.
  1. `1538_owner_request_change` — adds the nullable `owner_request.change_spec` (JSONB, NULL for every other kind); drops and re-adds `owner_request_kind_chk` with `CHANGE` added, so it still admits every kind it admitted before; adds `owner_request_change_spec_chk`, "kind is CHANGE exactly when `change_spec` is not null", which every existing row passes (no existing row is CHANGE and the new column is NULL); and adds the partial unique index `owner_request_change_pending_key` on (owner, `change_spec->>'runnerId'`, `change_spec->>'field'`) for PENDING CHANGE rows, on values no row has yet. Every statement can run twice.
- **Server:** the first boot applies the one migration. There is no configuration change and no backfill; CHANGE is filed only when an agent files one.
- **Runners:** the runner served at `/dl` is built from this tag and adds the CHANGE kind to `request_owner_action` and `orbit owner-request`, with the `change` parameter refused on any other kind. Orbit Cloud runners get it from the `orbit-cloud-runner:0.1.261-beta.89` image, built from this tag, which now installs `fonts-noto-core`. An older runner keeps working and simply cannot file a CHANGE.
- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. The CHANGE card, the On hold wording, the Needs you grouping and the unknown-status phase reading need this release's clients; an older client does not draw them, and the new payload fields are additive. No one-time step on a Mac, iPhone or Android device.

## Security fixes

None in this release. Two properties of new code are worth naming, since this release adds them:

- **The Files HTML preview runs with every sandbox permission off.** It is a `srcdoc` frame with `sandbox` set to no permissions, so a user's HTML file cannot read the client's storage, navigate the page or run a script with this origin.
- **The CSP admits framing only what the client fetched with the login.** `frame-src 'self' blob:` lets the PDF viewer frame its own object URL; `lib/userFile.ts` labels every object URL that is not a picture or a PDF as bytes, so none can open as a page. The `srcdoc` HTML preview is not governed by `frame-src`.

## Known limitations

- A CHANGE request's v1 covers a runner's Max Concurrent only; no other runner setting can be proposed yet.
- The Files previews (text and code, HTML, PDF) are on web only in this release; no macOS, iOS or Android change for them is in it.
- A session folder's scope menu, tag filter and scoped ⌘K are on web only in this release; Apple and Android folder pages are as before.

## Rollback

Previous tag v0.1.261-beta.88 (`4099b43165`). The one migration is additive — no table or column is dropped or renamed, no row is rewritten, and the kind check it re-creates admits every kind it admitted before — so an application-only rollback is schema-safe: `change_spec` stays unread, and the partial unique index covers only PENDING CHANGE rows, which an older server never writes. A CHANGE request still pending is applied by this release's Apply door, so apply or decline such requests before rolling back. Orbit Cloud runners are pointed back at the previous tag's image by a deploy of an earlier commit, and each moves to it once idle.

Client rollback is to the last published builds, v0.1.261-beta.88's DMG, TestFlight build and `orbit-android-0.1.261-beta.88.apk`.
