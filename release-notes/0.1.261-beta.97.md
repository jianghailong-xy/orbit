# Orbit 0.1.261-beta.97

## Summary

This release is mostly what every client draws about a session. The seven state words are replaced by three states — Queued, Running and Idle — read from the session's phase alone, with every other fact drawn as a mark; web, macOS, iPhone and Android draw it on the list row, the header, the task runs, the link card, search and the guest pages. Scheduled runs gain Rename on every client, a Run now that no longer costs an automatic slot, and a run that is no longer failed while it waits the way agents are taught. Web gets a new-session top area, ⋯ before Share in the session header, the decision bar inside the top capsule and one roomier menu style; Android gets Run now in the Runner popover. The runner sends only the Drive chunks a server lacks, and gives a slot back when a turn ends on a draining runner.

- **All clients: three states and marks.** `SessionDisplay.state` decides Queued, Running or Idle from `phase` alone, and `SessionDisplay.marks` draws Needs you, Failed, Retrying, On hold, Interrupted, Background, Will resume, Finished and Ended from the other facts (docs/mocks/session-display-three-states, `rules.mjs` without Disconnected, owner 2026-11-25). Web draws them on the list row, the header, the task panel's badge, Now card and Markdown, the Tasks list pill, the link card and the shared and guest headers. Apple draws them on the Mac sidebar rows, the Mac status bar, the iPhone and iPad rows (the state icon in the live-indicator slot, at most two marks and "+N", and "Idle, Interrupted" as the VoiceOver value), the task panel's run rows, the link card, search, the guest view and Shared with me. Android draws them on the list row, the row's word, the task run label, the copied task Markdown, search hits, the guest view and Shared with me. A payload without the facts draws what each surface drew before.

- **All clients: search and live updates carry the facts.** Search hits never carried the session facts, so search rows fell back to the old seven states, and the Background mark was missing wherever `activity` and `runningBgCount` were absent. Every payload kind now sends both, the shared head and search hits included, and the contract lists `searchHit` and `backgroundFields`; Apple's `session.updated` keeps the mark in step rather than waiting for the list to be read again.

- **Web: a new session's top area.** Following the owner's choice of option B, the draft reads "Claude Code ▾ / in [workspace ▾] › [folder ▾]", each a menu, instead of grey read-only text in a header far from the engine card; the hero's model line is gone because the composer says it and changes it; a wide window's draft drops its header and a phone keeps only Back and "New session".

- **Web: session header, address and capsule.** ⋯ comes before Share with Apple-style glyphs (28px buttons 2px apart, 16px glyphs in the title's colour, a green dot on Share while a link is live), and a coordinator session's Coordinator badge carries a › and opens its project, leaving the wide header as the title line alone. What waits on the reader (Ready to start, questions, requests, evidence, confirmations) is now the top capsule's first segment instead of a bar under the header; while something waits the capsule drops the reader's last message and keeps only the way to the top, its arrow describes the card the line names, and a phone floats the same capsule over the transcript. A copied `/sessions/<id>` no longer carries `?project=` or `?folder=`: the project sessions page lives in a tab-scoped store and is adopted once and dropped from an older link, and the list goes to where the session is filed.

- **Web: one menu style, and two panes that drag.** Every menu takes the roomier card (a hairline edge, 38px rows at 15px with 16px icons, inset dividers, a tinted Delete), and select dropdowns, dialogs, popovers and confirmations follow it with their own corners. The Scheduled page's inspector drags at its left edge like the task detail panel and remembers its width with the list at least 360px, and the diff drawer's commit and file rail takes a grab strip, keeps the width and resets on a double-click.

- **Web: rows and lists.** List rows draw every mark with the chips wrapping below a readable line, the ⌘K search rows draw the session's marks, keyboard focus is a tint from one rule with a guard test rather than Chrome's blue ring, the Tasks list pill draws the run state's own icon (so Queued shows the clock) and a parked run reads Idle with Will resume, and the Tasks list status column fits a Running pill with Background. The Scheduled page takes Up and Down to move the selection, and "Loading earlier messages…" shows only for a page slower than 1 s, staying at least 0.5 s.

- **All clients: Needs you folds like Pinned.** The session list's Needs you heading is the same fold button with a chevron; the fold takes its rows off the list and out of Up/Down and is remembered under `sessionList.needsYouCollapsed` on web, macOS, iPhone and Android.

- **Scheduled runs: Rename, on every client.** `POST /api/schedules/:id/rename` changes the title alone as a USER revision with Undo, no card and no hold, and a name-only change keeps `nextDueAt` so a rename cannot skip a due slot. Web renames from the row, the ⋯ menu or the title, and History reads a person's rename as "Renamed from "…"" with Undo (Undo posted to `/api/api/…` and answered 404 before this release). macOS edits the inspector title in place; iOS opens the system alert; Android gets the iPhone's long-press menu with Rename… and Rename… above Delete in the sheet's ⋯, in a Material dialog whose Save stays off while the name is empty or unchanged.

- **Scheduled runs: Run now no longer takes an automatic slot.** The weekly budget counted every started run, so six Run now presses in three days cost the daily engine-bump schedule its next three slots. Automatic runs (every trigger but MANUAL) now have the budget to themselves; a Run now from a session or a token counts toward its own budget and is refused over it; the owner's own press counts toward none.

- **Scheduled runs: a late report, and a run that is not idle while it waits.** NO_REPORT is the server's reading of an idle session, so once a person writes to the run's session the same session may still report: the run takes that outcome, the failure it counted is undone, and a push replaces the failure's banner. ENGINE_CRASHED takes a late report once the owner revives it; RUN_LIMIT, APPROVAL_TIMEOUT and the owner's stop stay final. A run reads its session from the phase fields alone: a pending wake-up, watch or armed retry is not idle, a background job or SubAgent under the turn is not idle, and an IDLE reading fails a delivered run only after a minute. The run block now tells agents that ending the turn without a report fails the run, and how to wait instead.

- **Android: Run now in the Runner popover.** A message a full runner, run or batch holds can now be run immediately on Android, as on web (docs/mocks/queued-run-now), with the over-limit tag and Extra sessions on demand, and its words held to `queuedCapacity.ts` by the parity test.

- **Runner: Drive sync sends only what Drive lacks.** A pass asks the server which chunks it holds (`POST /runner/drive/chunks/held`) and PUTs only the rest, and sends files of one chunk or less 64 at a time through one staging and one batch commit (`POST /runner/drive/batch`, up to 100 files from one staging bound to no entry). A server without the routes (404) gets the old per-file path.

- **Runner: a draining runner gives its slot back.** Every inbox fetch says `draining=1` while the pool drains for an update, and a turn completion says draining too; the control plane then holds new work but still hands out Stop, steers and expired-lease redeliveries, and a new `return-slot` route (the controller's 61st) gives back a slot nothing runs under. Stop on a session whose turn ended on a draining runner now drops its queue and leaves it idle instead of answering `SESSION_NEXT_TURN_STARTING`, and an interrupt filed behind a follow-up held for the update reaches every engine loop.

- **Runner: Codex Stop waits for Codex's word.** The Codex app-server Stop wrote "Interrupted" before Codex had agreed, sent nothing for a turn Codex started itself, never retried an unanswered `turn/interrupt`, and only logged a failure. It now follows the Claude path: the marker goes up once Codex confirms, the running turn is tracked from notifications whoever started it, a refusal whose turn had just ended writes no failure, an idle Stop says there was no running turn, and a real failure writes `interruptFailureMessage` into the transcript.

- **Orbit Cloud runners: ready sooner after a start.** A runner probes every engine at once instead of one after another, so its first heartbeat goes sooner, and a starting runner's heartbeat kicks the manager, so the runner reads READY as soon as it checks in.

- **Runner: engines and instructions.** Claude Code moves to 2.1.332, Kimi Code to 2.8.0 and Antigravity CLI to 1.5.17 (codex 0.172.0, opencode 1.19.6 and cursor 2026.10.14-941492e unchanged), and Kimi's instruction block now rides the first prompt and again after a reset. Instruction composition moved onto a unit registry for all seven carriers, the agent contract is 1.15.0 (primer 1.8.1), receipts carry recovery notes and an `orbit-<kind>:<id>` link, and four instruction rules became mechanisms: Claude's own sub-agent tool is disallowed where `delegate` is served, a create without `autoRunWhenReady` is refused, a keyless create derives an idempotency key, and a bad file link is corrected on the next turn.

## Upgrade impact

- **Migrations:** fourteen, applied by the apiserver on boot. All are **additive**: none drops a column or rewrites a row, and nothing is backfilled.
  - `1601_schedule_run_by_owner` adds `schedule_run.by_owner` (`BOOLEAN NOT NULL DEFAULT false`), which records whether the owner pressed Run now.
  - `1611_session_turn_state_phase` adds `session.turn_state` and `session.phase`, both nullable, two NOT VALID value CHECKs, two BEFORE row triggers that derive them from the stored word and the execution facts, and four SQL functions. It writes no row.
  - `1612_session_turn_state_phase_validate` validates those two CHECKs; it scans `session` under SHARE UPDATE EXCLUSIVE and changes no row.
  - `1621_session_legacy_status` creates one SQL function, the database twin of the TypeScript word projector. No table is touched and nothing calls it yet.
  - `1622_session_turn_state_checks` adds two more NOT VALID CHECKs on `turn_state`; a catalog change that checks no existing row, and a NULL passes both.
  - `1627`, `1628`, `1629`, `1631`, `1632`, `1633` and `1634` build seven indexes on `session` with `CREATE INDEX CONCURRENTLY`, so reads and writes go on; the index on `status` stays.
  - `1641_session_triggers_read_facts` restates nine functions and three trigger `WHEN` clauses to read the facts instead of the stored word, and adds `session_held_turn_state`. It writes no row.
  - `1643_schedule_run_idle_seen_at` adds `schedule_run.idle_seen_at` (nullable `TIMESTAMPTZ(3)`), which the one-minute idle settle reads.

- **Backfill:** not part of this release. A session written before this release keeps NULL in `turn_state` and `phase` until `scripts/session-turn-state-backfill.sh` is run; every read falls back to the stored word for such a row, so nothing must be run at upgrade time.

- **Configuration:** none. No environment variable or setting changes in this release.

- **Server:** `session.status` is still written and still served; removing it is a later deploy (docs/session-status-retirement-plan.md). What changes is that the word is now derived from the session's facts, so for the row kinds §3.4 of that plan names the displayed word differs once this server writes them: an end the runner did not honour reads Cancelled/Ended where it read Failed, and an old SUCCEEDED row with no end reason reads Ended (318 rows measured 2026-11-21). The owner accepted those two kinds. Session payloads gain the six facts, `activity` and `runningBgCount` on every kind, search hits and the shared head included; no existing field changes shape or name. The schedule rename door and the two Drive batch routes (`/runner/drive/chunks/held`, `/runner/drive/batch`) are new.

- **Runners:** the runner served at `/dl` is built from this tag. It sends only missing Drive chunks, batches small files, reports draining and returns slots, and waits for Codex's word on Stop. A runner older than this release keeps working: the drain fields it does not send behave as before, and it keeps the old per-file Drive path. A runner from this tag against a server without the new Drive routes (404) also takes the old per-file path.

- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. Web takes everything this release lists for it, including the three states and marks and the new-session top area. macOS and the iPhone take the three states and marks, the Background mark in search, task runs, shared Markdown and live updates, the Needs you fold and schedule Rename. Android takes the three states and marks, the Needs you fold, schedule Rename and Run now. No one-time step on a Mac, iPhone or Android device, and a client keeps working against an older server by drawing what it drew before.

## Security fixes

None in this release.

## Known limitations

- A client draws the three states and their marks only when the payload carries the session facts; against a server older than this release every surface keeps the old seven-word drawing.
- The "Disconnected" state the comparison board drew is not shipped: the owner's 2026-11-25 decision is the three states plus marks only, so a runner being offline is a mark, not a state.
- `turn_state` and `phase` stay NULL on rows written before this release until the backfill script runs, and those rows keep reading their stored word; a later deploy's strict CHECK and `phase NOT NULL` wait on that backfill.
- The Scheduled page's Run now is budgeted differently per presser: the owner's own press counts toward no budget, a session's or token's counts toward its own, and automatic runs have the automatic budget to themselves.
- Rename changes the title only; a rename by an agent later is not held (owner decision D2 B).
- Needs you's fold is remembered per client under `sessionList.needsYouCollapsed`; it is not shared between a phone, a Mac and a browser.

## Rollback

Previous tag v0.1.261-beta.96 (`ad1a93353f`). Application-only rollback is **schema-safe for this release**: every migration adds columns, constraints, functions, triggers or indexes, or restates function bodies; none drops a column, rewrites a row or backfills anything. A beta.96 apiserver runs against this schema unchanged — it writes the word only, and the triggers keep `turn_state` and `phase` derived from it — and it reads the stored word, so the §3.4 rows read their old words again.

Do not run `scripts/session-turn-state-phase-down.sql`: it drops what `1611` and `1612` add, and it says it is only safe before deploy D2, which is part of this release. Leave the columns, constraints, functions, triggers and indexes in place; the release records no other down-migration.

Client rollback is to the last published builds, v0.1.261-beta.96's DMG, TestFlight build and `orbit-android-0.1.261-beta.96.apk`. A client from beta.96 keeps working against this release's server — it reads the derived `status` it already knows and ignores the added fields — but it has the older seven-word display, no schedule Rename, no Needs you fold, no Android Run now popover and no new-session top area.
