# Orbit 0.1.261-beta.29

## Summary

This is the first published release since v0.1.261-beta.26. v0.1.261-beta.27 and v0.1.261-beta.28 were tagged, but
their release runs published nothing: the release-trigger isolation test, run as the first step of release.yml's
Android build, refused `agent-eval.yml`'s `schedule:` block as an unsupported filter line, so the Android build, the
supply chain and publish were skipped on every `v*` tag (v0.1.261-beta.27: the DMG and TestFlight built, nothing was
published). 56dfbdfa4 fixes the test, and this tag carries everything since v0.1.261-beta.26.

- **Web and macOS: Agent Tools.** The session menu on the web (after Find) and a toolbar item plus an "Agent Tools…"
  section in the agent's settings on the Mac open a read-only view of how this session's agent reaches Orbit: the MCP
  connection status in the engine's own words, the tool families it lists and why one is short, what the permission
  mode means for Orbit's calls, the instructions it reads in order, and the generated guide with four examples. The
  runner sends the report from the engine's own frames, and the server keeps the newest report on the session.
- **Web, macOS, iPhone and Android: removing an account moves its sessions instead of refusing.** An account removal
  no longer stops at "can't be removed while N sessions are on it": each session moves to another signed-in account
  on that machine (Automatic's pick) with its conversation, and the account is removed once the last has left. The
  Remove question says the sessions move first, the refusal speaks only of sessions that cannot move, and a removal
  waiting on them says how many are moving. Only sessions with no other signed-in account, on a runner too old to
  carry the conversation, or a Cursor conversation that has talked still block it.
- **Web, macOS, iPhone and Android: the owner's card says what is true of the branch.** A failed check on a project
  branch or a task-branch candidate no longer claims "the task passed on its own branch; it fails only on the combined
  tree". The server writes the row's sentence from the check's job kind and source kind — for a promotion check,
  "unchanged — the project branch did not move, and nothing reached <main>" — and a server older than that field
  leaves the previous sentence.
- **Schedules:** the over-budget refusal of a Run now names the runs actually started ("started 4 runs …; its owner
  allowed 1 a week"), and `schedule_run_now` now says a Run now counts against the runs-a-week budget, as the
  contract's §8.4 has it; the person can still start one from the app.
- **Agents find Orbit in one call.** A new `guide` tool and `orbit guide [TOPIC]` answer the five objects, the intent
  routes and 13 topics, with each step's MCP tool and CLI argv, so an agent no longer reads the whole catalogue (about
  300 KB with orchestration on) to make one call; `orbit capabilities --summary | --family | --id` serves the same
  offer a view at a time. Claude Code is given the playbooks skill as `orbit:playbooks`, Codex as `orbit-playbooks`.
  Engine instructions now say to look work up with `task_list` before filing it, to call `task_get` with no arguments
  after a compaction or a resume rather than answering from the summary, and that an engine's own sub-agents are as
  private as its plan.
- **Runner fixes.** Removing a secret grant no longer refuses every merge and withholds every diff while it scans: the guard
  reads the removed values pending in memory, so a commit that carries one is still refused but other merges go
  through, and a turn ending during a scan waits up to 30 seconds. An image redrawn in place and linked again in a
  later reply uploads again rather than showing the first drawing. Kimi, OpenCode and Antigravity sessions tell
  `orbit mcp` how deeply they are nested, so a nested session no longer outwaits the session above it. An account
  removal now carries a moved session the pool holds with no engine running — parked between turns for weeks — instead
  of waiting out its 6 hours.
- **Wording and telemetry.** "system prompt" becomes runtime instructions / base instructions on the web, macOS,
  Android and the CLI help. Each turn that touches Orbit files a counts-only `agent_contract_telemetry` system event;
  the runner setting `ORBIT_AGENT_CONTRACT_TELEMETRY=off` turns it off.

## Upgrade impact

- **Database migrations:** one, `0940_session_agent_tools`. It adds one nullable JSONB column,
  `session.agent_tools`, holding the newest Agent Tools report. It is additive: nothing is backfilled, no existing
  row is rewritten, and it is a catalog change only, so rolling the code back leaves the column in place, unread. It
  asks for the `session` table's lock in 2-second tries with 1-second gaps (up to 60) as `0478` does, so the table
  every runner call reads is not queued behind it. No other migration lands between v0.1.261-beta.26 and this tag.
- **Configuration:** nothing required. A runner may set `ORBIT_AGENT_CONTRACT_TELEMETRY=off` to stop the per-turn
  contract telemetry events; it is on by default.
- **Server:** this tag's server serves the Agent Tools report with the session, the branch sentence on the owner's
  card, and the schedules refusal wording. Against an older server, the Agent Tools view shows no report (null reads
  as "no report yet") and the cards keep their previous sentence.
- **Runner:** the runner served at `/dl` is built from this tag, so runners update to it and take the account-removal
  carrying, `guide` and the graded capabilities views, the playbooks skill, the spawn-depth and merge/diff fixes, and
  the engine-instruction changes above.
- **Clients:** each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261, build number
  = commit count) and Android via `android-update.json` are offered it. v0.1.261-beta.27 and v0.1.261-beta.28
  published nothing, so this is the update an installed client receives after v0.1.261-beta.26.

## Security fixes

None in this release. The secret guard stays in force: a commit that holds a removed secret's value is still refused;
only the scan around it no longer freezes unrelated merges and diffs.

## Known limitations

- Removing an account still refuses over a session that cannot move: no other signed-in account on that runner, a
  runner too old to carry the conversation, or a Cursor conversation that has talked. A removal waits at most 6 hours
  for running sessions to finish their turns, then fails and can be asked again.
- A turn that ends while a removal scan is running waits up to 30 seconds for it, and a diff can still be withheld
  until the scan finishes, though it now says why.
- The Agent Tools report exists only for sessions on a runner at this tag; a session started before it reads "no
  report yet", and an engine that reports no MCP connection keeps it that way.
- The black-box agent eval runs weekly only where model credentials are configured; CI always runs its deterministic
  layer and the contract tests.

## Rollback

The previous published tag is v0.1.261-beta.26, commit cf61ab06fbb86d2dd21808dca8616d30824bb907;
v0.1.261-beta.27 and v0.1.261-beta.28 were tagged but published nothing. The only migration since adds a nullable
column, so a client or server rollback to v0.1.261-beta.26 is schema-safe, and the column stays in place, unread. A
runner rolled back to it loses the account-removal carrying, `guide` and the graded capabilities views, the playbooks
skill, the spawn-depth fix and the merge-and-diff fix above.
