# Orbit 0.1.261-beta.78

## Summary

**This is the first release to ship what 0.1.261-beta.77 promised.** The v0.1.261-beta.77 tag's
release run failed: its Android job hit a stale source-text assertion in `RunnerUpdateLaterTest` —
`41be13d413` had moved the held tag's line, which `45fe88728d` now reads from the right-edge call —
so beta.77 produced no GitHub Release, no Android APK and no production runner. Everything
`release-notes/0.1.261-beta.77.md` describes ships here instead, above all `c0871d90dc`, which
teaches the runner to read Claude Code 2.1.330's `claude.ai` sign-in link so signing Claude Code in
from the web works again; this file does not repeat those notes.

**A GitHub workspace lands in the runner's home, not in `<home>/orbit-repos`.** New folders already
go in a managed runner's home once it has reported, so clones landing in `orbit-repos` split one
machine's workspaces across two places. `48b0896b0f` makes the runner accept a clone target anywhere
in home, sweep unfinished clones there too, and declare `clone-workdir/v2`; `cloneRootFor` in
`@orbit/shared` sends clones home only for a runner that declares it, so an older self-hosted runner
keeps cloning into its repos folder. The setup card and the From GitHub option now take their path
from the shared rule on web, macOS and Android (`881452df12`, `51a1f9ef35`, `3f9cfe732f`,
`5a13f5a73c`, `5843844a63`). A managed runner's first new folder goes in `/home/orbit` rather than
`/home/orbit/orbit-repos` (`6c62aa253a`), and a managed runner that is not up offers `/home/orbit`
whatever an earlier image declared, because it wakes on the current image (`05b41ea2d4` and its
macOS and Android ports). Migration `1434` gives managed runners that slept through the move the
`/home/orbit` path in their stored Repos Folder (`6a7106f95b`): `5` of the `7` managed runners on
production were still naming `/var/lib/orbit/home/orbit-repos`, asleep since 2026-11-17. A managed
runner's volume check now also scans home, which it missed for new-folder workspaces as well
(`48b0896b0f`).

**Model routing keeps a trailing `-max` as part of a model's name.** The id rule dropped a level
suffix from every id, so `qwen3.7-max` was keyed `qwen3-7` and a plain Qwen3.7 could have been taken
for it. `2a325d8061` keeps the whole id on the server and the page, folds only Antigravity's ids
(with `antigravityBaseModel`, where the engine is known), and migration `1463` re-keys the three Qwen
Max rows `1433` seeded without their `-max`. On web, `d9cff05d68` lines up every model's name whether
or not its row opens, sorts models by name with numbers as numbers (GPT-5.6, 6.1 and 6.2 together),
and joins an account whose runs the tier list lacks (Codex Pool's `gpt-6.2-sol`) to its model by the
server's id-rule key instead of showing it alone as "GPT-6.2-Sol".

**The project page reads the same on web, Apple and Android.** iOS gets Open items as a section on
the page, second after the title area as on web's mobile page, with the header `N need you · oldest
first` (`3a685589f6`, `1432a3aa88`); How it runs opens with web's run-settings summary, and the page
gains the `landingReason` half-sentence on met criteria, M/D-dated receipts, "Running · no output
10+ min" on a stalled task row, "Ready/Blocked · set to start by hand" on held rows, and tallies that
count unmet criteria apart ("N not met") (`3a685589f6`). `58da64ac2b` frames iOS's criteria-decision
receipt in the warning tone with a green verdict and folds out what the answer was about. Android
follows with the same page labels (`b0d6c297fe`) and the three coordinator cards after a project
starts: the criteria receipt with its "What this approved" fold, the confirmation receipt that
replaces the preview once a confirmation is on record, and Project started with its tasks set to
start by hand (`116242fc54`). Web gets the same labels (`f1a03be36f`) and stops counting unmet
criteria by their landing reason (`6dfe75e1b7`); macOS restores the How it runs summary row a merge
dropped (`f382b2a848`) and drops the page's With the coordinator group main removed
(`c793267196`).

**Two smaller client fixes.** Web's sign-in card now asks where to sign in, putting In this browser
and In the runner's browser in one row with the note and Copy sign-in link under it and a divider
before the paste; once the runner's browser is chosen its progress leads (`e4ac018b74`). Android
publishes the measured viewport after the transcript's initial scroll, so a waiting card no longer
falls back to the whole card and keeps its aligned position (`cde42e878d`).

## Upgrade impact

- **Database migrations:** two files are added between v0.1.261-beta.77 and this tag. Neither
  changes the schema and each only rewrites stored values; **both run twice safely**:
  - `1434_managed_runner_repos_root_home_orbit` updates `runner.repos_root` for managed runners whose
    path is under `/var/lib/orbit/home`, replacing that prefix with `/home/orbit` (so
    `/var/lib/orbit/home/orbit-repos` becomes `/home/orbit/orbit-repos`). It touches only rows that
    have a `managed_runner` row and is left as it is for every other runner; its own comment notes
    the second pass finds no managed runner still under `/var/lib/orbit/home`. No row is deleted and
    no column is added.
  - `1463_model_identity_max_is_a_name` re-keys three `model_identity` rows — the Qwen Max rows
    `1433` seeded — from `qwen3-7`, `qwen3-8` and `qwen4` to their `-max` forms, in `canonical_key`
    and, where no row already holds it, in `rule_key`. The rows keep what they point at and their
    names; rows already under the new key are left as they are.
  - On a database already carrying beta.77's ledger the pending files are these two; `1447` and
    `1462` are already recorded. The files are independent, so a boot applies whichever it has not
    yet recorded, in name order.
- **Configuration:** no new environment variable or setting is required.
- **Runner** (`src/runner-go`): changed in this range — `clone_workdir.go`, `managed_repo_recovery.go`
  and `transport.go`, which adds the `clone-workdir/v2` capability. The supply-chain job builds the
  runner binaries from this tag, and the runner served at `/dl` is built from this tag; a production
  deployment is what puts it there, so the runner at `/dl` shows this tag after the next production
  deploy. The managed-runner image must be rebuilt from `deploy/managed-runner/image` at this commit
  to carry the new runner and the volume check that scans home.
- **Engines:** unchanged in this range, so at this commit the managed-runner image and the
  apiserver's codex stage are the ones beta.77 named — Codex 0.171.0, Claude Code 2.1.330, Kimi Code
  2.7.2 and Antigravity CLI 1.5.14 (`5790704fb0`, in `release-notes/0.1.261-beta.77.md`); rebuilding
  the managed-runner image from this commit is what finally makes them live.
- **Clients:**
  - *macOS:* the project page's Open items, run-settings summary, landing half-sentence, dated
    receipts, stalled and start-by-hand rows, the unmet-criteria tallies, the shared new-folder and
    clone roots and the not-up managed runner's `/home/orbit` — on the beta channel.
  - *iOS:* the same, with Open items as a page section and the orange criteria-decision receipt, in a
    TestFlight build; marketing version 0.1.261, build number the commit count.
  - *Android:* the same page labels, the three coordinator cards after a project starts, the aligned
    waiting card and the shared folder rules, at `versionName` `0.1.261-beta.78` with the next
    `versionCode` and `android-update.json`.
  - *Web:* the sign-in card's one-row choice, the Model routing alignment, sort and account joining,
    the project page labels and Done tallies, and the setup card's shared folder roots, with the next
    server/web deployment rather than from this tag's client artifacts.
  - Older clients keep their existing reads and draw their existing page; no minimum client version
    is enforced.
- **One-time step:** none.

## Security fixes

None in this release. No commit in this range describes a security fix or names an advisory or CVE.

## Known limitations

Clones go into the runner's home only on a runner that declares `clone-workdir/v2`; an older
self-hosted runner keeps cloning into its repos folder, so a machine with old and new runners can
still hold workspaces in both places (`48b0896b0f`). A managed runner that has not reported is shown
`/home/orbit` whatever its stored capabilities say, because it wakes on the current image
(`05b41ea2d4`). Migration `1463` re-keys only the three Qwen Max rows `1433` seeded; a row keyed by
hand without its `-max` is not changed.

## Rollback

The server and runner in production before this release are v0.1.261-beta.76, commit
`5ef42cd203824cc54a9098181885bae6e9b0030e`. Its release run also failed, so the last client release
published on GitHub (DMG, Sparkle appcast, Android APK) is v0.1.261-beta.75; v0.1.261-beta.77 was
tagged but its release run failed, so nothing was published or deployed for it. An application-only rollback to beta.76 is schema-safe: neither
migration in this range changes the schema, and both only rewrite stored values, so beta.76 reads the
database unchanged. Two caveats the commits do not settle: `1434` moves managed runners' `repos_root`
to `/home/orbit`, which beta.76 predates only in that it never wrote that value; and `1463` leaves
three `model_identity` rows under keys beta.76's id rule does not compute (`qwen3-7` and its
siblings), and the commits do not say how a beta.76 server treats a model with no row under its key.

The client changes do not roll back with the code. Rolling macOS or Android back from this release
means installing beta.76's build, which loses everything in `release-notes/0.1.261-beta.77.md` as
well as this range's project page, sign-in card and folder changes; an iOS device can also go back to
a beta.76 TestFlight build.
