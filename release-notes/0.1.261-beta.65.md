# Orbit 0.1.261-beta.65

## Summary

This release is about **fewer needless reads, a new workflow view, a new Secrets page, a landing check the owner can see and undo, and the session-state server release**, with thirteen migrations behind them (the five the previous notes listed, and eight from that release, two of them backfills). The range is `v0.1.261-beta.64..origin/main` (`686e7b4961`).

**Session lists are read far less often.** *macOS:* the app no longer reads lists while it is hidden, minimized, occluded or closed. It owes the reads an event asks for and makes one per visible list when shown; the Open list is owed to the poll as a hint. The cause was measured on beta.64: 311 list reads plus 74 owner-confirmation and session-page reads in 10 hidden minutes (`6658194ae8`, `c280b7d1db`). *Android:* needs-you reconciliation reads the Open list as a `since=` delta from the store, not a plain `view=open` read, and a SYNC push clears answered reminders by that delta read whether or not the control stream is up (`cce63a6e70`, `d2e9bf0bfa`, `692c72a563`, `9bafe9bf20`). The session page's worktree poll now follows the control stream and stops with the Activity; it kept reading about 31 times a minute in production before (`fae012f332`). *Web:* a session event re-reads only the views that can show that session; owner-wide reads keep a 60 s safety read, and open owner requests and their history follow session events again (`0ed3ad39c1`, `0edee1d204`, `672f3b3d13`). **The web part is already live on the server; this tag ships the clients.**

**Android copy parity.** The Delivers hints and the pinned start-card snippet (DoneCopy and MainBranchCopy) no longer claim that the non-code mark decides landing, and the draft snippet gates upstream on a line, following the web (`9c2e23f5bb`, `1182f09d9d`).

**Orbit workflows have their own block and a switch.** A session's workflow is drawn as a block with its calls grouped by phase, a finished strip, and banners for an interrupted run, the cost limit and a script error, on web, macOS/iOS and Android (`4250cd0ea7`, `f9c7a37899`, `4d79c01772`, `42d179a2b4`, `282852b290`). Each Agent has a **Workflows switch** in its SubAgents settings, on by default, so every existing Agent keeps what it has. When it is off the server refuses the workflow route by name (`WORKFLOWS_DISABLED`) and the runner leaves the workflow tool out (`2f8587430c`, `bf9e51e23a`, `0013798bf6`, `7ca2d3680f`, `26d62fb8bf`). Settings → Routing gains a report with SubAgents and Workflows views (`3af2e3e754`, `2fcacba569`).

**A Secrets page.** Web Settings → Secrets lists saved secrets and the copies of them that sit on machines, with each copy's delivery hint, last use, and Delete or Remove that revokes the copies (`7f2f5a95ba`, `87b22d8d16`, `a1e6b457f5`). The machine page shows "Secrets on this machine" (`c331b2f559`). No secret value is added to any new column.

**New workspace on any machine.** iPhone, Mac and Android get the Workspaces + button and a row on the machine page. The setup card's folder takes a full path, as the web's does (`b004ba2279`, `e3867cc2e0`, `67480ee9ad`).

**A background SubAgent is one card from start to end on Apple clients**, and a stopped SubAgent is no failure (`ee619490cc`, `5372d1ad4c`). A message sent by another Orbit session no longer clears ended Background items on the web, as on iOS and Android (`14833cca83`).

**A session now records when a turn failed and why it was released, and "wait" means "finished all its work" (the session-state release, merged as `af55a2fb38`).** Every completed message or `!` turn records an outcome — answered, failed, interrupted or cancelled — with the error it ended on, and the session carries its last one; nothing reads them yet (`ef998477d6`). Every write that ends a session also records a release cause, and two causes mean only a failure: `engine_failed` (the runner finalized FAILED with no end asked) and `end_not_honored` (an end was asked and the runner never took it) (`b61e6307a2`, `48eba2e170`). `session_await` and `session_create(wait)` now wait for **SESSION_QUIESCENT**: the turn is settled, nothing it started still runs (no background job, SubAgent or turn the engine started itself) and nothing is set to wake it, so a child that ended its turn to wait on its own job no longer satisfies its parent's wait at once; three quiescent presets join the settled ones, which are unchanged (`c3260c968a`). A runner's beat states what is executing in each session and the server replaces what it had inferred, so an end report that never arrived no longer leaves a session reading as working; a session still executing on a runner the reaper judges lost is cleared, its SubAgent and workflow runs end interrupted owing their wakes, and each runner-hosted job gets a wake (`6421f34d62`, `6292f278a6`). An approval raised outside a dispatched turn — by a background job, or by a turn the engine started itself — now sends its alert and counts in needs-you (`abe2bcfd90`); a scheduled run does not land while its session is still executing (`fe573a4c52`); and the rail, the session row and a task's run read one definition of "working", a session whose jobs have all gone quiet being counted as `stalledJobs` rather than dropped (`e9fd6faa69`, `e728a4cb39`). A coordinator whose own model no longer works can be handed over: the note turn revives an ended coordinator instead of being refused with "the session has ended", and web, Mac, iPhone and Android offer **"New coordinator runs on"**, so the successor opens on another engine or provider, while "Same as this one" clears an earlier pick (`6905964d65`, `ffa83c644f`, `c67bc2624f`, `f95b34cad5`, `4a57721c1d`). **Apple and Android no longer fail on a session status word they do not know:** Apple decodes it to an unknown case that reads as ended, so one such row no longer fails the whole session list, and Android defaults it to `UNKNOWN` and resumes as it does an ended session instead of throwing (`b1681e6a41`, `9776c038bf`).

**The Apple apps build again.** The workflow finished strip still drew `SubagentFinishedLineView`, which went when a background SubAgent became one card; drawing nothing for a SubAgent's end, as the SubAgent branch beside it does, fixes the build that v0.1.261-beta.65's first tag failed (`686e7b4961`).

**Projects: the landing check is visible, attributable and revocable (contract revision 42, part two).**
- A project can start with no line and no repository; the start request then draws one sentence and the press sends no line (`12d11bc22e`, `063199c37d`, `111357a5bc`, `4e487f20ec`).
- A DONE task with no commits of its own queues no landing (`ca57151191`). The non-code mark and the codeless flag no longer decide landing (`2caec7aae9`, `c947101b8e`, `a4e574e8b9`).
- The coordinator can set the project-branch landing check without a card, and the project keeps who set it (owner, card, start or coordinator) and when (`4babe6e0fc`, `baa7691cc4`). The owner can say "No check".
- One task can be exempt from the project's landing check, with a reason of at most 280 characters, on a project-branch line only (`0df436f29f`, `833c77b3fe`, `b8f72cd659`, `fc5ab54510`). The merge check before main is never skipped.
- Each landing-check field keeps one history. The owner reads the coordinator's cardless changes and can revert each one (`ee254a1651`, `765f1d0158`).
- The web draws all of this: who set it, No check, the change list with Revert, the task exemption and "Skipped" in the landing's check list, and no Landing card while the project has no line (`b9310a3373`, `f0708d56d4`, `4e37af8809`). macOS/iOS draw who set it, No check and the change list with Revert (`c7b17038b8`). *Correction:* these notes first said macOS/iOS also draw the task exemption and "Skipped"; in this release they carry only the exemption's words, and an exempt task's skipped landing check reads as failed there. Both are drawn from v0.1.261-beta.72 (`af0be12465`, `87827952b7`).
- Android draws the start card with no line (one sentence; no line, branch, delivery or landing check sent) and the landing check with who set it, No check and the coordinator's change list with Revert, following iOS (`e41b55a383`, `bc61299579`). It does not yet draw a task's exemption.

**Smaller changes.** A person's `!` shell turn now runs in DeepSeek Harness sessions as it does on every other engine, in the worktree and not through the model, including `!cmd &` (`4b08af923e`). In the Orbit Cloud browser, closing the last tab no longer leaves the viewer on a black screen: Chrome starts again on the same display (`3f693fe7be`). Routing tiers Claude Haiku and Kimi K3 / K3.1 Pro by family on the engines without a table of their own, such as Cursor (`bd52265bb9`), and web Settings → Providers gets a Model tiers row of its own (`272e9d71d8`). The routing and web changes are already live on the server; the two runner changes reach machines with the runner built from this tag.

An operator will also notice that the apiserver unit suite no longer hides tests: `--test-force-exit` was dropped so every test is reported (`3d9bc8d89f`).

## Upgrade impact

- **Database migrations: thirteen, none dropping a column or renaming anything.** They apply on boot. The five the previous notes listed are unchanged; this range adds eight, listed with them in number order and flagged by what they write.
  - `1201_turn_outcome` adds three nullable TEXT columns — `conversation_turn.outcome`, `conversation_turn.error` and `session.last_turn_outcome` — and **two CHECK constraints** (`conversation_turn_outcome_chk`, `session_last_turn_outcome_chk`) holding the outcome to four words. Both are added NOT VALID and validated by `1202`. No default, so no row is rewritten, and no row is written. **Additive, with constraints.**
  - `1202_turn_outcome_backfill` **validates those two CHECKs** and **runs a batched UPDATE**: it walks `session` by id, 5000 rows at a time, committing each batch, and sets `last_turn_outcome` only where it is still NULL, from status and end_reason (`AWAITING_INPUT` → `ANSWERED`, `INTERRUPTED` with no end reason → `INTERRUPTED`, `FAILED` → `FAILED`, `SUCCEEDED` with `task_done` → `ANSWERED`; every other terminal row keeps NULL). It creates a procedure for the walk and drops it after the call; `conversation_turn` rows are not backfilled. **A backfill, not additive.** If a run stops halfway its committed batches stay: resolve it rolled back and deploy again.
  - `1261_session_release_cause` adds nullable `session.release_cause` and **one CHECK** (`session_release_cause_chk`) over fourteen values, NOT VALID here. No row is written, no default. **Additive, with a constraint.**
  - `1262_session_release_backfill` **validates that CHECK** and **runs a batched UPDATE over terminal rows** (`SUCCEEDED`, `FAILED`, `CANCELLED`), 5000 rows at a time: `finished_at` where NULL becomes `completed_at`, else `deleted_at`, else `updated_at`, and `release_cause` where NULL is set by a first-match rule (a LANDING session → `landing_settled`; an end reason → that reason; `FAILED` with an import cwd → `import_failed`; `FAILED` with a refused source → `setup_failed`; `FAILED` with `runner offline` → `runner_lost`; `FAILED` with `runtime not initialized` → `setup_failed`; `FAILED` with `cancel not honored` → `cancelled`; `FAILED` with a cancel requested → `turn_failed`; `CANCELLED` with a cancel requested → `cancelled`; otherwise `engine_exited`). Only NULL columns are written and no status is written. **A backfill, not additive.**
  - `1267_session_executing_event_at` adds nullable `session.executing_event_at TIMESTAMP(3)` and a column comment: no default, no constraint, no row written. **Plain additive.**
  - `1271_workspace_workflows_enabled` adds `workspace.workflows_enabled BOOLEAN NOT NULL DEFAULT true`. It is NOT NULL, but with a constant default, so no existing row needs a value and none is rewritten by hand. **Additive.**
  - `1310_project_landing_check_set_by` adds four columns to `project_codebase` (`landing_check_none` NOT NULL DEFAULT false, and nullable `landing_check_set_by`, `landing_check_set_by_session_id`, `landing_check_set_at`). **It adds two CHECK constraints** (`project_codebase_landing_check_none_chk`, `project_codebase_landing_check_set_by_chk`) and **runs one UPDATE**: every binding that already has a landing-check command or timeout is marked `OWNER` with no time, so a coordinator cannot change an existing value without a card (fail closed). Existing rows pass both checks. No drop, no trigger. Every statement can run twice.
  - `1350_task_landing_check_exempt` adds three columns to `task` (`landing_check_exempt` NOT NULL DEFAULT false, and nullable reason and session columns) and **two CHECK constraints** (`task_landing_check_exempt_reason_chk`, `task_landing_check_exempt_by_chk`) that every existing row passes with the defaults. No row is written.
  - `1390_project_setting_change` **creates a table**, `project_setting_change`, with its checks, an index, a partial unique index (a change is reverted at most once) and two foreign keys (one to `project` with ON DELETE CASCADE, one to itself). It adds one nullable column, `task.landing_check_exempt_owner_set_at`. The table starts empty and no row is written. No trigger.
  - `1400_owner_secret_saved_links` adds nullable `owner_request_secret.saved_secret_id` and `.runner_name` and `account_secret.last_used_at`, a foreign key (ON DELETE SET NULL) to `account_secret`, and a partial index. Existing rows keep NULL. No UPDATE or DELETE.
  - `1403_session_release_failure_causes` **drops and re-adds** `session_release_cause_chk` under the same name with two more values (`engine_failed`, `end_not_honored`), NOT VALID. **It replaces a constraint, so not plain additive, but it removes nothing a row holds and writes no row.**
  - `1404_session_release_failure_causes_validate` validates that CHECK; every stored value already passed the narrower list.
  - `1410_coordinator_handoff_successor` adds three nullable TEXT columns to `coordinator_handoff` (`successor_engine`, `successor_provider`, `successor_model`). No default, no constraint, no row written. **Plain additive.**
  - The comments in two files give an older number (`1270` and `1250`) than their directory names; the directory names are the ones that apply.
  - No migration drops a column, renames anything, or adds NOT NULL without a default. No migration adds a trigger. The one drop in this range is `1403`, which replaces `session_release_cause_chk` with a wider list under the same name.
- **Configuration: nothing to fill in.** No new variable is read from the operator's `.env`. The runner reads a new internal `ORBIT_WORKFLOWS` (`off` hides the workflow tool). The runner sets it for the MCP process it starts, so no one sets it by hand.
- **Runner and agent tools: the runner changes in the range the previous notes covered** (27 files under `src/runner-go/`). `orbit task create` and `orbit task update` take `--landing-check-exempt` and `--landing-check-exempt-reason`, and the tool descriptions for `task_create`, `task_update` and `project_update` say so (`b8f72cd659`, `833c77b3fe`, `094e47d1b5`). `project_request_start` takes no line (`12d11bc22e`). A session whose Agent has Workflows off is not offered the workflow tool (`bf9e51e23a`). The tool descriptions for codeless no longer say it decides landing (`a4e574e8b9`), and the operation catalog doc is regenerated (`1b1508bc67`, `a5e2e377b7`). **The runner served at `/dl` is built from this tag**, so a runner fetched from it has these tools. A runner older than this tag keeps working against this server: the server leaves the landing check out of an exempt task's LAND_TASK for it, and records the skip itself when an older runner lands without it (`0df436f29f`).
- **Runner and agent tools: the session-state range changes 20 files under `src/runner-go/`.** The beat now states, for each session the process supervises, what is executing in it — the engine's own turn, the subagents, the runner-hosted jobs and every background process — with the instant it was composed on the runner's clock, and the server replaces its inferred sets from it (`6421f34d62`, `6292f278a6`). `session_create(wait)` and `session_await` now wait for `SESSION_QUIESCENT`, with the presets `ALL_QUIESCENT_OR_ANY_NEEDS_ATTENTION` (the new default), `ALL_QUIESCENT` and `ANY_QUIESCENT` beside the unchanged settled ones; each predicate goes out under the lowest grammar it needs, so the old presets stay version 1, and the inline wait answers only once its watch has matched, so an inline answer and a wake decide by the same leaf (`c3260c968a`). `orbit watch create --predicate-version` takes 1 to 4 and describes `SESSION_QUIESCENT` (`c3260c968a`), and the operation catalog doc is regenerated for the new help. A runner that reclaims sessions at restart no longer treats a status word it does not know as terminal when the server's takeover answer has made it the lease owner (`a7a341811d`). **A runner older than this tag keeps working against this server:** a beat without the executing member writes nothing and the server's inferred sets stand (`6421f34d62`).
- **Clients:**
  - *macOS:* the beta users get the DMG and Sparkle appcast from this tag on the beta channel, with the hidden-app read gate, workflows block, Workflows switch, New workspace, the one SubAgent card and the landing check views, and from the session-state range the handover's "New coordinator runs on" picker on the Mac's sheet and a failed handoff's row, a session status word the build does not know decoded as ended instead of failing the session list, and the workflow finished-strip fix that makes OrbitApp build (`c67bc2624f`, `b1681e6a41`, `686e7b4961`).
  - *iOS:* TestFlight gets marketing version 0.1.261, with the build number as the commit count, with the same set, and the successor picker on the failed-handoff row (the iPhone confirm stays a system alert) (`c67bc2624f`).
  - *Android:* `versionName` `0.1.261-beta.65`, the next `versionCode` and `android-update.json` from this tag. It gets the Open-list delta reads, the stream-following session bar, the workflow block, New workspace, the copy-parity fix, the no-line start card and landing check views, "New coordinator runs on" on the hand-over confirm and the failed-handoff panel, and an unknown or missing session status that decodes to `UNKNOWN` and resumes as an ended session instead of throwing (`f95b34cad5`, `9776c038bf`).
  - No minimum client version is enforced and no one-time step is required on a Mac, iPhone or Android device.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE. `7ea5c175da` adds a security spec for the new Secrets page routes; it is a test, not a fix.

## Known limitations

- **The web's reduction in session-event reads is already in production, but the macOS and Android ones reach people only through this tag.** Until a client is updated it keeps the old read pattern (beta.64 measured 311 list reads in 10 hidden minutes on the Mac).
- **Main's PostgreSQL spec matrix and the Go runner job were red before this range's work.** `97f2ba8070` repairs the failures it names (a declared spawn env's home, the landing-schema frontier, the pinned project read count, and the fixtures of two revision-42 cases); no run in this range records them green, and this release was not cut from a green main (see below).
- **Until a machine's runner is upgraded to this tag, a session's executing sets still come only from the event stream:** an end report that never arrived leaves the session reading as working (`6421f34d62`).
- **`release_cause` is not yet constrained to be a failure cause exactly when the status is `FAILED`:** the migrations for that CHECK (`1405`–`1407`) are not in this release (`48eba2e170`).
- **A server rolled back to beta.64 does not enforce the new landing-check state** (see Rollback).
- **Android, macOS and iOS do not yet draw a task's landing-check exemption** (web does), and on macOS/iOS an exempt task's
  skipped landing check reads as failed; the project's landing check, No check and the change list with Revert are on
  all three (`bc61299579`, `c7b17038b8`).
- Commit messages and task evidence in this range state no other limitation, and none is invented here.

## Rollback

The previous tag is v0.1.261-beta.64, commit `47983e044cf7b6134ab785f8d419dff6516b2cff` (its tag object is `8f66ae333d6ad4878209a19eb15baa6f5a1140d8`). A server deployed from this tag rolls back to that commit; the native clients roll back by installing beta.64's build from its tag.

An application-only rollback to beta.64 is schema-safe. The five migrations add columns that are nullable or carry a constant default, one new table, two foreign keys, partial indexes and CHECK constraints, and beta.64's code neither reads nor writes any of them. Its writes still pass the checks: it leaves `landing_check_none` false, never fills the `set_by` or exemption columns, and `1310`'s one UPDATE only marks existing bindings `OWNER`. Nothing is dropped, so no backup or restore step is needed. Three behaviors do not roll back with the code: a task already marked exempt is no longer skipped by a beta.64 server, which runs the project's landing check on it; the owner's change list and Revert stay in the database but beta.64 does not show or write them; and an Agent with Workflows off keeps `workflows_enabled = false`, which beta.64 does not enforce. See [Release process](../docs/release-process.md#rollback-decision-and-procedure).

The eight migrations this range adds are schema-safe on the same terms. `1201`, `1261`, `1267` and `1410` only add nullable columns — `conversation_turn.outcome` and `.error`, `session.last_turn_outcome`, `session.release_cause`, `session.executing_event_at`, and `coordinator_handoff.successor_engine`, `.successor_provider` and `.successor_model` — with no default; `1403` widens one CHECK's list of values and `1404` validates it. beta.64's schema has none of these fields, so its code neither reads nor writes them, and its inserts leave them NULL, which every CHECK accepts. The two backfills (`1202`, `1262`) only wrote NULL columns, so the one value beta.64 does read that they change is `session.finished_at`: `1262` filled it on terminal rows that lacked it — the landing container's and the failed import's — and beta.64's code does read that column (the auto-retry grace and the landing observation's "every work session finished" test among others), so those rows now carry a timestamp beta.64's own writers would have left NULL. Two more behaviors do not roll back with the code: a handoff under way or saved with a successor pick is opened by beta.64 on the previous coordinator's engine, provider and model, because it does not read `successor_*`; and a watch stored under predicateVersion 4 (a `SESSION_QUIESCENT` wait, which is what `session_create(wait)` and `session_await` record now) is not a term beta.64 can decide, so it keeps its schedule until its TTL ends it, while a new runner's wait against a beta.64 server is refused by name (`PREDICATE_VERSION_UNSUPPORTED`) and returns the session as created with the reason under "watch" (`c3260c968a`).
