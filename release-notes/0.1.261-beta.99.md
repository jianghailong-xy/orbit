# Orbit 0.1.261-beta.99

## Summary

This release fixes the runner's Claude sessions after a compaction or a resume: a slash command such as `/compact` sent then is now run as a command instead of being answered as plain text. It also adds browser notifications — a browser registers as one more push device and gets every alert the phones get — and puts the rest of the web's right-hand panels on a canvas of their own, with a new dark palette. A released session waiting on its armed retry now reads RUNNING in every client, a project branch that cannot absorb main opens one line-sync item instead of reviving a DONE task, and a message whose translation failed can be cancelled on web, macOS and Android.

- **Runner: a Claude slash command goes through bare after a compaction or a resume (1dac5f274d).** The Orbit context-reset note (and any pending `!`-shell output or reply-file correction) was put in front of the next message, so a `/compact` sent after a compaction or a resumed session no longer started with `/` and Claude Code answered it as plain text. A slash command is now fed untouched, and what it would have carried waits for the next ordinary message; the runner reads only a leading `/name` as a command, so a path such as `/root/x is missing` is not one.

- **Runner: a Kimi plan review files Orbit's plan card (6e9b4b659f).** Kimi's ExitPlanMode approval arrived as an AskUserQuestion whose one question was the whole plan, so the owner read raw Markdown under a "Plan saved to:" path in the engine's own home. A single plan to approve is now an ExitPlanMode card (Approve → plan_approve, Keep planning → plan_revise), and the path line is dropped from both the plan and a choice between plans.

- **Server: a released session waiting on its armed retry is RUNNING (80a69fdd2a).** The owner ruled on 2026-11-26 that waiting for retry counts as the running state. `deriveSessionPhase` and the stored phase (migration 1667's trigger, now firing on `retry_at`) read a released session with `retry_at` set as RUNNING, still waiting on its WAKE, so every client words it Running · Retrying; a held session's armed retry stays IDLE, since RUNNING on a held row reads as a turn in flight. The shared session page keeps its waiting pace, since nothing streams until the retry revives the session, and its contract records the amended rule.

- **Server: one line-sync item when a project branch cannot absorb main (f4932af4bb, aee6b047d5, 5a8f8c19d2).** A MAIN_SYNC conflict was filed as the failure of whichever DONE task landed next, so a finished task was revived or reopened just to merge main. The conflict now opens one task-less INTEGRATION_CONFLICT about the line (IMS:<serial_key>) for the coordinator; the task stays DONE and its landing is queued again (MAIN_SYNC_HELD) behind the item; only a sync task filed from the item gets through, and its LANDED closes the item. The blocked-line detector also fires for a line-sync item with no sync task filed. A baseline fix whose own landing is still red is no longer re-queued: it queues nothing and the item is re-keyed to the coordinator. Legacy task-level items keep their old rule and the note's bridge (two are open on production).

- **Server: browsers register for Web Push (62c49e4e5c, 9b9210cdc1).** A browser is a third DeviceToken platform, `web`, behind the same `deliver()` path, so every alert kind, both Settings switches and the login-session rule apply unchanged. Settings → Notifications gains a "This browser" switch that subscribes the browser and registers it as one more device; `sw.js` shows each alert (not while an Orbit tab is in front), opens its page on a click, and closes approvals another device answered; sign-out unregisters the browser first. RFC 8291 encryption and VAPID are written on `node:crypto`, checked against the RFC's own test vector, and endpoints are limited to the browsers' push services so a registration cannot aim the server at an arbitrary host. Settings search finds the Notifications row where the server sends web push (94c62f4454).

- **Server: a withdrawn message keeps its files for the resend (e3c71ed6ed).** Attachments cascade with their turn, so a message taken back (queued or held Cancel, a steer discarded or withdrawn unread, the queue Stop empties) lost its files while every client puts them back in the composer by id, and the resend failed. Those doors now detach the files first, leaving them staged on the session like a composer upload; a turn a runner took in between gets its files back. The web workaround that re-downloaded and re-uploaded them is reverted (8888fd8410).

- **Server: the needs-you badge counts what the section lists (3b5a686fcf, 571e9b8949).** The Session list files a failed session with no retry armed under Needs you, but the workspace count left it out, so the badge read lower than the section; it now counts it. Conversely a failed member of a project is folded into its project row, which a failure does not light, so it is in no Needs you section; counting each made the badge far higher than the section (orbit-ws04 read 28) wherever a project had failed runs, so those are left out too.

- **Clients: a provider gateway's upstream timeout under a 406 is retried, and the retry card names the provider (dbe9112706, 4bad5a5a57).** DashScope answered a Qwen turn with `API Error: 406 Post "…/v1/messages": read tcp …: read: connection timed out` — its gateway timing out on its upstream. The leading 406 decided the turn was not retryable, so it died as a raw red line; the Go transport phrase is now a connection-failure group in shared, the runner and both clients, which the status check yields to, as ECONNRESET's does. The provider-unavailable and quota cards said "The qwen API" and "for claude" — the session's provider slug; each client now hands the card the name its composer already uses, so a key shows its own label and an engine sign-in shows its CLI's name.

- **Providers: a key knows its platform, and Qwen and Kimi take a Coding Plan (cd1107a3e5, 680003fde6, 58000d6f90, 56aff0c45b).** MiniMax, GLM and Moonshot each run an international and a China platform with separate keys, and a key from the other one came back as a bare "Invalid API key"; their presets now list both platforms, the connection test tries a refused key on the vendor's other one before calling it invalid, and the connect form asks which platform the account is on ("Switch to China" replaces "Save anyway"). Qwen's Model Studio now asks Beijing or Singapore the same way (the preset stays on Beijing). A Coding Plan key works only on its plan's own endpoint, so Qwen's connect page switches to a Qwen Coding Plan preset (its own endpoints and model list, with Alibaba's interactive-only rule shown), and Kimi's points to Kimi CLI's sign-in on a machine, because Kimi Code serves only the coding agents it lists. The connect form's Key type and platform switches now line up (c1ad2beee8).

- **Web: panels on a canvas, and the dark palette (2cd162c3c4, b0d46a19ad, f31929b4dc, 44171222e8, 1c9fc6fbff).** Above the drawer breakpoint the window is a standing grey canvas, the nav sits on it, and each page's content, the session list with its conversation and the right columns (project, session settings, task detail) are white panels with one radius, gap and elevation; the same treatment now reaches the Wiki's docked chat, entry drawer and over-page chat, the help drawer, Scheduled's inspector, Drive's details pane, a task over its project's page, and Settings, Admin and Help, whose nav sits on the canvas and page in a panel. The Wiki's directory column is sized to the panel. In dark, the session list sits a step below the conversation, the quietest text reaches 4.5:1, New session drops its blue, inline code is a light chip, and needs-you counts are amber numbers without a pill (option B); light is unchanged. Drawers take the menus' style (18px corners away from the edge, a hairline and the soft shadow), and the composer takes the panels' rim and shadow.

- **Web: the session header, tooltips and icons (fc31d44684, 9e60e8a40a, c03a5c0d01, ead75d1f3a, c1cd1d4b5f, 5b90314ec0, 3527b84eb3).** The wide-window session title is 17px, and beside it ⋯ and Share are 18px glyphs in 30px buttons, with Share as an open tray 14px from the ⋯; both use the app's Tooltip instead of the browser's grey title bubble. 40 of the app's 61 icon-only controls now take the app's Tooltip and keep their names as aria-labels (the 21 others show visible text, a disabled reason, or are not tips), and tooltips take the menus' 10px corners, padding and soft shadow. The ⋯ no longer jumps 10px left while its menu is open.

- **Web, macOS and Android: a message that failed to translate can be cancelled (077279b2db, b1784d57fa, 0efae23825).** A held message whose translation failed only offered Retry and Send as written, so a message the owner no longer wanted stayed in the conversation. Cancel now withdraws it through the existing `DELETE /sessions/:id/turns/:turnId` and puts what the owner wrote back in the composer; it is not offered on a session's opening prompt, which the server keeps, and the queued rows carry `opening` so that prompt gets no Cancel. macOS and Android read the files before the withdraw and stage them again as new uploads.

- **Web: smaller fixes (0f2a60fbf8, 503a4f0c86, 999f33cfed, 7052d93bae, 7844c0f6c7, 4ed568042a).** Settings and Admin's nav take the sidebar's width, so the page panel no longer jumps entering or leaving them. The account menu's end values and submenu arrow are centred on the row. Opening a project member from the column keeps the list on the coordinator's folder. ⌘D with a project row's menu open now runs the menu's project Complete instead of looking the id up among sessions. The Following chip leaves the session header, since a task the session waits on is already an eye in its Tasks card and any other wait is the Watching strip. Only Orbit Cloud workspaces wear the cloud; your own machines' workspaces keep the folder.

- **Release tooling: the Cloud runner image is pulled onto the node as soon as it is published (7868b1210e).** A runner's Pod pulls its image only as it starts, so the first runner on a new image waited for its 1.5 GB pull before any container started — 116 s on 2026-11-25, against about 9 s for the ones after it. The release now pulls the published image onto the production k3s node through orbit-ws03, by the digest a deploy writes into the profile.

- **Designs, boards and CI.** The range records the designs and boards behind these changes: the right column as its own window, the dark palette, the session title and header icon sizes, the composer edge, the Share tray, the workspace row icon, the Web Push design and its Settings shots, the translation-failure Cancel board, the DashScope 406 board, and the session list scale design with the owner's D1–D3 answers and T2 after T3 (452b8600bb, 03f289d40f, 9c2adcc82e). The session list scale and the Scheduled page's chat panel are designs and boards, not behaviour in this release; the owner chose the recommended option on all six Scheduled decisions (47bd5ce705, 36589ace1e, 64dadbe68c). CI: main's red docs check (a duplicate `### Drive` heading, MD024) and two pg specs are fixed (9228d4a26f), and the db-write inventory lists the attachment helper that was missing (24768da05e).

## Upgrade impact

- **Migrations:** three, applied by the apiserver on boot.
  - `1582_integration_main_sync_held` — **additive in what it changes:** it drops and re-adds `project_integration_job_event_enqueue_cause_chk` so an ENQUEUED event may carry the cause `MAIN_SYNC_HELD` beside DONE, RETRY, SKIP_CHECK, BACKFILL, BEHIND_WORK, BASELINE_HELD, DECISION and AUTOMATIC, and adds `project_integration_job_event_main_sync_held_chk`, which requires a `MAIN_SYNC_HELD` enqueue to be a LAND_TASK. It writes no row, rewrites no value, and drops no column or table.
  - `1656_device_token_web_keys` — **additive:** one nullable `web_keys` JSONB column on `device_token`. It writes no row; only web rows set it, and only when a browser registers for Web Push.
  - `1667_session_phase_retry_running` — **not additive: it writes rows.** It replaces `session_phase_of` with a six-argument form whose released branch reads RUNNING while `retry_at` is set and IDLE otherwise (1611's five-argument form is left in place, unused by the trigger), replaces `session_phase_from_facts` to call it, and recreates trigger `session_zz_phase` to fire on UPDATE OF `retry_at` as well, so arming and clearing a retry moves the phase. Then, in the same transaction, it sets `phase` = 'RUNNING' on every released row with `retry_at` set — a few rows at most, the retries armed at deploy time — and writes `phase` alone so no row trigger announces an end again. The trigger is created under SHARE ROW EXCLUSIVE, asked for 2 s at a time, 1 s apart, up to 45 tries; the functions lock no table, and the UPDATE touches only the armed released rows.
- **Backfill:** not a separate step. 1667's fill runs on boot and finds nothing on a database with no armed retry; 1582 and 1656 write no row.
- **Configuration:** three optional Web Push variables, `WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_PRIVATE_KEY` and `WEB_PUSH_SUBJECT`, passed through by `docker-compose.yml` and documented in `.env.example`; empty leaves browser notifications off. Web Push needs HTTPS and outbound internet. Generate the VAPID pair once (`npx web-push generate-vapid-keys`) and keep it: a new pair makes every browser subscribe again. The web image now serves `/sw.js` from the site root with `Cache-Control: no-cache`, so no operator step is needed for the service worker.
- **Server:** the phase rule above; the needs-you tally now counts failed sessions nobody is retrying and leaves out failed members folded into a project row; a MAIN_SYNC conflict opens one task-less line-sync item and queues the held landing (MAIN_SYNC_HELD) behind it instead of reviving a DONE task; the doors that withdraw a message detach its files first; a browser registers as DeviceToken platform `web`. No API route, field or payload changes shape or name, and no session field is removed in this release.
- **Runners:** the runner served at `/dl` is built from this tag. It carries the slash-command fix, the Kimi plan card and the 406 connection-failure classification. A runner older than this release keeps the old behaviour in all three: a slash command after a compaction or a resume is still answered as plain text, a Kimi plan review still arrives as a raw-text question, and a DashScope gateway timeout under a 406 is still not retried.
- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. There are no iOS app source changes in this range. A client older than this release shows the provider slug on the retry card, does not classify the 406 timeout as a connection failure, and lacks Cancel on a message whose translation failed; the browser notifications switch and the web's canvas, dark palette and header changes arrive only with web's deploy.

## Security fixes

None in this release.

## Known limitations

- Browser notifications need HTTPS and outbound internet, and the VAPID pair must be set; while `WEB_PUSH_*` is empty the server sends no browser push. A new VAPID pair makes every browser subscribe again.
- The service worker shows no alert while an Orbit tab is in front (owner decision D3 = A), so a subscribed browser stays quiet while that tab is open.
- A released session waiting on its armed retry reads RUNNING from this release. During a rolling hand-over an apiserver one release older publishes IDLE for those rows from its own derivation; the migration's header records that no reader acts on the stored column.
- The two legacy task-level MAIN_SYNC items open on production keep their old rule — the DONE task is revived or reopened for the merge — until they close; a new conflict uses the line-sync item.
- A runner older than this release keeps the slash-command, Kimi plan-review and 406 behaviours (see Upgrade impact). A client older than this release keeps its old cards and copy.

## Rollback

Previous tag v0.1.261-beta.98 (`b180423345e03b0143568459601bbceb444ec896`). Application-only rollback is **schema-safe for this release**: 1582 only swaps and adds CHECKs and writes no row; 1656 adds a nullable column a beta.98 server does not read; and 1667 writes only `phase`, whose readers are this release's derivation and the stored rule — a beta.98 replica derives and publishes IDLE for a released session from its own code, and the migration's header records that no reader acts on the stored column. Leave the objects in place: the release records no down-migration for 1582 or 1656. 1667 records its own rollback in the migration header — re-run 1611's `session_phase_from_facts` and `session_zz_phase`, then `UPDATE "session" SET "phase" = 'IDLE' WHERE "finished_at" IS NOT NULL AND "phase" = 'RUNNING'` — and `scripts/session-turn-state-phase-down.sql` drops its six-argument form with the rest of the phase machinery.

Client rollback is to the last published builds, v0.1.261-beta.98's DMG, TestFlight build and `orbit-android-0.1.261-beta.98.apk`. A beta.98 client keeps working against this release's server: no API shape or name changed, and the phase and needs-you counts are served, so it shows its own wording for them; it lacks the new cards, the browser switch and Cancel, and a runner from this tag serves it as before.
