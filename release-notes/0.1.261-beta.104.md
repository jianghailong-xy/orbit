# Orbit 0.1.261-beta.104

## Summary

Drive gets its own chat: the owner manages files by talking to an agent, with each turn's changes drawn as one card that Undo reverses, and the web, macOS, iOS and Android clients all host it. Alongside that, the new-session screen grows a single "place" pill for picking the workspace and folder, a sent message now waits in the transcript as a `Sending…` bubble instead of behind a spinner, moving a session to another workspace is one server-side request, and the owner is pushed once when a decision card becomes theirs.

- **Server and web: Drive chat (d595dca490, fc5a34a225, 95d0ca3676, 5afbca5c81, b9d77d2d74, 97bd985956, b9a682e1e7, 1436bcf4ce, c15f8a2a64; migrations 1680, 1681, 1700).** `POST /api/drive/chats` opens an ordinary session with `opened_by` `DRIVE_CHAT` and files the owner's first turn, with the open folder and selected entries as ids, in the same transaction; `GET /api/drive/chats` lists the owner's Drive chats Open (needs you, working, last spoken) then Completed, 50 a page, with a default "Runs in" workspace (the last Drive chat's, else Orbit Cloud, else a readable 400). Each delivered message carries an `<orbit_drive_chat>` note built from those ids, with the standing guidance resent when its text changes. Every drive write a Drive chat's agent makes is recorded in its turn's change group (new folder, new file, move, rename, Trash, edit); Undo reverses a group last-first and skips, with a reason, any item changed since. A chat's move or rename onto a live file is refused naming both files and kept as a Keep both / Replace question, and past a turn's 200th change further organising writes are held as a PENDING group until Apply. On Orbit Cloud a Drive chat changes the drive only through `drive_move`/`drive_put`/`drive_delete`, because a Docker mount cannot name the writing session; a mount write naming no session now counts as the chat's when it is the runner's only live session (b9d77d2d74), and a refused Drive-chat mount write fails `EEXIST`/`EDQUOT` and carries the door's own words in `errors.log` (97bd985956). A crossed-out folder chip sends `noFolder: true`, so a first turn is filed with no folder rather than the drive's top level (95d0ca3676).

- **Web: Drive hosts the chat as its right-hand panel (dde6868351, af4f9f9adf, cbf7fdd17c, ff56ca6c37, 47c42e9d20, e6a723c693, 1dd0017081).** The Wiki's panel, history, composer and round button were generalised by origin, so Drive can host the same chat: at ≥ 1200 px Drive opens it on the chat that needs the owner, else the most recent open one, else New chat with Runs in on the server's default workspace, and ✕ is kept per account until the round button is pressed. A Drive changes card offers Show all and Undo or Apply, a Replace a file? card asks before an overwrite, rows are marked New/Moved/Renamed until opened, a multi-select is sent as one files chip of `entryIds`, details overlay the list while the chat is open under 1760 px, and held groups and open questions count in the round button. Each change card is drawn after the last event of its turn, and the fixed "Recommended" line is gone because the question carries no advice from the agent (ff56ca6c37).

- **Web: one place pill picks the workspace and folder, and its menu nests folders under workspaces (eba7a91fb3, aebd696f31).** The grey "in [workspace] › [folder]" line, whose "⊘ No folder" read as an error, is now one bordered pill that names the folder only when one is picked; its menu lists workspaces as the top level with each workspace's folders as a submenu, this workspace first, and the search is pinned over the list (the shared Menu gained a header slot, and a submenu row shows selected). The old one long menu scrolled folders and the search off the bottom with many workspaces.

- **Web, Apple and Android: the new session page drops "Send a task to get started." (b06a46fa70).** Under the engine the page now says only where the session runs: the line is gone on every client, and the native drafts also drop the grey model name under it, which the composer already shows.

- **Web: a sent message waits in the transcript as a `Sending…` bubble (c373c43665, fe05c398c1, 194e70eec8, b7929b1b73; server 6bee03b9e5, migration 1730).** Pressing Enter moves the message out of the composer at once into a dimmed `Sending…` bubble; a send with no answer in 20 s ends and reads `Not sent` with Retry (the same `clientTurnId`, so it cannot arrive twice) and Put back, and a refusal says the same with the server's reason in the tooltip instead of a toast. The answer never touches the box, so text typed while a message is on its way is no longer wiped. On the new-session page the first message leaves the box at the press and waits in the engine picker's place, then the session opens, or reads `Not sent` with Retry and Put back. `POST /sessions` now takes an optional `clientRequestId`, so a Retry that reaches a create whose answer was lost answers with the session the first one made rather than opening a second (also when two race); migration 1730 adds a nullable `session.client_request_id` and a partial unique index per owner. No turn clock or Send spinner is drawn while a message is still sending (194e70eec8).

- **Server and clients: a move releases an idle session on the server, and a moved session reads as idle (1925d64535, d977ed7426, dc779391e2, 534bae9e4d, a84967ba78, 19c28694ff, dbbab084f0, 8e024d6f2d).** `POST /sessions/:id/move` now asks the session's, the target's and the folder's rules first, then lets an idle session go, waits up to 45 s for its runner to release it (which is when uncommitted work is committed), and moves it; a session whose end is already under way is waited for instead of refused, and no move refusal speaks of ending any more. The web dialog and coordinator's Change, the Apple Move panel, Change workspace and who-fixes-it card, and Android's directory move all send one request with the button reading Move and the progress line Moving… instead of ending the session, polling and then moving (the Android client waits up to 60 s, since OkHttp's 10 s read would cut the server's release wait). The move writes its own end reason, `moved`: the finalize and reaper still settle it `CANCELLED`, the next message still resumes it, and a landing still reads it as a person's end, but clients no longer draw a moved session as Ended — no Ended mark, no "Session ended" banner, and it reads as awaiting input in its header word and list glyph (the web, Apple and Android changes above; board `docs/mocks/session-move-released`, option A).

- **Server: decision cards push the owner once (8b37672bf4, 7f71262efa, 639e9c67df, 47e5d5e598; migration 1720).** Evidence cards, owner confirmations after a review ends, held criteria decisions, unconfirmed standard sets, done requests and record-as-done became the owner's with no push — several by time passing or another session ending. A sweep on the reconcile tick now reads the same rows the Needs-you count reads and pushes each card once, claimed in the new `owner_card_push` ledger, and the badge counts them. A coordinator's raised confirmation claims the same ledger key, so it is not pushed twice. The new `decision-card` push is now named and routed on Android (whose parser refuses an unknown kind and requires the session), routed explicitly on iOS, and opened from the payload on web, with a shared fixture sample generated from the real send pinning the wire shape on all three.

- **Server: a session's title and its recap use only the server's DeepSeek key (d25cacaca3, 4348f9b54e, 105b4b6704).** Without `DEEPSEEK_API_KEY` a session keeps the title cut from its first prompt: the server no longer spends the session's provider key on naming, and a claim no longer asks the engine running the session to name it. A recap is cosmetic and no longer costs the owner's provider quota, so without the server's DeepSeek key `recapEnabled` is false and every pass, settle and refresh stops before asking a model. The held-key helpers, their specs and the now-dead engine-naming acceptance script go with it.

- **Permissions: "Always allow" derives a narrower rule, and a schedule's deny patterns see inside substitutions (624c8fc3a5, 7bd6202a6f, dd4094a2c7, 8ff1d45254; ports 8042a51c89, e31b4df283, 8a6f5f7958).** Production had saved `cd src:*`, `fi:*`, `worktree list:*` (from inside `$(…)`), `ls OrbitKitTests:*`, `echo APPLIED_OK:*`, `cp:*` and `export:*` from six approved reads, and since 11-08 a standing grant can let a Cursor command out of the sandbox; the shared derivation now skips keywords, never reads inside substitutions, keeps a second word only for sub-command programs, and refuses programs that change files or the environment (`sh:*`, `python3:*`, `find -delete`/`-exec`, `sed -i`, `bun`/`deno run`, `npm exec`, `pnpm`/`yarn dlx`, and now `nohup`, `timeout`, `nice`, `command` and `builtin`). Saved rules now also cover commands with the harmless `2>/dev/null`, `2>&1` and similar output-discarding redirections, which the matcher used to refuse. The shared rule, its fixture, and the terminal, OrbitKit and Android ports change together. The derivation change made `bashSegments` keep `$(…)` and backticks whole, which would hide `gh pr merge` in `echo $(true; gh pr merge 1)` from a schedule's deny patterns, so only rule derivation reads substitutions whole now (8ff1d45254).

- **Runner: sandboxed Cursor Auto reads outside the workspace without a card, and refuses package installs (354f78f97d, e2ba44387d).** With the session sandbox in force the OS already refuses writes outside the writable roots, so the workspace-path check only turned reads into cards; every command now gets the sandboxed high-impact checks the inline branch applied, and `git worktree list` is routine there. Review found `npm i lodash` and `brew install x` still allowed with the sandbox in force, so the sandbox-only marker now names the common install forms, `osascript` and `kubectl`. The unsandboxed path, DSH and Codex are unchanged.

- **Server: a scheduled check still accepts an older client's per-segment prefix (173b731625).** `checkOnlyRuleRefusal` accepted only what `bashCommandRules` derives, so an un-updated client's `python3:*` on a scheduled check's card would have been refused; it now also accepts the plain per-segment prefixes clients derived before, since only the exact command is written.

- **Apple: the place pill with a native folder submenu, and the iOS draft no longer re-renders without end (0ba372f611, 210ca8051b, 246c3c4c85).** The native draft gets web's place pill: one bordered pill naming the workspace, and the folder once one is picked, opening one menu of workspaces then folders; it replaces the macOS-only workspace switcher sheet, a folder pick refiles the draft in place, and a workspace with folders opens them as a native submenu under None, this workspace first. A draft refiled from its place pill took `pendingDraftText` inside a page body, which made the outgoing and incoming compose pages on the iPhone's stack invalidate each other forever (100% CPU); that handoff mailbox is no longer observed.

- **Apple: Drive chat beside Drive on iPad, Mac and iPhone (5f8f6d85a3, b9a5f57d27, 51da90cb1b).** The Wiki chat's model, panel, composer, history and round button are generalised by `ChatOrigin` and docked on Drive — a third column on iPad and Mac (open by default, ✕ kept per account) and a two-height sheet on iPhone — with change and overwrite cards after their turn, folder/file chips and New/Moved/Renamed row marks. OrbitKit carries the Drive chat's reads and writes, the web's copy and card rules, the attachments and a transcript slot for per-turn cards. The folded inspector's round button now sits at the column's bottom right rather than its middle.

- **Android: Drive chat, the place pill and a workspace drill-in (7f80e2867e, b890bd2551, b19d6228d6, 2b34a08dd4, 0e0a4db1dc, 66ea11b052, b799ed9dd3).** Android gets the Drive chat models, rules and API in core, and the sheet and round button per the native board: a chat written once by origin (round button, non-modal half/full sheet, title menu with New chat and history, chips, cards) hosted by Drive — the button over Upload on folders and files, a new chat through `POST /api/drive/chats` with Runs in and examples, the session reader embedded with each change and overwrite card after its turn, Undo/Apply/Keep both/Replace, row marks until opened, and the folder carried as `driveContext` on every later message. The snackbar now clears the chat's round button, so Undo is not covered. The new-session place pill is one bordered pill opening one menu of workspaces then folders, and with many workspaces the menu lists workspaces alone, this one first, with a workspace's folders opening in place under None and a way back.

- **Clients: small fixes across the three clients (f726995e4f, eac9046fca, 12796a69b0, 0df5c90dd1, a465af06cb, 8b3828934f, 4c2d4fb908, 396f9a0ace, 19c28694ff, 842c93d189, fded91788c, 1031581a52, b5adf964d7, fbfa3527af, 013f479c5b, f4bac10e68).** The task panel beside a conversation no longer writes `?task=<id>` into the address; the open task is held beside the conversation for the badge and transcript links alike, and a pasted `?task=` still opens its task. On web the task panel's title gets its own row under Run now, more and close, so at 420 px identifiers no longer split mid-word, model and cost are one meta item, and the judgment chip stays on one line; the Apple clients join model and cost and keep the chip on one line (the title already had its own row there), and Android gives the title its own row too. The project sessions column's ✕ moves to the top-right, as every other panel's is. A running task's folded Tasks row shows the spinner alone on web, Apple and Android. An idle session that a watch or wake-up will resume draws as plain Idle on all three clients, with no "Waiting to resume" row line and no "Will resume" mark (a queued run with an armed retry keeps the mark), and an Apple idle row with nothing to preview now says Idle rather than the old "Waiting to resume". The evidence card's head says when its version was submitted ("submitted 7:59 PM") on web, Apple and Android, read from the pending row's `submittedAt`.

## Upgrade impact

- **Migrations:** five, all **additive**; none destructive and none requires a backfill.
  - `1680_drive_chat_session` — adds nullable `session.drive_chat_prompt_digest` and `conversation_turn.drive_context`, and drops and re-adds `session_opened_by_check` widened to include `DRIVE_CHAT` (re-added `NOT VALID`, so nothing is scanned). The check is widened, never narrowed; every existing row reads NULL in both new columns.
  - `1681_drive_chat_session_index` — validates the widened check and builds the partial index `session_drive_chat_owner_idx` `CONCURRENTLY`; it drops any invalid same-name index first (under a short `lock_timeout`).
  - `1700_drive_chat_change_group` — creates four new tables, `drive_chat_change_group`, `drive_chat_change`, `drive_chat_held_change` and `drive_chat_question`; nothing older reads or writes them.
  - `1720_owner_card_push` — creates the `owner_card_push` ledger table and its unique `(owner_id, card_key)` index; history only, no existing row is read or rewritten and no trigger is added or changed.
  - `1730_session_client_request_id` — adds the nullable `session.client_request_id` and a partial unique index over the rows that carry one, per owner; no row is rewritten.
  So an operator needs no one-time step, no `--stop-then-start`, and no manual resync. All are safe to run twice.
- **Backfill:** none.
- **Configuration:** none added or changed in this range.
- **Server:** new Drive chat routes (`POST /api/drive/chats`, `GET /api/drive/chats`) and the Drive change routes (change groups, Undo, Apply, the overwrite question, and the drive-list reads they use) are **additive**; no existing route, field or payload changes shape or name. `POST /sessions` accepts an optional `clientRequestId` (omitted by older clients, which keep working). `POST /sessions/:id/move` now releases an idle session itself, waits up to 45 s for its runner, and writes the new end reason `moved`; the legacy wire words are unchanged. Session titles and recaps now require the server's `DEEPSEEK_API_KEY`: without it, a session keeps its first-prompt title and `recapEnabled` is false — this is a behavior change for a deployment that relied on the session's own provider key.
- **Runners:** the runner served at `/dl` is built from this tag. This range changes runner-go code: the terminal's "Always allow" rule derivation now follows the shared rule (8042a51c89), sandboxed Cursor Auto gets the full high-impact checks and refuses common package-install forms (354f78f97d, e2ba44387d), and the Drive-mount daemon maps a refused Drive-chat write to `EEXIST`/`EDQUOT` and logs the door's words (97bd985956). An older runner keeps working; a move's server-side release waits on whatever runner the session has.
- **Clients:** web arrives with the deploy of this commit; macOS (beta-channel DMG), iOS (TestFlight) and Android (APK) come from this tag. An older client than this release keeps the two-step End-and-Move flow, the grey folder line instead of the place pill, the "Send a task to get started." line, the message left in the composer behind a spinner instead of the `Sending…` bubble, the Ended look for a moved session, and the "Waiting to resume" line and mark, and lacks Drive chat and the evidence-card submit time.

## Security fixes

- **"Always allow" no longer saves an over-broad rule (624c8fc3a5, 7bd6202a6f, dd4094a2c7, 8ff1d45254; ports 8042a51c89, e31b4df283, 8a6f5f7958).** A standing grant could save `sh:*` or `python3:*` (covering every script), a rule read from inside `$(…)`, or `cp:*`/`export:*` (changing files or the environment), and since 11-08 a standing grant can let a Cursor command out of the sandbox — so an approved read could later authorise an unrelated command or a file change. The shared derivation now skips shell keywords, reads no substitution, keeps a second word only for sub-command programs, and refuses programs that change files or the environment; the same rule is ported to the terminal, OrbitKit and Android. Users on an older client or runner still save the old, broader rules.
- **A schedule's deny patterns see inside command substitutions again (8ff1d45254).** The derivation change had made `bashSegments` keep `$(…)` and backticks whole, which would hide `gh pr merge` in `echo $(true; gh pr merge 1)` from a scheduled check's deny patterns; only rule derivation reads substitutions whole now, so a denied command cannot be hidden inside one. A deployment that ran only the intermediate derivation was exposed; this release ships the corrected one.

## Known limitations

- A Drive chat never replaces a live file: a move or rename onto one is refused and kept as a Keep both / Replace question (fc5a34a225).
- Past a turn's 200th change, a Drive chat's further organising writes are held in a PENDING group until the owner presses Apply (fc5a34a225).
- On Orbit Cloud a Drive chat changes the drive only through `drive_move`/`drive_put`/`drive_delete`, because a Docker mount cannot name the writing session (5afbca5c81).

## Rollback

Previous tag v0.1.261-beta.103 (release commit `4c2c0b9d5632c55976b34472169dc77a9b8d73b9`, whose source is `eba32202425c08f3a49c4a50f0dbe36bb399a3bc`). Application-only rollback is **schema-safe**: all five migrations in this range are additive — two new nullable columns, one widened `opened_by` check, five new tables and two new partial indexes — so a beta.103 server reads neither the new columns nor the new tables, never writes `DRIVE_CHAT`, and finds every check it knows still satisfied. No down-migration or backup/restore step is needed; deploy the previous commit for the server and web together.

Client rollback is to v0.1.261-beta.103's DMG, TestFlight build and `orbit-android-0.1.261-beta.103.apk`. A beta.103 client keeps working against this release's server — every payload it reads keeps its shape, and it omits `clientRequestId` — but it uses the two-step End-and-Move flow, lacks Drive chat, the place pill, the `Sending…` bubble and the evidence-card submit time, and draws a moved session as Ended.
