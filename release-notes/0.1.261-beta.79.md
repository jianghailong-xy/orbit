# Orbit 0.1.261-beta.79

## Summary

**This is the first release since v0.1.261-beta.75 to publish.** v0.1.261-beta.76, beta.77 and beta.78 were tagged, and
their iOS TestFlight and macOS DMG jobs built, but each one's Android job failed — beta.76 and beta.78 on Maven Central
answering GitHub's runners `429 Too Many Requests`, beta.77 on a test since fixed (`45fe88728d`) — so none published a
GitHub Release, the macOS beta channel or an Android update. Everything their notes describe ships here: read
`release-notes/0.1.261-beta.76.md`, `0.1.261-beta.77.md` and `0.1.261-beta.78.md` for it, among them the worktree bar
counting a session's work in commits on iOS, iPadOS, macOS and Android, and the Orbit Cloud browser's agent tools and
sign-in card.

**Android builds no longer depend on Maven Central answering every request.** `src/android/settings.gradle.kts` lists
Google's mirror of Maven Central (`https://maven-central.storage-download.googleapis.com/maven2/`) before
`mavenCentral()`, for plugins and dependencies; an artifact the mirror lacks falls through to Maven Central
(`442c720344`). Builds stay cache-free.

**Since beta.78:** an engine CLI's sign-in tab in the Orbit Cloud runner's browser closes itself once the sign-in
succeeds (`1be368a6ee`), and the web closes the browser viewer's tab with it (`7e19c474a2`); a web tab showing one
workspace's Open list now reads it only when a hint names that workspace or none, from Open-list counters keyed by
workspace (`971cd546b8`, `a4bc1930af`, `1ff149da6a`); and the hint tick reads no landing-rooted rows and keeps request
pairs inside one workspace (`dcb5180642`, `c482f20901`).

## Upgrade impact

- **Database migrations:** one since beta.78, `1464_open_list_scope_keys`. It adds no table or column: it replaces the
  Open-list counter trigger functions (`open_list_scope_key`, `open_list_bump_session`, `open_list_bump_via_session`,
  `open_list_bump_owner`, `open_list_bump_watch`) with `CREATE OR REPLACE FUNCTION`, so a write in one workspace bumps a
  counter key naming that workspace (`<source>@w:<workspace>` or `<source>@c:<workspace>`); the read side sums the keys
  per base source, so the list version reads as before (`971cd546b8`). The migrations beta.76–78 add are listed in their
  notes (`1237`, `1393`, `1432`, `1433` are additive).
- **Configuration:** none required.
- **Runner** (`src/runner-go`): changed since beta.78 (`1be368a6ee`, the sign-in tab closing). The runner served at
  `/dl` is built from this tag once a production deployment carries it.
- **Clients:** macOS (beta channel), iOS (TestFlight) and Android get everything beta.76–78 described plus the above.
  Android `versionName` `0.1.261-beta.79`.
- **Build:** Android resolves dependencies through the mirror first (`442c720344`); no operator action.

## Artifacts and verification

The tag is v0.1.261-beta.79, the release commit on `main`. From this tag `.github/workflows/release.yml` publishes the
macOS signed and notarized DMG with the Sparkle appcast (beta channel), an iOS TestFlight build, the Android signed APK
with its `.sha256` and `android-update.json` on the same GitHub Release, and from the supply-chain job the runner
binaries, SBOM, provenance, `release-manifest.json`, `SHA256SUMS` and `version.json`.

Checks a commit message records: `442c720344` records that with an empty Gradle cache and `--refresh-dependencies`,
`:app:testReleaseUnitTest` (`CommitsLogicTest`, `WaitingCardHoldShellTest`) passed with every artifact downloaded from
the mirror and none from `repo.maven.apache.org`. No other commit since beta.78 records a release-workflow or client
build result; this release claims none beyond it.

## Rollback

The previous published release is v0.1.261-beta.75. Client rollback means installing beta.75's builds, which lose
everything beta.76–79 added. On the server, `1464` changes how the Open-list counter triggers key their writes; its
commit does not say how a server from before it reads workspace-keyed counters, so check that before rolling the
apiserver back past it.
