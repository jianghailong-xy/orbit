# Orbit 0.1.261-beta.18

## Summary

- **A machine's setup card asks for one folder name, in home.** The Folder step on a machine with no
  workspace is now a single field prefixed with the machine's home directory (`/root/`, `/Users/<you>/`).
  A folder already there is used as it is; one that isn't is created as the session starts. The
  register-directory suggestion, "A new folder" under `~/orbit-repos` and "Another folder" are gone (web,
  Mac/iOS, Android). The runner in this release declares `create-workdir/v2`, which lets it create the
  folder directly in home; a runner from before it keeps the `~/orbit-repos/` prefix until it updates.
- **Composer: Tab takes the optimized prompt** (web and Mac).
- **Android: Scheduled.** Scheduled tasks are in the drawer, with their timeline, detail sheet, quick-add
  line, schedule cards in a conversation, and their place in Waiting on you.
- Fixes: a background Agent's end is reported under its launch call (runner); a background process no
  longer takes a session row's recap (clients); a new session's opening held for translation draws once,
  the decision strip points at a coordinator's open question, and the account menu's submenus draw rows at
  the menu's height (web).

## Upgrade impact

- **Database migrations.** None.
- **Runners.** This release changes the runner (`create-workdir/v2`: an Orbit-named new folder may be
  created directly in the home directory, never home itself, and still inside the repos root). Runners on
  the beta channel move to 0.1.261-beta.18 once the server is deployed after this tag; until a machine
  updates, its setup card keeps the `~/orbit-repos/` prefix.
- **Server.** The server that handles `create-workdir/v2` (aa6fff481) is already deployed; nothing more is
  required for it.
- **Configuration.** No changes required.
- **Clients.** Each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261,
  build number = commit count) and Android via `android-update.json` are offered it.

## Security fixes

None in this release.

## Known limitations

- The Mac/iOS setup card change was not compiled before this tag: the release run's `dmg` and
  `testflight` builds are its first compile. Its OrbitKit tests were updated but not run.
- A machine whose runner predates this release still shows `~/orbit-repos/` as the Folder step's prefix
  until it updates itself.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.18` and tag `v0.1.261-beta.18`. This tag publishes the
macOS DMG and Sparkle payload (beta channel), the iOS TestFlight build, the runner binaries, and
`orbit-android-0.1.261-beta.18.apk` with its `.sha256` and `android-update.json` on the same GitHub Release.
The runner change landed with its Go tests passing; the web change with its vitest suites passing; the
Android change with its JVM unit tests passing (MachineSetup, its copy parity with Swift, and the first
workspace shots).

## Rollback

Roll back to 0.1.261-beta.17 (d358c745c551e880ac72e7b4a1075e5a87a71fdc). No migrations, so an
application-only rollback is schema-safe. A runner rolled back to beta.17 stops declaring
`create-workdir/v2`, and its setup card returns to the `~/orbit-repos/` prefix. Runners do not move back by
themselves: roll them back with the `/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
