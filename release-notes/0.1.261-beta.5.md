# Orbit 0.1.261-beta.5

## Summary

The work merged since [0.1.261-beta.4](0.1.261-beta.4.md), on the beta channel.

- **A machine's "N of M running" counts sessions held by a background job.** When a runner decides whether
  to take new work, it counts a session as using one of its slots in two cases: the session is running a
  turn, or the session has its own runner-hosted background jobs (`bg_run`, kind job) still running. The
  machine page counted only turns, so a full runner could read "12 of 16 running" while new sessions
  stayed queued. Each heartbeat now names the sessions held only by background jobs, and the count
  includes them. A session counted both ways counts once.
- **Top-level sessions are told when to use `delegate`.**
- **A project row waiting on you opens the waiting session at its card** (web and iOS).

## Upgrade impact

- **Runners update themselves.** `0.1.261-beta.5` orders above `0.1.261-beta.4`, so runners self-update
  from `/dl` once a server built from this tag runs. A busy runner waits until it is idle. A runner shows
  its background-job sessions as running only after it updates. Until then the server counts that runner's
  turns alone, as before.
- **Database migrations:** `0780_runner_presence_background_job_sessions` adds
  `runner_presence.background_job_session_ids` (`UUID[] NOT NULL DEFAULT '{}'`). This is a catalog-only
  change on an UNLOGGED table, and the apiserver applies it on boot.
- **Configuration.** No changes required.
- **Clients.** macOS users who enabled "Receive beta updates" get this build. iOS ships to TestFlight
  (marketing version 0.1.261, build number = commit count). Android offers the APK to every install via
  `android-update.json`.

## Security fixes

None in this release.

## Known limitations

- The running count includes background jobs only for runners on 0.1.261-beta.5 or later.
- The known limitations of [0.1.261-beta.4](0.1.261-beta.4.md) still apply.

Checks run for the running-count change (task 34xZM2rNjWmzSGUz4QCH9):

- the runner's slot-holder and link-heartbeat tests;
- the full runner Go suite;
- the link-gateway heartbeat tests;
- 34 affected pg specs, among them `runner-presence.pg.spec` (4b) and `link-heartbeat.pg.spec` 14;
- the apiserver type check and the migration-ledger spec, run on the merge into main.

## Rollback

Roll back to 0.1.261-beta.4. The one migration adds a column with a constant default, so an
application-only rollback is safe, and older code ignores the column. Runners do not move back by
themselves: roll them back with the `/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
