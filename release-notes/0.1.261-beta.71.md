# Orbit 0.1.261-beta.71

## Summary

This release is about **Pause and Resume on the project row**, about **closing a failed merge with ✕**, and about **the server reading a session's release from one fact of the row instead of from its status word**. The range is `v0.1.261-beta.70..origin/main` (`7cb3bcdce4`).

**A project row pauses and resumes.** The row's second line now reads 2a/2b and carries a grey bar while paused, its first swipe slot (and its menu) follows the project's state — Pause, Resume or Complete — a full swipe fires nothing, Pause toasts with Undo on macOS (on Android and web the toast copy follows design §6), and Resume goes through the fuse door at the daily limit on web and Android. It is the same row on web (`07478dc1d9`), macOS (`10442167df`, `b51e26bc9c`) and Android (`4698166f48`, `dc6a7578a6`); `GET /projects/sidebar` now sends `pausedAt`, `pausedReason` and `fuse`, read in one statement for the whole page, and a daily-limit pause or resume publishes `project.changed` so other tabs and devices re-read the rail (`5e8d008969`).

**A failed merge closes with ✕.** A refused push or a conflict used to leave its red strip or section forever. The new `POST /sessions/:id/merge-failure/dismiss` clears the stored failure, so every client shows Merge (or In main) again (`ffb81f79be`); web's strip (`3b8edb89a8`), the Apple apps' worktree-bar section (`3d1c720ed4`) and Android's section (`335c84eec1`) each clear at once, call the endpoint and reload, and put the section back with a toast if the call is refused.

**A session's release is one fact of the row.** `session.finished_at` now means "released", and a failure is a fact of the turn that carried the release, not a stored cause of the session (`59721c967e`, `7d66046455`). Every server reader that compared a terminal status — send, stop, steer, merge and commit gates, the runner leases, the wake and credential gates, the failure readers of the work, the coordinator handoff sweep, the wiki and schedules (`a6f807633c`, `10bcf269ec`, `c055fded9c`, `3124a00a8e`, `760a1140e4`, `0ca0d7972f`, `6f9de0960f`) — reads the column instead, with the same answer for every stored row. Three answers do change where the old reading was wrong: routing no longer escalates on a run whose outcome was OK (`b9cc667dad`), an end that was asked for is a stop (`59721c967e`), and a revive finalized with nothing done records CANCELLED on the turn it cut off instead of keeping an old FAILED copy (`7d66046455`). `release_cause` stops being written and leaves the Prisma model (step R5, `9d197408dc`); the column stays in the database until a later deploy.

**Both row kinds are one row.** On web (`fd20fa42ea`) and macOS (`b089831707`) a project's row is now drawn by the same shell as its coordinator's session row. On web, session rows gain keyboard focus and a right-click menu while project rows gain the phone's held-press menu, the full swipe and the drag without a second wiring, and row text is no longer selectable; on macOS a project's row gains the native selection tag, Mac swipes and the shell's drag. On both, a drag shows a compact title card below-right of the pointer (`95a5067d0e`) instead of a faded copy of the whole row.

**Smaller changes.** A tab reads session counts only when a session's share of a tally actually moved, not on every heartbeat (`e513174734`). Pasting into the browser's address bar now uses the X clipboard, so it works when no page field has focus (`03fcf6431c`). The Agents line no longer counts failures (`d7016a3565`); while a run is going it stays on one line and keeps the model name, cutting the title before it drops the name to the engine's mark (`13698fe2c0`, `ccc37ceba3`, `9023389351`). A failed background process no longer shows a red "N failed" or pins the failure over the running names on web, Apple and Android; a failed item keeps its cross where it is named and in the list, and the Tasks row's failed count stays because a failed task can be restarted (`7cb3bcdce4`). A fresh install leaves managed runners (Orbit Cloud) off unless `--managed-runners` (`b73b9a649f`), and the install adds `docker-buildx` where Docker lacks it (`358a01dbf4`).

## Upgrade impact

- **Database migrations:** eight new files under `src/apiserver/prisma/migrations/`, 1,426 lines, all additions — no file changed or removed. All eight are additive: none drops a table, a column or a row, and a server from the previous release keeps working against the migrated schema.
  - `1401_session_release_fact_chk` adds the CHECK `session_release_fact_chk` NOT VALID: a session's status is terminal exactly when `finished_at` is set. It adds no column and rewrites no data, but it refuses any new write that breaks it.
  - `1402_session_release_fact_validate` first heals the rows a hand-over can leave behind (a terminal row without `finished_at` gets the value 1262 wrote; an open row with it has it cleared), then validates 1401. It writes only rows that break the constraint.
  - `1421_supersession_capacity_guards_read_release`, `1422_admission_aggregate_guards_read_release`, `1423_project_move_guard_reads_release` and `1424_acquisition_revive_reads_release` replace existing functions in place (three, two, one and three revive exemptions respectively), and `1425_ended_triggers_read_release` re-creates three ended-trigger `WHEN` clauses. Each keeps its object names and adds `finished_at` — and, in 1425, `last_turn_outcome` — to the column lists its triggers watch. No table, column or row is touched; every one of them answers exactly as before for every stored row, because 1401 holds the two spellings equal.
  - `1426_session_task_execution_claim_finished_at_idx` adds a second UNIQUE partial index on `session(task_id)` where `task_id` is set, the row is not deleted and `finished_at` is null, built `CONCURRENTLY`; 0130's status-set index stays and both are enforced. A later release drops the old one.
- **Ordering:** 1401 may run only in a release after the one that carried the release-fact work, and only once every replica runs that release. **Upgrade from v0.1.261-beta.70 (or any later tag) must be complete, its rolling deploy finished and no rollback target below it started, before this tag's apiserver boots its migrations.** A server older than beta.70 writes a terminal status with no `finished_at` and would be refused by 1401. An operator on an older tag passes through beta.70 first.
- **Release cause:** `session.release_cause` is no longer written and is gone from the Prisma model, but the column and `session_release_cause_chk` remain until a later deploy (step R8). A beta.70 server still writing them during a hand-over harms nothing.
- **Configuration:** nothing new to fill in. A fresh install now writes `ORBIT_MANAGED_RUNNERS_ENABLED=false`; `--managed-runners` opts in, and `--no-managed-runners` still works. An existing deployment keeps whatever its `.env` holds. `install-server.sh` installs `docker-buildx` with apt when Docker lacks it.
- **Runner** (`src/runner-go`, built from this tag and served at `/dl`): paste into the browser's address bar goes through the display's clipboard (xclip and xdotool, now pinned in the managed runner image) instead of DevTools' text insertion, which reached only page fields. A managed-runner deployment needs the rebuilt image; older runners keep working, minus the address-bar paste.
- **Clients:**
  - *macOS:* the project-row Pause/Resume, the merge-failure ✕, the shared row shell, the running-Agents line and the quieter Agents and background rows, on the beta channel (DMG and Sparkle appcast).
  - *iOS:* TestFlight marketing version 0.1.261, build number the commit count, with the merge-failure ✕, the running-Agents line and the quieter Agents and background rows.
  - *Android:* `versionName` `0.1.261-beta.71`, the next `versionCode`, and `android-update.json`, with the project-row Pause/Resume, the swipe actions, the merge-failure ✕ and the quieter background rows.
  - *Web:* the project-row Pause/Resume, the merge-failure ✕, the shared row shell, the quieter counts, Agents and background rows read, with the next server/web deployment, not from this tag's client artifacts.
  - No minimum client version is enforced, and no one-time step is needed beyond the upgrade ordering above.

## Rollback

The previous tag is v0.1.261-beta.70, commit `46d94bd7899e2ccb49cae1c5fe3af8144bae5fa1`. A server deployed from this tag rolls back to that commit. Native clients roll back by installing beta.70's build.

An application-only rollback to beta.70 is schema-safe, and to no release older than it. Beta.70 carries the release-fact writers (1261/1262), so its terminal writes set `finished_at` and satisfy 1401's CHECK; the replaced functions and triggers keep answering as beta.70 expects; 1426 adds its index beside 0130's, which stays in force; and `release_cause` is still in the database, so beta.70 keeps writing it as before. A release before beta.70 cannot be the rollback target: 1401 refuses its terminal writes.

The client changes do not roll back with the code: installing beta.70's macOS, iOS or Android build loses the project-row Pause/Resume, the merge-failure ✕ and, on macOS, the shared row shell and the running-Agents line; a web client from beta.70 keeps the old rows and the old read behaviour.
