# Orbit 0.1.261-beta.70

## Summary

This release is about **a project row dragged onto a folder on web and macOS**, about **the iOS share sheet's Add opening Orbit instead of only posting a notification**, and about **the server hinting a browser tab only when its list actually moved**, so a running session no longer makes every tab re-read. The range is `v0.1.261-beta.69..origin/main` (`b947c72d56`).

**A project row drags onto a folder.** On web and macOS, a project row now carries its coordinator and can be dropped on a folder head, where it is filed as the row's Move does and its member sessions follow; a project with no coordinator stays put (`fa34c73d6f`).

**The iOS share sheet jumps to Orbit.** Add now reaches `UIApplication` through the responder chain and opens `orbit-session://<id>?share=<entry>`; the app registers that scheme on iOS and claims the entry from it, and if the open fails the notification still posts (`2fcf48dd14`). The share sheet's New session row no longer wears a blue +, which made it look like a button opening a dialog, and the chevron beside its workspace is now the up-down pair, because it opens a menu rather than a pushed page (`b947c72d56`).

**A tab hears only when its list moved.** Every update of a session row or a conversation turn used to bump the account's Open-list version whatever column it touched, so a running session's heartbeats, which carry a worktree snapshot, rewrote every session of its runner and hinted every open tab; `open_list_bump_session` and `open_list_bump_via_session` now compare a row's new and old values without the columns no Open list draws (`updated_at`, the context gauge, the worktree snapshot, claim and recap bookkeeping), as 0512 and 0641 already do for their tables (`a4d50a1350`, migration `1420`). On web, the tab also read `/sessions/counts` on every `list_changed` hint (38/min, 85% 304) and `/owner-requests?state=open` on every session event (16/min, 96% 304); counts now read only on events that can move a tally, judged from each session's last summary, and open requests read on the new `owner_requests.changed` event, while safety reads and the reconnect read are unchanged (`a53f9ae134`).

**Owner requests announce their own change.** A new opt-in realtime control event, `owner_requests.changed`, is published to streams that declare `hints=owner_requests`; because owner requests are written by about thirty call sites across five services, the hint is derived from the account's `owner_request` rows once a second rather than from each writer (`86e8c7dbf4`, `13c9d9b89e`). The version read now takes only PENDING requests, through the `(owner_id, state, created_at)` index, instead of counting and ageing every request the account ever had (`0b1fbc94d6`), and the pending evidence decisions read answers 304 with an ETag computed without the read's clock and ages, keeping ages to whole minutes so a minute crossing is a 200 (`6d1d52860c`, `86e8c7dbf4`).

## Upgrade impact

- **Database migrations:** one — `1420_open_list_undrawn_writes`. It is additive: it only `CREATE OR REPLACE`s the two trigger functions `open_list_bump_session` and `open_list_bump_via_session`, keeping their names, arguments and every trigger, so no table is locked, no column or table is added or dropped, and no data is rewritten. The apiserver applies it on boot like any other migration. Its only behaviour change is that an update differing in none of the columns an Open list draws stops bumping the version; every drawn column, every INSERT and DELETE, and every other table bump as before.
- **Configuration:** nothing new to fill in.
- **Runner** (`src/runner-go`, built from this tag and served at `/dl`): no runner change in this range — `git diff --stat v0.1.261-beta.69 origin/main -- src/runner-go` is empty. A runner from beta.69 or this tag works the same, and older runners keep working.
- **Clients:**
  - *macOS:* the project-row drag onto a folder, on the beta channel (DMG and Sparkle appcast).
  - *iOS:* TestFlight marketing version 0.1.261, build number the commit count, with Add opening the app (falling back to the notification), and the share sheet's New session row and workspace picker affordances.
  - *Android:* `versionName` `0.1.261-beta.70`, the next `versionCode`, and `android-update.json`. No Android behaviour changed in this range.
  - *Web:* the project-row drag and the quieter counts and owner-request reads reach users with the next server/web deployment, not from this tag's client artifacts.
  - No minimum client version is enforced, and no one-time step is needed.

## Security fixes

None in this release.

## Known limitations

- **iOS share sheet:** Add opens Orbit through a path Apple does not document for extensions (the responder chain to `UIApplication`). It has been compiled but not yet run on a device; if iOS refuses it, Add falls back to the "tap to finish" notification, as in beta.69.

## Rollback

The previous tag is v0.1.261-beta.69, commit `a46e5da2592491d41d918e09969917297021b609`. A server deployed from this tag rolls back to that commit. Native clients roll back by installing beta.69's build.

An application-only rollback to beta.69 is schema-safe: migration `1420` replaces two trigger functions and adds no column, table or data, so beta.69's apiserver runs against the migrated schema unchanged. The replaced functions stay in place and keep bumping for every drawn column, so the older application behaves as before; reverting the comparison itself needs beta.69's earlier function definitions restored by hand, which a plain rollback does not do.

The client changes do not roll back with the code: installing beta.69's macOS, iOS or Android build loses the project-row drag and, on iOS, the share sheet's Add opening the app and its New session row affordances; a web client from beta.69 keeps the old drag and the old read behaviour.
