# Orbit 0.1.261-beta.58

## Summary

This release makes **one model picker for task runs and delegate, with Smart model selection on by default**
(`d4698bc5a9`), and **a read-only Kimi SubAgent's shell calls follow the parent session's permission mode**
instead of filing an approval card every time (`22b6530657`). On Android, **a created session takes its draft's
place**, as on iOS (`ad72f616d8`).

- **One model picker for task runs and delegate; Smart model selection on by default (server; web, iOS/macOS,
  Android).** `d4698bc5a9`: delegate respects the account's Smart model selection switch: off, a SubAgent runs on
  its parent's model; a model the caller or definition names is still used. The switch is on unless the owner
  turned it off. Task runs keep their own tier logic (coordinator hint, rules, Optimize For floor, escalation) but
  pick the model at that tier from the SubAgent router's pool: every provider × engine × model, less
  blocked/signed-out/region-blocked/full accounts. The Agent's own engine and credential keep the run while they
  can take it at the tier; a verification prefers another engine; pins still win. The per-Agent
  `modelRoutingProviders` list is no longer read. The task's Suggested picker previews each tier from the same
  pool. Optimize For shows only while the switch is on, and both descriptions are reworded.
  `docs/model-routing-design.md` §6 notes the change.
- **A read-only Kimi SubAgent's shell calls follow the parent's mode (runner).** `22b6530657`: a read-only
  SubAgent on Kimi runs in plan mode, which asks about every shell call, so a parent in Auto got a card for each
  `git grep` its read-only helper made. Per the owner's decision of 2026-11-20, such a request follows the parent's
  mode as it stands when asked: under Auto or Bypass the runner approves it with no card, and under any other mode
  the card is filed as before. Edit tools stay with plan mode.
- **A created session replaces its draft page (Android).** `ad72f616d8`: sending from the new session page pushed
  the session over the draft, so Back returned to the draft. The session now takes the draft's place (iOS
  `openCreatedAgentSession` / `NavState.replaceTop`): Back goes to the page the draft was opened from.
  `1898329317` adds that Back press to the new-session device journey.
- **Android dark pages are pure black (Android).** `44f723ccb7`: dark-mode pages draw pure black, the composer card
  `#1A1A1A`, and the usage gauge loses its outline.
- **Tooling.** `93a4ac2611` adds the `compare-android-ios` skill (one page on both clients, side by side); `ee24b4078f` lets `src/android/scripts/composer-device-test.sh` take an
  `A07_DISPLAY=WIDTHxHEIGHT@DPI` override for a test run, and `4065a171ed` pins the `client-screenshots` skill's
  iOS shots to an iPhone 17 Pro.

## Upgrade impact

- **Database migrations: none.** `git diff --stat v0.1.261-beta.57 <this tag> -- src/apiserver/prisma/migrations/`
  is empty; this range adds no migration file, renumbers none and changes none.
- **Configuration: none.** `docker-compose.yml` and the environment files do not change in this range, and no
  new `ORBIT_*` variable is read.
- **Operator decision: Smart model selection is on unless the owner turned it off.** An account that never set
  the switch now routes delegate and task runs through the shared pool; an owner who wants SubAgents on the
  parent's model turns Smart model selection off in Settings.
- **Server and web:** the routing change is apiserver and web code, and reaches an instance only when it is
  upgraded from this source; tagging does not deploy the server.
- **Clients:** macOS beta users and TestFlight (marketing version 0.1.261) get the settings change above;
  Android gets it, the draft-page fix and the black dark pages, with `versionName` `0.1.261-beta.58`.
- **Runner:** `src/runner-go/` changes in `22b6530657` only. **The runner served at `/dl` is built from this
  tag**, so a runner fetched from it answers a read-only Kimi SubAgent's shell request by the parent's mode; an
  older runner keeps filing the card.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE.

## Known limitations

- **Under Auto or Bypass a read-only Kimi SubAgent's shell commands run without a card and without any
  check of the command.** In `22b6530657`'s own words: "The runner does not check the command, so under
  those two parent modes a read-only Kimi child is read-only by its plan-mode instructions alone." Edit
  tools stay with plan mode. Recorded in `docs/subagent-design.md` §5.3.
