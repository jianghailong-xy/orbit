# Orbit 0.1.261-beta.95

## Summary

The feature called Documents is Drive again on the server and on all four clients; a wiki chat's agent can finally read the wiki it is asked about; and a managed runner that runs out of memory or crashes now holds itself together, retries on its own, and tells its owner what happened. Operators will also notice that a project line held by an open item reaches the coordinator and then the owner, and that a task run stuck with no evidence is reported.

- **Drive, on the server, the web, macOS, iPhone, iPad and Android.** Documents is renamed back to Drive (project 35370KiEBDnxlOS5Yyaxh). The server's module is `src/drive`; the owner's routes answer at `/drive` and the runner's at `/runner/drive`, with `/documents` and `/runner/documents` kept as aliases for clients, bundles, mount daemons and runners deployed while it was called Documents; download links are minted under `/api/drive/dl`; the personal access token scope is `drive` (both `documents` and `files` are still read as `drive`); and the ten `document_*` tables plus `document_sync` are `drive_*` again. New deployments name the store `ORBIT_DRIVE_*`, with `ORBIT_DOCUMENTS_*`, then `ORBIT_FILES_*`, still read when the newer name is unset. The agent interface says Drive too: `drive_put|get|list|move|delete|sync` and `orbit drive …`, with the `documents_*` names and `orbit documents` still served unlisted for engines and prompts already out there, and `drive_put` links a file as `orbit-drive:<id>` (Agent Contract 1.14.0). The mount daemon is `orbit-drive-mount`, serving the `drive.orbit.dev` CSI driver and mounting at `/run/orbit-drive`; the runner accepts all three roots while old Pods drain, and mounts the drive at `~/Drive` only, removing a leftover link at `~/Documents` or `~/Files`. Web, macOS, the iPhone and Android put Drive in the sidebar and drawer, the + menu (File / Image / Drive), the page, Storage, the picker, the token scope and the transfer and sync cards; `/documents/*` and `/files/*` redirect to `/drive/*`, and a transfer card strips a `/run/orbit-drive/drive` path as it did the old mount's. Boards are in `docs/mocks/drive`, `docs/mocks/drive-sync-card` and `docs/mocks/drive-sync-tray`.

- **Wiki chat: the agent can read the wiki (`wiki_read`).** A wiki chat's agent could only draft, so a chat asked about a page answered "open the right page and ask again". The runner now serves `mcp__orbit__wiki_read` and `orbit wiki read`, answered by `GET /api/runner/wiki/read` with the chat's wiki contents, a search, one document or section, or a card of the chat's own: read-only, opening with the view-not-a-source header, with the pending plan draft and the space's writer jobs, cut at 60,000 characters with `more`, and refused `WIKI_SESSION_EXCLUDED` for another session as `wiki_draft` is. Delivery attaches the wiki's contents on a chat's first message and re-sends the chat prompt when its digest changes (migration 1562), and the prompt ends by telling the agent to use `wiki_read` if it has one, so a chat on an older runner is never told to use a tool it lacks. A call that read the wiki can no longer be cited as an entry's source, and is dropped from docs material.

- **Wiki chat: a bounded rewrite is written without a press, with Undo.** Option A of the chat design (D4–D6, D11): when a chat's rewrite sections fit the space's automatic allowance for the UTC day, the card is queued in the drafting transaction and reads "Rewritten from main" — never "Confirmed by you" — with Undo and See changes; otherwise it stays a draft, records why (`web`, `budget`, or waiting on another open card, which that card's Apply or Discard releases) and keeps Apply with an "Apply to write: …" line (migration 1574). Web and macOS draw both, and a rewrite card written from main now floats the Wiki updated line as an applied one does. `wiki_draft` carries the server's `state` and `held`, so an agent is told a card was written instead of being told nothing was.

- **Managed runners: memory pressure is survived, not restarted.** A managed runner's max concurrent is capped by its container's memory — `floor((limit − 1 GiB) / 1 GiB)`, at least 1, the new `managed_runner.concurrency_cap` column (migration 1561) — and a value above it is lowered, with the answer and the Machine page saying so; nothing is claimed while the container has less than 1 GiB free, and reclaimed RUNNING sessions take their turn permits one at a time. The watchdog ranks victims by PSS, excludes reclaimable file cache, starts each settle window when the kill is observed, explains a kernel OOM in the affected session, and a 64 MiB reserve child (`orbit orbit-headroom`) frees its memory as soon as `memory.events oom_kill` rises and re-arms once no kill has followed. Claude's shell launcher now returns the shell's 128+signal instead of 255 and no longer re-raises signals, so a turn the runner ended is not labelled as another tool's OOM. `/tmp` moves onto the data volume — `.orbit-tmp`, a `Subpath` mount on Docker (which needs Docker 26 / API 1.45) and the PVC's `subPath` on Kubernetes — so filling it is ENOSPC instead of a tmpfs held in memory or an emptyDir eviction of the Pod; the daemon empties it at start and when a session ends with nothing else running, and holds new work below a free-space reserve. Docker runners get a preallocated ext4 data volume, so a disk-full write returns ENOSPC and admission can pause.

- **Managed runners: a retryable failure is retried on its own.** Where `POD_OUT_OF_MEMORY` parked Orbit Cloud until a manual retry, every retryable cause now gets a next try 15 minutes out, doubling to 6 hours, taken up when due and work is waiting; the attempt count resets an hour after the last restart, and demand reports the runner as coming back. A proven stop marks the machine OFFLINE in the same transaction that records the stop proof, and the reaper reads that OFFLINE as silence rather than sign-off so the next generation reclaims its sessions; a Kubernetes eviction for temporary storage reads `POD_RESTARTING_STORAGE_FULL` / `POD_STORAGE_FULL` rather than a plain restart. The status answer carries `nextAttemptAt` and `attempt`: web shows "Attempt N · next automatic try at …" with Retry now on the machine page and above the composer, and lets the owner send while a retry is scheduled; Android and OrbitKit decode the same fields and treat such a runner as taking work.

- **Projects: an idle run and a held line now tell someone.** A task run that ended its turn with no evidence and no progress was never reported once nothing else fired; after 30 minutes a timed check queues one `TASK_RUN_STOPPED` fact per idle period, naming the task, its last progress and the session to nudge. When an open `MAIN_SYNC` or baseline-red item holds other tasks' landings with that run idle for 60 minutes, the coordinator gets one notice per idle period and the owner one push after `exceptionEscalationSeconds`, through the orphan-notice ledger. An evidence revision nobody can decide now gets its own owner `EVIDENCE_UNDECIDED` item and push instead of hiding behind an open `MAIN_SYNC` item already handed to the coordinator — the case that sat 33 hours with no notice.

- **Apple: Record as done… stays, and a Drive transfer is one card.** `GET /sessions/:id` carries neither `pendingApprovals` nor `waitingKind`, so every detail refresh cleared the waiting kind and took the owner's "Is this project done?" card down, which the unchanged list row never restored; only a record that carries the count moves the waiting state now. A run of `drive_put` / `drive_get` calls that used to fold into a steps line is one transfer card on the Mac and the iPhone — bar, bytes, speed and time left, a row per file by folder, a stall after 20 s, totals when finished, and one file as a line — and a `drive_sync` call draws its sync card. Both bars are drawn rather than a `ProgressView`, which turns grey in a window that is not key and draws nothing while it counts files, and a one-file line no longer says 0 B/s before a byte has moved.

- **Engines and tooling.** The managed-runner image and the apiserver's codex stage move to Codex 0.172.0, Claude Code 2.1.331, Kimi Code 2.7.3 and Antigravity CLI 1.5.16 (build 1.5.16-5250855658717184); OpenCode 1.19.6 and the Cursor CLI are unchanged. The Agent Contract is 1.14.0, the operation catalogue 1.12.0 and the primer 1.4.7, and the API reference, operation catalogue and agent tools guide are regenerated. The deploy's release-image check no longer dies of SIGPIPE when `grep -q` exits at its match, a race that refused v0.1.261-beta.94 in about 3% of runs under systemd-run.

## Upgrade impact

- **Migrations:** five, applied by the apiserver on boot.
  - `1561_managed_runner_oom_recovery` adds one nullable `INTEGER` column, `managed_runner.concurrency_cap`. **Additive**: no row is written and no default is set.
  - `1562_wiki_chat_delivery_markers` adds two nullable, defaultless columns on `session`, `wiki_chat_prompt_digest` (`TEXT`) and `wiki_chat_contents_version` (`INTEGER`). **Additive**: the running release neither reads nor writes them, and `NULL` means "never delivered", so a chat opened before it gets both on its next message. `session` is read by every runner call, so the table's lock is taken in 2 s tries, up to 45 times.
  - `1574_wiki_chat_draft_auto` adds three nullable, defaultless columns on `wiki_chat_draft` (`auto_queued_at`, `held`, `held_by_id`), one partial index, and restates five CHECK constraints so a card written without a press can be undone, seen and told. **Additive**: no existing row has the new columns set, so every row passes the new checks and none is rewritten.
  - `1590_pat_scope_drive` is **not a schema change**: it rewrites the `scopes` arrays of `personal_access_token` and `pat_device_login`, replacing `documents` (or the older `files`) with `drive`. No row is added or removed, no table, column, trigger or function is touched, and a second pass finds nothing to change. Both old names are still read as `drive` by this release.
  - `1592_drive_tables` is **a catalog rename, not additive**: `document_staging`, `document_staging_chunk`, `document_version_chunk`, `document_trash_group`, `document_entry`, `document_version`, `document_commit`, `document_removed_entry`, `document_change`, `document_mount_credential` and `document_sync` become `drive_*`, with the constraints, indexes and `document_change_seq_seq` of those tables renamed by the same rule (for the ten tables that is exactly the names they had before 1551). No row, column, value, default or reference changes and nothing is created or dropped; the locks are taken 1 s per table, up to 40 tries, and every statement skips a table already renamed.

- **Configuration:** `ORBIT_DRIVE_*` is the primary name for the store (backend, directory, S3 endpoint/bucket/region/keys/mirror, quotas) and `ORBIT_DRIVE_ENABLED` the switch. `ORBIT_DOCUMENTS_*` and, before it, `ORBIT_FILES_*` are still read in that order when the newer name is unset, by the API, the Compose file, the backup sidecar and the mount daemon. An existing deployment that sets the old names keeps working unchanged; a new one should use the new names, and the configuration reference now has a row for every deprecated one.

- **Server:** nothing beyond the five migrations. There is no backfill and no one-time database step. Older clients and runners keep working: `/documents` and `/runner/documents` still answer, the capabilities wire key is still `documents`, and `documents_*` tools are still served.

- **Managed-runner operators:** Kubernetes runners adopt the `drive.orbit.dev` CSI driver. Its rollout installs it beside the old `documents.orbit.dev` and `files.orbit.dev` drivers, moves the apiserver and the profile's namespace together, drains the old Pods, and then removes the old driver; admission still admits both old drivers at their own paths while they drain. Docker runners' `/tmp` uses a `Subpath` volume mount, which needs **Docker 26 (API 1.45)**. A self-hosted deployment that runs no managed runners needs neither.

- **Runners:** the runner served at `/dl` is built from this tag. It adds `wiki_read`, lists the `drive_*` tools and `orbit drive`, reads the drive at `/run/orbit-drive` (then the two older roots) and mounts `~/Drive`, adds the memory reserve, the memory-aware claim and reclaimed start, the `/tmp` sweep and free-space reserve, the kernel-OOM explanation and the launcher signal handling, and gives Claude sessions the shared Go and npm cache env. A runner older than this release keeps working, but it has no `wiki_read` and lists `documents_*` rather than `drive_*`, which the server still serves. Orbit Cloud runners get the change from the `orbit-cloud-runner:0.1.261-beta.95` image, built from this tag.

- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. macOS and the iPhone take the Drive labels, the transfer and sync cards and the Record-as-done fix; Android takes the Drive labels and reads a managed runner waiting on a scheduled retry as taking work. No one-time step on a Mac, iPhone or Android device.

## Security fixes

None in this release.

## Known limitations

- A runner from before this release has no `wiki_read`, so a wiki chat on it is told "If you have a wiki_read tool" and cannot read the wiki; its rewrite cards still draft for a press.
- `drive_*` are the listed tool names only from this release's runner. An older runner lists `documents_*`, which the server still serves; an engine holding the old names keeps working through the aliases.
- `wiki_read` refuses another session's chat (`WIKI_SESSION_EXCLUDED`), as `wiki_draft` does, so a wiki chat cannot read a peer chat's turn.
- A rewrite card's `held` reason is recorded when it is drafted. A card held for `budget` is not re-evaluated by a later press that day, because that reason cannot be worked out again; a card held for `draft` is written when the card it waits on is applied or discarded.
- The Kubernetes side-by-side CSI rollout and the Docker 26 requirement are operator steps, not automatic.
- The release-image check fix removes a spurious refusal only; a deployment genuinely older than its release-built runner image is still refused.

## Rollback

Previous tag v0.1.261-beta.94 (`4de371402a`). Application-only rollback is **not schema-safe for this release**. `1592_drive_tables` renames the live tables to `drive_*`, so a beta.94 apiserver — whose Prisma models and raw SQL name `document_*` — finds no such table and answers its drive requests with an error until it is replaced; nothing it fails to write is lost, since the writer (upload, mount, tool, sync) retries. `1590_pat_scope_drive` also leaves stored tokens and pending device logins holding `drive`, a scope name beta.94 does not know (its names are `documents`, with `files` as an alias), so such a token's Drive access is refused until a release that knows `drive` runs again. The three additive migrations (1561, 1562, 1574) leave the previous release working.

This release records no down-migration. To roll back, restore the database from a backup taken before the upgrade ([backup runbook](postgres-backup-restore.md)), or rename the eleven tables and their constraints, indexes and sequence back to `document_*` and rewrite the scopes back before the older apiserver boots. Neither path was exercised when these notes were written.

Client rollback is to the last published builds, v0.1.261-beta.94's DMG, TestFlight build and `orbit-android-0.1.261-beta.94.apk`; a client from beta.94 has no Drive labels and no transfer card, and it keeps working against this release's server, which still answers `/documents`.
