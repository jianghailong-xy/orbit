# Orbit 0.1.261-beta.16

## Summary

- **iPhone photo uploads work again:** a camera photo picked from the library no longer fails with
  "Upload failed — photo.png". A HEIC photo, or any image over the 5 MB limit, goes up as a JPEG at most
  2048 px on its long edge; smaller PNG, JPEG, WebP and GIF images go up unchanged. Pasted images on Mac and
  iPhone, owner and guest alike, get the same treatment, and a failed upload now says why.
- **A merge no longer waits for the session's turn:** it runs beside the turn, and a commit waits for
  changes to stop.
- **Merge conflict panel and merge error** are inset under the worktree bar and laid out as head, why and
  steps (web, Mac/iOS, Android). With Translation on, Resolve in session now clears a settled conflict.
- **Hosted runners** no longer show "Updates are turned off" with Fix with an agent: a managed runner's
  version is not compared with a release (web, Apple, Android).
- **Web:** a machine with no workspace shows its setup card alone, and the card creates the workspace; a
  transcript restored from the stream's replay keeps paging to older events; a project row opens the
  project's page from a session shared with you.
- **Turns that carry only Orbit's blocks** draw as a From Orbit line, never as your bubble (web, Mac/iOS,
  Android).
- **Sharing:** the guest invite field suggests people you invited before
  (`GET /api/sessions/:id/guests/suggestions`).

## Upgrade impact

- **Database migrations.** `0870_account_remove_sessions` (beta.14/15) is renumbered to
  `0910_account_remove_sessions`, because its number clashed with `0870_managed_runner_image_roll`. It uses
  `ADD COLUMN IF NOT EXISTS`, so a database that already applied it under the old name is unaffected. Additive
  only.
- **Runners.** This release changes the runner (merges beside a running turn). Runners on the beta channel
  move to 0.1.261-beta.16 once the server is deployed after this tag.
- **Server.** The merge change, the guest suggestions route, workspace creation from the setup card and the
  Resolve-in-session fix take effect when the server is deployed.
- **Configuration.** No changes required.
- **Clients.** Each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261,
  build number = commit count) and Android via `android-update.json` are offered it.

## Security fixes

None in this release.

## Known limitations

- The iOS ☰ count badge fix stays reverted: on iOS 26 the badge is still clipped at the drawer button's
  edge.
- Client CI's navigation check fails on `ProjectsView.swift:138` (a stored project selection). It is a
  code-structure check, not a build failure, and is not fixed in this release.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.16` and tag `v0.1.261-beta.16`. This tag publishes the
macOS DMG and Sparkle payload (beta channel), the iOS TestFlight build, the runner binaries, and
`orbit-android-0.1.261-beta.16.apk` with its `.sha256` and `android-update.json` on the same GitHub Release.
The photo upload fix compiled in Client CI on iOS and macOS, where the OrbitKit tests also passed (with the
then-failing runner copy parity test removed; it has since been fixed on main by `cdf85851d`). Each other change
landed with its own tests, and the release run's builds compile this tag.

## Rollback

Roll back to 0.1.261-beta.15. Migration 0910 only adds a column (if it is missing) that beta.15 also has, so
an application-only rollback is schema-safe. Runners do not move back by themselves: roll them back with the
`/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
