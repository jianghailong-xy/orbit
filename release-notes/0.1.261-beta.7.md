# Orbit 0.1.261-beta.7

## Summary

The work merged since [0.1.261-beta.6](0.1.261-beta.6.md), on the beta channel.

- **Orbit's Agents say who did the work, where, and what came of it (iOS and macOS).** A `delegate` call is
  now named **Agent** in the conversation. Its block's second line shows the engine and model it ran on,
  led by `Claude →` when Orbit moved the work to another engine, then the tier and type, `Read-only`, and
  `on <workspace>` for a run on another machine. The third line shows how many files it changed, or the
  first line it handed back, with its time and cost. While it runs, the line shows what it is on, its clock
  and its steps. Opened, the block lists the files it changed (not committed). Agents started together fold
  into one group with a progress head. The composer band has an **Agents** line that opens every run of
  the session, and the folded pill counts them. The server's `GET /sessions/:id/subagents` now also returns
  each run's engine, read-only flag, changed files and description.
- **Translated conversations.** Settings › Translation (web, iOS/macOS, Android) translates the owner's
  messages before the engine gets them, and translates agent replies, question cards, approvals and
  suggestions back. A failed translation offers Retry or Send as written.
- **Coordinator handoff.** From the context gauge or popover, **Compact** or **Start a new coordinator**.
  The outgoing coordinator writes a handoff note and its header reads "Handing over" while the composer
  is locked; the successor opens with the note, and the replaced coordinator's active waits move to it.
- **A conversation shows only its own needs-you** in the phones' nav-bar capsule.
- **Fixes:** the worktree bar keeps the Merge button's title on a phone; a promotion in flight when a
  task's rework lands no longer puts the rework on main; the sticky question quotes what the owner wrote.

## Upgrade impact

- **Database migrations,** applied by the apiserver on boot:
  - `0532_conversation_turn_translation` adds three nullable columns to `conversation_turn` and a CHECK
    added `NOT VALID`, retrying on a 2 s lock timeout.
  - `0550_approval_translation` adds a nullable `approval.translation` JSONB column.
  - `0810_coordinator_handoff` creates the `coordinator_handoff` table.
- **Runners update themselves.** `0.1.261-beta.7` orders above `0.1.261-beta.6`; the runner change is one
  live-only event kind for translation. A busy runner waits until it is idle.
- **Configuration.** No changes required. Translation is off until the owner turns it on.
- **Clients.** macOS users who enabled "Receive beta updates" get this build. iOS ships to TestFlight
  (marketing version 0.1.261, build number = commit count). Android offers the APK to every install via
  `android-update.json`. The Agent block's engine chip, Read-only mark and changed files need this
  release's server: against an older server the block still draws, without them.

## Security fixes

None in this release.

## Known limitations

- The Agent block's changed files carry no line counts yet, and the session list still says
  `Running N agents` without naming the engines. Web and Android still draw the earlier SubAgent block.
- From the Agents sheet, a run whose block the loaded conversation no longer holds does not scroll.
- `ListRowShapeTests` fails on main for `ComposerView.swift`, a list this release does not change; the
  macOS and iOS apps build.
- The known limitations of [0.1.261-beta.6](0.1.261-beta.6.md) still apply.

## Rollback

Roll back to 0.1.261-beta.6. The migrations only add nullable columns and a new table, so an
application-only rollback is safe; older code ignores them. Runners do not move back by themselves: roll
them back with the `/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
