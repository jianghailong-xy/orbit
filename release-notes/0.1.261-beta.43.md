# Orbit 0.1.261-beta.43

## Summary

This release finishes the landing skip on the native clients and gives web the Agents line. macOS, iOS and Android draw the owner's "Land without the check" on a landing that is still queued or running, the server door and the web card for which shipped in v0.1.261-beta.42, so the skip now appears on every client. The web gains the session's Agents row above the composer, as iOS draws it, and the Agents sheet on iOS and macOS drops its two figures. On the server, an auto-run start plan that was bound and never created its Session is given back and planned afresh once the task's pins change, so a task re-pinned to another engine is dispatched instead of replaying the refused create on every sweep. It adds no database migration.

- **Land without the check on the landing card (macOS, iOS and Android).** The Apple clients and Android now draw the owner's skip of a landing still in flight, as the web card already did: "Land without the check" in the card's foot where the server says `skippable`, behind a confirmation — Apple asks it through `orbitConfirmation`; the server's `skipCheck` is said in the place of "Nothing to do" (stopping / landing without the check); and a refusal is shown under the card with "Nothing to do" hidden while it shows. OrbitKit decodes the two fields, carries them through the job line and the card (`skipTaskId`, `skipNote`) and posts the skip. Android wires both the project page and the project's sessions page and reads the integration again after it. A commit pins the Apple card's new lines. The words are held to the web's `LANDING_WORDS` by `ProjectCopyParityTest` on Android and the copy parity test on Apple.
- **The session's Agents line above the composer (web).** A session's page gains the Agents row the iPhone has, between the Tasks card and the branch bar: folded, it says what the running Agent is doing, or the newest one with how it ended and its time; opened in place like Background processes, it lists the runs (Running, then Done), and a row scrolls to its delegate block and opens it. It shows no cost, as on Apple. The session's SubAgent runs are read once in `WorkspaceView` and shared with the transcript. The Agents sheet on iOS and macOS drops its two figures (runs, engines · machines), and OrbitKit's summary its now-unused spread.
- **A bound start plan that never created its run is re-planned when the task's pins change (server).** A `dep: run` request bound to a CREATE plan whose create was refused — Claude Code signed out, for one — stayed BOUND, and a pin change does not move the dispatch epoch, so every sweep replayed the same refused plan whatever the task now said (production 2026-11-18: attempt 908 replaying Claude for a task re-pinned to Cursor), while the signed-out hold judged the current pins and let it through. A bound single-run CREATE plan is now given back (BOUND to OPEN, fenced on the lease) and planned afresh only when a dispatch-relevant pin (engine, provider, model, assignee workspace, runner) changed since it was bound and its Session provably does not exist; the Session insert locks the request row FOR UPDATE, so a plan whose run exists or whose create is in flight is still taken over, never replaced. The sweep's quota and signed-out holds now judge `boundPlansInForce`: a kept bound plan's engine and credential, else the task's current pins. The pg spec `task-auto-run-stale-bound-plan` is added with it.
- **Also.** `db-write-inventory.ts` gains the line for the auto-run write above. The rest of the range is test material: `SessionAgentsStrip.test.tsx` for the web row, the Android card, data and entries-shot tests, and the OrbitKit card, wiring, section-copy and subagent-block tests. No user-facing change comes from those files.

## Upgrade impact

- **Database migrations: none.** The diff of `src/apiserver/prisma/migrations/` between v0.1.261-beta.42 and this release is empty: no migration is added, changed or removed. The newest migrations remain 1070_owner_card_translation and 1080_owner_card_translation_more from v0.1.261-beta.41, both additive (nullable JSONB columns and one new table), which an apiserver already at that tag applied on boot; there is no manual step in this release.
- **Server:** the auto-run re-plan is an apiserver change (`src/apiserver/src/tasks/tasks.service.ts`, with its pg spec and write-inventory line), so the apiserver must be deployed from this commit or later for it. The web client ships with the same deploy.
- **Runner:** this range changes nothing under `src/runner-go` and no operation catalog. The runner served at `/dl` is built from this tag. No commit names an engine version change and no minimum runner version is set: a runner from an earlier tag keeps working.
- **Configuration:** no variable, compose file or deploy script changes in this range; nothing must be set before or during the upgrade.
- **Clients:** macOS beta users get the DMG on the beta channel, TestFlight gets marketing version 0.1.261 with the build number as the commit count, and Android gets `android-update.json` from this tag. The Apple and Android clients draw the skip only where the server sends `skippable`; OrbitKit defaults it to false and `skipCheck` to nil from a server that does not send them, as the web client already read both as optional. No minimum native client version above the previous release is set by this range.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE, and no dependency is added, removed or moved.

## Known limitations

None known. The web's Agents row shows no cost, as the Apple Agents sheet does; that is by design, not a limit of this release.

## Rollback

The previous tag is v0.1.261-beta.42, commit f2639bce196ca40c94579e1884ff337af7272318 (its tag object is f6cabf63374a38bd49410ed8ca413c769489c2fc), which is published, with the DMG, the APK and the runner assets on its release. This range adds no database migration, so an application-only rollback to that tag is schema-safe: nothing is left to undo, no backup or restore step is needed, and no data is affected. Rolling back restores the older behaviour: the Apple clients and Android lose "Land without the check" and the `skipCheck` line on the landing card, the web loses the Agents row above the composer, the Agents sheet on iOS and macOS shows its two figures again, and a bound start plan whose create was refused is replayed on every sweep until the task's pins stop changing. Rolling back only the server to beta.42 leaves the skip working on clients from this tag, because the beta.42 server already sends `skippable` and `skipCheck`; against a server older than beta.42, which sends neither, these clients draw no skip. See [Release process](../docs/release-process.md#rollback-decision-and-procedure).
