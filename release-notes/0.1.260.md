# Orbit 0.1.260

## Summary

Everything in [0.1.259](0.1.259.md), plus the work merged since. The runner change that prompted this
version: an agent coordinating a project can now ask for a task to be taken out of that project
(`task_update` with `projectId: null` and `handoff`, or `orbit task update --no-project --handoff-reason`).
The server files it as a move request, and the task leaves its project when the account owner confirms
it on the project page. Earlier runners refused that request before it reached the server, as a
"crossing with no destination". Also in this version: "Fix with an agent" on a machine warning starts a
session on that machine (web, macOS/iOS, Android); an engine update warning can be dismissed until the
next release; a session that merges itself mid-turn has the merge queued when the turn ends; Codex's
failed-install hint offers OpenAI's install script off macOS instead of `brew`; managed-runner
placement skips a channel host the apiserver cannot reach, and their firewall coexists with k3s.

## Upgrade impact

- **Runners update themselves.** `0.1.260` orders above `0.1.259`, so runners self-update from `/dl` as
  usual (a busy runner waits until it is idle). An agent can ask to take a task out of its project only
  once its runner has updated.
- **Database migrations:** `0705_runner_engine_update_dismissals`, `0740_session_merge_after_turn` and
  `0760_runner_attention_fixes`, applied by the apiserver on boot.
- **Deployment.** No configuration changes are required.
- **Clients.** No tag is cut for this version yet, so the native changes reach macOS, iOS and Android
  with the next client release.

## Security fixes

None in this release.

## Known limitations

- The known limitations of [0.1.259](0.1.259.md) still apply.

## Artifacts and verification

The version of record is `package.json` `0.1.260`; `/dl/version.json` names it once the server built from
this commit runs. The runner fix is covered by `task_handoff_declaration_test.go`: the MCP and CLI
update doors now send `projectId: null` with `handoff` to the server, while a `handoff` naming no
project and the create doors are still refused before the request. The full runner Go suite was run
before merging.

## Rollback

Roll back to 0.1.259. The three migrations only add to the schema, so an application-only rollback is
safe. Runners do not move back by themselves: roll them back with the `/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
