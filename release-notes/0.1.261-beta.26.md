# Orbit 0.1.261-beta.26

## Summary

- **The owner's exception card is organised around "Who fixes it?"** On the web, Mac, iPhone and Android, an
  item that has become yours (a merge conflict, a failed check, an integration error, a failed task, a delivery
  review) now reads:
  - a heading that names the live cause ("the coordinator can't take messages", "the coordinator didn't get to it",
    "the coordinator conversation ended", "the coordinator handed it over"),
  - a "Who fixes it?" block: the coordinator's row says why it can or can't take the item, with the button that
    brings it back (Enable / Restore / Bind its workspace, Change workspace…, Start a new coordinator), then "Ask the
    coordinator again", or "or Chat about this first" when it can be reached; your row has "Fix it myself" and the
    other ways onto the work,
  - "Closes by itself once this work lands" on items with a task branch, folded Details (files capped at 5), and
    Mark as handled and Cancel task in a separate "Already settled?" group, with one waiting clock.
- **A slash command is sent as written.** A message starting with `/` is no longer held back for translation.
- **A queued message hides the composer's prompt suggestion** on the web.
- **Hosted runners' engines.** The engines footer of an Orbit Cloud runner says its CLIs move with each Orbit
  release, and the Mac machine page names a managed runner by the id it carries.

## Upgrade impact

- **Database migrations:** none.
- **Configuration:** nothing to change.
- **Server:** the card reads fields the server already serves (`coordinatorUnreachable`, the coordinator status and
  the project's escalation window). orbitd.io runs 237f0f9d6, which carries this card's web side.
- **Clients.** Each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261, build
  number = commit count) and Android via `android-update.json` are offered it. Against a server older than
  0.1.261-beta.24 the card reads the cause from the row alone.

## Security fixes

None in this release.

## Known limitations

- On Android and in the Mac/iPhone apps, Enable / Restore / Bind open where the workspace is configured (the
  workspace page, or the project page on Android) rather than acting on the card; the card turns into the reachable
  one when you come back.
- The iPhone card's text rules (one heading line, folded settled items, failing lines in Details) are designed
  (docs/mocks/owner-card-ios-text) but not in this release.

## Artifacts and verification

The macOS DMG and Sparkle appcast, an iOS TestFlight build, and the Android APK with `android-update.json`, all from
this tag. The card was checked on its final commit with the web typecheck and full web suite (8,226 tests), the
OrbitKit suite on Linux (5,472 tests), the Android card tests (606 core + 56 app), and the macOS build and tests on
GitHub's macOS runners.

## Rollback

The previous tag is v0.1.261-beta.25. This release adds no migration, so a client or server rollback to it is
schema-safe.
