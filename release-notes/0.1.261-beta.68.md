# Orbit 0.1.261-beta.68

## Summary

This release is about **a session row you can drag onto a folder**, about **the Background row above the composer**, and about **Android's task pages showing a landing-check exemption**. On web and macOS a session row can be dropped on a folder row to file it there; the Background row uses the app's own running mark and lets an ended item clear at the agent's next turn; and an Android task page now shows that its landing check is exempt and why. It also fixes **images inside Markdown table cells on Apple** and an Android schedule-history test that failed on a slow CI host. The range is `v0.1.261-beta.67..origin/main` (`319cf77397`).

**A session row drags onto a folder to file it (web and macOS).** A shortcut for the Move panel's first group: dropping a row on a folder row, or on a folder page's head for No Folder, runs the same move request and toast as Move…, through a hook both now share (`e103e1afaa`, `6f5283f2e9`).
- **Web:** the drag carries its own data type, so drop-to-upload on the session pane still reacts to files only (`e103e1afaa`); while a row is dragged the list auto-scrolls and no longer selects the text it passes over in Chromium (`8978a1c717`).
- **macOS:** the rules live in OrbitKit's `SessionFolderDrag`, tested beside the web's, and the list auto-scrolls near its edges while a drag is held (`6f5283f2e9`).

**The Background row above the composer uses the app's running mark, and clears an ended item sooner.**
- **macOS:** the row used the system activity indicator while the rest of the app uses `SpinnerGlyph`, so the screen showed two kinds of loading; it now uses the app spinner (`7761e3bc29`).
- **Android:** the tray's running mark was a smaller grey ring; it now draws the app's running mark like iOS (13 pt, 2 pt stroke, accent) (`e5aaa88687`).
- **Shared rule (D1, revised 2026-11-21):** an ended item's cut-off is now the later of the person's last typed message and the start of the agent's latest turn, so a failed item the agent was woken by stops pinning once it has followed up. Applied in the shared row and web (`5678fe6991`), OrbitKit with the turn start decoded from a saved transcript snapshot (`80f19b4dfc`, `184bb0d3c0`), and Android (`9a937aba2b`).

**Apple draws images inside Markdown table cells.** A table cell was drawn by the inline Markdown parser, which drops images, so a reply that listed its screenshots in a table showed empty cells on iOS and macOS while web showed the pictures; a cell holding an image now splits into text and image pieces, and those images also join the session image viewer's pages (`3c52fe2c99`). A cell's image has its own smaller size limit, so one image at the 300 pt prose limit no longer pushes the other columns off a phone's screen, and cells fill the row's height instead of drawing their bottom edge under a one-line cell beside an image (`319cf77397`).

**Android shows a task's landing-check exemption.**
- A task read's `landingCheckExempt`, its reason, by-session and owner-set-at are decoded; an exempt task's Landing section shows "Landing check · Exempt", the reason, who marked it and when, and Remove exemption, as web's `TaskLandingExempt` does (`22189bf97a`).
- A `LANDING_CHECK` entry skipped `TASK_EXEMPT` was drawn as a failed check that opened on its own and read inline output; it now reads "Landing check · Skipped" with "Exempt: <reason>" and the skipped arrow, as web does (`33b4952524`).

**Under the hood** (`e2617f72a1`, `5adc7808b2`, `735ccb799a`): the built-in tier pg spec's model of no family changed from grok-4.7, which the measured Grok family now tiers S/M, to muse-spark-1.3, which no rule ranks; the Android schedule-history test waits for the session's detail before Back, so a slow CI host cannot press Back first and lose the folder; and the engine-session door census gets a driver for the background-job stop route, which had none.

## Upgrade impact

- **Database migrations:** none. No file under `src/apiserver/prisma/migrations/` changed in this range (`git diff --stat v0.1.261-beta.67 origin/main -- src/apiserver/prisma/migrations/` is empty), so there is nothing to run and no schema change to reason about.
- **Configuration:** nothing new to fill in.
- **Runner** (`src/runner-go`, built from this tag and served at `/dl`): no runner change in this range. A runner from beta.67 or this tag works the same; older runners keep working.
- **Clients:**
  - *macOS:* drag-to-folder, the Background row's app spinner and Markdown table-cell images on the beta channel (DMG and Sparkle appcast).
  - *iOS:* TestFlight marketing version 0.1.261, build number the commit count, with Markdown table-cell images.
  - *Android:* `versionName` `0.1.261-beta.68`, the next `versionCode`, and `android-update.json`, with the landing-check exemption, the skipped row and the Background row's running mark.
  - No minimum client version is enforced, and no one-time step is needed.

## Security fixes

None in this release.

## Known limitations

- **iOS does not draw the landing-check exemption yet.** The task page's exemption panel and the "Landing check · Skipped" row are on web and now Android; no commit in this range adds either to iOS, and web is the reference (`33b4952524`).
- **Drag-to-file is on web and macOS only.** No commit in this range adds the drag shortcut to iOS or Android, which keep filing a session through Move….

No commit message in this range records a workflow run or the full macOS, iOS, web or Android suites, and this release does not claim them run.

## Rollback

The previous tag is v0.1.261-beta.67, commit `af727666d23ee253c9c91e0e847d73fcab2f95b4`. A server deployed from this tag rolls back to that commit. Native clients roll back by installing beta.67's build.

An application-only rollback to beta.67 is schema-safe: this range changes no migration and no stored data.

The client behaviors do not roll back with the code: a beta.67 client loses drag-to-file, the Background row changes, the Markdown table-cell images and the Android landing-check exemption views.
