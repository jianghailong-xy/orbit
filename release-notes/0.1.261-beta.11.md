# Orbit 0.1.261-beta.11

## Summary

The work merged since [0.1.261-beta.10](0.1.261-beta.10.md), on the beta channel. beta.10 reached TestFlight
only: its macOS build stopped at the Settings screen ("unable to type-check this expression in reasonable
time") and its Android job at one flaky test, so neither the macOS beta update nor the Android APK was
published. For macOS and Android this release therefore also carries everything in the
[beta.10](0.1.261-beta.10.md) and [beta.9](0.1.261-beta.9.md) notes: scheduled tasks, the prompt optimizer,
Show both languages, ~30 translation languages, the recovery contract and managed runners in Machines & models.

- **Fixed (macOS): the Settings screen builds in the release configuration.** Each of its sections is a view of
  its own, so the compiler no longer times out on it; nothing on the screen changed.
- **Fixed (server): a message held for its translation no longer wedges its session.** When a turn ended or a
  session finished, the server marked every unanswered message answered, including one whose translation had
  failed; the database refused the combination and the runner retried the write every 2 s. Such a message now
  stays waiting with Retry, Send as written and withdraw. Already deployed to production.
- **A background job gone quiet** is drawn as the wake line in the agent's stream, and a turn that said nothing
  draws no empty bubble (web, iOS, macOS, Android).
- **Web:** a Machines submenu in the account menu, whose managed runner shows its state rather than Ready; the
  translation flip moves to the start of your message's meta row.

## Upgrade impact

- **Database migrations.** None since beta.10. Over beta.8 there are `0645_create_request_receipt`,
  `0830_schedule_run_start`, `0840_schedule_attention` and `0860_schedule_check_only_asks`, all additive and
  already applied in production.
- **Runners.** Runners on the beta channel move to 0.1.261-beta.11 once the server is deployed after this tag
  (`/dl` serves the newest tag at deploy time). Nothing in the runner changed since beta.10.
- **Configuration.** No changes required.
- **Clients.** macOS users who enabled "Receive beta updates" get this build. iOS ships to TestFlight
  (marketing version 0.1.261, build number = commit count). Android offers the APK to every install via
  `android-update.json`.

## Security fixes

None in this release.

## Known limitations

- Android has no Scheduled page yet; schedules are created and read on web, iOS and macOS.
- The known limitations of [0.1.261-beta.10](0.1.261-beta.10.md) still apply.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.11` and tag `v0.1.261-beta.11`. This tag publishes the
macOS DMG and Sparkle payload (beta channel), the iOS TestFlight build, the runner binaries, and
`orbit-android-0.1.261-beta.11.apk` with its `.sha256` and `android-update.json` on the same GitHub Release.

The Settings fix built as a signed, notarized DMG in a manual release run on its branch (run 43782339535), and
the five OrbitKit suites that read that file passed (52 tests). The held-message fix was red on the old code and
green on the new in `held-turn-drain.pg.spec.ts` (3/3 against PostgreSQL 16), with 3,051 apiserver unit specs
passing. The Android test that failed in beta.10's release job
(`EvidenceFilesCardTest.theViewerStaysOnItsPictureAcrossTheActivityBeingRecreated`) passed in main's Android CI
on a later commit.

## Rollback

Roll back to 0.1.261-beta.8, the last release whose macOS and Android builds were published. The migrations
since then only add tables, columns, indexes and allowed values that beta.8 does not read, so an
application-only rollback is schema-safe. Runners do not move back by themselves: roll them back with the
`/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
