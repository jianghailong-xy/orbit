# Orbit 0.1.261-beta.73

## Summary

This release **adds a Quality view to Model tiers on web, macOS, iOS and Android**, with the **parent's rating of a SubAgent run** behind it, and carries fixes to the Android session reader, the Apple apps, coordinator hand-over and the runner. The range is `v0.1.261-beta.72..origin/main` (`e9972036cf`).

**Every model now shows how well it completes work.** A parent session can rate a SubAgent run it started, 1 to 5 with an optional note, with the new `subagent_rate` tool or `orbit subagent rate` on the runner (`c4148065b8`); the rating stores the rater's own engine, provider and model, a later rating replaces the earlier one, and a foreground delegate's result now carries one line asking for it. A SubAgent is not offered the tool, and a check-only schedule is denied it. The server takes a rating at `POST /runner/sessions/:id/subagents/:runId/rating`, and `GET /providers/subagent-tiers` gives every model its decayed SubAgent rating and its task first-pass rate over 90 days, with quota and capacity failures left out (`e8de36aac6`). Model tiers draws a SubAgents line (the rating with rated/total) and a Tasks line (first-pass rate over done tasks), each reading "Not enough …" below its minimum and "No runs yet" with neither, and who rated sits in a tooltip on the SubAgents line (`3017117289`). The Mac gets a column and the iPhone the lines under the model, where the "SubAgents" label no longer wraps (`967174e707`). Android follows iOS: lines under the model on a phone, a column on a tablet, a tap on the SubAgents line showing who rated, with the tablet columns rebalanced so the figures, the model id and an "Older · uses …" tier all fit (`cf78eb5217`). The display only: routing reads none of it.

**The Android session reader holds a card where it was put.** A WAITING request that found no card stood until the page closed, so a decision card arriving minutes later pulled the list away from a reader in history; it now lapses after 10 s and when the reader touches the list (`5979c61339`). The opened card, and a record jumped to, are put back whenever the cards item or the window's rows change, until the reader touches the list or 5 s pass with nothing moving it — and the quiet restarts only when a put-back actually moved the view, where before every change restarted it and a busy conversation held a card already in place for ever (`52789f2f15`). A reader resting on the cards with no event row in view now tells the model it is not following, so a resync does not reseed under them.

**The Apple apps read a task's exemption from its record.** A task page's origin badge now reads the newest unreverted exemption record that set it, as web does — Coordinator, Approved on a card, or You, with its time — and it is read for an owner's own mark too; the landing's check list orders a step's status as web does, failed before skipped, and a TASK_EXEMPT line reads no inline output (`3ca2e6e132`, `60963ce4f5`). The Agents line and its sheet now draw their running mark with the app spinner, like the Background row beside them (`1a5e48ec25`).

**Coordinator hand-over no longer stops when the model cannot start.** A coordinator whose model was broken could not be handed over: reviving it to write its note never reached the engine, and the hand-over stopped as "the turn failed" even though the owner had already picked another model. When the note turn fails undelivered, the hand-over now goes on without a note on the picked successor; with no pick it fails as `COORDINATOR_CANT_RUN`, whose sentence says to pick another model and hand over without a note (`7a341a1bcc`).

**A sandbox warning can be handed to an agent.** The runner now recognises Codex's missing-bubblewrap line as a recoverable degraded-sandbox diagnostic instead of a failed turn, keeping the raw stderr beside it for older clients (`611cde1c9d`); a warning a session caught can be handed to an agent (`5e57dcc4a3`), and the transcript's sandbox warning offers "Fix with an agent" on web, the Apple apps and Android (`d3870d0e0b`, `0cfc972e92`, `e9972036cf`).

**Model routing is one place.** On web, Model tiers and the Routing report are merged into Settings → Providers → Model routing (`fa5f3df27b`), and "Smart model selection" is renamed "Route by tier" (`a13c747b4d`).

**Smaller changes.** The Open-list hint change was withdrawn: flat coordinator Open-list conversations draw the five LANDING-only sources — owner items, their owed state through promotion and integration, and the merge approval's main branch — so writes to them count toward the list hint again, and tests pin each of the five out of every flat, project-scoped and `since=` read (`6601a84b41`, `1001583629`, `c795ab78b5`). A remote SubAgent may now upload files from its own worktree — the one it runs in — while other runs' worktrees stay refused (`d5092af4df`). Host setup run without root from an account's own copy now prints the root-owned copy to put in place and the setup to run from it, so the first sudo attempt succeeds (`a8f2334d56`). On web, a popover closed by a press outside no longer hands the focus ring back to its trigger in Safari (`50b973e8ba`). `release-notes/0.1.261-beta.65.md` is corrected: only the exemption's copy reached the Apple apps in beta.65, and its drawing shipped in beta.72 (`a6069c52b1`).

## Upgrade impact

- **Database migrations:** one new file under `src/apiserver/prisma/migrations/`, 28 lines, new — no migration file is changed or removed.
  - `1429_subagent_run_rating` is additive only. It adds six nullable columns to `subagent_run` — `rating_score`, `rating_note`, `rated_at`, `rater_engine`, `rater_provider`, `rater_model` — a check that `rating_score` is NULL or between 1 and 5, and an index on `("owner_id", "created_at")` for the Model tiers view's 90-day read. It has no UPDATE or DELETE, existing rows keep NULL in all six, no table is altered beyond those additions, and every statement can run twice. The commits that add it call it "migration 1420" in their messages; the file in this tag's tree is `1429_subagent_run_rating`.
- **Ordering:** beta.72's requirement stands unchanged. **Every replica must already run v0.1.261-beta.70 or later before this tag's apiserver boots migrations 1401+.** A server older than beta.70 writes a terminal session status with no `finished_at` and is refused by 1401. `1429` sits after `1428` and needs no particular order around the rest.
- **Release cause:** unchanged from beta.71. `session.release_cause` is no longer written and is gone from the Prisma model, but the column and `session_release_cause_chk` remain in the database until a later deploy (step R8). A beta.70 server still writing them during a hand-over harms nothing. The coordinator hand-over's `failure_code` gains `COORDINATOR_CANT_RUN` as a value; it is a comment-only change in the Prisma model and needs no DDL.
- **Configuration:** nothing new to fill in.
- **Runner** (`src/runner-go`, built from this tag and served at `/dl`): the binary carries the `subagent_rate` tool, `orbit subagent rate`, the rating ask in a foreground delegate result, the remote SubAgent's own-worktree upload, and the host-setup message for a non-root account copy. A managed-runner deployment picks these up by updating the runner; older runners keep working, and the rating tool needs this server's new route. The SubAgent rating's parent and the Model tiers display both come from this release; the display needs this server and a client that draws it.
- **Clients:**
  - *macOS:* the Model tiers Quality column, the Apple exemption and spinner fixes, and the hand-over copy, on the beta channel (DMG and Sparkle appcast).
  - *iOS:* TestFlight marketing version 0.1.261, build number the commit count, with the Quality lines, the same Apple fixes and the hand-over copy.
  - *Android:* `versionName` `0.1.261-beta.73`, the next `versionCode`, and `android-update.json`, with the Quality display, the reader card hold, and the hand-over copy.
  - *Web:* the Model tiers Quality column, the popover focus fix and the hand-over copy, with the next server/web deployment, not from this tag's client artifacts.
  - No minimum client version is enforced, and no one-time step is needed beyond the upgrade ordering above.

## Rollback

The previous tag is v0.1.261-beta.72, commit `1de50bb03b26f9b4c1c4c4ee3236be1da74f5f94`, the last release published for macOS, iOS and Android. A server deployed from this tag rolls back to beta.72's commit.

An application-only rollback to beta.72 is schema-safe, and to no release older than beta.70. `1429_subagent_run_rating` only adds nullable columns, a check every stored NULL row satisfies, and an index beta.72 never uses; beta.72 writes no rating, reads no rating, and the newer triggers and functions it runs are the ones it shipped with. A release before beta.70 cannot be the rollback target: 1401 refuses its terminal writes.

The client changes do not roll back with the code. Rolling macOS or Android back from this release means installing beta.72's build, which loses the Model tiers Quality display, the Apple fixes and the Android reader card hold. An iOS device can also go back to the beta.72 TestFlight build.
