# Orbit 0.1.261-beta.1

## Summary

The work merged since [0.1.260](0.1.260.md), on the beta channel. A queued session now shows its first
message before a runner claims it (the opening turn is listed under the id its turn will have); the iOS
session list's pinned section header is glass and runs edge to edge on the pinned header; the task card's
unfold chevron stands bare when there is no "+N"; project pages list only crossings and a trashed
coordinator is replaced rather than left dangling.

The macOS sidebar crash fix that this project was about is **not** new here: it merged on 2026-11-14 at
09:05 UTC and is already in the 0.1.260 stable release, which was tagged later that morning. This beta
exists because the project asked for the sidebar fix to ship as a beta before the rest of its work; that
shipping already happened, and this tag is the field build for the client changes above. Its evidence
(200 real WindowServer clicks on the fixed build; twelve real-click runs on beta.242 as a negative
control, none reproducing the one-off race) is in `docs/evidence/macos-sidebar-crash/`.

## Upgrade impact

- **Clients.** macOS users who enabled "Receive beta updates" get this build; everyone else stays on
  0.1.260, which already carries the sidebar fix. iOS ships to TestFlight (marketing 0.1.261, build
  number = commit count). Android offers the APK to every install via `android-update.json`.
- **Runners and server.** The version of record is `package.json` `0.1.261-beta.1`; `/dl/version.json`
  names it once a server built from this commit runs. Deployments pinned to a stable tag are unaffected.
- **Database migrations.** None between 0.1.260 and this tag.
- **Configuration.** No changes required.

## Security fixes

None in this release.

## Known limitations

- The macOS sidebar crash was a one-off race that no harness could force: twelve real-click runs (about
  2,400 WindowServer clicks) against the beta.242 build, including targeted runs that remove and restore
  the Wiki row while clicks land on it, all stayed alive. The fixed build survives the same 200 real
  clicks and its evidence is recorded as an honest negative control; the beta channel is the field check.
- The known limitations of [0.1.260](0.1.260.md) still apply.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.1` and tag `v0.1.261-beta.1`; `release.yml`'s
identity job refuses a tag whose name and package version disagree or whose notes are missing. This tag
publishes `Orbit-v0.1.261-beta.1-arm64.dmg` and `.zip` (macOS beta channel, Sparkle), the iOS TestFlight
build, and `orbit-android-0.1.261-beta.1.apk` with its `.sha256` and `android-update.json` on the same
GitHub Release. The sidebar change's macOS/iOS builds, OrbitKit suite and real-click runs are recorded in
`docs/evidence/macos-sidebar-crash/`; the client fixes merged since 0.1.260 were gated by the client CI
runs on main.

## Rollback

Roll back to 0.1.260. There are no migrations or configuration changes between the two, so an
application-only rollback is safe. Runners do not move back by themselves: roll them back with the
`/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
