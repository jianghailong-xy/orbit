# Orbit 0.1.261-beta.49

## Summary

This release reworks the **tool-call approval card** on every client. The card no longer prints the call's
input as JSON: it asks what the call does ("Run a command?", "Edit a file?", "Fetch a web page?", ...), shows
the tool name as a badge, states the description once (translation first, the agent's original in grey), and
draws the call itself by tool — a `$` command folded after 12 lines with its timeout, background and
sandbox-off chips; a path and a diff for an edit; the URL or pattern for a fetch or search; key/value fields
plus "Show raw input" for anything else. The release also tells the **prompt optimizer what a card reply
answers**, keeps ✦ Optimize on while a card's *Chat about this* reply is armed on web, and lets the iPhone
composer fold Optimize to ✦ before the model name truncates. A queued scheduled run gets its own clock mark,
an Android baseline card draws its heading again, and the release pipeline now merges the Sparkle appcast
when a release publishes rather than when its DMG builds.

- **Tool-call approvals (web, macOS/iOS, Android).** The plain "Approve tool call" card printed
  `JSON.stringify(input)`: a multi-line command came out as one escaped line and the description appeared
  twice. Every client now draws the call itself, with the blocks above. Web moves `Pre`, `Diff` and `KeyVals`
  into `ToolBlocks.tsx` so the card reuses the transcript's blocks without loading the transcript. The board
  is `docs/mocks/tool-call-card`. On macOS the transcript's monospace fold now takes a line count, so a card
  folds at 12 lines and the transcript at its usual limit.
- **Prompt optimizer, card replies.** `POST /prompt-optimizations` takes `replyingTo`: what a draft armed by
  a card's *Chat about this* answers, as the card shows it (a question card's questions and options;
  otherwise the reply bar's subject and the facts it carries). The server reads up to 4,000 characters of it
  and puts it in front of the draft, telling the model to keep the draft a reply to it. Web and macOS send
  it; Android has no armed card reply, because its *Chat about this* writes the card's facts into the draft
  itself. `replyingTo` is not one of the "Used: …" chips, since the card it came from is on screen.
- **Web: ✦ Optimize stays on while a reply is armed.** The web composer turned the optimizer off whenever a
  reply was armed, so a question card's chat reply could not be optimized. It now matches macOS/iOS and
  Android, and what *Use* puts in the box answers the card like any typed reply.
- **iOS: the composer footer folds Optimize, then the effort.** A full footer folds the Optimize control to
  its 32 pt ✦-only form and then drops the effort label, before the model name truncates; Optimize sits
  below the model control's layout priority, and the phone model chip gains a name-only form. Each narrower
  form is used only where the row has no room for the wider one (board `composer-usage-tap` 04, option C).
- **iOS: the context gauge keeps its width beside Optimize.** A min-only frame let a full toolbar squeeze the
  plan bar and ring capsule below its content, which then drew over the model name and Optimize; the gauge
  now holds its width.
- **Scheduled runs: a queued run's circle wears a clock mark.** A QUEUED run drew the same empty circle as an
  occurrence still to come. It now carries clock hands inside the ring on web, macOS/iOS and Android.
- **Android: a failing landing baseline draws its own card.** A baseline row (`INTEGRATION_CHECK_FAILED`
  with `baseline`) took the "Who fixes it?" layout, whose early return skipped its heading ("Baseline checks
  failing on <branch>"), "Landings on hold" and "View held tasks". It now draws them as web and iOS do.
- **Release pipeline: the appcast is merged at publish time.** The `dmg` job seeded its appcast from the feed
  live on GitHub Pages when it built, and `publish` pushed that file back later. A release whose DMG waited
  for a macOS runner while a newer release published wrote back a feed without the newer version: on
  2026-11-16 beta.22 left beta.23 out. The `dmg` job now writes an appcast holding this release's entry
  alone; `publish` reads `appcast.xml` from `gh-pages` as it stands, merges the entry in with
  `scripts/sparkle-appcast.mjs` (same version replaced, newest build first, entries copied byte for byte),
  and pushes; a push that loses to another release reads the branch again and merges again. The Sparkle key
  stays in the `dmg` job, since each entry is signed over its own zip and the feed itself is unsigned.
  `docs/github-pages.md` and `docs/supply-chain.md` are updated to match.
- **Also.** Design boards are added and updated under `docs/mocks/`: `tool-call-card`,
  `composer-usage-tap` 04, `feishu-hide-orbit` and `feishu-open-access`, and the iOS session-row glyph board
  now marks option B as the chosen one.

## Upgrade impact

- **Database migration: none.** No file under `src/apiserver/prisma/migrations/` differs from
  v0.1.261-beta.48, so this apiserver applies exactly the migrations beta.48 already applied, on boot as
  usual. There is nothing to run by hand, and no schema change makes a rollback unsafe.
- **Server:** the only server change is the prompt optimizer's `replyingTo` (`src/apiserver/src/sessions/
  prompt-optimizer.ts`, with the shared request type in `src/shared/src/prompt-optimizer.ts`). Tagging does
  not deploy the server: it reaches an instance only when that instance is upgraded from this source. An
  older apiserver drops the unknown field rather than refusing it (its `ValidationPipe` whitelists and does
  not forbid extra properties), so the request still succeeds and the draft is optimized without the card
  context until the server is upgraded.
- **Web:** the tool-call card, the Optimize fix and the queued-run mark reach browser users only when the
  deployment's web is rebuilt from this source; the tag does not deploy the web app.
- **Runner:** no Go file under `src/runner-go/` differs from v0.1.261-beta.48, so a runner from the previous
  release behaves identically. The runner served at `/dl` is built from this tag.
- **Configuration:** nothing must be set on a server, and the release pipeline needs no new secret. The
  appcast change removes the `dmg` job's download of the published feed and moves the merge into `publish`,
  which pushes `appcast.xml` with the workflow's own `GITHUB_TOKEN`; the Sparkle key remains in `dmg`.
- **Clients:** macOS beta users get the DMG on the beta channel. TestFlight gets marketing version 0.1.261,
  with the build number as the commit count. Android gets `versionName` 0.1.261-beta.49 and
  `android-update.json` from this tag. Nothing the clients draw here needs a newer server: the tool-call
  card, the queued-run clock mark and the Android baseline card all draw data the clients already receive.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE. No dependency is
added, removed or bumped: `package-lock.json` is unchanged between the two tags, and `package.json` differs
from v0.1.261-beta.48 only in the version line the release commit writes and in `test:release-identity`,
which now also runs `test/sparkle-appcast.test.mjs`. The appcast change keeps the Sparkle signing key where
it already was, in the `dmg` job, and adds no new credential; the `publish` job's push to `gh-pages` uses the
workflow token.

## Known limitations

- **A card reply is only as good as the server.** Until the server is upgraded from this source, it ignores
  `replyingTo`, so the optimized draft is not told which card it answers. Nothing fails; the reply context
  is simply absent.
- **Android does not send `replyingTo`.** Its *Chat about this* writes the card's facts into the draft
  itself, so the optimizer there is never told the card separately. This is by design in this release.
- **The macOS DMG container is not codesigned.** It is notarised and stapled, so Gatekeeper accepts the app,
  but `spctl` reports the `.dmg` itself as having no usable signature. This predates this release.
- **On a full iPhone composer footer the Optimize control is drawn as a ✦ glyph alone.** That is board
  `composer-usage-tap` 04, option C: the narrower form is used only where the row has no room for the wider
  one, and the word comes back as the row widens.

## Rollback

The previous tag is v0.1.261-beta.48, commit `c5177650a6a7aac9d015a915cb6edd9527860ba3` (its tag object is
`99acd1af902ef69e471f8dfa2c2df8c231e074ad`). For clients, rolling back removes the new tool-call card, the
queued-run clock mark, the web Optimize fix and the iOS composer-footer changes; they draw what they drew
before.

An application-only rollback to beta.48 is schema-safe, because this release adds no migration: the two tags
carry the same `src/apiserver/prisma/migrations/` tree, so the schema stays as it is. No backup or restore
step is needed. See [Release process](../docs/release-process.md#rollback-decision-and-procedure).
