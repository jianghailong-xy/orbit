# Orbit 0.1.261-beta.77

## Summary

**Claude Code sign-in works again on runners carrying Claude Code 2.1.330.** `c0871d90dc` teaches the runner to read 2.1.330's sign-in link: where earlier versions printed a `claude.com` link, 2.1.330 prints `https://claude.ai/oauth/authorize?<token>`, so the relay never saw a link. Before this fix, signing Claude Code in from the web — Add account, or Sign in on a machine's engine row — left the card on "Starting sign-in on the runner…" until the relay gave up after 90 seconds, then failed with "couldn't read a sign-in URL" and took the new account away again. The same range moves the managed-runner image and the apiserver's codex stage to Claude Code 2.1.330 (`5790704fb0`), so the fixed runner is the one that ships with 2.1.330.

**An engine's sign-in can now finish in the Orbit Cloud runner's browser.** `52eeb7c894` adds a `browser` login command to the runner: it opens the waiting attempt's link as a tab of the runner's shared Chrome, keeps agents' browser calls out until the attempt ends, and takes Claude Code's code from its callback so the owner pastes nothing; runners that have a browser declare `login-runner-browser/v1`. `1b0b182953` adds `POST /runners/:id/browser/sign-in` on the server, behind the browser switch and only for the owner's Orbit Cloud runner declaring that version: it marks the attempt as waiting on its link (`runner.login_browser`), and the heartbeat hands the runner `browser` until its report on that attempt says what became of it, which the sign-in card reads. `74808e9db3` puts it on the web card: on that runner the card offers to finish the sign-in there, the press opens the browser tab in control, and the card follows the runner's answer, waiting for Claude Code's code from that browser with the paste a press away. `040984fc9c` makes an engine row's Sign in start the sign-in as + Account does — with no tab opened first — and once the link is there the card offers this browser or the runner's; Kimi keeps its site choice, and a panel reopened on its waiting sign-in takes it up instead of starting another. `b9646aaffd` updates the design doc to say what the code does.

**A schedule's Change… opens a change conversation bound to the schedule instead of a blank composer.** `313eef7602` draws the first message from the schedule as it is (does, when, runs in, may, costs, and what changes at once versus needs Allow); no engine starts and nothing is written until the person's first words. `GET /api/schedules/:id/change` gives the open conversation or the opening, and `POST` opens it with the words or says them in the one already open. Migration `1447` adds the `SCHEDULE_CHANGE` run source, `session.change_schedule_id` and its opening, and `asked_text` on revisions and change requests. Each message reaches the agent with an `<orbit_schedule_change>` note naming the schedule at delivery; a change made from it is the person's (`changedBy USER`) and is still judged as a session for the envelope; history shows the words and links the conversation; the conversation is in no session list. Web, iOS/macOS and Android all follow the board.

**Model routing picks the model first, then the account, and draws each model as one row.** `1181f070c2` makes SubAgents under Intelligence and Balance choose the model by preference — the owner's provider order, then the owner's tier over a rule's over an engine table's, then the table's order — and only then the account that runs it, by quota; Balance lets another same-tier model take over when the preferred one has no subscription with room or when a weekly/monthly quota resets within a day. Cost is unchanged, and task runs keep the old order (`rankTogether`) so their picks do not move. On web, `7ee1ad1d2a` draws each model as one row with its accounts' runs summed and Tier and Price "Varies" where they differ; a click opens a row per account; Quality reads on one line with both lines in full in its tooltip, and Cost is gone from the table and its totals line. On iOS and macOS, `df57d4467d` gives the Infrastructure page's Model tiers the same shape: one model's rows on every provider as one block, the first naming the model by its vendor name and carrying its Quality with "Pooled across N providers", the rows under it showing only provider, tier and price. `9817a6601e` describes the two-step order in the Optimize For tooltip under Settings › Providers › Model routing and in the design doc.

**Android's held tag sits at the right edge, and the engines move to their latest stable versions.** `41be13d413` right-aligns `Queued · runner full · Cancel` (and `· runner updating`) under the reader's message, which drew at the list's left edge under a right-aligned bubble where iOS and web align it to the end. `5790704fb0` bumps the managed-runner image and the apiserver's codex stage: Codex 0.170.0 → 0.171.0, Claude Code 2.1.328 → 2.1.330, Kimi Code 2.6.3 → 2.7.2, Antigravity CLI 1.5.12 → 1.5.14; OpenCode 1.19.6 and Cursor CLI are unchanged.

## Upgrade impact

- **Database migrations:** two files are added between v0.1.261-beta.76 and this tag, and **both are additive**:
  - `1447_schedule_change_conversation` adds the value `SCHEDULE_CHANGE` to the `session_run_source` enum with `ADD VALUE IF NOT EXISTS` (its own comment notes no statement in the file uses the value, so it is safe inside the migration's transaction); adds two nullable columns to `session`, `change_schedule_id` (`UUID`) and `schedule_change_opening` (`JSONB`); adds a foreign key from `session.change_schedule_id` to `schedule.id` with `ON DELETE SET NULL ON UPDATE CASCADE`; adds a partial index `session_change_schedule_idx` on `(change_schedule_id, created_at DESC)` where the column is not null; and adds nullable `asked_text` (`TEXT`) to `schedule_revision` and to `schedule_change_request`. No row is written; every stored row reads NULL in the new columns.
  - `1462_runner_login_browser` adds one nullable column, `runner.login_browser` (`TEXT`), holding `requested` from the press until the runner answers and then its answer (`opened`, `failed` or `code-taken`), or NULL when nobody asked and with every new sign-in. Its own comment calls it catalog-only: no stored row is rewritten, and every stored row reads NULL, which is what every sign-in was until now.

  Neither file updates or deletes an existing row and no other table is altered. On main the migration names run 1431, 1432, 1433 and then these two; `1447` sorts below `1462`, and both are independent, so a boot applies whichever it has not yet recorded in the Prisma ledger, in name order.
- **Configuration:** no new environment variable or setting is required. The sign-in in the runner's browser is behind the browser switch and appears only for the owner's Orbit Cloud runner that declares `login-runner-browser/v1`; elsewhere the card offers the owner's own browser.
- **Runner** (`src/runner-go`): changed in this range — `login.go` (the `claude.ai` link and the `browser` login command), `login_runner_browser.go`, `browser_supervisor.go`, `runloop.go`, `transport.go` and `types.go`. The supply-chain job builds the runner binaries from this tag, and the runner served at `/dl` is built from this tag; a production deployment is what puts it there, so the runner at `/dl` shows this tag after the next production deploy.
- **Engines:** the managed-runner image and the apiserver's codex stage move to Codex 0.171.0, Claude Code 2.1.330, Kimi Code 2.7.2 and Antigravity CLI 1.5.14 (`5790704fb0`); the managed-runner image must be rebuilt from `deploy/managed-runner/image` at this commit to carry them and the sign-in changes.
- **Clients:**
  - *macOS:* an engine row's Sign in and the runner-browser sign-in card, the schedule change conversation, and the Model tiers block per model — on the beta channel.
  - *iOS:* the same three, in a TestFlight build; marketing version 0.1.261, build number the commit count.
  - *Android:* the schedule change conversation and the right-aligned held tag, at `versionName` `0.1.261-beta.77` with the next `versionCode` and `android-update.json`.
  - *Web:* the Model routing page's one-row-per-model layout and two-step copy, the schedule change page, and the sign-in card's browser choice, with the next server/web deployment rather than from this tag's client artifacts.
  - The server-side additions are additive: an older client keeps its existing reads and draws its existing page, and no minimum client version is enforced.
- **One-time step:** none.

## Security fixes

None in this release. No commit in this range describes a security fix or names an advisory or CVE.

## Known limitations

The sign-in in the runner's browser exists only on the owner's Orbit Cloud runner with the browser switch on and declaring `login-runner-browser/v1` (`1b0b182953`, `52eeb7c894`); anywhere else the card offers the owner's own browser. Antigravity's sign-in keeps its pasted code rather than taking it from the browser, and Kimi keeps its site choice (`b9646aaffd`, `040984fc9c`). The schedule change conversation is in no session list by design, so it is reached from the schedule it changes (`313eef7602`).

## Rollback

The previous tag is v0.1.261-beta.76, commit `5ef42cd203824cc54a9098181885bae6e9b0030e`. An application-only rollback to it is schema-safe: both migrations in this range only add an enum value, nullable columns, a foreign key, an index and nullable text columns, and beta.76 writes none of them and reads none of them. One caveat the commits do not settle: beta.76 does not know the `SCHEDULE_CHANGE` run source, so a change conversation opened on this release would be read by older code, and the commits do not say how it treats one; check that before rolling back a server that has opened one.

The client changes do not roll back with the code. Rolling macOS or Android back from this release means installing beta.76's build, which loses the schedule change conversation, the Model tiers block per model, the sign-in card's browser choice and the Android right-aligned held tag; an iOS device can also go back to a beta.76 TestFlight build.
