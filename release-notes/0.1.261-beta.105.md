# Orbit 0.1.261-beta.105

## Summary

Beta.104's release run failed on two Android unit tests — `PendingTrayCopyParityTest`, fixed on main by `42df69e26d`, and `ProjectRowWaitingShellTest`, fixed by `4f926c7dcb` — so beta.104 published only its iOS TestFlight build: no GitHub Release, no macOS DMG or Sparkle update and no Android APK. For macOS and Android this release therefore also carries everything in `release-notes/0.1.261-beta.104.md` — Drive chat, the one place pill, the `Sending…` bubble, the server-side session move and the decision-card push among it — and these notes point there instead of repeating it. On iOS, beta.104's TestFlight build already carries that work, and this release adds only what follows.

What follows is the runner link surviving a weak network. On 2026-11-27 the runner on ai-sg, on a path losing up to 30% of large packets, reconnected every 10–40 seconds for 23 minutes and then went OFFLINE while it was visibly reconnecting: a large message held the socket's single write lock for seconds, so pings, pongs and heartbeats timed out behind it. The gateway, the runner and the apiserver are fixed as one change, and a runner that keeps reconnecting is now counted present.

- **Gateway: no ping to a runner it is hearing from, and no message over 16 KiB (209d1c8119; `docs/runner-link-design.md` §15.15).** The ping tick now checks whether the runner sent anything since the last one and, if it did, pings nothing and re-arms: on a slow path its pong would wait behind its own upload. A ping that spent the WebSocket library's 5 s waiting for the write lock was never written and the connection is still open, so it is retried at the next tick instead of closing the connection; a ping whose own write stalled, and any data write that passes its deadline, now closes as the new disconnect reason `write_timeout` instead of `connection_lost` or `ping_timeout`. Every message the gateway writes is at most 16 KiB — a larger frame is cut into `Chunk` pieces, as frames over 256 KiB already were — so one message holds the write lock for a piece's time rather than seconds. `connection closed` now logs the bytes read and written, the largest message written and the longest single write, and `link_disconnects_total` gains `write_timeout` beside the new `link_ping_write_blocked_total`.

- **Runner: only bytes read prove the path alive, writes have no fixed deadline, and both directions send at most 16 KiB a message (209d1c8119; §15.15).** The runner's link socket counts bytes read and written, and its pinger skips a ping while a write is in progress or one took over a second, because such a ping would stall in the flush and the library would close the connection. A watchdog judges a connection dead only when a write has made no progress and nothing has been read for 45 s, replacing the 10 s per-message write limit; a write that is moving is never cut, however long it takes. Before each piece the runner waits, outside the library's write lock, for the kernel's send queue to leave room in the send buffer (Linux `SIOCOUTQ`, macOS `SO_NWRITE`), so a pong can always be written; this is what makes the gateway's ping answerable while a weak path is backed up. Event batches drop from 1 MiB to 256 KiB, pieces are 16 KiB, heartbeats and calls are written between the pieces of a batch, and the link heartbeat's wait is 75 s (unchanged on HTTPS). Failures are logged with their real cause instead of `use of closed network connection`, and a connection that lived under 60 s and that the runner itself judged dead gets an 8 s reconnect floor.

- **Server: a link Welcome counts as being heard, for at most 5 minutes past the last heartbeat (209d1c8119; migration 1750; §15.16).** Presence was written by heartbeats alone, and a reconnecting runner's heartbeats queued behind its event resend or died with the connection. The gateway already calls the welcome route for every new connection, and that write now sets a new `runner_presence.last_heard_at` for the process's own link row — never creating one, and on renewals and repeated welcomes too. Event ingest and RPCs deliberately do not count, so a runner whose work loop is stuck while its engine still emits events goes offline 90 s after its last beat as before. Every reader of presence now uses one rule, `GREATEST(last_beat_at, LEAST(last_heard_at, last_beat_at + 5 min), runner.last_heartbeat_at)`: the reaper's mass-disconnect and offline looks, cell losses, the owner-secrets list, the wiki worker, the session and open lists, help ask, the main checkout, the Cursor key check, delete approval and `/runner/runners`. Clients read the presence instant as `lastHeartbeatAt`, so the web, macOS, iOS and Android need no change and an older client stops drawing a just-reconnected runner as offline. A heartbeat's `lost_at` now also counts a Welcome since the previous beat.

- **Server: a new gauge counts link runners whose full reconcile is overdue (209d1c8119).** `orbit_runner_reconcile_stale` counts reachable runners on the link whose last full reconcile is older than 5 minutes and 45 seconds — the 5-minute reconcile period plus a missed beat — because a healthy runner has up to one beat past the period in which it has not yet reconciled; a reconcile still owed is not counted, and neither is an HTTPS runner, which reconciles on every beat. `orbit_runner_oldest_heartbeat_age_seconds` now measures presence rather than the last beat. Both are documented in `docs/self-hosting.md`.

- **Tests: the reds that broke beta.104's build and main's specs (42df69e26d, 4f926c7dcb, fb318b75af, c316d08759, 0f233c1b2d).** `PendingTrayCopyParityTest` had counted the web's "Put back in the composer" links at two; the `Sending…` bubble's Not sent state added a third, so the check that every Android release build runs had been red since. `ProjectRowWaitingShellTest` told a member opened from the row menu apart from one opened at the end; since the shared always-allow derivation names `echo` instead of every echoed line, the folded command card fits on screen at the tail and its head is in view there, so the test now tells the two opens apart by where the transcript ends. The waiting card in `fb318b75af` keeps its height with each filler line running its own program, which the label names. On the apiserver, the Drive-chat note test (c316d08759) and steer-dequeue's hand-built `conversation_turn` table (0f233c1b2d) had gone red on main's pg shards 1/3 and 3/3 after the Drive chat and its `drive_context` column landed.

- **Docs and drills.** `docs/runner-link-design.md` gains §15.13, §15.15 and §15.16; the link gateway README documents the new ping rule, the `write_timeout` reason, `link_ping_write_blocked_total` and the 16 KiB messages; `docs/self-hosting.md` documents the presence rule and the new gauge; and `scripts/runner-link/drills/weak-link-drill.sh` with `weak-link.compose.yml` is the end-to-end weak-link drill (a runner behind a WireGuard tunnel under `tc netem` loss) that reports what each runner version does. The protobuf change is a comment on `Chunk` only: no field, number or wire shape changes, and the runner's reassembler already accepted pieces of any size.

## Upgrade impact

- **Migrations:** one in this range, **additive**: `1750_runner_presence_last_heard_at` adds a nullable `TIMESTAMP(3)` column `runner_presence.last_heard_at` with `ADD COLUMN IF NOT EXISTS`. The table is UNLOGGED, so it rewrites no row, adds no index and no trigger, and the statement can run twice. The migration was written as 1673 on its task branch and renumbered when it landed, because 1680–1730 had landed on main meanwhile; it was never applied anywhere as 1673. A deployment upgrading from the previous published macOS/Android release, v0.1.261-beta.103, also applies the five additive migrations described in `release-notes/0.1.261-beta.104.md` (1680, 1681, 1700, 1720, 1730).
- **Backfill:** none. Existing presence rows read NULL in `last_heard_at` until their next Welcome, and presence falls back to the heartbeat.
- **Configuration:** none added or changed. The new gauge and the changed heartbeat-age semantics need no setting; the 5-minute cap is a server constant.
- **Server:** no route, field or payload changes shape or name. `lastHeartbeatAt` in the runner payloads now reports the presence instant (a beat or a Welcome capped at 5 minutes past the last beat) instead of the last beat alone. Everything that dispatched work or judged a runner online uses the same rule, so a runner that reconnects stays dispatchable.
- **Gateway:** the link gateway must be rebuilt to get its half — it stops pinging a runner it hears from and writes 16 KiB pieces. A new runner against the old gateway, and an old runner against the new gateway, both keep working in either order; with the old gateway a busy runner's pongs can still queue behind a large message on a badly lossy path. The gateway's own README lists the new metric and disconnect reason.
- **Runners:** the runner served at `/dl` is built from this tag. This range changes runner-go's link code throughout: the socket counters, the write watchdog, the send-buffer wait, 16 KiB pieces, 256 KiB batches, the 8 s young-connection backoff and the named end reasons. An older runner keeps working against this server and gateway, but keeps the 10 s write limit and 1 MiB batches that dropped it on the ai-sg path.
- **Clients:** nothing client-facing changes shape. Web arrives with the deploy of this commit; the macOS beta-channel DMG, the iOS TestFlight build and the Android APK come from this tag. An older client needs no change: the server now sends the presence instant as the `lastHeartbeatAt` it already reads and computes offline from, so it too stops drawing a just-reconnected runner as offline. macOS and Android also get beta.104's work in this release; iOS has it from beta.104.

## Security fixes

None in this range's own changes. For macOS and Android this release also ships beta.104, whose notes record its two security fixes: the over-broad "Always allow" rule derivation and the schedule deny patterns that could not see inside command substitutions.

## Known limitations

- A path that loses small packets as well as large ones still drops the link. When TCP itself goes silent for 30–40 seconds, the runner's 20 s ping (40 s without a pong), its 45 s write watchdog and the gateway's 60 s pong wait judge the connection dead, as they should; those deadlines were deliberately not widened. The ai-sg path this release fixes loses large packets.
- Recovering a long outage's backlog is slower than before: each session may have one event batch in flight per acknowledgement round trip, and a batch is now at most 256 KiB instead of 1 MiB, so the backlog drains faster on a low-latency path and more slowly on a high-latency one.
- A managed runner's manager still judges it by heartbeat telemetry alone (the previous image's silence and sleep), not by the presence rule, so a managed runner on a weak link can still be treated as silent by its manager while the apiserver counts it present.

## Rollback

The previous published macOS and Android release is v0.1.261-beta.103 (release commit `4c2c0b9d5632c55976b34472169dc77a9b8d73b9`, whose source is `eba32202425c08f3a49c4a50f0dbe36bb399a3bc`); the previous TestFlight build is beta.104 (tag v0.1.261-beta.104, release commit `33a7b452f554c2bfa6e95f457e5bf2fabd0d542b`, source `b06a46fa70d5736acdb425fbb26320e4ed78d339`).

Application-only rollback is **schema-safe**: this range's one migration adds a nullable column to an UNLOGGED presence table, so an earlier server neither reads nor writes `last_heard_at`, and every migration between beta.103 and this tag is additive. No down-migration or backup/restore step is needed; deploy the previous commit for the server and web together. A rolled-back server treats a reconnected runner as offline until its next beat, which is the pre-fix behavior.

Client rollback is to v0.1.261-beta.103's DMG and `orbit-android-0.1.261-beta.103.apk`, and to beta.104's TestFlight build on iOS. A beta.103 client keeps working against this release's server — every payload it reads keeps its shape, and it sees the presence instant in the `lastHeartbeatAt` it computes offline from — but it loses beta.104's macOS and Android work as well. With the server also rolled back to beta.103, that client reads a just-reconnected runner as offline until its next beat, which is the pre-fix behavior.
