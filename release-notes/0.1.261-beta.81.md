# Orbit 0.1.261-beta.81

## Summary

**This is the first release to publish since v0.1.261-beta.75.** v0.1.261-beta.76 through beta.80 were tagged, but none produced a GitHub Release, a macOS beta-channel update or an Android APK: each one's Android release job failed. beta.77 failed on `RunnerUpdateLaterTest` (fixed by `45fe88728d`); beta.78 failed on `ConversationCardWidthShotsTest` and `ShareDeliveryTest`; and the same `ConversationCardWidthShotsTest` holds back beta.79 and beta.80, because `116242fc54` left a Project started card that draws nothing without `by`/`projectId`/`projectTitle`, so it measured 0 dp and the test failed. `86d9d9f57b` gives that card a payload it draws, so the Android job can pass. Everything the notes of beta.76–.80 describe therefore ships here, and this file carries their user-facing content.

**Claude Code sign-in works again, and an engine's sign-in can finish in the Orbit Cloud runner's browser.** `c0871d90dc` teaches the runner to read Claude Code 2.1.330's `https://claude.ai/oauth/authorize?<token>` sign-in link (earlier versions printed a `claude.com` link), so signing Claude Code in from the web no longer hangs on "Starting sign-in on the runner…" and then withdraws the account. `52eeb7c894` adds a `browser` login command that opens the waiting attempt's link as a tab of the runner's shared Chrome and takes Claude Code's code from its callback; `1b0b182953` puts it on the server behind the browser switch for the owner's Orbit Cloud runner (controlling `runner.login_browser`); `74808e9db3` and `040984fc9c` put it on the web sign-in card, whose engine-row Sign in now starts the sign-in and then offers either browser, while Kimi keeps its site choice. `1be368a6ee` and `7e19c474a2` close the sign-in tab in the runner's browser and the web's viewer once the sign-in succeeds. The Orbit Cloud browser also gains its agent tools, all behind the browser switch: `browser_status`, `browser_open`, `browser_clear_logins` and `browser_request_sign_in` (with their `orbit browser …` commands) and the `BROWSER_SIGN_IN` owner card on web, Android, Mac and iPhone (`579f76c619`, `d1e88673d4`, `c932a07d58`, `34c0e3f01d`, `82b4fd3d4c`, `b18fb7be83`, `1fd6fa8fc9`); with the switch off the browser is absent from every listing.

**Run now admits a message past a full runner.** When a message waits because the runner, a run or a batch holds every slot, its owner can press Run now: the session's oldest queued turn gets a pass and the claim takes it past all three slot gates while turns plus job-held slots stay under Max Concurrent plus the runner's new Extra sessions on demand (default 2). The runner never stops a running turn to make room (`e4d349c0cf`, `f2183db509`). The runner advertises this to the server, which shows Run now only for a runner declaring `over-capacity/v1`; the web marks the overflow turn and shows the server's refusal, and runner settings let the owner edit that allowance, including zero to turn Run now off (`d70b033d8f`, `e9c7fc2d09`).

**Orbit Files arrives, with the web Files page and the drive on the server and the runner.** The account's drive gets its owner page under Wiki — folder tree, list with who last wrote each file, preview, resumable upload, download, rename/move, grouped Trash with per-item restore, earlier versions, and one-file share links that scan the file for credentials — and Storage moves into Files with the drive's bytes counted once (`45878216e0`, `2645cae173`, `137eb9a652`, `5f3087ec2f`, `34cb70618b`, `6e945e1d1a`, `55b52cfcf4`). The name layer (entries, versions, Trash groups, commits, change feed), a runner drive door, resumable upload and ranged download, `DRIVE_FILE` share links, a `files` token scope and signed download URLs land on the server and runner (`a583d50525`, `b070830559`, `ee4adeb57c`, `8f9894ff55`, `b2cd7e7ee5`); agents reach the drive through `drive_put`/`get`/`list`/`move`/`delete` and `orbit drive put|get|ls|mv|rm` on every runner (`96f9bb5e40`); on Orbit Cloud the drive is a FUSE mount at `/run/orbit-files` behind a new CSI node plugin, and `~/Files` links to it (`cfa00c7bcb`, `90f56f33b9`, `a440a82633`, `03446cc8b9`). Trash moves and deletes run in bounded batches, and the weekly scrub verifies drive and attachment bytes (`d02b0a124a`, `e1b5381a50`, `39e154c019`).

**Model routing names one model's rows alike across engines, pools their Quality, and chooses the model before the account.** Id rules take off an engine's wrapping; what they cannot settle is asked of DeepSeek once in the background and kept in the new `model_identity` table, seeded from production's 116 model ids (`62caf021ee`, `069b42dd64`). The server pools a model's Quality and the web draws each row with its shared name, one model's rows together and a pooled "Pooled across N providers" line (`3066f39c25`, `da6a6ea5a2`, `d9cff05d68`). `1181f070c2` makes SubAgents choose the model by preference and only then the account that runs it, over a two-step order now documented in the Optimize For tooltip (`9817a6601e`); on web, `7ee1ad1d2a` opens each model to its accounts and drops Cost, and on iOS/macOS `df57d4467d` draws one model's rows on every provider as one block. `2a325d8061` keeps a trailing `-max` as part of a model's name, so `qwen3.7-max` is no longer keyed `qwen3-7`, and migration `1463` re-keys the three rows `1433` seeded.

**A schedule's Change… opens a change conversation bound to the schedule, and a GitHub workspace lands in the runner's home.** `313eef7602` draws the first message from the schedule and starts no engine until the person's first words; `GET`/`POST /api/schedules/:id/change` open or continue it, and migration `1447` adds the `SCHEDULE_CHANGE` run source and the conversation's columns. `48b0896b0f` makes a GitHub clone land in the runner's home rather than `<home>/orbit-repos` for a runner declaring `clone-workdir/v2`, with a shared rule in `@orbit/shared` used by the setup cards on web, macOS and Android (`881452df12`, `51a1f9ef35`, `3f9cfe732f`, `5a13f5a73c`, `5843844a63`); a managed runner's first new folder goes in `/home/orbit` (`6c62aa253a`), a not-up managed runner offers `/home/orbit` whatever an earlier image declared (`05b41ea2d4`), and migration `1434` gives managed runners that slept through the move that path in their stored Repos Folder (`6a7106f95b`).

**The project page reads the same on web, Apple and Android, and the worktree bar counts commits on Apple and Android.** iOS gains Open items as a page section with `N need you · oldest first`, web's run-settings summary, the `landingReason` half-sentence, M/D-dated receipts, stalled and start-by-hand rows and unmet-criteria tallies (`3a685589f6`, `1432a3aa88`, `58da64ac2b`); Android follows with the same labels, the three coordinator cards after a project starts and the aligned waiting card (`b0d6c297fe`, `116242fc54`, `cde42e878d`); web gets the same labels and stops counting unmet criteria by landing reason (`f1a03be36f`, `6dfe75e1b7`), and macOS restores its How it runs summary row and drops a stale group (`f382b2a848`, `c793267196`). Following the web, the worktree bar on iOS, iPadOS, macOS and Android reads "3 commits" ("+ uncommitted" / "Uncommitted · 8 files" otherwise), and the Worktree changes sheet opens on a Commits / All changes control (`916f4a0b99`, `68751ed4b1`).

**Feishu alert cards carry their details by default.** Migration `1491` makes `feishu_app.message_detail` default to `FULL` and moves every stored app to `FULL`, because an approval card had read "Details hidden by your settings" so the owner had to open Orbit to see what a tool would run; whoever wants titles only turns "Include details in alerts" off again (`4f636b99c2`). A notify sent outside any session no longer offers "Reply to this message to reply to the session" (`2ece58067a`).

**Smaller fixes and moves.** Android builds resolve Maven Central through Google's mirror first, so they no longer depend on Maven Central answering every request (`442c720344`); Android's held tag sits at the right edge of the reader (`41be13d413`); a web tab showing one workspace's Open list reads it only on a hint naming that workspace or none (`971cd546b8`, `a4bc1930af`, `1ff149da6a`, `dcb5180642`); web reopens a stream lost while the tab was hidden and reads it once (`32891f8e5d`), shares one in-flight subagents read per session (`a957f07fe1`), and no longer loses the next click to a machine drag (`bf08deec7f`); native clients skip `DRIVE_FILE` share-link rows they cannot draw (`d53e7596db`); Codex Auto runs with its sandbox off on an Orbit Cloud runner where bwrap cannot start, with a truthful transcript notice (`c5b295407f`, `ecc210a093`); and a managed runner's sleep drains only on an idle report sent after the request (`3754a9e64a`). The runner now tells agents when to use the workflow tool, next to `delegate` (`cc04a9b403`). The engines move to Codex 0.171.0, Claude Code 2.1.330, Kimi Code 2.7.2 and Antigravity CLI 1.5.14 (`5790704fb0`).

## Security fixes

One tenant-scoping fix: `1b1c7a8e71` looks up a runner by id and owner before rejecting account parameters, so a request naming a runner the account does not own consistently returns not found without writes; a user on an older server that lacks it could have had such a request answered differently. No advisory or CVE is named. The new Files surface is gated rather than a fixed issue: a token reaches `/drive/*` only with the explicit `files` scope, terminal credentials are refused the owner's drive routes, a drive path in an evidence citation is refused, and a shared file is scanned for credentials with the owner shown a warning (`b2cd7e7ee5`, `842c3978a2`, `b070830559`, `8f9894ff55`). No other commit in this range describes a security fix.

## Known limitations

- The Orbit Cloud browser's tools and the `BROWSER_SIGN_IN` card exist only on the owner's managed runner with the browser switch on; off or self-hosted, they are absent rather than withheld. Sign-in in the runner's browser needs a runner declaring `login-runner-browser/v1`; Antigravity's sign-in keeps its pasted code, and Kimi keeps its site choice (`a0bb6d91d2`, `1b0b182953`, `b9646aaffd`, `040984fc9c`).
- A model id outside the 116 seeded is asked of DeepSeek once in the background the first time the page meets it; until that answer arrives its rows show the rule-derived identity (`069b42dd64`). Migration `1463` re-keys only the three Qwen Max rows `1433` seeded; a row keyed by hand without its `-max` is not changed.
- The schedule change conversation is in no session list by design, so it is reached from the schedule it changes (`313eef7602`).
- Clones go into the runner's home only on a runner that declares `clone-workdir/v2`; an older self-hosted runner keeps cloning into its repos folder, so a machine with old and new runners can still hold workspaces in both places, and a managed runner that has not reported is shown `/home/orbit` whatever its stored capabilities say (`48b0896b0f`, `05b41ea2d4`).
- The Files drive's mount and the `~/Files` link are for Orbit Cloud (managed) runners whose cluster runs the `files.orbit.dev` CSI plugin; on a self-registered runner an agent reaches the drive through the `drive_*` tools and `orbit drive` CLI instead. A drive file cannot be executable by group or others, writable by them, or setuid, so `cp -p`, `rsync -a` and `install -m755` of an executable copy its bytes and then fail, and a file created executable is kept `0644` (`cfa00c7bcb`, `90f56f33b9`, `03446cc8b9`, `96f9bb5e40`, `fdf7c67fd8`, `84dd4f1b33`).
- Run now is refused at the door for a runner that is offline, updating, Keep Free, cloning or under a worktree fence, and appears only for a runner that declares `over-capacity/v1` (`e4d349c0cf`).

## Rollback

The immediately previous tag is v0.1.261-beta.80, commit `4f636b99c2575ada9d589792eb85574d47939f8e`, but no release has published since v0.1.261-beta.75, commit `c8db847bbdd4bd168260b937b151f639d6434a53`; v0.1.261-beta.76 through beta.80 were tagged and did not publish, so the last builds a user can install and the last artifacts on GitHub are beta.75's. An application-only rollback to beta.75 is schema-safe: every migration in this range either adds new tables, nullable or defaulted columns, indexes or a widened CHECK, or replaces functions or rewrites stored values, and none drops a table or column or deletes a row; beta.75 writes none of the new columns and reads none of them. Two caveats the commits do not settle: `1434` moves managed runners' `repos_root` to `/home/orbit`, which beta.75 predates, and `1464` changes how the Open-list counter triggers key their writes, so check how a beta.75 server reads workspace-keyed counters before rolling the apiserver back past it; `1463` also leaves three `model_identity` rows under keys beta.75's id rule does not compute.

The managed-runner image does not roll back safely once it has moved a volume's home or its `orbit-repos` marker; roll it forward rather than back. The client changes do not roll back with the code: rolling macOS or Android back from this release means installing beta.75's build, which loses everything beta.76–.81 added; an iOS device can also go back to a beta.75 TestFlight build.
