# Orbit 0.1.261-beta.53

## Summary

This release brings the **Android composer's last differences from iOS into line** and puts **every registered
provider into SubAgent routing**, with a Kimi tier table. A session's **Tasks list now orders its rows the way the
Agents list reads**, a **failed run stays visible on the Agents line while other runs go**, and web gets
**Appearance's choices marked**, **Add a machine aligned** with the machine names and a **Scheduled count that
matches Apple and Android**. The managed-runner image moves to **Claude Code 2.1.328** and **Antigravity CLI
1.5.12**, the runner's `delegate` instruction now claims subagent and background work, and Compose passes the
Orbit Cloud browser's switch through to the apiserver. Nothing in this range changes the database schema or
requires an operator step.

- **Android's composer, down to iOS's details (Android).** The context ring is in the accent, amber from 75% and
  red from 90%, 16 dp, dashed only where the engine never reports one; the plan's bar sits beside it from the
  start, read as the composer opens, in the accent and amber near its limit, red spent. The permission mode is
  always on the toolbar, and a session that names none shows the mode it runs in (Default; Cursor CLI's Accept
  Edits). Images are 48 dp thumbnails with 8 dp corners, dimmed with a spinner while uploading, their x out on the
  corner; other files are a one-line chip (paperclip or spinner, name, size in iOS's decimal units, x). Optimize is
  iOS's pill: 13 sp medium in a 26 dp capsule, 32 dp wide with the mark alone when the row is full, busy in the
  text colour at 5%/12% (`bde4fdc0b8`).
- **Every registered provider joins SubAgent routing (server, web, Apple, Android).** The owner's rule is that
  anything registered with Orbit takes part, and only the order differs (`c68e99c81a`). Kimi's built-in sign-in
  gets a tier table (S/M K3, L/XL K3.1 Pro, else K3) and its quota and account are read like Claude's and Codex's.
  Every tier joins the pool: the asked tier, then higher tiers nearest first, then each untiered provider × engine's
  default model, then lower tiers — so Antigravity, Cursor, OpenCode, DSH and untiered custom endpoints now route
  instead of being removed. A subscription whose quota was not read ranks after those with known headroom (still
  before metered keys in Cost) rather than being removed or read as free. Policy version `p4-every-provider-1`;
  reasons name a pick outside the asked tier, and the tier footer copy is updated on web, Apple and Android.
- **A session's Tasks list reads like the Agents list (server; web, iOS/macOS and Android draw it as served).**
  The open list put Failed first and Done near the bottom; it now puts running rows first, then every other row
  newest first whatever its status, and each row's pill still says how it ended (`3915d3ad0b`).
  `GET /sessions/:id/created-tasks` keeps its single statement: each status still gives its newest `limit` off the
  index, now merged by age alone.
- **The Agents line counts failures while another run is going (web, Apple).** The failure count was only shown
  with nothing running, so a failed run stayed hidden behind the spinner until every other run had ended. The
  summary now counts failures in every state (web and OrbitKit) and draws "✕ n failed" before the spinner; on Apple
  the title gives way first and the failure count keeps its room, and VoiceOver and the aria-label say it
  (`9f30767447`).
- **Appearance's choices wear a mark (web).** The account menu's Machines level draws a mark before every row, while
  Appearance's System, Light and Dark were bare words; each now has its own in the same grey and column — a
  monitor for System, a sun for Light and a moon for Dark — and the current choice keeps its check at the row's end
  (`783401dbc4`).
- **Add a machine starts where the machine names do (web).** Since each machine row wears its OS mark before its
  name, Add a machine sat 24 px to the left of the names with its + in the end column the state dots use; its + now
  leads in the machines' icon column and the row draws nothing at its end (`4869f802b4`).
- **The Scheduled count in the sidebar matches Apple and Android (web).** The drawer count now also counts the
  schedules and waiting tasks whose condition cannot be read, through one shared rule, `scheduleNeedsCount` — held,
  failing with no run under way, condition unreadable (`ae4d62ebd0`).
- **The runner's delegate claims subagent and background work (runner).** The delegate paragraph only said to
  prefer `delegate` "when Orbit should pick the model, record the cost or run the work elsewhere", and the tool's
  description said nothing about when; headless Claude Code runs sent "work in the background" or "use a subagent"
  to the built-in Agent tool, and delegate got 2 of 18. The paragraph now claims both outright with Orbit's reasons
  (model, cost, a result that survives an engine recycle), and the description adds one sentence saying the same;
  with that it got 17 of 18, while the three prompts that should not delegate stayed at 0 of 54. The longest
  instructions shape grows 34 bytes to 7,216 of 7,424, and the always-loaded description grows 258 bytes. Renaming
  the tool to `subagent` was measured too and changed nothing, so the name stays `delegate` (`82bbd9ee86`).
- **Managed-runner engines (runner image).** Claude Code goes 2.1.327 → 2.1.328 with its optionalDependencies
  layout unchanged, and Antigravity CLI 1.5.11 → 1.5.12 (build id `1.5.12-5281398513336320`, sha512 sums from the
  manifests, confirmed by download) (`843bd03d9e`).
- **A running NATS picks up a changed nats.conf (deployment).** A running orbit-nats keeps the single-file
  nats.conf it started on, and Compose's config hash does not see a new one, so release `bad532ba86`'s `vnc.*`
  grants never reached NATS. The two-stage plan now compares the container's `/etc/orbit-nats/nats.conf` with
  `src/link-gateway/nats.conf`, as it does for db-proxy, gateway and pgbackup, and plans and forces a recreate on a
  difference; the single-host `upgrade.sh` does the same after it brings the link up (`be86ac4498`).
- **Compose passes the Orbit Cloud browser's switch (deployment).** Setting `ORBIT_MANAGED_RUNNER_BROWSER_ENABLED`
  in `.env` had no effect on a Compose deployment, because the apiserver's environment lists its variables
  explicitly; it is now passed through. The default stays off, and the topology test pins the new line
  (`9139540409`).
- **The Orbit Cloud browser in a tab of its own, with paste (web, server, runner, link gateway).** Settings' Open
  browser and the drawer's Take control open `/runners/:id/browser`: only the viewer and a slim bar, in control with
  Fit / 100% and Done, or view only with the session's link and Take control; the drawer becomes a view-only quick
  look whose Open in new tab hands its stream over. ⌘V / Ctrl+V in the viewer sends the text over the viewer's
  WebSocket while that viewer is in control (at most 64 KiB, one at a time), as a new `StreamPaste` link frame
  (`link-stream-paste-v1`); the gateway relays it, and the runner inserts it into the focused page through Chrome's
  DevTools and answers `StreamPasted`. The text is never logged; copying back is best effort. Chrome starts with
  `--test-type`, so the unsupported-flag bar is gone (`ab7cfe740f`; lab scripts and samples `2ff30be143`,
  `a8f18dad45`, `d059973165`, `9fa2a08970`).
- **Also.** Two apiserver censuses again account for `0173cdeb0a`'s job-card reaper — the db-write inventory entry
  for `reapApprovalsOfEndedJobs` and the coordinator count's `countLiveApprovals` — both red on main since that
  commit (`505307a642`). Documentation lands for the browser switch (`5fdb15463d`), a board for opening the browser
  in a tab of its own with paste (`a9778bda2d`), and the owner's decisions on a session's D1, D5 and D8
  (`c7efa7bf9d`).

## Upgrade impact

- **Database migration: none.** `git diff v0.1.261-beta.52 origin/main -- src/apiserver/prisma/migrations/` is
  empty: this range adds no migration and changes none. `1090_runner_browser_state`, from v0.1.261-beta.52, is
  still the newest and was already applied by the previous release; the apiserver has nothing to run by hand here.
- **Configuration: no new switch.** The one change is that a Compose deployment now passes an existing variable,
  `ORBIT_MANAGED_RUNNER_BROWSER_ENABLED`, through to the apiserver; its default stays off, and a value already in
  `.env` takes effect on the next upgrade. No one-time step is required.
- **Runner:** the managed-runner image moves to Claude Code 2.1.328 and Antigravity CLI 1.5.12, and `src/runner-go/`
  changes (the delegate paragraph and tool description, and the browser's paste through DevTools), so a runner from
  this tag is needed for those. The runner served at `/dl` is built from this tag.
- **Link gateway:** `src/link-gateway` changes to relay the new `StreamPaste` frame, so a deployment needs its link
  gateway rebuilt from this source for the browser's paste to work; nothing else in the link changes.
- **Server:** the SubAgent routing policy (`p4-every-provider-1`) and the Tasks-list ordering are apiserver changes;
  each reaches an instance only when it is upgraded from this source, and tagging does not deploy the server. The
  web changes reach browser users when the deployment's web is rebuilt from this source; the tag does not deploy
  the web app. The NATS recreate is done by the upgrade path on a changed `nats.conf`.
- **Clients:** macOS beta users get the DMG on the beta channel. TestFlight gets marketing version 0.1.261, with
  the build number as the commit count. Android gets `versionName` 0.1.261-beta.53 and `android-update.json` from
  this tag.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE, and the root
`package.json` and `package-lock.json` do not change in this range at all — the release commit writes only their
version lines. The NATS fix (`be86ac4498`) makes an intended `vnc.*` grant reach NATS on upgrade; it closes no
exposure on an older release, since the grant was simply absent.

## Known limitations

- **The macOS DMG container is not codesigned.** It is notarised and stapled, so Gatekeeper accepts the app, but
  `spctl` reports the `.dmg` itself as having no usable signature. This predates this release.
- **The browser is one per managed runner, for two viewers at most**, unchanged from v0.1.261-beta.52. A session
  other than the lease holder is told which session holds it, and a third viewer of the same runner is refused. A
  self-hosted runner is never offered the browser.

## Rollback

The previous tag is v0.1.261-beta.52, commit `738ac2b02d9df4cb0bfdd3c71c6aaf0ad587a43b` (its tag object is
`c8df3792cd3d5e1ac6015eaab303f24ddfa61afc`), which was published as a GitHub Release on 2026-11-19. Rolling back
removes the Android composer details, the every-provider SubAgent routing and its tier footer copy, the Tasks-list
ordering, the Agents-line failure count, web's Appearance marks and Add a machine alignment, the Scheduled-count
rule, the Orbit Cloud browser's tab and paste, the runner's delegate and engine updates, and the NATS and Compose
fixes.

An application-only rollback to beta.52 is schema-safe, because this range carries no database migration at all:
the schema stays as beta.52 left it, with `1090_runner_browser_state`'s two nullable columns that an older
apiserver neither reads nor writes. No backup or restore step is needed. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
