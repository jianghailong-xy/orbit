# Orbit 0.1.257-beta.1

## Summary

This is the first release under the single-version rule: the version in the root `package.json` is the
version of record, the tag is that version with `v`, and the GitHub Release, macOS and Android artifacts,
TestFlight build, runner binaries, `/dl/version.json`, Sparkle appcast and `android-update.json` all name
it. It also carries the runner and macOS fixes published as 0.1.255 and 0.1.256, and the release notes you
are reading are now the Release body rather than a generated changelog.

## Upgrade impact

- **Version jump.** The clients move from the old `0.1.2-beta.N` tag line to `0.1.257-beta.1`. macOS and
  Android compare build numbers (the commit count), which keeps increasing, so the beta channel and
  installed Android apps update normally; the displayed version jumps once.
- **Runners must be reinstalled once.** Runners released before this one compared versions component by
  component and read the `-beta` suffix as zero, so `0.1.257-beta.1` looked older than `0.1.256` and they
  will not self-update to it. On every machine running an older runner, install this release once:

  ```bash
  curl -fsSL <your-origin>/install.sh | bash
  ~/.orbit/bin/orbit version        # → 0.1.257-beta.1
  ```

  Every later release is ordered correctly again. A runner that has been reinstalled is rolled back or
  forward by the normal `/api/runner/release` pointer.
- **No database migrations** and no configuration changes since the previous tag. The server and web
  report `0.1.257-beta.1`; pin the deployment to the tag `v0.1.257-beta.1`.
- **iOS** ships marketing version `0.1.257` to TestFlight (Apple requires a numeric
  `CFBundleShortVersionString`); the commit-count build number carries the beta iteration.

## Security fixes

None in this release. The dependency-alert remediation tracked in
[Project maturity](../docs/project-maturity.md) is not part of this release; do not take this section as
evidence that it landed.

## Known limitations

- Orbit remains pre-1.0 and only the newest published release is supported (see
  [SECURITY.md](../SECURITY.md)).
- Releases tagged before this one do not share the package version (`v0.1.2-beta.245` carried
  `package.json` 0.1.254); they are historical and are not evidence of the current rule.
- `v0.1.0` is the only non-prerelease release in the repository and predates the current schema and
  pipeline. It is not a supported line.

## Artifacts and verification

The tag is `v0.1.257-beta.1`; the full source SHA is that tag's commit. The release workflow publishes
`Orbit-v0.1.257-beta.1-arm64.dmg`, its Sparkle payload `Orbit-v0.1.257-beta.1-arm64.zip`,
`orbit-android-0.1.257-beta.1.apk` with its `.sha256` and `android-update.json`, a TestFlight build of
`0.1.257`, and runner binaries whose `/dl/version.json` names `0.1.257-beta.1`. Before the tag was cut,
`node scripts/release-identity.mjs check-tag v0.1.257-beta.1` checked that all of these derive from the
package version and that these notes carry every required section; the release workflow runs the same
check before it builds anything. Record the workflow run URL and the asset digests in the Release once the
run finishes.

## Rollback

The previous tag is `v0.1.2-beta.245` (its `package.json` names 0.1.254); deployments that followed the
untagged `0.1.255`/`0.1.256` increments have no tag of their own, so record the image IDs and source SHA
before upgrading. There are no migrations in this release, so an application-only rollback to the previous
source is schema-compatible. Keep PostgreSQL and its archive running, and reinstall the previous DMG or
select the previous TestFlight build only after confirming server compatibility. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
