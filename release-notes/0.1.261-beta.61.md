# Orbit 0.1.261-beta.61

## Summary

This release is a pass over the SubAgent router and the conversation's small doors, not a new feature. The router
learns the engines it never picked (Cursor, Antigravity), a resume can no longer change engine, a session create the
runner cannot start is refused with its reason, and a message no runner has taken gets a Cancel. Two things an
operator will notice: **the per-Agent Smart model selection switch is gone — the account's switch alone decides**
(`acb7448a49`), and **the background-job CPU/memory limits begun the same day are withdrawn before they shipped**
(`2c8d4e83de`, `39cbfcdb2e`, reverted by `3df4d7cfc7`). The native clients finish the card polish web got in beta.60,
and Android's session page now draws its transcript and bar as iOS does.

- **Background job CPU/memory limits are not in this release (none of it ships).** `2c8d4e83de` (runner cgroup limits
  for `bg_run` jobs, `Delegate=yes` in the runner units) and `39cbfcdb2e` (the Settings › Machine Job CPU / Job Memory
  rows, the server columns and the heartbeat field) were withdrawn by `3df4d7cfc7`, together with `cae2742c5e`'s copy
  file. What remains, on purpose: migration `1260_runner_bg_job_limits`, which production has applied, its ledger line,
  and the two `Runner` columns it added, now marked unused in `schema.prisma` so the schema still describes the
  database — nothing reads or writes them. The Machine page has no Job CPU or Job Memory row, no heartbeat carries
  limits, and the runner has no `bg-limits` command (see Known limitations).
- **SubAgent routing: Cursor and Antigravity are tiered by model family, and their quota is read (server; routing).**
  `461afb5030`: `MODEL_FAMILY_TIERS` tiers any catalogue without a table of its own by family (Claude Sonnet/Opus,
  Gemini Flash/Gemini, Composer), each tier taking the family's newest model by version and the effort clamped to the
  model's reported levels; a key's model that neither its preset nor the owner tiers takes falls to its family's lowest
  tier; `engineState` caps Antigravity by its shared buckets and a Cursor account by its met usage limit. Before this,
  both engines joined as an untiered default that ranked after every exact and higher-tier candidate.
- **A SubAgent resume stays on its engine, and the router review fixes (server; runner).** `b1f352c466`: a resumed
  SubAgent on this machine was routed afresh and the runner started the conversation's engine with the new pick's model
  and key, which failed (seen twice in production on 11-19, reproduced). The runner now names the run it continues
  (`resumeOf`) and refuses a target on another engine; the server opens it on its last attempt's engine, provider, model
  and effort, never routed, and refuses when that cannot start. The same commit's review fixes: Balance puts every
  usable subscription before any metered key as Cost does; Opus's own weekly window at 90% takes Opus out on that
  account, and a family's window no longer counts toward the account's near-limit and expiry; a runner's signed-out
  sign-in removes only that sign-in; a named model is checked like any candidate, the first provider that can run it is
  the pick and the rest its fallbacks; an untiered provider runs the runner's default, else its own, each only if
  listed, else its first model; and the reason strings no longer say "most headroom" for a key or "No price known"
  unless a key is the pick. Policy version `p6-subscriptions-first-1`; a resume is `subagent-resume-v1`.
- **`session_create` refuses a child its runner cannot start (server; runner).** `3d0a21ee3f`: a spawn onto an agent
  whose runner was offline or below its Keep Free was accepted and then held by the claim queue — on 2026-11-19 six
  children sat PENDING on wikova for an hour and the caller saw only `PENDING`. `spawnFromSession` now reads the target
  workspace's runner before writing and refuses with `SESSION_RUNNER_OFFLINE` (WAIT 60 s; a managed runner still coming
  up keeps its wait) or the new `RUNNER_DISK_BELOW_FLOOR` (AWAIT_USER_FIX), using the claim gate's own comparison
  (`diskBelowFloor`, moved to `runner-disk-gate.ts`). A spawn that names no workspace is judged on the parent's. The new
  code is in the recovery contract (table, fixture vector, Go and TS dispositions), and `session_create`'s description —
  which the runner serves — names both refusals.
- **A forked task create matches the card that approved it (server).** `5dd308afd8`: the card stores the runner's body
  with `fork.sessionId` in base62, while the gate compared it after `ValidationPipe` had turned it into a uuid, and
  `sessionId` was not in `ID_FIELDS` — so every `forkFromSession` create and batch was refused
  `TASK_WRITE_NEEDS_OWNER_CARD` although its card was approved. `sessionId` is now compared as the row it names, like
  the other id fields; the new specs send the runner's body through the real pipe and DTOs.
- **Worktree isolation can no longer be turned on in a folder that is not a git repository (server; web).**
  `923eba15da`: `agent_update` set `enableWorktree` on a workspace the runner had probed as not a git repository — the
  owner's card was approved, then the write refused. A write that leaves `enableWorktree` on while `workDirIsGit` is
  false is now refused `409 WORKTREE_NEEDS_GIT` (`worktree-needs-git.ts`), in `WorkspacesService.update` (web PATCH,
  MCP and CLI) and in the runner door before its owner card (`f9288416f5`), so nobody is asked to approve a write that
  will be refused. Unknown is not no: an unprobed directory, a write that moves `workDir`, a cloned workspace and one
  with `autoInitGit` go through, as do turning isolation off and a PATCH of unrelated fields. Web disables the switch,
  with the reason, while the probe says the folder is not a git repository.
- **A job waiting on its runner's local lock reads as waiting and names the holder (server; web, macOS/iOS, Android;
  runner).** `bbac1c8089`: the runner already reported `WAITING_LOCAL_LOCK` and the read model already made it a
  `blockingReason`, but every client drew the claim's quiet liveness ("fetching · no output for 78m") and the reason
  named nobody. The in-flight read now finds the earliest other RUNNING job on the same runner, repository and target
  ref, and names its kind and project (to its own owner only) with its `jobId`; the clients read "waiting · <who holds
  it> · claim 1" on the step's clock, while a SILENT runner keeps its own words.
- **The Open-list `since=` read builds only the rows that moved, and two other reads stop scanning whole tables
  (server).** `045fc3cc31`: the version is the account's, so on a busy account every read built the whole list
  (production 2026-11-19: about 550 rows built to send 1–3, the database's largest cost). A snapshot now keeps marks —
  each source's counter, the runners' names, statuses and liveness, the deadlines passed, and per row a token of
  everything the row query reads — and a read whose version moved runs a cheap probe and builds only the rows whose
  token moved, plus queued rows; the row overlay is read for every row only when its own sources, a deadline or a held
  question moved. Anything it cannot account for (tags, scheduled wake-ups, a new source) still builds the whole list.
  No write path, trigger or migration changes and the `since=`/ETag contract is unchanged. `46510926e4` (migration
  `1270`) adds the two indexes two reads were missing: a COMMIT citation's lookup on `session_merge_receipt
  (source_sha)` reads 564 → 2 buffers on a production-sized fixture, and the wiki facts read's settled-task arm falls
  from ~28.7k buffers to ~180.
- **Smart model selection is the account's switch alone (server; web, macOS/iOS, Android).** `acb7448a49`: with the
  account's switch on, every task run on every Agent is routed and applied — the shadow mode an Agent's own switch left
  runs in is gone. The Agent's "Smart model selection for tasks" switch and the "Engines it may use" picker are removed
  on web, Android and macOS/iOS; the task page and the Agent's Model line follow the account switch, and the switch's
  hint is reworded. `workspace.modelRouting` and `modelRoutingProviders` are still accepted and returned but no longer
  read; `docs/model-routing-design.md` notes the change.
- **Cancel beside `Queued · runner full` on a message no runner has taken (web; macOS/iOS).** `e90dc6fb93` (web),
  `eecb692828` (iPhone and Mac): the accepted message under the held tag had no way out, unlike one queued behind
  another. The tag now carries Cancel in the tint; it withdraws the turn through the existing cancel door, drops the
  placeholder, returns the session to awaiting input and frees its slot, and puts the words back under any draft. Never
  on the session's opening prompt, which the server keeps (`QueuedTurnInfo.opening` now reaches the bubble on the native
  clients).
- **A background SubAgent is one card from start to end (web).** `1dcecd179b`, board
  `docs/mocks/subagent-card-and-end-line`: as Claude Code's built-in Agent, the delegate card now carries its run's end
  — a word chip for every end but DONE, the folded line becomes the ending, and the opened card closes on an end block
  with what the agent read. The turn the `<orbit-subagent-finished>` wake opened draws nothing, a queued wake waits on
  its card with Don't send instead of in the queued tail, and the Agents strip no longer counts stopped runs as failed.
  The wake text and protocol are unchanged; `SubagentFinishedCard` and its CSS are removed. It follows `dcf7b9f04f`,
  which had the card read the run's own end rather than the call's running receipt (a green check even for FAILED,
  INTERRUPTED and STOPPED runs).
- **Android: a background SubAgent is one card from start to end too (Android).** Task "Android: draw a background

## Upgrade impact

- **Database migrations: two files, both additive.** The apiserver applies both on boot, in order, in one Prisma
  transaction per migration; neither uses `CONCURRENTLY`, and every statement can run twice.
  - `1260_runner_bg_job_limits` adds two nullable columns to `runner` with `IF NOT EXISTS` — `bg_job_cpus`
    (`DOUBLE PRECISION`) and `bg_job_memory_mb` (`INTEGER`), NULL meaning no limit on that dimension. It belongs to the
    withdrawn limits feature: production has already applied it, and this release's server and runner neither read nor
    write the columns. An instance that never applied it gets two empty nullable columns, which no code reads.
  - `1270_receipt_source_sha_task_updated_idx` adds two indexes with `IF NOT EXISTS` —
    `session_merge_receipt_source_sha_idx` on `session_merge_receipt (source_sha)` and `task_owner_updated_idx` on
    `task (owner_id, updated_at)`. No row is written. Each build is one pass over its table and holds a SHARE lock that
    long; the migration's own comment records the production sizes it was measured on (`task` 115k rows,
    `session_merge_receipt` 6.2k), so this is the one upgrade-time cost to expect.
- **Configuration: nothing to fill in.** No new `ORBIT_*` variable is read and no `.env` edit is needed. The only
  configuration work is documentation: the reference now has the `ORBIT_RUN_STOPPED_WAKE_MODE` row that
  `docker-compose.yml` has read since `36fbd172de`, before beta.60 (`c1b22773cd`). The `orbit bg-limits` command and
  `config.json` field from the withdrawn feature are not in this release.
- **Server and web:** the routing changes (family tiers and quotas, resume on its engine, the account-only switch), the
  `session_create` refusals, the forked-create card match, the worktree-isolation refusals, the local-lock wait, the
  `since=` read and migration `1270` are apiserver changes; each reaches an instance only when it is upgraded from this
  source — tagging does not deploy the server. The web changes (`acb7448a49`, `e90dc6fb93`, `1dcecd179b`, `cea9128233`,
  `94c8a172be`, the Machine settings removal, the worktree switch's disabled state) reach browser users when the
  deployment's web is rebuilt from this source.
- **Clients:** macOS beta users get the DMG and Sparkle appcast from this tag on the beta channel; TestFlight gets
  marketing version 0.1.261, with the build number as the commit count; Android gets `versionName` `0.1.261-beta.61`
  and `android-update.json` from this tag. No minimum client version is enforced, no one-time step is required on a
  Mac, iPhone or Android device, and no account or workspace has to be reconfigured. An Agent whose own Smart model
  selection switch was set keeps the setting stored but unread (`acb7448a49`).
- **Runner:** the `src/runner-go/` changes in this range are the live-mode publish on a wake (`89337d19f5`), the commit
  list's `--no-merges` (`49dc719c72`), `resumeOf` and the other-engine refusal (`b1f352c466`) and the `session_create`
  description that names both refusals (`3d0a21ee3f`). **The runner served at `/dl` is built from this tag**, so a
  runner fetched from it publishes a waking claim's permission mode, lists only the session's own commits, and names
  the run it resumes and refuses a target on another engine. An older runner keeps its earlier behaviour for each of
  those, and none of it is required for an older runner to keep working with this server.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE, and no dependency in
`package.json` or `package-lock.json` changes. `89337d19f5` is the change in this range that alters an approval
outcome: a read-only Kimi SubAgent's shell calls follow the parent session's live mode, and that holder now
receives a mode the owner chose while the engine was cold — before it, a session switched from Auto to Default kept
approving those calls with no card. The commit records this as a correctness fix observed on v0.1.261-beta.60, not as a
security fix, and the runner still does not check the command itself (see Known limitations).

## Known limitations

- **The background job CPU/memory limits do not exist in this release.** The Machine page has no Job CPU or Job Memory
  row, no heartbeat carries limits, and the runner has no `bg-limits` command or config field; migration 1260's two
  columns remain in the database and the schema says they are unused (`3df4d7cfc7`). There is nothing to configure and
  no way to limit a `bg_run` job from this tag.
- **macOS/iOS do not yet draw a background SubAgent as one card from start to end.** Web (`1dcecd179b`) and Android
  (`3268b26cc2`) do; macOS/iOS were not changed in this range and keep the previous delegate card.
- **Cancel beside the held tag reaches web and macOS/iOS only.** `e90dc6fb93` and `eecb692828`; Android was not changed
  in this range.
- **The one-width conversation card and the 4-line reply fold are web only** (`cea9128233`, `94c8a172be`).
- **The `since=` Open-list change is server-side and deliberately partial:** anything its marks cannot account for —
  tags, scheduled wake-ups, a new source — still builds the whole list (`045fc3cc31`).
- **A `session_create` refusal needs a reading.** With no runner reading, or no Keep Free floor, it refuses nothing,
  and a managed runner still coming up keeps its wait (`3d0a21ee3f`).
- **Worktree isolation: unknown is not no.** An unprobed directory, a write that moves `workDir`, a cloned workspace
  and one with `autoInitGit` still go through (`923eba15da`).
- **A read-only Kimi SubAgent's shell command is still not checked.** `89337d19f5` changes which mode the runner
  reads, not what it does with the call: under Auto or Bypass the call is approved with no card and no check of the
  command, as recorded for `22b6530657` in the beta.60 notes.

## Rollback

The previous tag is v0.1.261-beta.60, commit `697044d9a0352661b9adde24f795f735097cbeec` (its tag object is
`cd98efc70e868b37b3add0223aecd16819c5e659`), the `chore(release): prepare 0.1.261-beta.60` commit on top of
`350ff1bc6672b7586922557cb77f04c8406d0566`. A server deployed from this tag rolls back to that commit; the native
clients roll back by installing beta.60's build from its tag.

An application-only rollback to beta.60 is schema-safe. Both migrations this release carries are additive —
two nullable columns and two indexes, each guarded by `IF NOT EXISTS`, none dropping or altering anything — and beta.60
neither reads nor writes any of it. The `bg_job_*` columns are read by nothing in either release, and the two indexes
only change how the planner reaches rows. No backup or restore step is needed. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).

Rolling back to beta.60 reverts the commits in this range: the per-Agent Smart model selection switch and the "Engines
it may use" picker return, Cursor and Antigravity route untiered again, a resume is routed afresh, a session create the
runner cannot start is accepted and held, a forked task create is refused after its card is approved, a long-lived
`since=` read builds the whole list, the web and native card changes revert to beta.60's cards, and the runner returns
to listing merge commits and to the stale live mode after a cold wake. The withdrawn background-job limits were never
in beta.60 either, so nothing reappears.
