# Orbit 0.1.261-beta.55

## Summary

This release makes the **confirmation of a project's criteria readable after the fact**: its receipt no longer says
only "You confirmed 7 criteria at seal …", and a fold opens to the numbered criteria in the words that were
confirmed, on **web, iOS, macOS and Android**. **iOS Scheduled rows gain swipes and a long-press menu**: a schedule
swipes right to Pause/Resume and Run now and left to Delete and Change…, a run under way swipes to Stop / Open run, a
draft to Not now, and every action is in the long-press menu, which the Mac gets as a right-click. **Android's drawer
becomes iOS's**: the drawer stays put and the page slides off it as a rounded card, over pill rows and one-line
workspaces. Every client's **machine page now leads with the country its IP is in**. Two database migrations: one additive,
one an index setting; no runner source and no image changes in this range.

- **A confirmation receipt opens to what was confirmed (server; web, Apple, Android).** The "Decision recorded"
  receipt of a criteria confirmation could not be opened, and the "— 1 new" it showed lived in the pressing
  window's memory; the record kept no words (`15877e2656`). Migration `1200_standard_set_confirmation_wording` adds
  two nullable JSONB columns to `project_standard_set_confirmation`: `criteria_wording`, one object per criterion
  (`definitionId`, `ordinal`, `text`, `verificationMethod`) as the set stood when confirmed, and `criteria_changes`,
  what the set changed since the confirmation before it (or NULL when there was none). All three writers fill them
  (`confirmationWords`). The confirmation read now publishes `changes`, `criteria` (the confirmed words, marked
  UNCHANGED / EDITED / REMOVED since) and `wordingRecorded`; an older record shows today's words where the content
  hash still matches and none where it moved. On every client the headline drops the seal and says what the
  confirmation changed ("You confirmed 7 criteria · 1 new, 6 unchanged"), and a fold, closed by default, holds the
  change card's own rows, the numbered criteria in the words confirmed, a note when some moved or the words were
  never kept, and the seal. The window-held "what this press changed" plumbing is removed. The owner approved the
  board in `docs/mocks/acceptance-receipt-fold` (fold closed, seal in the fold, hash-matched words for older records,
  all four clients together).
- **A machine page leads its header line with the country its IP is in (web, macOS, iOS, Android).** The line under
  the title now starts with `📍 Japan`, or `📍 Japan (via proxy)` when the region check went through one, read from
  the Claude region check's last answer (`runner.region`); nothing new is stored (`9c1e1c4492`). A machine no check
  has decided shows the line as before. On web, hovering it says when it was checked. Board:
  `docs/mocks/orbit-cloud-location`.
- **iOS Scheduled rows swipe both ways and long-press, by kind (iOS, macOS).** As `docs/mocks/scheduled-swipe-ios`
  decided: a schedule swipes right to Pause/Resume (full swipe) and Run now, left to Delete (asks first) and
  Change…; a run under way swipes left to Stop (asks first) and right to Open run, so a run's row no longer deletes
  its whole schedule; a draft swipes left to Not now (`47d1ace42d`). The long-press menu carries every action, and
  the Mac gets it as the row's right-click (`ScheduleRowActions.swift`). iOS 26's compact list draws the session
  list's round buttons. Stop and Open last run are new shared copy, in `src/shared/src/schedule.ts` and
  `contracts/schedule.contract.json`. The first swipe, Delete only, landed just before (`1fac762b1e`); before it the
  phone's rows had no swipe and Delete lived only behind the detail sheet's ⋯.
- **The Android drawer follows iOS (Android).** `OrbitDrawerShell` replaces `ModalNavigationDrawer`: the drawer stays
  put and the page slides right as a rounded card with a shadow (iOS `CompactShell`), with no scrim; tapping the
  peek, dragging back or Back closes it. `DrawerRow` is ~44 dp with an inset rounded selection tint and an accent
  icon when selected (iOS pill / `DrawerMetrics`). Workspace rows are one line, "name · runner", with one trailing
  slot — needs-you count, spinner, or Offline / managed runner state — and the running count stays in the row's
  state description. The header has a search disc, and a New session capsule and round Settings button are pinned
  over the rows' bottom (`811dd5a1f1`).
- **Server: two database hot spots cooled (server).** `run_event`'s trigram index now takes each entry as it is
  written instead of queueing it: an insert that found GIN's pending list past 4 MB used to merge all of it in its own
  statement, 4-5 s in production while ingest held the session row (`4e51d7a5ea`). And `client_version` is throttled
  per build, not per client kind: two builds of one client open at once (an old web tab beside a new one) took turns
  rewriting their row on every request (`1e2c40067c`).
- **Docs and boards.** The three boards above: `acceptance-receipt-fold`, `orbit-cloud-location`, and
  `scheduled-swipe-ios` (`36aeca1adf`), and the Orbit Files drive product proposal (`336a952675`).

## Upgrade impact

- **Database migrations: two.** `1200_standard_set_confirmation_wording` (the commit that added it calls it
  `1170`; main's `1170` is beta.54's `session_open_list_owner_idx`, and it landed at the tip as `1200`) adds two
  nullable JSONB columns to `project_standard_set_confirmation`, `criteria_wording` and `criteria_changes`, and two
  CHECK constraints that require an array and an object respectively. Each CHECK is satisfied by NULL, so no stored
  row is refused or rewritten. It contains no INSERT, UPDATE or DELETE, every statement can run twice, and the
  apiserver applies it on boot. Nothing is dropped or renamed. The columns are new, so an older apiserver neither
  reads nor writes them. `1220_run_event_text_trgm_fastupdate_off` changes no schema: it sets `fastupdate = off` on
  the `run_event_text_trgm` GIN index and merges what is already queued (`gin_clean_pending_list`). The commit records
  it applied twice on a throwaway database (the second run merged nothing). On a large pending list the first boot's
  merge takes as long as that list takes to merge.
- **Configuration: no new switch.** Nothing in `.env` or Compose changes, and no environment variable is added.
- **Runner:** `src/runner-go/` is unchanged in this range, so a runner from this tag behaves as beta.54's; the region
  line is read from the server's region check, not from the runner's own source. **The runner served at `/dl` is
  built from this tag.** No managed-runner image or engine version changes in this range.
- **Server:** the receipt's stored wording, its three writers and the confirmation read are apiserver changes, and
  each reaches an instance only when it is upgraded from this source; tagging does not deploy the server. The web
  changes (the receipt fold and the machine page line) reach browser users when the deployment's web is rebuilt from
  this source; the tag does not deploy the web app.
- **Clients:** macOS beta users get the DMG on the beta channel. TestFlight gets marketing version 0.1.261, with the
  build number as the commit count. Android gets `versionName` 0.1.261-beta.55 and `android-update.json` from this
  tag. No one-time step is required on a Mac, iPhone or Android device.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE, and the root
`package.json` and `package-lock.json` do not change in this range at all — the release commit writes only their
version lines. The receipt fold shows what a confirmation said to someone who could already open the confirmation;
it adds no new reader and changes no access check.

## Known limitations

- **A confirmation made before this upgrade can show no confirmed wording.** Its row reads NULL in both new columns.
  The receipt says the words were never kept, and shows today's words only where the content hash still matches;
  where it moved, it shows none. There is no backfill, because the words were never stored.
- **The country line needs a decided region check.** A machine no check has decided shows the line as before, with
  no country, until a check answers.
- **The macOS DMG container is not codesigned.** It is notarised and stapled, so Gatekeeper accepts the app, but
  `spctl` reports the `.dmg` itself as having no usable signature. This predates this release.

## Rollback

The previous tag is v0.1.261-beta.54, commit `fbbd2e514f3b4025221efe44decd84dd2506405e` (its tag object is
`5fcb9aa5a2ba2f385eb8437b70ee474d09c3094f`), prepared on 2026-11-19. Rolling back removes the confirmation receipt's
fold and the confirmed wording it reads, iOS's scheduled-row swipes and long-press menu (both the both-ways actions
and the Delete-only swipe before them), the Mac's row right-click menu, Android's iOS-style drawer, and the machine
page's country line.

An application-only rollback to beta.54 is schema-safe: `1220` changes only an index's storage setting, which
beta.54 runs with as well, and `1200` is additive: the two `project_standard_set_confirmation` columns are new and
nullable, an older apiserver neither reads nor writes them,
and no row was rewritten. Rows written by this release keep their wording and changes, which beta.54 ignores. No
backup or restore step is needed. See [Release process](../docs/release-process.md#rollback-decision-and-procedure).
