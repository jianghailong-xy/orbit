# Orbit 0.1.261-beta.27

## Summary

- **Removing an account moves its sessions instead of refusing.** On a runner's page, removing a Codex, Claude
  Code, Antigravity, Kimi or Cursor account that sessions are on no longer stops at "can't be removed while N
  sessions are on it". Each session moves to another signed-in account on that machine (Automatic's pick) with its
  conversation, and the account is removed once the last one has left: a session waiting for input moves within a
  heartbeat, a running one when its turn ends. While it waits, the web, Mac, iPhone and Android pages say "Moving N
  sessions to another … account". Only sessions that can't move (no other signed-in account, a runner too old to
  carry the conversation, a Cursor conversation that has talked) still block it, and only those are listed. The
  Remove question now says the account's sessions move first.
- **Agent Tools.** The session menu on the web, and a toolbar item and settings section on the Mac, show how the
  session's agent reaches Orbit: its tools, mode and instruction layers. Runners give Claude Code and Codex a
  playbooks skill, and agents get a `guide` tool (`orbit guide`) so one call never needs the whole operation
  catalogue.
- **The owner's card says what is true of the branch.** A failed check on a project branch or a task-branch
  candidate no longer claims "the task passed on its own branch".
- **Runner fixes.** An image redrawn in place and linked again in a later reply uploads again rather than showing the
  first drawing; Kimi, OpenCode and Antigravity sessions tell `orbit mcp` how deeply they are nested, so a nested
  session no longer outwaits the session above it.
- **Schedules.** The over-budget refusal of a Run now names the runs actually started.

## Upgrade impact

- **Database migrations:** `0940_session_agent_tools` adds one nullable JSONB column to `session`. It is additive
  and already applied on orbitd.io.
- **Configuration:** nothing to change.
- **Server:** moving sessions off an account being removed is server-side; orbitd.io runs 96c35c3ed, which has it.
  The branch sentence on the owner's card (3d0f92ec6) needs a server at this tag; an older server leaves the clients'
  previous sentence.
- **Runner:** the runner served at `/dl` is built from this tag, so runners update to it, with the Agent Tools report,
  the `guide` tool and the fixes above.
- **Clients.** Each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261, build
  number = commit count) and Android via `android-update.json` are offered it. Against a server older than 96c35c3ed
  no "Moving" line appears, and a removal with sessions on the account is refused as before.

## Security fixes

None in this release.

## Known limitations

- Removing the last account Orbit uses while Default is removed from Orbit still refuses over its sessions: there is
  no other account for them to move to.
- A removal waits at most 6 hours for running sessions to finish their turns, then fails and can be asked again.

## Artifacts and verification

The macOS DMG and Sparkle appcast, an iOS TestFlight build, and the Android APK with `android-update.json`, all from
this tag. The account-removal change was checked with the apiserver typecheck and unit specs, the session account
spec on PostgreSQL 16 (18 tests), the web removal and copy tests (52 tests), and the Android account tests (25
tests). Its macOS/iOS code is compiled by this release's macOS and iOS builds; its OrbitKit tests were not run.

## Rollback

The previous tag is v0.1.261-beta.26. The only migration since adds a nullable column, so a client or server
rollback to it is schema-safe.
