# Orbit 0.1.261-beta.107

## Summary

This release is two new runner log lines, and nothing a client draws. A runner now logs its first engine probe once at start: how long the whole probe took and each engine's share, with the part spent asking that engine's added accounts. A managed runner now logs its first heartbeat once at start: whether it was taken, when after the process started, how long it waited and for what, how many attempts it took, and how long the last one's round trip was. The commits give the reason as a beta.98 Cloud runner whose first heartbeat still came 8–10 s after it was online while the probe takes 2–3 s in the same image at the Pod's 2 CPUs. The only other commit in the range is a design board under `docs/mocks/drive-chat` for a Drive chat docked on the right; it ships no code.

## Upgrade impact

- **Migrations:** none in this range. `git diff --stat v0.1.261-beta.106 origin/main -- src/apiserver/prisma/migrations/` is empty, so the schema is exactly beta.106's.
- **Backfill:** none.
- **Configuration:** none added or changed. Both lines are always on.
- **Server, gateway and clients:** no change. No web, macOS, iOS or Android source file differs from beta.106, so the DMG, TestFlight build and APK from this tag carry only a new version and build number. Web arrives with the deploy of this commit.
- **Runners:** the runner served at `/dl` is built from this tag. Its probe and heartbeat behavior is unchanged; what is new is output. At start it writes `engine probe: first answer in <total>: <engine> <time>, …` — each engine in its spec's order, with `(accounts <time>)` where that part rounded above zero — and, on a managed instance, `startup heartbeat: <taken|not taken>, <time> after the runner started: waited <time>, <after the engine probe answered|without the engine probe's answer>; <n> attempt(s), the last answered in <time>`. Both are written once per process start; later probes and beats write nothing new.

## Security fixes

None in this release. No commit in this range names a security issue or a fix for one.

## Known limitations

- The lines are diagnostics, not a fix. No commit in this range records a measurement taken from them, so the cause of the 8–10 s first heartbeat a beta.98 Cloud runner saw is not identified here.
- Each line is written once per process start, so a slow probe or beat later in the process's life leaves nothing in the log.
- After a first heartbeat the runner logs no aggregated timing for later beats, so the new lines cannot show a steady-state slowdown on their own.
