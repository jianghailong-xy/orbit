# Orbit 0.1.261-beta.25

## Summary

- **A read-only SubAgent no longer asks before every command.** `explore` and other read-only SubAgents on Claude
  Code ran in Plan mode whatever the parent's mode was, and Plan asks before every Bash call. Under an Auto parent
  the read-only delegate was the one that interrupted the owner most. A read-only Claude SubAgent now runs in its
  parent session's mode and stays read-only by not being given Edit, MultiEdit, Write or NotebookEdit. On Kimi,
  Cursor, Antigravity and OpenCode a read-only SubAgent still runs in Plan, which is what keeps it read-only there.
  Codex and DSH keep their read-only sandboxes.
- **The session row names the running agent.** While a SubAgent works, the session list on the web, Mac, iPhone and
  Android shows "Agent: <its description>…", or "Running N agents · <newest description>…" for several, instead of
  "Running Agent…". The Mac and iPhone composer's Agents band shows the running run's description as well.
- **Mac and iPhone build again.** 0.1.261-beta.24's macOS and iOS builds failed to compile on the machine page, so
  that tag published no DMG, TestFlight build or Android APK. This release fixes it and carries 0.1.261-beta.24's
  client changes (workspaces from GitHub, Orbit Cloud naming) to the clients for the first time.
- **Orbit Cloud runners keep their home on their volume.** A managed runner's data volume is now mounted at
  `/home/orbit` and is the `orbit` user's home; checkouts stay in `/home/orbit/orbit-repos`. A runner whose image
  pull outlasts the startup deadline is now waited on instead of being failed while its Pod is still pulling.
- **iPhone project sessions button.** The button over a project conversation shows the running dot, then the
  spinner, while any member session, landing or merge in its sheet is active.
- The coordinator's opening brief no longer names a timeout as a reason a rerun comes out differently.

## Upgrade impact

- **Database migrations** (applied by the apiserver on boot):
  - `0980_managed_runner_home_orbit`: workspaces on managed runners whose folder is under `/var/lib/orbit/home`
    now name the same folder under `/home/orbit`. Workspaces on other runners are untouched.
- **Orbit Cloud runners.** The managed runner image changes. Existing runner volumes are discarded and rebuilt,
  not migrated: each hosted runner moves onto the new image when it is next idle, and its earlier volume contents
  do not carry over.
- **Runners.** This tag's runner starts a read-only Claude SubAgent in the mode the server names instead of forcing
  Plan. The server and the runner each used to force Plan, so the change needs both this deploy and runners on this
  release. Runners update themselves.
- **Behavior change.** Under an Auto parent, a read-only Claude SubAgent can still write files through Bash. Only
  Auto's own safety check stands in the way, not a hard rule. If the SubAgent's model cannot run Auto, it falls back
  to Default and asks before each Bash call, as before.
- **Configuration:** nothing to change.
- **Clients.** Each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261, build
  number = commit count) and Android via `android-update.json` are offered it. The session row's agent name needs the
  server deployed from this release or later; against an older server the row keeps its old label.

## Security fixes

None in this release.

## Known limitations

- The read-only guarantee of a Claude SubAgent under an Auto or Bypass parent rests on its withheld edit tools and on
  Auto's check, not on a sandbox: Bash can still write.
- Existing Orbit Cloud runner volumes are rebuilt, not migrated, so anything a hosted runner kept on its volume
  is gone after the move.
- The Mac and iPhone fix has not yet been shown by client CI to compile: client CI on main was still queued when this
  tag was cut. This release's own macOS and iOS jobs are its first compile.

## Rollback

Roll back to 0.1.261-beta.24 (209a2e8567c64da160f276c3fc6fe0e35745b17e). Migration `0980` changes no schema, only
managed workspaces' folder paths, so an application-only rollback is schema-safe. The paths are not moved back:
after a rollback, managed workspaces name `/home/orbit` folders that the earlier image does not mount there, and
hosted runners need their volumes rebuilt again. Rolling back also puts read-only Claude SubAgents back in Plan
mode. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
