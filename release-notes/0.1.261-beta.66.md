# Orbit 0.1.261-beta.66

## Summary

This release is about the **bg_run Job card**: a background job started with `bg_run` is one card from start to end on web, macOS/iOS and Android. A person can stop a running job from the app, and a running card shows the job's newest output. It also carries **one read that places a workspace list's projects**, and **fixes for the two backfill migrations** that failed production's first deploy of the session-state release. The range is `v0.1.261-beta.65..origin/main` (`127255096e`).

**One Job card per bg_run job.** The generic "orbit · bg_run" tool card, and the separate line each wake drew, are replaced by one card. The board was approved 2026-11-20, with the owner's rulings R1–R4 of 2026-11-21.
- **Header:** a terminal icon, the description as the title, a job / watch / service kind chip and the run time.
- **Folded:**
  - running, with a spinner and its newest line;
  - exit 0, with a check and the last two lines;
  - exit N, with a red chip and cross, the last two lines in red and Show full output;
  - killed, with a line naming who stopped it: the person, the agent, a runner restart or self-update, or a cancelled session;
  - quiet Nm, in amber;
  - a service that keeps spinning;
  - new output, which refreshes the tail.
- **Opened:** the command, where and when it ran, the last 40 lines with Show all, and each time it woke the agent with what the agent read.
- **Wakes and the queued tail:** the turn a job's end, new output or stall opens draws nothing; a `schedule_wakeup` with no job keeps its line. A queued job wake shows "Waiting for the agent to read it · Don't send" on the card, not in the queued tail.
- **Background list:** a failed job counts in red, and tapping a job scrolls to its card.
- **Phone width:** the kind chip and run time move to a second grey line.
- **Commits:** web `615717a204`, `d464fd5dc2`, `57fce06185`; Apple `a5147a504b`, `360955ba7e`, `d6f8ed4191`; Android `305e802ec9`, `2dae1c3c37`.

**A person can stop a running bg_run job.**
- **Route:** `POST /sessions/:id/background/jobs/:jobId/stop` records the stop on the session. Every heartbeat answer to a runner that declares `bg-owner-stop/v1` lists it, until the job ends (`3dedf184c0`).
- **Runner:** kills the job as `bg_kill` does, under reason `stopped_by_owner`. The job record, the background list (with a per-job `stoppable`) and the wake say who stopped it (`2bd2bff481`).
- **Clients:** draw Stop with a "Stop this job?" confirmation on a running card and on a running job's row in the Background list. Stop is hidden when the job's runner cannot take it.

**A running card shows the job's newest output.**
- **Route:** `GET /sessions/:id/background/jobs/:jobId/tail` returns at most 40 lines and 8 KB, with ANSI removed (`5332a89e4a`).
- **Path:** the server asks the runner hosting the session over a new runner-link request/answer frame, relayed by the link gateway to runners that declare `bg-output-tail/v1` (`e1a7f6ba52`).
- **Polling:** clients read it every 5 s, only while the card is on screen, the app is in front and the job runs.

**A workspace list places its projects with one read.** `GET /sessions/project-placement` answers each named project's coordinator, its members waiting on the owner and its session count, with a body ETag (`9b41aa0e49`, `9fc1037c8e`). The web uses it instead of one or two reads per project (`3d3c4bba61`). The per-project read stays for older clients.

**The session-state backfills apply under Prisma.** `prisma migrate deploy` runs a migration file as one transaction, so the per-batch COMMIT in `1202` and `1262` failed on a populated database. Each is now one set-based UPDATE with the same rules, wrapped in `SET … RESET` (`47650af1b5`, `97e3afb64e`), and is tested with the real `prisma migrate deploy` (`580af2370d`).

## Upgrade impact

- **Database migrations:**
  - `1410_session_bg_job_stop_requests` adds `session.bg_job_stop_requests TEXT[] NOT NULL DEFAULT ARRAY[]::TEXT[]`. It is NOT NULL with a constant default, so no row is rewritten by hand. There is no UPDATE or DELETE, and it can run twice. **Additive.**
  - `1410_coordinator_handoff_successor`, listed in beta.65's notes, is renumbered `1411_coordinator_handoff_successor` because two migrations claimed 1410 (`127255096e`). Its three `ADD COLUMN IF NOT EXISTS` statements are unchanged, so on a database that already applied it under 1410 it applies again as a no-op.
  - `1202_turn_outcome_backfill` and `1262_session_release_backfill` are rewritten as described above. Their rules and the columns they write are unchanged, and they write only NULL columns. A database that already applied them is not re-run.
  - No migration drops or renames anything, adds a trigger, or adds a constraint in this range.
- **Configuration:** nothing new to fill in.
- **Runner** (`src/runner-go`, built from this tag and served at `/dl`):
  - it carries out an owner's stop of a job (`stopped_by_owner`) and answers tail reads;
  - it declares `bg-owner-stop/v1` and `bg-output-tail/v1`.

  A runner older than this tag keeps working. The server refuses a stop for it with `RUNNER_CANNOT_STOP_JOB` and a tail read with `RUNNER_CANNOT_READ_JOB_OUTPUT`, and marks its jobs not stoppable, so the clients hide Stop and show no live line.
- **Link gateway:** it gains the tail request/answer frame. A deploy that includes it recreates `link-gateway`, which briefly drops runner connections; they reconnect on their own.
- **Clients:**
  - *macOS:* the Job card on the beta channel (DMG and Sparkle appcast).
  - *iOS:* TestFlight marketing version 0.1.261, build number the commit count, with the Job card.
  - *Android:* `versionName` `0.1.261-beta.66`, the next `versionCode`, and `android-update.json`, with the Job card.
  - No minimum client version is enforced, and no one-time step is needed.
- **Server already live:** the server and web part up to `43da70123b` has been in production since 2026-11-21 10:56Z. The commits after it (`1ca07976c5`, `64ab98958d`, `127255096e`: docs, the write inventory and the migration renumber) are not deployed yet.

## Security fixes

None in this release. The new routes take the same ownership check as `GET /sessions/:id/background`, and the tenant-isolation census covers them (`243dd5b539`); this is not a fix.

## Known limitations

- **Stop and the live tail work only on runners built from this tag or later.** Until a machine's runner updates, its jobs show no Stop and running cards show only the spinner.
- **The Job card's native screenshots were taken outside a live session.** Apple's were rendered from the shipped views with sample jobs, and Android's are Robolectric frames. Placement in the transcript is covered by tests. Android's rewritten device test (`CardsDeviceTest.aJobsWakeTurnDrawsNoLine`) compiles but was not run on a device.
- **The opened Background list's header on Apple still reads "N running · N total".** Only the folded row changed in this work.
- **Main's PostgreSQL spec matrix and Go runner job were red before this range.** `d7db008807` repairs the landing fixtures it names; this release does not claim them green.

## Rollback

The previous tag is v0.1.261-beta.65, commit `1faaa04efbf09fb7083e6eb21bf501fa286656af`. A server deployed from this tag rolls back to that commit. Native clients roll back by installing beta.65's build.

An application-only rollback to beta.65 is schema-safe.
- `1410_session_bg_job_stop_requests` adds a column with a constant default that beta.65's code neither reads nor writes.
- The renumbered `1411` only adds nullable columns beta.65 already has.
- The rewritten `1202`/`1262` change no schema.

Two behaviors do not roll back with the code:
- A stop already recorded on a session is ignored by a beta.65 server.
- A runner from this tag talking to a beta.65 server is never asked to stop a job or read a tail, and works as before.
