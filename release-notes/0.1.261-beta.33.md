# Orbit 0.1.261-beta.33

## Summary

A two-fix release on top of v0.1.261-beta.32, both in the Apple clients' conversation view: a translated
message's bubble hugs its own words again instead of taking the row, and a steps line no longer reads a running
turn as finished while a call is still in flight. No server, runner, web or Android behaviour changes.

- **A bilingual bubble hugs its words instead of taking the row.** The English under the owner's words (and its
  dashed divider) fill what they are offered, so a translated bubble grew to the row however short it was. The
  bubble now lays out with the session-message card's `hugWidth` layout — off while it holds an Orbit card,
  which takes the row by design — so it hugs the wider of its two lines and wraps long ones at the column.
- **A pending session status counts as live for the steps row.** The steps line only counted `.running` as
  live, so a window whose pages carry no `status` event stayed `.pending` and was read as over: a call still in
  flight got folded into "ran 2 shell commands" while its row kept spinning. Both `.running` and `.pending` now
  count as live, using `sessionStatus`, so the call sits under the line until it answers and joins the line once
  the turn is over.

## Upgrade impact

- **Database migrations:** none. The diff between v0.1.261-beta.32 and this tag under
  `src/apiserver/prisma/migrations/` is empty.
- **Configuration:** nothing to change.
- **Server:** nothing to redeploy and nothing to undo; the diff between the two tags contains no apiserver file at
  all.
- **Runner:** the runner served at `/dl` is built from this tag. Its source is unchanged between
  v0.1.261-beta.32 and this tag, so a runner on that version needs no update.
- **Clients:** web and Android carry nothing new in this release. macOS and iOS carry both fixes, in shared
  files the iOS target compiles: `Views/Console/MessageBubbles.swift`, `Views/SessionMessageCardView.swift` and
  `Views/Console/ConsoleView.swift` under `src/macos/OrbitApp/Sources/OrbitApp`. Each client builds from this
  tag: macOS beta users, TestFlight (marketing version 0.1.261, build number = commit count) and Android via
  `android-update.json` are offered it.

## Security fixes

None in this release.

## Known limitations

- The limitations v0.1.261-beta.32 named still stand, since nothing they touch changed in this release: help is
  web-only on all clients, and Ask runs on Claude only, on a machine whose runner declares `help-ask/v1`.

## Artifacts and verification

The tag is v0.1.261-beta.33, and this file is in the release commit's tree. The release publishes the macOS DMG
and Sparkle appcast (beta channel), an iOS TestFlight build and the Android APK with its `.sha256` and
`android-update.json` on the same GitHub Release, all from this tag; the runner served at `/dl` is built from it
too.

Neither commit records a check run: the console-steps commit and the bilingual-bubble commit each carry only
their description and, in the second, the co-author trailer. Verification therefore rests on release.yml's
identity gate and its macOS, iOS and Android build jobs; no release run is recorded in these commits.

## Rollback

The previous tag is v0.1.261-beta.32, commit 2b68e05b9. This release adds no migration — the diff between the two
tags is three Swift view files — so an application-only rollback to v0.1.261-beta.32 is schema-safe, and with no
server behaviour change there is nothing server-side to undo. Rolling the clients back restores both the wide
translated bubble and the steps line reading a running turn as finished. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
