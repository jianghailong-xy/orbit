# Orbit 0.1.261-beta.48

## Summary

This release brings **Share to Orbit** to the three native clients. Orbit now appears in the system share sheet on
iOS, in the Share menu on macOS, and among Android's share targets. Files, images, text and links shared to it go
to a session you pick, or a new-session draft, and appear there as staged attachments in the composer; you add a
message and send it yourself. Nothing is sent on your behalf. The release also carries **translation failure
reasons**: when the owner's held message or a card answer cannot be translated, the web, Apple and Android clients
now say why (timeout, network, the translator's HTTP status, empty or truncated output, no key, unavailable), and
the composer warns while translation is unavailable. The server stores and returns the reason, skips a failing
translator for 60 s, and pushes the owner when a held message has gone unseen for 60 s.

- **iOS: a Share Extension (`OrbitShare`).** It is embedded in the app and accepts up to 10 files, images, movies,
  text items or URLs. Its "Add to Orbit" page lists *New session* in your default workspace and your recent open
  sessions, with search and an optional note. The extension holds no token and makes no network call: it reads a
  recent-sessions snapshot the app writes to the App Group `group.io.orbitd.app`, and copies the shared items there.
  Items over 25 MB are struck out with "Too large (max 25 MB)" and the rest still go. After Add, a local
  notification ("N file(s) ready in “title” — tap to finish") opens the session. Opening Orbit within 10 minutes
  does the same. The app then stages each item through the composer's own attach path and toasts
  "N shared file(s) added". Entries left unclaimed are swept after 24 h.
- **macOS: a Share-menu extension.** `build-dmg.sh` now builds `Orbit.app/Contents/PlugIns/OrbitShare.appex`. It
  shares its picker with iOS and is signed before the app, with its own sandbox and App Group entitlements. Orbit
  appears in the Share menu of Finder, Preview and other apps; Add opens the chosen session in Orbit with the items
  staged.
- **Android: a share target.** A new `ShareActivity` takes `ACTION_SEND` and `ACTION_SEND_MULTIPLE` for any file
  type and for text. Its "Add to session" page reuses the session list's rows and search; tapping a row opens that
  session, or a new-session draft, with the items staged through `ComposerModel.importAttachment`. A link, or text
  of up to 2,000 characters, goes into the composer's text, and longer text becomes `shared-text.txt`. More than
  10 items keeps the first 10, with a toast saying so.
- **Translation failure reasons.** Every client draws the stored reason under a held message or a card answer that
  could not be translated, and tags the composer while the translator is unavailable. A turn that failed before
  this release has no reason and keeps the generic line.
- **Also.** Commit 82cb43dfd3 brings three Android unit tests (`ProjectDataTest`, `ProjectPageTest`,
  `LandingCheckShotsTest`) in line with the landing-check start body and the "Who fixes it?" card. They had been
  red since that change and failed the v0.1.261-beta.46 release build. The design for Share to Orbit is
  `docs/share-to-orbit-design.md`, with its board in `docs/mocks/share-to-orbit/`.

## Upgrade impact

- **Database migration: one, additive.** `1100_conversation_turn_translation_failure` adds two nullable columns to
  `conversation_turn`, `translation_failure_reason` and `translation_http_status`. It also adds a CHECK constraint,
  first as NOT VALID and then validated. It takes no table rewrite, writes no row and backfills nothing; it asks
  for its lock 2 s at a time, up to 60 tries, and can run twice. The apiserver applies it on boot.
- **Server:** the translation changes are in the apiserver, under `sessions/` and `users/`. Tagging does not deploy
  the server: it reaches an instance only when that instance is upgraded from this source. The share feature needs
  no server change.
- **Runner:** no Go file under `src/runner-go/` differs from v0.1.261-beta.47, so a runner from the previous release
  behaves identically.
- **Configuration:** nothing must be set on a server. The release pipeline now needs the repository secret
  `IOS_SHARE_PROVISION_PROFILE_BASE64` (the OrbitShare App Store profile) beside a regenerated
  `IOS_PROVISION_PROFILE_BASE64` that includes the App Group. Both were set on 2026-11-18, together with the App
  Group and the `io.orbitd.app.OrbitShare` App ID in the Apple Developer account.
- **Clients:** macOS beta users get the DMG on the beta channel. TestFlight gets marketing version 0.1.261, with
  the build number as the commit count. Android gets `android-update.json` from this tag, with `versionName`
  0.1.261-beta.48. Sharing works against any server, since it uses the existing `POST /attachments`. A client from
  this tag against a server older than this release draws the generic translation failure line, because the old
  server returns no reason.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE. No dependency is added,
removed or bumped: `package.json` and `package-lock.json` differ from v0.1.261-beta.47 only in the version lines the
release commit writes.

The share extensions were built to keep credentials out of them. The iOS/macOS extension's only entitlement is the
App Group (and the macOS sandbox); it holds no keychain group and contains no `URLSession`, `URLRequest`, `SecItem`
or API client. The Android share activity hands its items to the app by Intent, with a read grant on each content
URI.

## Known limitations

- **Shared files upload as soon as they are staged**, before you press send. They go to your own Orbit server
  through `POST /attachments`, exactly as a file added with the composer's `+` does, and nothing reaches a session
  until you send. This is the owner's ruling (criterion 5, revision 2), not a defect.
- **First signed TestFlight build with the extension.** This is the first tag whose TestFlight job signs two
  targets. If the `testflight` job fails at signing, the cause is the App Group or the OrbitShare profile, not the
  code.
- **iOS notification tap.** Tapping the "ready" notification to open the session is covered by a unit test only.
  The recorded run used the second path, opening Orbit within 10 minutes. With notifications turned off, the
  extension's done screen says "Open Orbit to finish".
- **macOS Safari.** Orbit in Safari's Share menu was not captured in the recorded run; Finder and Preview were.
- **The macOS DMG container is not codesigned.** It is notarised and stapled, so Gatekeeper accepts the app, but
  `spctl` reports the `.dmg` itself as having no usable signature. This predates this release.
- **Android, over 25 MB.** An item over 25 MB is still handed to the composer, where it shows the existing
  "File exceeds the 25MB limit" chip.

## Rollback

The previous tag is v0.1.261-beta.47, commit 55cae623df4e8948df8707f4dce0ea27c29b7d82 (its tag object is
16243f579a9c7c6794b8771c3ad8133d811e2722). For clients, rolling back removes the share targets and the translation
failure lines. Items already staged stay as ordinary uploaded attachments.

On a server that applied migration 1100, an application-only rollback to beta.47 is schema-safe. The previous
apiserver never reads or writes the two new nullable columns, and its writes satisfy the CHECK, which accepts NULL
for both. No backup or restore step is needed, and the columns can stay. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
