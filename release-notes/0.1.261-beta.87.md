# Orbit 0.1.261-beta.87

## Summary

- **The Waiting on you inbox is gone on all four clients, and requests are answered where they were asked.** An owner request's card stays in the conversation that asked it; a session list's Needs you row (web, macOS), the iPhone capsule or the Android needs-you bar says what waits ("Decision for you", "Key needed", "Steps for you", "Confirm for you", "Approve task move" / "Approve N task moves"). `/waiting?request=<id>`, an `orbit://owner-request/<id>` link and a request's notification tap now open that conversation, scrolled to the card with its input focused; other `/waiting` links open the session list. The sidebar item, drawer row and page or sheet the inbox used are removed on web, macOS, iOS and Android, and the in-app help points at the new places (`find-what-needs-you.md`).

- **Terminal-login approvals moved from the inbox to each machine's page, and Settings → Terminals is gone.** A machine's page lists its own "Terminals to approve" under its title (ten-minute lifetime shown), and — new — its approved terminals between Workspaces and About, newest first, "Approved <date>" over "last used · expires", each with Revoke and the same confirm. The section draws nothing for a machine with none. The web and Android settings nav counts waiting requests; the iPhone and Android settings lists lose their Terminals row, the Apple Settings row and page are removed, and `/settings/terminals` (the web and Android route) opens Machines. On Apple a request is noticed once as a toast rather than a resident bar; its press opens that machine's page with the request's card lit. The card, its approve/deny doors and the API are unchanged.

- **A batch of cross-project task moves is one card answered in one press, on web, macOS, iOS and Android.** The card is drawn both in the session that asked ("Move these tasks into <target>?") and in the target project's coordinator, and Approve / Refuse sends every waiting move in one `POST /sessions/:id/task-moves/decision` with the crossing key the card read. If any key names another crossing the server writes nothing and the card shows the refusal and stays answerable; an answer at one end turns the other into "Approved at another end". Move batches group by asker, so one card is one asker's moves. The card names criteria by number ("for criteria 4–11"), never by their opaque key.

- **A session with a question waiting on the owner never stays in Completed or Trash.** A filed session that has a pending owner request it asked, a pending task move it asked, or a pending task move into a project it coordinates returns to Open — after Complete, Trash, a finished project's Complete and the reaper filing a done task's run, and on every reaper tick. The first tick after this upgrade is also the backfill for sessions filed before it existed.

- **Web draws an agent's Files transfer as one card.** A run of `drive_put` / `drive_get` calls used to fold into a steps line, so a 15-file upload showed no progress. It now draws one transfer card with the bar, bytes, speed and time left, a row per file grouped by folder, a stall warning after 20 s and one line once every file is in; a single file stays a line. The counts are live, reported by a runner from this tag.

- **Web: a dispatched turn reads Running again.** A dispatched turn was drawn as Awaiting reply, with no Stop and a dead approval card; the legacy run status now tells a dispatched turn from work outside one, and the task panel badge says On hold for a held run.

- **Session wording: a finished session says Finished, and a held run says On hold.** Succeeded is replaced on the web watch strip and task run badge, the Apple link card and task panel run row, and Android, held equal across the clients by parity tests. A guest header without release facts keeps its old Succeeded word.

- **The Apple apps read session phase and release facts.** Sending, End and Move, settlement alerts, the menu count and guest polling use the additive wire fields, with the legacy behavior kept for older servers.

- **The web session's Browser chip is gone.** The browser is reachable from Settings → Orbit Cloud runner → Browser only; the chip, its drawer and the code only they used are removed, and the design document says so.

- **Server and runner.** New session routes `GET /sessions/:id/task-moves` and `POST /sessions/:id/task-moves/decision` serve the move batch (the decision is an owner-channel door, refused for a terminal credential and for a landing session); session rows now count open owner requests and pending moves in the needs-you signal, and the crossings read and the task-move route carry `requestedCriterion.ordinal` (additive; clients fall back to the criterion's words against an older server). The reaper's waiting-session sweep now starts from the pending questions instead of scanning every filed session. The runner reports a transfer's bytes ("Uploaded X of Y bytes", every half second) as the call's live `tool_output`.

## Upgrade impact

- **Migrations:** two, both additive — no column or row is changed, and applying them writes no rows.
  - `0591_open_list_owner_requests_and_moves` adds six triggers (insert/update/delete on `owner_request` and on `project_handoff_approval`) so those writes bump the Open list's version counters; without them a 304 answer would leave a row amber after its question was answered.
  - `0592_pending_owner_question_indexes` adds one partial index, `owner_request_pending_asker_idx` on `(asked_by_session_id, expires_at) WHERE state = 'PENDING'`, for the sweep above. Pending task moves are already served by `0386`'s partial index.
- **Server:** the two new session task-move routes are the release's only new API. On the first reaper tick after the upgrade, filed sessions with a pending question come back to Open, so they may reappear in the Open list.
- **Runners:** the runner served at `/dl` is built from this tag and adds the `drive_put` / `drive_get` byte output the web transfer card's bar reads. Orbit Cloud runners get it from the `orbit-cloud-runner:0.1.261-beta.87` image, built from this tag. A runner older than this tag sends no byte counts, so no live progress is drawn.
- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. No configuration change and no one-time step is needed.

## Security fixes

None in this release. The terminal credential's refusal of the new session task-move routes (they are an owner-channel door) closes a gap that exists only within this release: the routes are introduced here, so no earlier release is exposed.

## Known limitations

None known.

## Rollback

Previous tag v0.1.261-beta.86 (`c51afbd77d`). Both migrations are additive — triggers and one index only, with no row or column change — so an application-only rollback is schema-safe and the triggers and index may stay in place. Clients roll back by installing beta.86's builds. A deploy of a commit before this tag points Orbit Cloud runners back at the beta.86 image, and each moves to it once idle.
