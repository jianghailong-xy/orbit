# Orbit 0.1.261-beta.40

## Summary

This release is a client-polish pass with one server fix and newer runner engines. Notices now say what the session row says, an owner request is announced once and opens its card, Withdraw hands back the words the reader typed, a session a full runner holds reads "Waiting for a free slot", and the "Orbit attached" line is gone from every transcript. On the server, an owner item whose coordinator is down with no retry now reaches the owner. This range has no database migration and no configuration change.

- **Notifications name the wait (iOS and Android).** A notice for a wait the server names a kind for (a confirmation, a project ready to close, and so on) said the tool call's "Needs your reply"; it now says what the session's row says for that kind, and only a blocked tool call keeps "Needs your reply". An owner request stops no turn, so every wake while the session waited re-announced the same request, worded as a tool approval and keyed by the session's last turn; a wait the server names a kind for is now keyed by that kind, the request's notice says "Waiting on you", and a press opens the session's oldest pending request in the Waiting on you inbox, as the request's push does (the inbox alone when this device has not read the request yet).
- **Withdraw hands back the words the reader wrote (web, Apple and Android).** With Settings › Translation on, withdrawing a message from the tray put the English delivered to the engine back in the composer, though the row showed what the reader typed. Withdraw now restores the original on every client: Apple's `cancelQueued` and `withdrawSteer` (`ComposerLogic.withdrawnText`, nil wherever `restorableText` is), Android's row restores, and web's `cancelQueued` and steer withdrawals. Put back for an undelivered message and the Stop fold are unchanged.
- **A session a full runner holds reads "Waiting for a free slot" (web, macOS and Android; the copy is in the OrbitKit row code iOS shares).** The list row said only "Runner full", which did not say the message goes out on its own; the owner's pick C on the `session-row-runner-full` board keeps plain words and no clock, since the row's own time already counts the wait from `lastTurnAt`. Run full and Batch full read the same. Web and macOS rows carry a tooltip with the gate's name, the popover's sentence and the wait; the conversation header, foot tag and popover keep their words.
- **The "Orbit attached" line is drawn nowhere (web, Apple and Android).** The owner decided on 2026-11-18 (option 3 on the attached-where board) that the "⊕ Orbit attached: <kind>" line, and the rows or fold it opened, are no longer drawn in a transcript — not under the owner's bubble, not in a session message's foot, not at the bottom of Orbit's own cards. This supersedes 2026-10-27 (`docs/mocks/attached-context-note`). What delivery appended is still recorded and still kept out of the person's words; only its rendering goes. The clients drop the line, its renderers (background-job rows, referenced-task cards, wiki-context rows), the props and model fields that only fed them, their CSS, and the parsers left with no reader; `SessionMessageCard.splitNote` becomes `narrowerLine`, the one part still drawn, and tests that pinned the line now pin its absence.
- **No dangling dot before the translation foot (Apple).** A delivered translation's foot ("Sent to the agent in English", "Show original") was always preceded by "·", so a message with no timestamp, or one a runner holds (its tag drawn instead of the time), read "📄 · Sent to the agent in English". The dot now goes only with something drawn in the state-or-time slot, as web's separator needs `node.ts`.
- **An owner item reaches the owner when its coordinator cannot take the turn (server).** Since 3810329b60 an undelivered coordinator item had no deadline and was hidden from the owner. A coordinator FAILED with no auto-retry never takes the turn, so such an item stayed silent for ever; on production an `INTEGRATION_CONFLICT` opened while its coordinator was already down held its lane by M2 and left a `LAND_TASK` QUEUED for 98 hours, with nobody told. The no-deadline wait now holds only while the coordinator can still take the turn (`openItemCoordinatorCanTake`: live, or FAILED with `retry_at` set). Otherwise the item is visible and escalates one window after it opened.
- **Newer runner engines.** The managed-runner image and the apiserver image move to Codex 0.169.1 (from 0.169.0), OpenCode 1.19.6 (from 1.19.5) and Kimi Code 2.6.3 (from 2.6.2); platform layouts are unchanged. Claude Code 2.1.326 and Antigravity CLI 1.5.10 are current, and Cursor CLI is unchanged.
- **Also.** The Dependency audit job's 11 high findings all trace to picomatch GHSA-fc5q-39xc-vjpf, which every release up to 4.0.7 carries and no patched release fixes; `scripts/npm-audit-gate.mjs` now fails on every high or critical advisory except the dated entries in `scripts/npm-audit-allowlist.json` (one, picomatch, expiring 2026-12-18, as the account owner chose), with `test/npm-audit-gate.test.mjs` pinning those rules under `test:supply-chain`, and basic-ftp goes to 6.2.4 (dev). A second commit raises minimatch to 11.0.1 under `@nestjs/cli` for GHSA-g3hv-75wg-m249 (dev). Four pg specs are corrected on the test side for 1060's `condition_ended_with_task` trigger counts and for its task objects in the landing-observation frontier compare. An Android evidence test failure is fixed by keeping the tile thumbnail and viewer producers on `Dispatchers.Main.immediate`; on a device the effect dispatcher already resumes on main, so that was test-only. The session-handoff design and board, and the queued-row board, are docs only and not user-facing.

## Upgrade impact

- **Database migrations: none.** The diff of `src/apiserver/prisma/migrations/` between v0.1.261-beta.39 and this release is empty: no migration is added, altered or removed, so a database already at v0.1.261-beta.39 needs no schema step and none of this range's changes is additive or destructive.
- **Server:** the open-item escalation change (`openItemCoordinatorCanTake`, the no-deadline wait, and the escalation window) is an apiserver change, so the apiserver must be deployed from this commit or later. Until then, an item whose coordinator is FAILED with no `retry_at` stays hidden from the owner with no deadline. The web client ships with the same deploy; its changes in this range are presentation only.
- **Runner:** this range changes no `src/runner-go` source, and the runner served at `/dl` is built from this tag. The managed-runner image and the apiserver image carry the newer engine versions named above; no runner capability or wire change is named by any commit, so a runner from an earlier tag keeps working.
- **Configuration:** no variable is added or changed, and `docker-compose.yml` is untouched. `scripts/npm-audit-allowlist.json` is CI tooling, not deployment configuration.
- **Clients:** macOS beta users get the DMG on the beta channel, TestFlight gets marketing version 0.1.261 with the build number as the commit count, and Android gets `android-update.json` from this tag. The client changes in this range are copy, restored composer text, a removed transcript line and a tooltip; no minimum native client version above the previous release is set by this range.

## Security fixes

None in this release. Nothing in this range fixes a product security issue, and no advisory or CVE is named for a shipped component. The dependency-audit commits are tooling only: basic-ftp 6.2.4 and minimatch 11.0.1 are dev dependencies, `npm audit --omit=dev` finds nothing, and picomatch's advisory carries a dated CI exemption because no patched release exists.

## Known limitations

None known. The picomatch advisory (GHSA-fc5q-39xc-vjpf) is unpatched upstream and reaches only build and test tooling (vite, vitest, tinyglobby, `@nestjs/cli` via `@angular-devkit`); its CI exemption expires 2026-12-18 and it is part of no shipped artifact.

## Rollback

The previous tag is v0.1.261-beta.39, commit 61d26fa4486. This range adds no migration, so an application-only rollback to that tag is schema-safe: nothing needs undoing and no data is affected. Rolling back restores the older behaviour: notices name the tool call again and an owner request can be re-announced on each wake, Withdraw restores the translation instead of the reader's words, a full runner's row reads "Runner full", the "Orbit attached" line is drawn again, and an owner item whose coordinator is FAILED with no retry is hidden again. The clients from this tag would then talk to an older server; every client change in this range is presentation or composer text, so the server behaviour above is what changes. See [Release process](../docs/release-process.md#rollback-decision-and-procedure).
