# Orbit 0.1.261-beta.20

## Summary

Changes since [0.1.261-beta.19](0.1.261-beta.19.md).

- **Resuming a remote SubAgent:** `delegate` with `resume` now continues a SubAgent that ran on another workspace,
  with its conversation, on the workspace and runner it ran on, in a new worktree of that workspace's HEAD.
  Before, the resume was refused as "left no conversation to resume".
- **Settings on iOS and Android** take the web nav's groups: Personal, Machines, Providers.
- **Web:** a bare machine's card makes a workspace from a folder and a name; an engine row's update warning offers
  Fix with an agent; a question answered on another client leaves the web card; account menu levels draw each
  icon after its label.
- **Composer:** Tab optimizes a draft (web and Mac).
- **Clients:** an Agent block and its group head show no cost.
- **Managed runners:** a runner with no login waits for one instead of failing, and is ready by itself once one
  is signed in.
- **Apple:** a user message's state reads as the web's; the setup card's Folder step carries no step number.
- **Upgrade:** a two-stage build makes room on the build host first.

## Upgrade impact

- **Database migrations.** None since beta.19.
- **Runners.** Runners on the beta channel move to 0.1.261-beta.20 once the server is deployed after this
  tag. This release changes the runner: it keeps an ended remote SubAgent's conversation for 7 days after its
  last run, continues it on a resume, and declares `subagent-remote-resume/v1`.
- **Server.** The server side of remote resume is already deployed (production runs 164e3613f). Until the
  target workspace's runner declares `subagent-remote-resume/v1`, the server refuses a remote resume as too old.
- **Configuration.** No changes required.
- **Clients.** Each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261,
  build number = commit count) and Android via `android-update.json` are offered it.

## Security fixes

None in this release.

## Known limitations

- A remote resume works only once both the parent's runner and the target workspace's runner run this release.
- A resumed remote SubAgent starts from the workspace's current HEAD: what it changed in its earlier run was
  discarded, and it is told so.
- A remote SubAgent's conversation is kept for 7 days after its last run. A resume fails, with the reason, if
  the target workspace has since moved to another runner or now runs another engine, and Claude Code cannot
  reopen it if the workspace's Claude account changed in between.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.20` and tag `v0.1.261-beta.20`. This tag publishes the
macOS DMG and Sparkle payload (beta channel), the iOS TestFlight build, the runner binaries, and
`orbit-android-0.1.261-beta.20.apk` with its `.sha256` and `android-update.json` on the same GitHub Release.
Remote resume was checked by the runner's SubAgent and remote SubAgent tests and by the remote SubAgent
PostgreSQL spec (16 of 16) before it merged; it has not been run end to end across two machines.

## Rollback

Roll back to 0.1.261-beta.19. No migrations since then, so an application-only rollback is schema-safe.
Runners do not move back by themselves: roll them back with the `/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
