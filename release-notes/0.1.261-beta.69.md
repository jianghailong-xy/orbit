# Orbit 0.1.261-beta.69

## Summary

This release is about **an iOS crash when a conversation opens**, about **a folder's count matching the rows its page lists**, and about **CI keeping the iOS dSYM of every TestFlight build**. A TestFlight build that crashed the app when a conversation opened is addressed by type-erasing the transcript and the composer band; a folder row no longer counts a filed project's member sessions, so a folder holding one project reads 1 on web, iOS/macOS and Android. The range is `v0.1.261-beta.68..origin/main` (`931fb9c63c`).

**The iOS conversation-open crash.** TestFlight 0.1.261 (13668) crashed on the main thread's stack guard; symbolicated with a dSYM rebuilt by CI's toolchain, the stack ran out inside `ConsoleView.body -> consoleBody -> transcriptAndBand` while the runtime instantiated that view type, which nested the transcript and the whole composer band under two dozen more modifiers, each holding a runtime-sized stack copy (`99118d6ebb`). An `AnyView` at the band and at `consoleBody`'s base cuts both the type and the copies. The band's erasure is in the iOS branches; the one at `consoleBody`'s base applies to macOS too. Behaviour and copy are unchanged. That this build opens the conversation which crashed is to be confirmed on the device that crashed.

**A folder counts the rows its page lists.** A folder row counted every member session of a project filed there while the folder's page lists the project as one row, so a folder holding one project could read 6. The count is now the rows the folder's page lists on web (`931fb9c63c`), iOS/macOS through OrbitKit's `SessionProjectGrouping`, and Android; needs-you and activity still read every member.

**CI keeps each TestFlight build's dSYM** as an `ios-dsym-<run>-<attempt>` artifact for 90 days, because App Store Connect offers no dSYM download and a rebuild is not byte-identical, so a TestFlight crash can only be symbolicated against that archive's own dSYM (`93cafc247c`).

- **Configuration:** nothing new to fill in.
- **Runner** (`src/runner-go`, built from this tag and served at `/dl`): no runner change in this range. A runner from beta.68 or this tag works the same; older runners keep working.
- **Clients:**
  - *macOS:* the folder count on the beta channel (DMG and Sparkle appcast).
  - *iOS:* TestFlight marketing version 0.1.261, build number the commit count, with the conversation-open crash fix and the folder count.
  - *Android:* `versionName` `0.1.261-beta.69`, the next `versionCode`, and `android-update.json`, with the folder count.
  - No minimum client version is enforced, and no one-time step is needed.

## Rollback

The previous tag is v0.1.261-beta.68, commit `9ebf596f31cbbb38a264fe68d1a8a07b336d18e2`. A server deployed from this tag rolls back to that commit. Native clients roll back by installing beta.68's build.

An application-only rollback to beta.68 is schema-safe: this range changes no migration and no stored data.

The client changes do not roll back with the code: installing beta.68's iOS build or 0.1.261 (13668) brings back the conversation-open crash, and a beta.68 web or native client keeps the old folder count.
