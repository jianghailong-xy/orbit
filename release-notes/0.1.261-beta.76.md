# Orbit 0.1.261-beta.76

## Summary

**The Orbit Cloud browser gains four agent tools and an owner sign-in card, all behind the browser switch.** `browser_status` reads the runner's browser and whether its profile holds saved logins (`579f76c619`); `browser_open` and `orbit browser open [--url]` ask the runner to start the browser and open a page in the shown tab through Chrome's DevTools (`d1e88673d4`); `browser_clear_logins` and `orbit browser clear-logins` file a card and, on a person's yes, stop Chrome and delete the profile (`c932a07d58`); `browser_request_sign_in` and `orbit browser request-sign-in` give the browser lease up, file a `BROWSER_SIGN_IN` card and wait for the owner's answer, then take the lease back (`34c0e3f01d`). The card names the site and the asking session and says the owner signs in themselves and every agent on the runner can use the login; Open browser opens the runner's browser in control and Not now declines (`82b4fd3d4c`), and it draws on web and Android (`b18fb7be83`) and on Mac and iPhone (`1fd6fa8fc9`). With the switch off, the browser is absent from every listing — `orbit mcp`, `orbit capabilities`, the agent-tools report and the engines' pre-approved rules — rather than withheld (`a0bb6d91d2`, `4d5863e919`). On the Orbit Cloud runner with it on, a CLI tool's sign-in page opens in the shared Chrome through `$BROWSER` and an `xdg-open` shim first on `PATH` (`69dca5e7d6`), and an open sign-in card shows above the web tab's bar, where I'm signed in answers the card DONE (`df95c106e6`).

**Model routing now names one model's rows alike across engines and pools its Quality.** Id rules take off an engine's wrapping; what they cannot settle is asked of DeepSeek once in the background and kept in the new `model_identity` table (`62caf021ee`). The server pools a model's Quality over every provider listing it, and the web page draws each row with the model's shared name, rows of one model together, a single Quality cell naming the providers it is pooled with, and the pooled line "Pooled across N providers" (`3066f39c25`, `da6a6ea5a2`). The table is seeded with DeepSeek's reading of production's 116 model ids (`069b42dd64`), so the first load already shows `deepseek-flash` as DeepSeek V4.1 Flash and `kimi-k3` as Kimi Code's K3; an id seen later is asked of DeepSeek as the page meets it.

**The worktree bar now counts a session's work in commits on iOS, iPadOS, macOS and Android.** Following the web, the bar reads "3 commits", with "+ uncommitted" while the worktree holds work no commit has, or "Uncommitted · 8 files" before the first commit; the Worktree changes sheet opens on a Commits / All changes control when the runner reports commits, uncommitted work first and then the commits newest first with the runner's own labels, and a commit pushes a screen with its message and files (`916f4a0b99`). A wide Apple bar (iPad, Mac) leads with the newest subject and a phone does not; a runner too old to report commits keeps the previous bar and sheet. Android follows the same board, with the bar reading "3 commits", the Commits / All changes tabs and the commit screen (`68751ed4b1`). `916f4a0b99` records OrbitKit tests for decoding, logic, and the views' wiring over their source; `68751ed4b1` records `CommitsLogicTest` (6), `WorktreeBarLogicTest` (17) and `WorktreeBarTest` (20), all passing.

**Android's conversation catches up with iOS, and a few fixes land across the clients.** A sent image now sits over the bubble with the English the agent got inside it, files as chips, and copy · time · the translation's press on one line (`f3ff5d86d3`); the steps line, the Jump to latest disc and the 12 dp row spacing match iOS (`59b700ed5d`); a message the server accepted but no runner has taken offers `Cancel` beside `Queued · runner full`, withdrawing the turn and putting its words back in the composer (`5df3b171ce`). On web, a stream lost while the tab was hidden is reopened on return, read once, then resumed at the outage pace (`32891f8e5d`); a selected session's observers share one in-flight subagents read with one trailing read (`a957f07fe1`); and a machine drag no longer eats the next click under load (`bf08deec7f`). The managed-runner image no longer makes an empty `orbit-repos` on a new volume — the work directory is `home`, and on a volume an earlier image ran on the next start moves the config and identity marker out of `orbit-repos` to `home` (`6d4791e6f9`).

## Upgrade impact

- **Database migrations:** four files are added between v0.1.261-beta.75 and this tag, and **all four are additive**:
  - `1237_runner_browser_open_request` adds two nullable columns to `runner`, `browser_open_requested_at` (`TIMESTAMP(3)`) and `browser_open_request` (`JSONB`); no default, nothing backfilled.
  - `1393_owner_request_browser_sign_in` adds two nullable columns to `owner_request`, `browser_site` (`TEXT`) and `browser_runner_id` (`UUID`); drops and re-adds `owner_request_kind_chk` with `BROWSER_SIGN_IN` added (a superset, so every existing row passes) and adds `owner_request_browser_sign_in_chk` tying the two columns to that kind. Its own comment calls it a constraint swap, two nullable columns and one CHECK: no row is written, no trigger or function is named, and every statement can run twice.
  - `1432_model_identity` creates the `model_identity` table (`rule_key` primary key, `canonical_key`, `name`, `decided_at` defaulting to `CURRENT_TIMESTAMP`).
  - `1433_model_identity_seed` inserts 116 rows into `model_identity` with `ON CONFLICT ("rule_key") DO NOTHING`; it writes only the new table and no existing row.

  None updates or deletes an existing row, and no other table is altered. `1237` and `1393` sort below migrations a deployed server has already applied (through `1431`) while `1432` and `1433` sort above, but all four are independent, so a boot applies whichever it has not yet recorded in the Prisma ledger, in name order, with no ordering constraint between them.
- **Configuration:** no new environment variable or setting is required. The browser tools and the `BROWSER_SIGN_IN` card appear only when `ORBIT_MANAGED_RUNNER_BROWSER_ENABLED` and managed runners are on; off, they are absent from every listing. **The managed-runner image must be rebuilt from `deploy/managed-runner/image` at this commit** for the `home` work directory and the `orbit-repos` move to reach it.
- **Runner** (`src/runner-go`): changed in this range — the Orbit Cloud browser tools (`browser_open.go`, the clear-logins and sign-in paths) and the `$BROWSER`/`xdg-open` opener for engine CLI sign-in. The supply-chain job builds the runner binaries from this tag, and the runner served at `/dl` is built from this tag; a production deployment is what puts it there, so the runner at `/dl` shows this tag after the next production deploy.
- **Clients:**
  - *macOS:* the worktree bar's commit count and the `BROWSER_SIGN_IN` card — on the beta channel.
  - *iOS:* the same worktree bar and `BROWSER_SIGN_IN` card in a TestFlight build; marketing version 0.1.261, build number the commit count.
  - *Android:* the worktree bar's commit count, the `BROWSER_SIGN_IN` card, `Cancel` on a queued runner-full message, and the bubble, steps-line and jump-disc parity, at `versionName` `0.1.261-beta.76` with the next `versionCode` and `android-update.json`.
  - *Web:* the model-routing block and pooled Quality, the sign-in banner, the stream-return fix, the shared subagents read and the drag-click fix, with the next server/web deployment rather than from this tag's client artifacts.
  - The server-side additions are additive: an older client keeps its existing reads and draws its existing page, and no minimum client version is enforced.
- **One-time step:** a runner on a volume an earlier image ran on moves its config and identity marker from `orbit-repos` to `home` on the first start of an image built at or after this tag, and does nothing on later starts; no operator action beyond rebuilding the managed-runner image is needed.

## Security fixes

One tenant-scoping fix: `1b1c7a8e71` looks up a runner by id and owner before rejecting account parameters, so a request naming a runner the account does not own consistently returns not found without writes. No other commit in this range describes a security fix, and none names an advisory or CVE.

## Known limitations

A model id not among the 116 seeded is asked of DeepSeek once in the background the first time the page meets it (`069b42dd64`); until that answer arrives its rows are shown under the rule-derived identity. The Orbit Cloud browser's tools and the `BROWSER_SIGN_IN` card exist only on a managed runner with the browser switch on; off or self-hosted, they are absent rather than withheld (`a0bb6d91d2`).

## Rollback

The previous tag is v0.1.261-beta.75, commit `c8db847bbdd4bd168260b937b151f639d6434a53`. An application-only rollback to it is schema-safe: all four migrations in this range only add nullable columns, a new table and new rows, or swap a CHECK for a superset, and beta.75 writes none of them and reads none of them. Before rolling the managed-runner image back, note that this image moves a volume's config and identity marker from `orbit-repos` to `home` on its first start (`6d4791e6f9`); the commit does not say how an earlier image treats a volume moved that way, so check that before rolling the image back.

The client changes do not roll back with the code. Rolling macOS or Android back from this release means installing beta.75's build, which loses the worktree bar's commit count, the `BROWSER_SIGN_IN` card, and the Android queue Cancel and conversation parity; an iOS device can also go back to a beta.75 TestFlight build.
