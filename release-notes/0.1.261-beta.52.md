# Orbit 0.1.261-beta.52

## Summary

This release gives a **managed runner a browser**: one shared Chromium per managed runner with a
one-session lease, a `browser` MCP tool for Claude Code and Codex, and a web viewer with Take control,
Hand back and Clear saved logins. Clients also get an **Agents line that names the models and machines that
did the work**, a **Tasks bar that says what runs**, **every machine list marked by its OS**, a **folder row
that shows one number**, and a corrected **Android composer card**. v0.1.261-beta.51 was tagged but never
published — its Android release job failed, so there is no GitHub Release and macOS and Android users never
got it (its iOS TestFlight upload did go through) — and everything it carried ships here.

- **The managed runner's browser (server, runner, web).** Behind a new switch,
  `ORBIT_MANAGED_RUNNER_BROWSER_ENABLED`, effective only with `ORBIT_MANAGED_RUNNERS_ENABLED` on
  (`d63b35d1f1`). A managed runner from this release's image ships pinned Chromium, Xvfb, x11vnc, Noto CJK
  and emoji fonts and `@playwright/mcp` 0.0.85, nothing starting at boot (`121bb171a3`). Each managed runner
  runs one browser: the first session to acquire the lease holds it until its turn ends (or 5 minutes
  without a call), another session is told which session holds it, and the browser stops 15 minutes after
  the last call or viewer (`02c3520255`). `orbit browser-mcp` is a stdio proxy in front of playwright-mcp
  over Chrome's DevTools, offered to Claude Code and Codex only while the runner offers the browser
  (`3321fd4d5a`); playwright-mcp's snapshots now go to the session's run directory rather than its
  checkout (`884410faaf`). Frames for byte streams are an additive minor revision of the runner link
  (`link-stream-v1`, 256 KiB each way, at most 2 streams per runner, `7280abe352`), and the gateway relays
  StreamOpen only to a verified managed runner (`6a17220355`).
- **The web viewer (web, server).** When the server reports the feature on, a session on the account's
  managed runner gets a **Browser chip** above the composer while its browser is running, opening a noVNC
  drawer scaled to fit; **Take control** and **Hand back** switch the same stream without making any request
  to the session (`079619bfba`). The drawer is fed by `GET /api/runners/:id/browser/vnc` — web login only,
  the caller's own managed runner only, at most two viewers across apiserver processes, opening a stream
  starts the browser (`079f28488c`); the viewer's access token is kept out of access logs (`d8d136ed17`).
  Settings → Orbit Cloud runner gains **Open browser**, the saved-logins line and **Clear saved logins**
  behind a confirmation, riding the heartbeat like Update Runner Now (`5ef038def4`). Nothing is drawn when
  the server reports the feature off.
- **The Agents line names models and machines (web, Apple).** At rest it shows the run count, "4 machines"
  when any ran on another workspace, then each model with its run count, most-used first; while running,
  the title and its machine and model chip when either is not the session's own; a failure reads as a red
  "n failed". Always one line — web folds models into "+n" under 720px and drops the words under 520px,
  Apple picks what fits (`94c320a2d4`). Apple's Agents sheet is one list, running first then ended newest
  first, as the web strip already was (`d2c03e0ab8`).
- **The Tasks bar says what runs (web, Apple, Android).** Folded past one task it no longer counts
  ("13/14 done"): it names the newest running task, after "N running · " when more than one runs, or
  "<total> · <newest task>" with none running, and ends with that task's own status pill; a red
  "N failed · " leads while any task failed (`bd4f3ad098`).
- **Every machine list marks the machine's OS (web, macOS/iOS, Android).** Each machine wears the mark of
  the OS it reported (its `os:<goos>` capability) — Apple, Linux, Windows, a monitor when it has not said —
  in place of the one drive icon every row shared; Orbit Cloud keeps its brand cloud and stays first
  (`a957d68268`).
- **A folder row shows one number (web, macOS/iOS, Android).** With someone waiting, the needs-you badge
  alone sits in the total's slot and the total moves into the label ("1 run needs your reply · 5 runs");
  VoiceOver and TalkBack still read the total (`ae4c2796a4`, `52fe386369`).
- **Android's composer as iOS draws it (Android).** One rounded card holds the attachments, the text and
  the toolbar: + and the permission mode on the left; the model with its effort, a context ring, Optimize
  and a round Send/Stop on the right. The context line becomes a ring that opens a bottom sheet; a full row
  gives way as iOS does (Optimize folds to ✦, then the effort, then the name). A failed upload drops its
  chip and says "Upload failed — <file>: <reason>" (`69da451119`). The waiting-card test the beta.51
  Android job tripped over now reads the command's own foot, which is what the change moved
  (`1ba6bc9d38`).
- **A new session defaults to a credential that can run on its machine (web, iOS/macOS).** When nobody
  picked one and what the workspace last ran on can't run here, the draft lands on the same engine's first
  credential that runs, else the first other installed engine with one, and the hero says why ("Using
  DeepSeek · Anthropic unavailable on jdcloud · Details"). An explicit pick is never moved (`6969aaab15`).
- **An escalated baseline item keeps the baseline card (web, iOS/macOS).** A shared baseline item no longer
  takes the "Who fixes it?" layout, whoever holds it, and web's escalated card is headed with the baseline
  title; Android already drew it this way (`9120d2b8b3`).
- **A job's approval card closes when its job ends (server).** A killed `bg_run` job's PENDING card left a
  conversation reading "Waiting for approval" with nothing to press; it is now collected with the job's end
  and counted only while the job still runs (`0173cdeb0a`).
- **A scheduled run waiting on its background job is not NO_REPORT (server).** A run whose session ended
  its turn to wait for a `bg_run` job was failed NO_REPORT about 30 s later, and its eventual report was
  refused; an idle session now counts as working while it has a running job or watch, or a turn still
  pending (`17bb9ace28`).
- **OpenCode key and catalog fixes (runner, server).** A 401 reads as a provider auth failure, so the turn
  says "Failed to authenticate"; the catalog probe runs with a private, empty config as sessions do; and
  the runner pages drop "no provider key found" when the owner holds an Orbit key OpenCode can spend
  (`6ba3b1370e`).
- **The bilingual message foot on a narrow row (iOS/macOS).** "Sent to the agent in English · Hide
  original" no longer wraps into two lines beside the time; it moves to a line of its own under it when the
  row has no room, kept as one row (`f94beb63cf`, `258c2803e2`).
- **Also.** Web's "Copied" reset timers are cleared on unmount (`7fa951c12d`); `merge-check.sh` and CI now
  run the suites a change touches — the shared package and the deployment topology test, which is also in
  the JavaScript job (`fbb24cbc8a`, `b224068d03`, `4edfc5ffca`, `528500c523`); the browser routes and
  writes are classified in the server's registries (`b574ad1b33`); the API reference is regenerated
  (`a28c56c828`); and a session-status three-state design lands under `docs/` (`00d8e9c5f2`).

## Upgrade impact

- **Database migration: one, additive.** `src/apiserver/prisma/migrations/1090_runner_browser_state/migration.sql`
  is new: `ALTER TABLE "runner"` adds two nullable columns, `browser_state` (`JSONB`) and
  `browser_clear_requested_at` (`TIMESTAMP(3)`), with no default and nothing backfilled. It drops or changes
  nothing and writes no row, and an older apiserver neither reads nor writes the columns, so it is
  schema-safe in both directions. The apiserver applies it on boot as usual; there is nothing to run by hand.
- **Configuration: one new switch, off by default.** `ORBIT_MANAGED_RUNNER_BROWSER_ENABLED` is read once
  (trimmed and lowercased, `true` on; absent, empty or anything else off, the last with one warning) and is
  effective only with `ORBIT_MANAGED_RUNNERS_ENABLED` on. A self-hosted runner never gets the browser.
  Nothing else must be set, and the release pipeline needs no new secret.
- **Runner:** the managed-runner image carries the pinned browser packages above plus `@playwright/mcp`
  0.0.85, recorded in `pins.json` and checked at build time into `tool-versions.json`; nothing starts at boot
  and no port is exposed. `src/runner-go/` changes (link streams, the browser supervisor and MCP proxy, the
  OpenCode fixes), so a runner from this tag is needed for the browser and the OpenCode fixes. The runner
  served at `/dl` is built from this tag.
- **Server:** the browser routes, the approval-card and scheduled-run fixes and the OpenCode key adjustment
  are apiserver changes; each reaches an instance only when it is upgraded from this source, and tagging
  does not deploy the server. The web changes reach browser users when the deployment's web is rebuilt from
  this source; the tag does not deploy the web app.
- **Clients:** macOS beta users get the DMG on the beta channel. TestFlight gets marketing version 0.1.261,
  with the build number as the commit count. Android gets `versionName` 0.1.261-beta.52 and
  `android-update.json` from this tag. Every client change here except the browser viewer draws data the
  server already sends; the viewer needs a server from this source with the browser switch on.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE. Two dependencies
are added: `@novnc/novnc` 1.7.0 (web, MPL-2.0) and `ws` ^8.22.1 (apiserver); the root `package.json` and
`package-lock.json` otherwise change only in the version lines this release commit writes. The new viewer's
access token is kept out of access logs — its location writes no access log and a pin test holds
`gateway/nginx.conf` to logging the request through `$logged_request`, whose map drops the query
(`d8d136ed17`) — and the gateway relays StreamOpen only to a verified managed runner (`6a17220355`).
Neither fixes an exposure on an older release: the browser routes do not exist before this one.

## Known limitations

- **The macOS DMG container is not codesigned.** It is notarised and stapled, so Gatekeeper accepts the app,
  but `spctl` reports the `.dmg` itself as having no usable signature. This predates this release.
- **The browser is one per managed runner, for two viewers at most.** A session other than the lease holder
  is told "The browser is in use by session <title> (<id>); try again after it finishes", and a third viewer
  of the same runner is refused. A self-hosted runner is never offered the browser.

## Rollback

The previous tag is v0.1.261-beta.50, commit `a1282659a41fb8ffbb8994e286eb447551017b0a` (its tag object is
`69a41b74dc5c1169059aa9ab9324dd457d264084`). Rolling back also removes everything v0.1.261-beta.51 carried,
since that tag was never published: the escalated baseline card on web and iOS/macOS, the new-session
credential fallback, Android's composer card, the one-line bilingual foot, the OpenCode fixes and the
scheduled-run wait — along with this release's managed-runner browser, Agents line, Tasks bar, machine marks
and folder row.

An application-only rollback to beta.50 is schema-safe, because migration `1090_runner_browser_state` only
adds two nullable columns with no default or backfill: an older apiserver runs against a schema that merely
carries them and is unharmed. No backup or restore step is needed. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
