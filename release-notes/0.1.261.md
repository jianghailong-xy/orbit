# Orbit 0.1.261

## Summary

The stable release after `v0.1.260`, with everything merged since that tag. The changes an operator will notice
are in the runner's self-update. From this release on, a busy runner takes an automatic update in the night
instead of during the working day. A drain that runs past five minutes interrupts the turns still running
instead of holding new sessions behind them, and the cut turns resume on the updated runner. A session queued
before any runner has claimed it now shows its first message instead of an empty page. Project pages no longer
list the crossings their target's coordinator already answers, and trashing an open project's coordinator
opens the next one at once. On iOS 26 the session list's pinned section header is glass. On iOS and Android
the needs-you fold's chevron no longer squashes when there is no count. macOS and iOS label a shared pool
"Shared", as the web does. These notes also correct the 0.1.260 notes, which left out five database migrations
and a dependency security fix (see Upgrade impact and Security fixes).

## Upgrade impact

- **Runners update themselves.** `0.1.261` orders above `0.1.260`, so runners self-update from `/dl` as usual.
  The update to 0.1.261 is taken under the rules of the runner it replaces: under 0.1.260, a busy runner drains
  after an hour of deferral and waits for its turns to finish. From 0.1.261 on, a runner that goes idle still
  updates at once, but a busy runner's automatic update waits six hours for it to go idle. If it never does, it
  drains at the first check between 02:00 and 06:00 local time after that, which can be the next night, about
  26 hours after the release. A release the owner postponed with Later keeps its plain deferral and ignores that
  window. Once a drain has lasted five minutes, the runner takes the update as Update Now does: it interrupts the
  turns still running, and they resume on the updated runner. The runner log says when the interruption came
  from the drain limit.
- **No database migrations** since `v0.1.260`.
- **Correction to the 0.1.260 notes.** 0.1.260 applied five more migrations than its notes listed, beside
  `0705_runner_engine_update_dismissals`, `0740_session_merge_after_turn` and `0760_runner_attention_fixes`:
  - `0660_terminal_credential`: new `terminal_login` and `terminal_credential` tables.
  - `0661_approval_decided_by_terminal`: the approval check widened to a `TERMINAL` credential.
  - `0662_turn_sender_client`: two nullable `conversation_turn` columns.
  - `0663_approval_decided_terminal_machine`: a nullable `approval.decided_terminal_machine_name`, and the
    approval and activity checks widened to `TERMINAL`.
  - `0730_session_work_subdir`: a nullable `session.work_subdir`.

  All five are additive: they create tables, add nullable columns and widen checks, and none rewrites existing
  rows. A deployment upgrading from `v0.1.2-beta.246` (package 0.1.256), the release before `v0.1.260`, straight
  to 0.1.261 applies fifteen migrations on boot: the six in the [0.1.257 notes](0.1.257.md),
  `0720_runner_presence_resources`, the three the 0.1.260 notes name, and these five.
- **API.** `GET /projects/:id/handoffs` adds `toProject.coordinatorSessionId` to each row: null when the target
  project has no coordinator or its coordinator is in Trash. It is additive, and a client that does not read the
  field lists every row as before.
- **Deployment.** No configuration changes are required. Pin the deployment to the tag `v0.1.261`.
- **Clients.** macOS ships on the stable channel; iOS ships marketing version `0.1.261` to TestFlight; installed
  Android apps are offered `0.1.261`. These builds carry the native changes merged since `v0.1.260`.

## Security fixes

None in this release: nothing merged since `v0.1.260` fixes a security issue or changes a dependency.

**Correction to the 0.1.257–0.1.260 notes**, which each said "None". `v0.1.260` is the first published release
with the DeepSeek Harness MCP client fix. It moves `@modelcontextprotocol/client` and `@modelcontextprotocol/core`
from 2.0.0 to 2.4.0 in the two DSH lockfiles: `src/runner-go/dsh-install`, which runners install DSH from, and
`scripts/deepseek-harness-p0`. It fixes two advisories, reported as Dependabot alerts #75–#78:

- [GHSA-6qxp-vccf-f47h](https://github.com/advisories/GHSA-6qxp-vccf-f47h) (CVE-2026-104850, high): the SDK's
  OAuth client could send its credentials to an authorization server that a remote MCP server advertised.
- [GHSA-6prh-2h8m-c8cw](https://github.com/advisories/GHSA-6prh-2h8m-c8cw) (CVE-2026-111769, moderate): its
  HTTP transport re-sent custom headers and request bodies across cross-origin redirects.

Neither path was reachable through Orbit. Its DSH sessions configure no OAuth, and they run MCP servers over
stdio only: an HTTP entry is refused before the process starts. A machine that installed DSH before `v0.1.260`
keeps its old tree, because a published `engines/dsh/0.2.0-rc.2` directory is not reinstalled when the lockfile
changes; fresh installs take the patched one. See
[dependency security](../docs/dependency-security.md#mcp-client-in-the-deepseek-dsh-lockfiles-2026-11-13).

## Known limitations

- Android still labels a shared pool `SHARED`, where the web, macOS and iOS say "Shared".
- These limits from earlier notes still hold:
  - A failed model-list probe on a signed-out Claude is logged, but its cause is not known
    ([0.1.257](0.1.257.md)).
  - The machine page's resource history lives on an UNLOGGED table and empties on a database crash, and
    macOS CPU is averaged by `ps` ([0.1.258](0.1.258.md)).
  - The note on unattached reply files covers only links outside the session's directories
    ([0.1.259](0.1.259.md)).

## Artifacts and verification

The tag is `v0.1.261`. Its full source SHA is that tag's commit, which the account owner confirms before the
tag is created. The release workflow publishes:

- `Orbit-v0.1.261-arm64.dmg` and its Sparkle payload `Orbit-v0.1.261-arm64.zip`;
- `orbit-android-0.1.261.apk`, its `.sha256`, and `android-update.json`;
- a TestFlight build of `0.1.261`;
- the runner reference binaries;
- `SHA256SUMS`, a CycloneDX SBOM, SLSA provenance and `release-manifest.json`, with a GitHub artifact attestation
  ([supply chain](../docs/supply-chain.md)).

`/dl/version.json` names `0.1.261` once the server built from the tag runs.
`node scripts/release-identity.mjs check-tag v0.1.261` checks that every surface derives from the package version
and that these notes carry every section. The release workflow's `identity` job runs the same check before it
builds anything.

The tag is cut only once a dispatch of `ci.yml` on the release commit has reported all six of `main`'s required
checks green on that commit: JavaScript, Go runner, Swift core, Dependency review, Container images and
PostgreSQL specs. A dispatch of `client.yml` must also have built macOS and iOS. Record those run URLs and the
asset digests in the Release once the release run finishes.

## Rollback

The rollback target is the previous published release,
[`v0.1.260`](https://github.com/jianghailong-xy/orbit/releases/tag/v0.1.260) (source
`9328d738028b849b01df992ebba1c32b6935fd6e`). Record the image IDs and the source SHA you are running before
upgrading. 0.1.261 adds no migration, so the 0.1.260 application starts against the upgraded schema and an
application-only rollback is safe.

Runners do not move back by themselves: roll them back with the `/api/runner/release` pointer. A runner back on
0.1.260 takes later automatic updates under 0.1.260's rules again.

Keep PostgreSQL and its archive running. Reinstall the 0.1.260 DMG or select its TestFlight build only after
confirming server compatibility. Android's `versionCode` only increases, so fix forward rather than downgrade
the APK. See [Release process](../docs/release-process.md#rollback-decision-and-procedure).
