# Orbit 0.1.261-beta.6

## Summary

The work merged since [0.1.261-beta.5](0.1.261-beta.5.md), on the beta channel.

- **A project row waiting on you opens the waiting session at its card, now on Android too.** In the session
  list, a project row whose second line reads "Waiting on you · <session>" opens that session instead of the
  coordinator, at the top of the waiting card rather than at the transcript's end. The card sits below the
  floating needs-you bar. Every other project row still opens the coordinator. Web and iOS shipped in
  0.1.261-beta.5; this completes the three clients.
- **A queued message says what holds it.** A turn waiting for a slot reads `Queued · runner full` (or
  `run full`, `batch full`), the way `Queued · runner updating` already did. The popover counts the slots,
  for example "HPC is using all 16 slots: 10 sessions are running a turn and 6 hold a slot with a background
  job". This is on web, iOS/macOS and Android alike.
- **New sessions start on the workspace's last model.** A new-session draft takes its model from the
  workspace's `lastModel`, and the workspace default now counts only conversations a person opened. A
  coordinator, a judgment, a wiki chat or a Feishu message no longer moves it. Project tasks, coordinators
  and MCP children start on their anchor. Task details' "Runs with", `orbit status` and dispatch now read
  one resolution.
- **The needs-you bar can be swiped away.** On iOS and Android, an upward swipe dismisses the floating
  needs-you capsule. While it is dismissed, the menu icon shows how many items are waiting. A conversation
  that starts waiting again later brings the bar back.
- **Projects:** a reworked task's landing is carried again and reads off main until it is.

## Upgrade impact

- **Database migrations:** `0670_session_opened_by` adds `session.opened_by` (`TEXT NOT NULL DEFAULT
  'PERSON'`) with a CHECK added `NOT VALID` and then validated. The constant default makes it catalog-only,
  and the apiserver applies it on boot.
- **Runners update themselves.** `0.1.261-beta.6` orders above `0.1.261-beta.5`, so runners self-update
  from `/dl`, and a busy runner waits until it is idle. `orbit status` prints each workspace's "Runs with"
  only on an updated runner.
- **Configuration.** No changes required.
- **Clients.** macOS users who enabled "Receive beta updates" get this build. iOS ships to TestFlight
  (marketing version 0.1.261, build number = commit count). Android offers the APK to every install via
  `android-update.json`.

## Security fixes

None in this release.

## Known limitations

- On Android, the subtraction of the floating bar's height when bringing a waiting card into view has no
  test of its own. It matters only when other cards sit above the waiting card.
- The known limitations of [0.1.261-beta.5](0.1.261-beta.5.md) still apply.

## Rollback

Roll back to 0.1.261-beta.5. The one migration adds a column with a constant default, so an
application-only rollback is safe, and older code ignores the column. Runners do not move back by
themselves: roll them back with the `/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
