# Orbit 0.1.261-beta.54

## Summary

This release puts a **`workflow` tool in the runner**: one JavaScript script that runs many SubAgents and wakes the
parent session once, with concurrency shared with SubAgents and its default raised from 4 to 8. A session's **first
seven task creates need no owner card**, a **read-only remote SubAgent now runs in place on a workspace that is not a
git repository**, and the **session list is planned once per connection instead of on every call**, with an index for
the Open view. Two database migrations, both additive; the managed-runner and web images now end and retry a download
that stops moving. No Android or Apple product source changes in this range — Android's APK differs from beta.53 only
in its version lines.

- **A script that runs many SubAgents (runner, server).** A `workflow` MCP tool hands the runner a JavaScript script
  (goja) whose `agent()`, `parallel()`, `pipeline()`, `phase()` and `log()` calls run SubAgents on the delegate path
  (`e3a80bee2d`). The workflow runs in the background and wakes the parent once, with
  `<orbit-workflow-finished>`; its calls owe no wake of their own. Calls wait on `SUBAGENT_LIMIT_REACHED`, and
  stop, announce and park cover workflows as they do turns; each call is drawn as a delegate block nested under the
  workflow call. On the server: migration `1180_subagent_workflow`, `POST`/`PATCH /runner/sessions/:id/workflows`,
  the workflow wake, takeover and sweep. `maxCostUsd` is optional and there is no default limit; a workflow stops at
  1,000 calls. The design and its owner decisions landed first (`ef2a59c425`).
- **A session's first seven task creates need no owner card (server, runner).** A `task_create` or
  `task_create_batch` card is written already answered while the session's created tasks, counted with the card's
  own, stay under 8; the card that would reach 8 and every one after is asked as before. A session narrower than the
  account default is still asked, because what it files runs in that default. DAG changes are unchanged. On
  production over the last 30 days this skips 329 of 405 person-answered create cards, and 4 of the 6 refusals in
  that window fall under it (2 were test cards) (`622a621d08`). The runner's primer moves to **1.4.2**: its cards
  paragraph says "(not for a session's first 7 tasks)", and `task_create` / `task_create_batch`, over MCP and the
  CLI, say when the card is answered at once and when the person is asked. Two phrases in that paragraph were
  shortened to keep the primer inside its 3,200-byte budget, and the snapshots, the generated Agent Tools guide
  (docs, web, macOS), the operation catalogue doc and the contract's `primerVersion` are regenerated
  (`7fa954bb4a`).
- **A read-only remote SubAgent runs in place on a non-git workspace (server, runner).** A delegate call to a
  workspace whose work dir is not a git repository was refused outright (`SUBAGENT_WORKSPACE_NOT_GIT`), even for a
  read-only check, and the refusal led agents to suggest `git init` in someone else's directory. A read-only call
  (`explore`, or `readonly: true`) is now placed there in place, and its claim carries `inPlace`; the target runner
  must declare `subagent-remote-in-place/v1`, else `SUBAGENT_WORKSPACE_LACKS_NEEDS` up front. The runner runs the
  child read-only in the work dir, makes no worktree, records an empty tree so recovery and GC never remove the work
  dir, and refuses a resume across a git/non-git change. A call that may edit is still refused, now naming the
  read-only route and a session there, and warning off `git init` — it changes the directory and commits whatever it
  holds, secrets included. The owner's 2026-11-19 decision and its limits are in `docs/subagent-design.md` §10.2
  (`5555deeac8`).
- **A stored SubAgent reason names a fallback's own tier (server).** When the router's pick cannot start where a
  SubAgent runs and one further down runs instead, the stored reasons named only the router's pick. Each fallback now
  records its own tier, and `appliedDecision` adds the same "nearest tier above / untiered / below" line the router
  gives its own pick; attempts do not carry the tier. Policy version `p4-every-provider-2` (`57657a0328`).
- **The session list is planned once per connection (server; web, Apple and Android draw what is served).**
  `listRows`' statement (~34 KB) opts into `PREPARED_STATEMENT`, so PostgreSQL reuses its generic plan instead of
  planning it on every call. Measured on production (2026-11-19), custom against generic plan, same rows by
  checksum: unpaged open list planning ~19 ms → 0.12 ms; one workspace `LIMIT 50` planning ~20 ms → 0.13 ms; one
  project `LIMIT 50` planning ~22 ms → 0.16 ms, execution 5.5 → 3.7 ms (`3830181e11`).
- **A queued row's gate is computed only for a queued row (server).** The queue-reason lateral in `listRows` was
  joined on `s.status = 'PENDING' AND s.cancel_requested_at IS NULL`; the planner flattened it and evaluated every
  gate for every row, then dropped all but the PENDING ones. The condition now sits inside it, behind `OFFSET 0`.
  Measured on production (2026-11-19), same rows by checksum: open list unpaged 153,907 → 27,877 buffers, 297 → 110
  ms; one workspace's column `LIMIT 50` 108,230 → 9,138 buffers, 162 → 58 ms. Migration `1170` adds
  `session_open_list_owner_idx`, the Open view's own predicate over `owner_id`, turning its sequential scan of all
  4,231 pages for ~1,300 open rows into an index scan (unpaged list 110 → 85 ms, measured in a rolled-back
  transaction) (`66124c0338`).
- **A download that stops moving is ended and retried (managed-runner image, web image).** The managed runner
  image's three engine downloads (Kimi Code, Antigravity, Cursor) and the web image's rcodesign download had no
  connect timeout, no stall detection and no retry: on 2026-11-19 the release build sat 18 minutes at 81.7 MB of the
  Kimi binary on a dead connection until the curl was killed by hand. They now run with `--connect-timeout 30`,
  `--speed-limit 4096 --speed-time 60` (a stall) and `--retry 5 --retry-delay 10 --retry-all-errors`, with no total
  `--max-time`, so a slow download that is still moving finishes. The image's three engines share one `FETCH`
  argument (`5638055cd0`).
- **Per client.** Web's only source change in this range is the regenerated `agentToolsGuide.generated.json` (the
  guide now names primer 1.4.2), so nothing else in the web app changes; it also gets the faster session list and
  the card-free first creates as the server serves them. Apple's only change is the same regenerated
  `AgentToolsGuide.generated.swift` in OrbitKit; macOS and iOS are otherwise unchanged in source and draw the above
  as served. **Android has no source change in this range**: beta.54's APK differs from beta.53's only in the version
  lines this release commit writes. The workspace's concurrent SubAgent limit also rises for the owner: default 4 → 8,
  and existing workspaces at 4 are set to 8.
- **Docs.** The workflow design and its mock board (`ef2a59c425`), a board for the browser's agent tools (sign-in
  request, status, open, clear; owner decisions 2026-11-19, `4ce6037da7`), and a test that argues
  `past-create-allowance`'s exclusion from the db write inventory (`e30b43b0ef`).

## Upgrade impact

- **Database migrations: two, both additive.** The apiserver applies them on boot. `1170_session_open_list_owner_idx`
  creates a partial index on `session(owner_id)`; it writes no row and every statement in it can run twice. It is not
  `CONCURRENTLY` — Prisma runs the migration in a transaction — so it holds a SHARE lock for one pass over a 33 MB
  table. `1180_subagent_workflow` creates the `subagent_workflow_run` table, adds four nullable columns to
  `subagent_run` with a foreign key and indexes, changes `workspace.subagents_max_running`'s default from 4 to 8, and
  sets existing workspaces at 4 to 8. Neither migration drops or rewrites anything. `1180`'s table and columns are new,
  so an older apiserver neither reads nor writes them; the rows `1180` updates are data, and stay 8.
- **Configuration: no new switch.** The one change an operator sees is the workspace concurrent SubAgent limit: the
  default is now 8, and any workspace stored at 4 — including one set to 4 on purpose — is raised to 8 by `1180`.
  Nothing in `.env` or Compose changes.
- **Runner:** `src/runner-go/` carries the `workflow` tool, primer 1.4.2 and its tool descriptions, and the in-place
  read-only claim path, so a runner from this tag is needed for those; a runner without
  `subagent-remote-in-place/v1` is never given an in-place run. The managed-runner image's engine versions are
  unchanged in this range (still Claude Code 2.1.328, Antigravity CLI 1.5.12, Kimi 2.6.3, Cursor `2026.10.14-941492e`,
  opencode 1.19.6); only how its downloads are fetched changes. **The runner served at `/dl` is built from this tag.**
- **Server:** the workflow endpoints and migration `1180`, the create allowance, the fallback reasons
  (`p4-every-provider-2`), the prepared session-list statement and migration `1170` are apiserver changes; each
  reaches an instance only when it is upgraded from this source, and tagging does not deploy the server. The web
  changes reach browser users when the deployment's web is rebuilt from this source; the tag does not deploy the web
  app.
- **Clients:** macOS beta users get the DMG on the beta channel. TestFlight gets marketing version 0.1.261, with the
  build number as the commit count. Android gets `versionName` 0.1.261-beta.54 and `android-update.json` from this
  tag. No one-time step is required on a Mac, iPhone or Android device.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE, and the root
`package.json` and `package-lock.json` do not change in this range at all — the release commit writes only their
version lines. The in-place read-only route (`5555deeac8`) is a new way to run an existing read-only SubAgent, not a
fix for an exposure: it still refuses a call that may edit, and the refusal now names the read-only route and a
session instead of leaving the agent to try `git init`.

## Known limitations

- **The macOS DMG container is not codesigned.** It is notarised and stapled, so Gatekeeper accepts the app, but
  `spctl` reports the `.dmg` itself as having no usable signature. This predates this release.
- **A workflow has no cost cap by default.** `maxCostUsd` is optional and applies only when the parent model gives
  it; without one the workflow is visible in spending but does not stop on cost. The only backstop is 1,000
  `agent()` calls per workflow, and the calls share the workspace's `subagentsMaxRunning` limit with ordinary
  SubAgents.
- **An in-place read-only SubAgent is read-only only in its edit tools.** The Claude child keeps the parent's Bash
  mode, so what its shell writes is not discarded, and Codex's read-only sandbox has no network — a database or
  network check needs Claude there. A resume is refused when the work dir's git status changed between runs.
  A remote SubAgent, as before, sees the target workspace's own HEAD and returns text only.
- **The browser is one per managed runner, for two viewers at most**, unchanged from v0.1.261-beta.53. A session
  other than the lease holder is told which session holds it, and a third viewer of the same runner is refused. A
  self-hosted runner is never offered the browser.

## Rollback

The previous tag is v0.1.261-beta.53, commit `1fd77f36b033dd5a6a5ddf39dee718a1b2331d29` (its tag object is
`420f824c721d38b012cee4b39f46be7c1ad9fc25`), which was published as a GitHub Release on 2026-11-19. Rolling back
removes the `workflow` tool, the card-free first seven task creates and primer 1.4.2, the in-place read-only remote
SubAgent, the fallback tier reasons, the prepared session-list statement and the queued-row gate fix, and the
download stall retry in the two images.

An application-only rollback to beta.53 is schema-safe, because both migrations in this range are additive: the
`subagent_workflow_run` table and the four nullable `subagent_run` columns are new, and an older apiserver neither
reads nor writes them; `session_open_list_owner_idx` is a new index it does not know about and does not need. What a
rollback does not undo is the data `1180` changed: workspaces set to 8 keep 8, and beta.53 reads and enforces that
value, so they run up to 8 SubAgents at once. No backup or restore step is needed. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
