# Orbit 0.1.261-beta.12

## Summary

The work merged since [0.1.261-beta.11](0.1.261-beta.11.md), on the beta channel.

- **iOS: the session list's section titles scroll away with their rows.** Today, Yesterday, Pinned, tag and
  search titles no longer pin under the title bar on a glass band of their own; the only glass at the top is the
  title area's soft edge, which the rows pass under. A folder's page does the same. The Mac is unchanged.
- **Owner cards name an unreachable coordinator.** When the coordinator can't take messages, an escalated
  item's heading and its push say "Now yours — the coordinator can’t take messages", and the card offers only
  the actions it can carry out (web, iOS, macOS, Android).
- **Android: more pushes.** Crossing requests, coordinator confirmation raises and schedule alerts arrive as
  notifications, each checked against the server before it shows so a decided request leaves no stale one.
  The session setting "When a turn finishes" is now "When the session finishes".
- **New wiki… leaves the drawers and sidebars** (iOS, macOS, Android, web); the wiki head is a menu.
- **Runner:** a relative link in a reply now finds a file the session saved in its uploads directory, and a
  link found nowhere says "Not attached: … does not exist". A runner in a container reports the container's
  CPU, memory and volume rather than the host's.
- **Managed runners:** the managed runner image bundles every supported engine; a hosted runner left on a
  previous image rolls onto the profile's image once idle, and the two-stage upgrade builds that image and
  points the profile at it.
- **Smaller fixes:** the Apple clients' Max Concurrent dialog copy follows the web's; the web's bilingual
  "sent to agent" footer shows only on hover; Back to Orbit fills its settings nav row.

## Upgrade impact

- **Database migrations.** `0870_managed_runner_image_roll` adds one nullable column,
  `managed_runner.image_roll_to`, with no default. Additive; the running release neither reads nor writes it.
- **Runners.** Runners on the beta channel move to 0.1.261-beta.12 once the server is deployed after this tag
  (`/dl` serves the newest tag at deploy time). This release changes the runner (attachment links, container
  resource reporting).
- **Configuration.** No changes required. Deployments with a registry that run managed runners on Kubernetes
  now also build and push `orbit-managed-runner` in the two-stage upgrade, when its inputs changed.
- **Clients.** macOS users who enabled "Receive beta updates" get this build. iOS ships to TestFlight
  (marketing version 0.1.261, build number = commit count). Android offers the APK to every install via
  `android-update.json`.

## Security fixes

None in this release.

## Known limitations

- Android has no Scheduled page yet; schedules are created and read on web, iOS and macOS.
- The iOS section-title change was checked by source-wiring tests only; it had not been looked at on a
  simulator or device before this build.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.12` and tag `v0.1.261-beta.12`. This tag publishes the
macOS DMG and Sparkle payload (beta channel), the iOS TestFlight build, the runner binaries, and
`orbit-android-0.1.261-beta.12.apk` with its `.sha256` and `android-update.json` on the same GitHub Release.

Main's client workflow passed on `6a5b102a8`, which carries every client change in this release; its Xcode jobs
do not run on pushes, so the release run's `dmg` and `testflight` jobs are the first Xcode builds of the iOS
section-title change.

## Rollback

Roll back to 0.1.261-beta.11. Migration 0870 only adds a nullable column that beta.11 does not read, so an
application-only rollback is schema-safe. Runners do not move back by themselves: roll them back with the
`/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
