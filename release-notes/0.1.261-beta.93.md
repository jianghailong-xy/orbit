# Orbit 0.1.261-beta.93

## Summary

- **Web: an agent's `documents_sync` call is drawn as its sync's card in the conversation.** The card shows the same live progress as the Documents tray, and keeps updating after the agent's turn ends because the sync runs in the background; a sync that ends cleanly folds to one line, while one that fails, is stopped or finishes with failures stays open. A board of the card is in `docs/mocks/documents-sync-card`.

- **Runner: `documents_sync` names its sync in the call's answer.** The runner opens the sync's record before starting the job and hands the job its id, so the conversation can draw the call as that sync's card; a job that fails to start ends the record as `FAILED`. A runner from before this release returns no `syncId`, and its call stays a plain tool line.

- **Server: one Documents sync can be read by id.** `GET /api/documents/syncs/:id`, and its `/api/drive/syncs/:id` form, returns a sync whatever its age, past the tray's 24-hour list, so an old call's card still finds its sync; another account's sync is not found.

- **Web: a finished transfer stays a card, and a receipt's size and link are read.** The owner read the finished card folding to one line as the card disappearing, so a finished run now stays a card with its green bar, totals and file list, hidden only by Hide files. Runners answer `documents_put` with a receipt whose own answer is under `entity`, which the card did not read: every finished row showed no size and Show in Files never appeared.

- **macOS: the Documents page.** The Mac app gains a Documents row under Wiki, shown unless the server says `documents.enabled` is false, with Trash and Storage under it: a Finder-like list with inspector and previews, uploads by toolbar, Cmd-U and Finder drop, rename on Return, move by sheet or drag onto a folder, the Share Link sheet with the secret warning, and the toolbar progress ring with the agents' syncs. Shared OrbitKit code holds the drive's routes and the web's reading rules — entries, versions, Trash, share checks and links, usage and syncs; the capability switch; sizes, dates, who wrote a file, previews, and the Trash, Storage and popover copy — plus an upload queue that resumes from what the server holds, also after a relaunch. Follow-up commits fit the four list columns so Size and Modified are not cut off, wrap sheet sentences, size the uploads popover, replace Storage's tuple key paths with a small struct, and make the download destination and the Finder reveal model properties (Downloads, on by default) so a harness on the Mac runner can download without touching the owner's folders.

- **Docs: a board for the Documents sync card.** The owner found no sign of a running sync in the conversation, only in the Documents tray; the board draws a live sync card at the call that outlives the turn.

## Upgrade impact

- **Migrations:** none. The diff from v0.1.261-beta.92 to this release touches no file under `src/apiserver/prisma/migrations/`: no table, column, index or function is added, altered or backfilled, and there is no schema change to apply.
- **Configuration:** no new or changed environment variable. The macOS Documents row follows the existing `documents.enabled` capability and is hidden when the server reports it false.
- **Server:** nothing to apply beyond the new apiserver. There is no backfill and no one-time database step.
- **Runners:** the runner served at `/dl` is built from this tag and returns `syncId` from `documents_sync`. A runner older than this release keeps working against the new server; its `documents_sync` call simply stays a plain tool line. The conversation sync card needs this release's runner, for the `syncId` in the call's answer, and this release's server, for the read by id; web and server are one deploy, so they arrive together. Orbit Cloud runners get the change from the `orbit-cloud-runner:0.1.261-beta.93` image, built from this tag.
- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. The macOS app takes the new Documents page; iOS and Android take no user-visible change in this release. No one-time step on a Mac, iPhone or Android device.

## Security fixes

None in this release.

## Known limitations

- The conversation's Documents sync card needs this release's runner: a runner from before it returns no `syncId`, so its `documents_sync` call is drawn as a plain tool line.
- Documents ships on macOS only in this release. iOS and Android have no Documents screen and no Documents row; the native boards describe all three platforms, but only the Mac page is implemented.

## Rollback

Previous tag v0.1.261-beta.92 (`63ce16fb19`). Application-only rollback is **schema-safe**: this release contains no database migration, so there is nothing the previous release would fail to read and nothing to undo; the previous apiserver and web run against the same schema. On a rolled-back deployment the sync card, the by-id route and the finished-transfer card change are gone, as with any code rollback.

Client rollback is to the last published builds, v0.1.261-beta.92's DMG, TestFlight build and `orbit-android-0.1.261-beta.92.apk`; a Mac app from v0.1.261-beta.92 has no Documents page.
