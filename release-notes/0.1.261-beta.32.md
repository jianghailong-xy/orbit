# Orbit 0.1.261-beta.32

## Summary

A small fix release on top of v0.1.261-beta.31: the composer's folded band stops widening the conversation, and
three tests that were red on main are brought up to the code they guard. No server, runner, web or Android
behaviour changes.

- **The folded band's pill gives way instead of widening the page.** On the iPhone (iOS 26, where the composer band
  folds to one pill while you read back through a conversation), a long landing chip ("Merged → scratch/…") sat under a row-wide `.fixedSize()`, so the pill grew wider
  than the screen, the band under it widened, and the whole conversation slid sideways for as long as the band
  stayed folded. Each count now holds its own size, and the landing chip truncates at its tail.
- **Three reds on main, with the code they guard unchanged.** The commits only move expectations to behaviour
  already shipped in v0.1.261-beta.31: the Projects tool family is counted at 20 tools because `project_ruling_record`
  (a069d8ff5) is one; a read-only Claude SubAgent is expected to keep its parent's mode and its read-only flag
  rather than run in plan, since 9f64a96f5 keeps it read-only by withholding its edit tools; and the census of
  readers of the project criterion derivation now names the successor coordinator's state digest (a5a5c1c03), a
  reader that renders met / not met text and writes and refuses nothing.

## Upgrade impact

- **Database migrations:** none. The diff between v0.1.261-beta.31 and this tag under
  `src/apiserver/prisma/migrations/` is empty.
- **Configuration:** nothing to change.
- **Server:** nothing to redeploy for behaviour; the only apiserver changes between the two tags are two test
  files (`project-criterion-satisfaction.pg.spec.ts` and `subagent-approvals.pg.spec.ts`).
- **Runner:** the runner served at `/dl` is built from this tag. Its source is unchanged between
  v0.1.261-beta.31 and this tag, so a runner on that version needs no update.
- **Clients:** web and Android carry nothing new in this release. macOS and iOS carry the folded-band fix: it is
  `src/macos/OrbitApp/Sources/OrbitApp/Views/Console/FoldedBandBar.swift`, part of the SwiftUI shell the iOS
  target compiles, and the commit is filed as `fix(ios)`. Each client builds from this tag: macOS beta users,
  TestFlight (marketing version 0.1.261, build number = commit count) and Android via `android-update.json` are
  offered it.

## Security fixes

None in this release.

## Known limitations

- The band's landing chip now truncates at its tail, so a long target ("Merged → scratch/…") is cut in the folded
  band; unfolding the band shows it in full.
- The limitations v0.1.261-beta.31 named still stand, since nothing they touch changed in this release: help is
  web-only on all clients, and Ask runs on Claude only, on a machine whose runner declares `help-ask/v1`.

## Artifacts and verification

The tag is v0.1.261-beta.32, and this file is in the release commit's tree. The release publishes the macOS DMG
and Sparkle appcast (beta channel), an iOS TestFlight build and the Android APK with its `.sha256` and
`android-update.json` on the same GitHub Release, all from this tag; the runner served at `/dl` is built from it
too.

The fix commit records no check run, but the session that made it ran two before it landed:
`ComposerBandFoldWiringTests` on Linux (swift:6.1, 9 tests including the new
`testTheMarksRowGivesWayInsteadOfWideningThePill`, 0 failures), and client.yml run 44047000259 on the fix commit,
where "iOS (generate + build)" passed; that run's macOS job stopped at `AgentToolsTests`' Projects count, the red
the next commit below fixes. Nobody has seen the fix on a phone yet; the macOS test commit changes the Projects count in
`AgentToolsTests` and records only that Swift core was red on `'Projects 19'`; and the apiserver test commit
updates its two pg specs without recording a run against PostgreSQL. Beyond these, verification rests on
release.yml's identity gate and its macOS, iOS and Android build jobs; no release run is recorded in these
commits.

## Rollback

The previous tag is v0.1.261-beta.31, commit 7575f565b. This release adds no migration — the diff between the two
tags is one product file and four test files — so an application-only rollback to v0.1.261-beta.31 is schema-safe,

band bug on the phone. See
