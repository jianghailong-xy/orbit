# Orbit 0.1.261-beta.2

## Summary

The work merged since [0.1.261-beta.1](0.1.261-beta.1.md), on the beta channel. The headline is
**SubAgent**: a session can hand a piece of work to a routed child agent with the `delegate` tool. The
child works in the parent's own worktree, and its steps show nested and folded under the call in the
transcript. Orbit picks its engine, provider and model by tier and the agent's Optimize For setting
(Cost by default) across every enabled provider, and moves it to the next candidate on a quota or
capacity failure. A background SubAgent keeps its parent Running and wakes it when it ends. A SubAgent
can also run on another workspace of the same repository, chosen by name or by required runner
capabilities (for example `os:darwin`). It runs there in a temporary worktree of that workspace's own
HEAD and returns text only. Agents' settings can turn SubAgents off, change Optimize For, block
providers and cap how many run at once; the Providers page shows a Tier per model. The design is in
`docs/subagent-design.md`.

Also in this beta: main-checkout Git can discard files and commit without a message box; a request to
take a task out of its project reaches the owner; the update pill says it is restarting once Update Now
is taken; and session settings.

This beta exists so that runners pick up SubAgent: the server side is already deployed, but 0.1.261-beta.1
was tagged before SubAgent merged, so its runners have no `delegate` tool.

## Upgrade impact

- **Runners.** Runners on the beta channel move to 0.1.261-beta.2 and gain the `delegate` tool and the
  remote SubAgent mode. A runner still on 0.1.261-beta.1 keeps working; its sessions simply have no
  `delegate` tool.
- **Clients.** macOS users who enabled "Receive beta updates" get this build. iOS ships to TestFlight
  (marketing 0.1.261, build number = commit count). Android offers the APK to every install via
  `android-update.json`.
- **Database migrations.** Added since 0.1.261-beta.1: `0524_subagent_run`,
  `0526_model_provider_model_tiers`, `0527_subagent_run_wake`, `0528_approval_subagent_run`,
  `0642_subagent_run_remote`, `0700_session_settings` and `0770_main_checkout_discard`. They add tables
  and nullable columns only, and are applied by the apiserver on boot.
- **Configuration.** No changes required. SubAgents are on by default; an agent's settings can turn them
  off.

## Security fixes

None in this release.

## Known limitations

- On iOS and Android the SubAgent block's "Why" line still shows the raw routing reasons rather than
  web's one-line summary (follow-up task in progress).
- A Codex account pool cannot yet be a SubAgent's routed pick or fallback target (follow-up task in
  progress); Claude account pools can.
- The known limitations of [0.1.261-beta.1](0.1.261-beta.1.md) still apply.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.2` and tag `v0.1.261-beta.2`; `release.yml`'s
identity job refuses a tag whose name and package version disagree or whose notes are missing. This tag
publishes the macOS DMG and Sparkle payload (beta channel), the iOS TestFlight build, the runner
reference binaries, and `orbit-android-0.1.261-beta.2.apk` with its `.sha256` and
`android-update.json` on the same GitHub Release. SubAgent was gated by its project's tasks: runner-go,
apiserver unit and pg specs, web Vitest, and an HPC-to-Mac end-to-end run on a staging stack.

## Rollback

Roll back to 0.1.261-beta.1. The migrations above only add tables and nullable columns, so an
application-only rollback is safe; the new tables are simply unused. Runners do not move back by
themselves: roll them back with the `/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
