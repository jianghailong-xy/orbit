# Orbit 0.1.261-beta.88

## Summary

- **This release also carries 0.1.261-beta.87's changes for macOS and Android.** v0.1.261-beta.87 published no GitHub Release: its Android lint check failed on a test (`StateFlowValueCalledInComposition`), fixed in `851ff7b3d2`. For macOS and Android this release therefore also carries beta.87's changes, which `release-notes/0.1.261-beta.87.md` lists.

- **A landing into a protected `main` goes through a pull request when GitHub refuses the direct push (server, runner and web).** GitHub refuses the App's push on a branch whose rules require a pull request (GH006, GH013). Orbit now pushes the same tested commit to its own branch, `orbit/land/<id>`, and opens and merges a pull request once GitHub's checks and reviews allow. The wait is one new state of the integration job, `PULL_REQUEST`, and the pull request is a row of its own (`github_pull_request`). A failing GitHub check ends the landing `CHECK_FAILED` with the check and its Actions log and hands the task a fix turn naming the pull request; a target that moved is caught up through the next generation (catch-ups are not counted, a refused merge is); a closed pull request or a foreign head ends it `ERROR` with an item; the owner is told once when a pull request waits for a review (migration 1547). The task row, the project's in-flight jobs and the landing view carry the pull request, and a task whose landing waits on one reads as running. A session's own Merge lands the same way and its detail carries `mergePullRequest`.

- **Push as me is the opt-in faster way past a protected branch (server, runner and web).** A workspace cloned from GitHub can take Push as me from its signed-in owner. Orbit then pushes the target with the owner's own GitHub token on a runner that declares `push-as-me/v1`, and reports whether the push went as the owner and which rules GitHub said it bypassed. The token is answered once per landing generation or merge operation, past the push boundary; the server refreshes the owner's connection and revokes that token once the push reports back, never the grant. A protected refusal, a token GitHub refuses, or one Orbit will not hand out falls back to the pull request, and the workspace keeps the last refusal until a Push as me landing is accepted.

- **Web: each workspace gets a Landing section, and the landing card draws the pull request states.** The section offers Pull request default and Push as me faster; the card draws the pull request states with the Faster tip and the fallback notice, and a failed GitHub check gets its own label ("Pull request open" is the new state's). An attempt held on its pull request reads as waiting for GitHub rather than stopped, the Faster tip hides when the workspace is on Push as me and links to its Landing section, the board notices when the installation has not accepted the pull request permissions, the pull request block names its workspace, and the Landings window draws the pull request states.

- **Account health: an account that refuses runs is blocked, demoted and skipped (server and runner).** Runners now classify a failed turn (usage limit, capacity, account action required, credential refused, access denied, transport, request refused), and Orbit keeps one `account_health` row per account and model: a classified refusal blocks it for 1 hour to 24 hours, the breaker does the same for 30 minutes to 24 hours, a capacity refusal cools it down for five minutes, and one run tests it at the end of a block. The router leaves a blocked account out (keys included) with the provider's words and ranks a suspect one last; an account's refusal no longer counts toward tier escalation or the auto-run budget; when nothing can run, the task is held until the first trial is due. A run refused at admission is replaced at once, at most three an hour, and Automatic account choice, Claude pool members and Codex pool logins skip a blocked account. A SubAgent moves on an account's refusal; a named model still does not move.

- **A pin on a blocked account holds, or relaxes behind the new `relaxBlockedPins` setting (server, web, Apple and Android).** Off by default: a pinned task holds with the pin named and the setting linked, and web places the pinned-tasks setting below Optimize For. On: the pin relaxes provider first, then engine, at the same tier; a model pin only onto the same model, and never onto a provider the owner blocked. Routing policy version 4.

- **Every client draws a blocked account and offers Check again.** Web, macOS and iOS, and Android draw the account line — the provider's words, the next trial and Check again (`POST /account-health/:id/check`) — on a runner's account row and on blocked keys, Claude pool members and Codex pool logins; a key's or pool block's push opens Providers. A held task shows the reason as one quiet line under its title and in the task view (with Open account, and Run elsewhere on Apple and Android), a relaxed run says where it went, and a project's open items group held tasks under one Needs you row. An `account-needs-action` push fires on a refusal's first occurrence and the breaker's third trip and opens the runner; Android lists and parses it and drops it once the block clears.

- **Sign out… on a runner's Default account (web, macOS and Android).** The account menu offers Sign out… when Default is signed in and the runner declares `<engine>-default-sign-out/v1`; it confirms first, and asks again resending with force when the runner refuses because sessions are running on Default. `POST /runners/:id/accounts/:engine/default/sign-out` hands the request to the runner on the heartbeat. A sign-out deletes only Default's login credential (Claude's credentials file and Keychain item, codex and kimi logout, Cursor's `auth.json`, antigravity's token) and keeps Default's name and the sessions it names where they are. The removal's "can't be removed" panel stays off a sign-out refusal.

- **A multi-part run question can now be answered.** `session_reply` dropped the answers from the request, so every reply to a run question with more than one part was refused; it now forwards them.

- **Server and runner.** New routes: `GET /account-health`, `POST /account-health/:id/check`, `POST /runners/:id/accounts/:engine/default/sign-out`, the public `POST /api/integrations/github/webhook`, and the session detail's `mergePullRequest`. A session row now stores the runner's failure kind, its scope, the provider's words, whether the failure was at admission, and what account health did with the run (`account_health_effect`); a run with that effect is not counted for escalation or the auto-run budget. A refused run is replaced only once its release has freed the task. A session merge through a pull request records its receipt as `SERVER`. The runner declares `push-as-me/v1`, `integration-pull-request/v1`, `session-merge-pull-request/v1` and `<engine>-default-sign-out/v1` for its five engines, withholds `ORBIT_GIT_CREDENTIAL` from every agent environment, and pushes the landing branch when GitHub refuses a protected target. The GitHub App's admin read answers `webhookUrl`, `webhookSecretSaved` and `lastDeliveryAt`.

## Upgrade impact

- **Migrations:** six, all additive — none drops or renames a table or column, none adds a `NOT NULL` column without a default, and none rewrites a stored row.
  1. `1492_runner_account_sign_out` — adds `runner.account_remove_action` (nullable text) and `runner.account_remove_force` (`NOT NULL DEFAULT false`). Catalog-only: no stored row is rewritten.
  2. `1493_session_failure_kind` — adds four nullable `session` columns (`failure_kind`, `failure_scope`, `failure_said`, `admission_failure`) with no default and no backfill; a run without them keeps reading through the legacy text markers.
  3. `1494_account_health` — a new table, `account_health`, with its cascading foreign keys, CHECK constraints and indexes. Nothing existing is touched.
  4. `1495_session_account_health_effect` — one nullable `session` column plus a CHECK constraint on it. It adds a constraint, but every existing row is NULL and passes.
  5. `1527_pull_request_landing` — the largest: new nullable columns on `workspace`, `project_integration_job` and `session`; `github_app_config.webhook_secret_enc` (`NOT NULL DEFAULT ''`); two new tables, `github_pull_request` and `github_webhook_delivery`; and re-created CHECK constraints, two unique index definitions and the terminal-guard trigger function, all widened to admit the new `PULL_REQUEST` state. Every constraint and index it drops is re-created to admit everything it admitted before. It takes `ACCESS EXCLUSIVE` locks on six hot tables in 1-second tries (up to 40) so a busy server queues for about a second at a time rather than for the migration's length.
  6. `1547_pull_request_review_announced` — one nullable column, `github_pull_request.review_announced_at`.
- **GitHub App:** pull-request landing and Push as me need the installation to accept the App's added permissions (Pull requests, Checks, Commit statuses, Actions, Workflows) and the App's webhook configured; the URL, secret and events are in `docs/design/protected-branch-landing.md`, Appendices B and C, and the admin read answers whether the secret is saved and when GitHub last delivered. Until the installation has them, a landing pushes directly exactly as before.
- **Server:** the first boot applies the six migrations. There is no configuration change and no backfill; account health starts learning from failures as they happen, and the first block can appear on any client that reads it.
- **Runners:** the runner served at `/dl` is built from this tag and adds the failure kinds, pull-request landing and session-merge capabilities, Push as me and Default sign-out. Orbit Cloud runners get it from the `orbit-cloud-runner:0.1.261-beta.88` image, built from this tag. An older runner keeps working: its failures are read through the legacy text markers, it answers `PUSH_PROTECTED` instead of pushing a landing branch, and the clients hide Push as me and Sign out… until it declares the capability.
- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. The account-health lines, the held-task lines, the relaxed-run sentence and Sign out… need this release's clients; an older one simply does not draw them. No one-time step on a Mac, iPhone or Android device.

## Security fixes

No security issue fixed here affects an earlier release. Two token-hygiene changes ship with Push as me, which this release introduces:

- **The Push as me token never reaches an agent's environment.** `ORBIT_GIT_CREDENTIAL` was kept out of engine environments only because nothing set it outside the push command; it is now a user credential environment key, so `envWithAgent` and every spawn drop it, and a test holds each environment site plus a landing's hooks and files to that. Without it, an agent running beside a Push as me landing could read the owner's GitHub token from its environment.
- **The Push as me token is revoked once the push reports back.** The server refreshes the owner's connection and then revokes the token it handed out (never the grant), so a copy read during the push stops working while the connection stays live. A refused refresh or revoke is logged and changes nothing else.

## Known limitations

- The Landing section and the pull request landing states are on web only in this release; no macOS, iOS or Android change for them is in it, so those clients' landing views are as before.
- Sign out… on a runner's Default account is on web, macOS and Android; no iOS change for it is in this release.
- With every account a task could run on blocked, the task is held until the first trial is due (at most 24 hours) unless `relaxBlockedPins` is on. The tested workarounds are turning that setting on, and clearing the block with Check again on the account row.

## Rollback

Previous tag v0.1.261-beta.87 (`f08170c41a`, the release commit after `e00011fbdb`). All six migrations are additive — no table or column is dropped or renamed, no row is rewritten, and every constraint and index `1527` re-creates admits everything it admitted before — so an application-only rollback is schema-safe; the new columns stay unread and the three new tables stay in place. A landing already waiting on its pull request is advanced by this release's pull request door, so let such landings finish or stop before rolling back. Orbit Cloud runners are pointed back at the previous tag's image by a deploy of an earlier commit, and each moves to it once idle.

Client rollback is to the last published builds: v0.1.261-beta.87 published no GitHub Release, so there is no beta.87 DMG or APK to fall back to and the previous published builds are v0.1.261-beta.86's.
