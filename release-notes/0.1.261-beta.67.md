# Orbit 0.1.261-beta.67

## Summary

This release is about the **Models and SubAgents pages' Tier column** and about **which model the router picks for a task's size**. An older member of a model family that routing never uses now reads "Older · uses `<newest>`" instead of "Not set", and five model families are tiered against a benchmark measured on 2026-11-21. It also fixes a **translation chip that kept reading "Translating…"** on iOS and web while the runner was full. The range is `v0.1.261-beta.66..origin/main` (`e285717a41`).

**Five model families are tiered from a measured benchmark.** Task 351AxJztYRw7WA2Ik86DK ran a 10-task auto-graded benchmark against the tier anchors and the owner approved its proposal on 2026-11-21 (`95c535824b`). Each entry sits after every existing rule, so no ranked pick is displaced, and is pinned to the measured model ids so the newest-member rule cannot pick an unmeasured model:
- Claude Fable: L/XL, after Opus (it passed everything, at about 1.8× Opus's cost);
- Gemini Pro Orchestrator Neon: L/XL, after Gemini;
- DeepSeek Flash: S/M;
- Grok: S/M (its L/XL runs died on Cursor transport errors);
- GPT-5.6 Sol, Terra and Luna: S/M (they pass S/M/L and miss the XL task);
- gpt-oss-120b failed every S task and stays untiered.

**An older family member reads "Older · uses `<newest>`".** A built-in engine's older model (Cursor's `claude-opus-5` beside `claude-opus-5-5`) was listed as Not set, although routing deliberately uses the newest. The tier view now carries `supersededBy` for it, and an owner's own tier clears it (`7a5090790c`).
- **Web:** the Tier cell is grey in place of the orange Not set and is still a tier button; the server sorts such rows after the tiered ones and before plain Not set (`244b6e2f37`).
- **iOS and Android:** grey in place of the orange Not set on the Swift and Kotlin tier tables, still a tier menu. Android follows iOS (`5de6e87f78`, `188939e8b6`).
- **macOS:** the Tier column is wide enough for the label; a Mac pop-up button title cannot wrap and it had been cut to "Older · us…" in 110 points (`335acc1dd2`).
- The flag is display only: no routing decision reads it.

**A held message's translation chip settles from the queue listing.** A message held for translation while the runner is full stayed in the conversation, and:
- **iOS:** `reconcileQueuedTurns` skipped its listing row as if it had been echoed, and with the runner full the echo never came, so the bubble kept reading "Translating…" after the server had translated it (`29611cf00a`);
- **web:** a local accepted bubble outranked the snapshot copy and a late send response re-applied TRANSLATING over a settled row (`c489c6803e`);
- **Android** already read the translation from each active listing; a test now pins that (`e285717a41`).

**Under the hood** (`2f2018bf7d`, `3075083b63`): the link protocol's round-trip samples now cover the `BackgroundJobTailRequest`/`Response` frames added in beta.66, public-id coverage knows the `bg_run` job routes' `jobId`, and the entry-point contract counts `SessionsService`'s eighth dependency — the remaining pre-existing reds in the Go runner and JavaScript jobs. The PostgreSQL CI shards now get 90 minutes.

## Upgrade impact

- **Database migrations:** none. No file under `src/apiserver/prisma/migrations/` changed in this range (`git diff --stat v0.1.261-beta.66 origin/main -- src/apiserver/prisma/migrations/` is empty), so there is nothing to run and no schema change to reason about.
- **Configuration:** nothing new to fill in.
- **Runner** (`src/runner-go`, built from this tag and served at `/dl`): no runner protocol change in this range. A runner from beta.66 or this tag works the same; older runners keep working.
- **Clients:**
  - *macOS:* the new Tier column on the beta channel (DMG and Sparkle appcast).
  - *iOS:* TestFlight marketing version 0.1.261, build number the commit count, with the new tier table and the translation fix.
  - *Android:* `versionName` `0.1.261-beta.67`, the next `versionCode`, and `android-update.json`, with the new tier table.
  - `supersededBy` is an optional field on the tier response, so a client that does not know it keeps reading Not set. No minimum client version is enforced, and no one-time step is needed.

## Security fixes

None in this release.

## Known limitations

- **The tiering covers what the 10-task benchmark measured.** Grok's L/XL runs died on Cursor transport errors, so it is tiered for S/M only; gpt-oss-120b failed every S task and stays untiered. A family outside the list routes as before.
- **The "Older · uses…" label reflects routing, not an owner's intent.** Setting a tier on the older model clears the label, but the flag is display only and no routing decision reads it.

## Rollback

The previous tag is v0.1.261-beta.66, commit `063ae5873e7a6e4b4599cef601c36ea4ad123dea`. A server deployed from this tag rolls back to that commit. Native clients roll back by installing beta.66's build.

An application-only rollback to beta.66 is schema-safe: this range changes no migration and, apart from the optional `supersededBy` field, no stored data.

Two behaviors do not roll back with the code:
- A beta.66 server routes without the measured tiers, so the model picks listed above return to the older rules.
- A beta.66 server omits `supersededBy`, and clients read "Not set" for those rows as before.
