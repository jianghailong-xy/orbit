# Orbit 0.1.261-beta.92

## Summary

- **Runner: Antigravity can now be signed in with Google on a macOS runner.** Measured on a Mac with agy 1.5.16, agy keeps its sign-in in the login Keychain via `/usr/bin/security` unless `SSH_CONNECTION` is set, in which case it uses the token file in the Gemini directory — so the per-account file model the Linux runner already uses carries over. The runner adds a darwin PTY for the sign-in, pins every Google-mode agy on macOS to the token file, and declares a new capability, `antigravity-google-login-macos/v1`; contract §16.12 records the measurement and the design. Linux is unchanged.

- **Server, web, Android and Apple: a Mac runner that declares the capability is offered the sign-in like a Linux one.** An older Mac runner reads `needs_update` ("Update this runner"), and `unsupported_platform` is left for operating systems other than Linux and macOS, with platform-neutral copy on web, Android and the Apple clients.

- **Web: a shared Documents file link has its own public page.** `/s/<token>` for a file link used to fall through to the session view, which crashed on the file root ("Something went wrong"). It now shows the file's name and size, a Download, and a preview of the pinned version when it is a PDF or a picture.

- **Docs: a design for an owner-applied request.** The owner request CHANGE design — an agent proposes a runner's Max Concurrent and the owner applies it — with the owner's rulings (an editable number, Max Concurrent only, applied even if the value moved since it was asked) and mock boards on all four clients. Design docs and boards only; nothing implements it in this release.

- **Docs: Documents boards for the native apps.** Mockups for bringing Documents to macOS, iOS and Android — a new Android board in Material 3 with the app's own colours, the upload tray with an agent's directory sync on iPhone and Mac, and the iPhone and Mac screens moved from "Files" to "Documents" to match the shipped web page. These are design boards only; no native Documents screen ships in this release.

## Upgrade impact

- **Migrations:** none. The diff from v0.1.261-beta.91 to this release touches no file under `src/apiserver/prisma/migrations/`: no table, column, index or function is added, altered or backfilled, and there is no schema change to apply.
- **Configuration:** no new or changed environment variable.
- **Server:** nothing to apply beyond the new apiserver. There is no backfill and no one-time database step.
- **Runners:** the runner served at `/dl` is built from this tag and declares `antigravity-google-login-macos/v1` on macOS. A Mac runner older than this release does not declare it, so the Machines & models page asks for an update ("Update this runner") before it will sign Antigravity in with Google; an older runner keeps working against the new server, and the new runner keeps working against a server from before this release. Orbit Cloud runners get the change from the `orbit-cloud-runner:0.1.261-beta.92` image, built from this tag.
- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. The Android and Apple clients take only the copy change: their "not supported on this runner's operating system" hint and the "Update this runner" one. No one-time step on a Mac, iPhone or Android device.

## Security fixes

None in this release.

## Known limitations

- Google sign-in on macOS needs this runner release: a Mac runner that does not declare `antigravity-google-login-macos/v1` reads `needs_update` until it is updated, so the sign-in is not offered on it.
- On macOS the sign-in is kept to the token file in the account's Gemini directory rather than the login Keychain, so a Google sign-in made by hand on that Mac — which agy keeps in the Keychain — is not the sign-in an Orbit session uses.
- A shared file link previews a PDF or a picture only; any other kind of file is reached through Download.
- The Documents boards for the native apps are mockups: macOS, iOS and Android still have no Documents screens in this release.

## Rollback

Previous tag v0.1.261-beta.91 (`a1bdc1f145`). Application-only rollback is **schema-safe**: this release contains no database migration, so there is nothing the previous release would fail to read and nothing to undo; the previous apiserver and web run against the same schema. On a rolled-back deployment the macOS Google sign-in served by the control plane, the platform-neutral copy and the shared file page are gone, as with any code rollback.

Client rollback is to the last published builds, v0.1.261-beta.91's DMG, TestFlight build and `orbit-android-0.1.261-beta.91.apk`.
