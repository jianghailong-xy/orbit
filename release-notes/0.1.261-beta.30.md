# Orbit 0.1.261-beta.30

## Summary

Three follow-ups from the Scheduled tasks walkthrough, on top of v0.1.261-beta.29, plus the coordinator handoff v2
work and the managed-runner fix that landed on main since.

- **Schedules: Always allow on a check-only run saves the exact command.** A CHECK_ONLY scheduled run's approval used
  to save a prefix rule such as `Bash(python3:*)`, so one approval let later check-only runs run any python3 command
  unasked. These grants now hold the exact command, are matched literally at the scheduled approval door and never
  enter the engine's allowlist; prefixes saved earlier by scheduled runs are ignored there. The card names the exact
  command on web, macOS/iOS, Android and the terminal. Other approvals are unchanged.
- **Schedules: What it does keeps what the check does.** After a rule or timezone change without a fresh read-back,
  the inspector shows the current When with the first sentence of the run's instructions, not just the title, and
  `schedule_update` asks the agent for a fresh read-back (when and what) on every such change.
- **Codex accounts: a clearer refusal.** When a session's chosen Codex account slot reports signed out and Default is
  signed in, the refusal names Default, says how to select it, and that a plain `codex login` updates Default.
- **Coordinator handoff v2.** A successor coordinator opens with a server-rendered state digest, pending waits follow
  the handoff, owner rulings are kept as project records (`project_ruling`), and the handoff confirm names each
  pending wait's kind on every client.
- **Runners list.** `GET /runners` marks the managed runner, so no client shows it as "orbit-managed" first.

## Upgrade impact

- **Database migrations:** one, `0970_project_ruling`. It creates the new table `project_ruling` and touches no
  existing table or row; `down.sql` drops it. Additive, so the apiserver and web are handed over without a gap.
- **Configuration:** nothing required.
- **Server:** serves the exact-command scheduled grants, the read-back fallback, the Codex refusal wording and the
  project rulings. Clients older than this tag still show the previous Always allow scope text on a scheduled card;
  the server saves the exact command either way.
- **Runner:** the runner served at `/dl` is built from this tag, so runners update to it and take the new
  `schedule_update` read-back wording and the terminal card's exact-command scope. A Claude process that already
  loaded a broad scheduled grant keeps it in memory until it restarts.
- **Clients:** each client builds from this tag: macOS beta users, TestFlight (marketing version 0.1.261, build number
  = commit count) and Android via `android-update.json` are offered it.

## Security fixes

- CHECK_ONLY scheduled runs no longer get a command-prefix grant from a single Always allow, which let a later
  check-only run execute any command with that prefix, including ones that write files. The grant is now the exact
  approved command, and earlier scheduled prefix grants no longer apply.

## Known limitations

- A Codex account slot whose credentials have expired but which `codex login status` still reports as signed in can
  still be chosen for a new session; only a slot reported signed out gets the new refusal. Keep a workspace pinned to
  Default if one of its slots has lapsed.
- The read-back fallback takes the first sentence of the run's instructions; an agent that passes a fresh read-back
  reads better.
- On main, `SessionProjectPageWiringTests.testTheWaitingMemberOpensAtTheTopOfItsCard` (Swift core, macOS) and two
  `ProjectMergeShellTest` cases (Android) were already failing before these commits; they are not caused by this
  release's changes and remain open.

## Artifacts and verification

The tag is v0.1.261-beta.30, and this file is in the release commit's tree. The release publishes the macOS DMG and
Sparkle appcast (beta channel), an iOS TestFlight build and the Android APK with its `.sha256` and
`android-update.json`, all from this tag; the runner served at `/dl` is built from it as well.

Checks run while the three fixes were built: schedule doors pg spec 30/30 and schedule attention pg spec 20/20 on
PostgreSQL, the touched apiserver unit specs (78, 66 and 48 tests), web `ApprovalPanel` 61/61, go vet with the
schedule, catalog, terminal approval and account tests, and Android `DshApprovalCardTest` 3/3. The OrbitKit approval
parity test was not run locally. The three commits were pushed to main without waiting for the PR's CI; that CI's
failures are the pre-existing ones under Known limitations. Beyond these, verification rests on release.yml's
identity gate and its macOS, iOS and Android build jobs.

## Rollback

The previous tag is v0.1.261-beta.29, commit 89974b914. The only migration since adds a new table, so an application
rollback to v0.1.261-beta.29 is schema-safe: the table stays in place, unread. A runner rolled back to it serves the
previous `schedule_update` wording, and a server rolled back to it saves scheduled Always allow grants as prefixes
again.
