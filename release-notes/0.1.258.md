# Orbit 0.1.258

## Summary

Everything in [0.1.257](0.1.257.md), which was prepared but never tagged or published, plus two changes.
The machine page in Settings gains a Resources section: the machine's CPU, memory and disk, with a line of
the last hour, read from the runner on every heartbeat. The Disk row moves there from Capacity. The web
app installed from Chrome on macOS gets a white tile for its icon instead of macOS's gray plate.

## Upgrade impact

- **Runners update themselves.** `0.1.258` orders above `0.1.256` and `0.1.257-beta.1`, so runners
  self-update from `/dl` as usual (a busy runner waits until it is idle). A runner reports CPU and memory
  only from this release on (capability `machine-resources/v1`); until it updates, its machine page shows
  "Update runner" in those two tiles, and Disk is read from its workspaces as before. Linux and macOS
  runners report all three figures; Windows runners report none yet.
- **Seven additive database migrations** since `v0.1.2-beta.246`, applied by the apiserver on boot: the six
  listed in the [0.1.257 notes](0.1.257.md) and `0720_runner_presence_resources`, which adds a nullable
  JSONB column to the UNLOGGED `runner_presence` table. None drops a column or rewrites existing rows.
- **New route.** `GET /api/runners/:id/resources` (owner-scoped, `runners:read`) answers the machine's
  latest reading and its last hour.
- **Deployment.** No configuration changes are required. The notes for 0.1.257 on the two-stage
  deployment and the gateway's handover include apply unchanged.
- **Clients.** No tag is cut for this version yet, so no new macOS, iOS or Android build ships with it.

## Security fixes

None in this release.

## Known limitations

- The resource history lives on `runner_presence`, which is UNLOGGED: a database crash or failover empties
  it, and each machine's page shows no reading until its next heartbeat (about 30 seconds) and no history
  older than that.
- On macOS, CPU is the sum of every process's `%CPU` from `ps` over the core count, which `ps` averages over
  a few seconds rather than exactly the 30 s between heartbeats.
- The known limitations of [0.1.257](0.1.257.md) still apply.

## Artifacts and verification

The version of record is `package.json` `0.1.258`; `/dl/version.json` names it once the server built from
this commit runs. The resources change was tested on its own branch: runner Go tests (full package, and the
new parser and disk-choice tests), the apiserver unit suite, PostgreSQL 16 specs for the column, the link
heartbeat statement and the HTTPS heartbeat and route (`runner-resources.pg.spec.ts`,
`runner-presence.pg.spec.ts`, `link-heartbeat.pg.spec.ts`), and web vitest and tsc for the machine page.
The macOS reading code compiles but its tests were not run on macOS.

## Rollback

The rollback target is the previous published release,
[`v0.1.2-beta.246`](https://github.com/jianghailong-xy/orbit/releases/tag/v0.1.2-beta.246) (package
0.1.256); 0.1.257 was never published. Record the image IDs and the source SHA you are running before
upgrading. The migrations are additive, so the previous application starts against the upgraded schema;
see the 0.1.257 notes for the rows its migrations allow. Runners do not move back by themselves: roll them
back with the `/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
