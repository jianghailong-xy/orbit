# Orbit 0.1.261-beta.9

## Summary

The work merged since [0.1.261-beta.8](0.1.261-beta.8.md), on the beta channel.

- **Agents use SubAgents to work on another agent's machine (runner).** `delegate` is now loaded up front in
  Claude Code instead of hidden behind ToolSearch, and the engine instructions, `agent_list` and
  `session_create` say to call `delegate` with `workspace` set to the other agent's name when only that piece's
  result is needed. Before this, sessions asked to read production data opened a separate session on the
  production agent every time.
- **Recovery contract.** Refusals and failures from tasks, projects, sessions and spawns carry stable codes, a
  recovery action and whether the call may have written; `project_create` and `session_create` keep a receipt
  per request id, so a retried create returns the first one instead of filing twice; `orbit capabilities`
  states retry, idempotency and interaction per command.
- **Translation.** One list of about 30 languages for both sides, an agent-language preference (no translation
  when the two are equal), both language pickers over the full list on web, Apple and Android, Show original on
  the meta row of translated messages, and a reply's translation now reaches a client that was away when it
  was written.
- **Managed runners in Machines & models** on macOS, iOS and Android: entry, confirmation and machine row; a
  managed runner that is coming up or has failed says so instead of Offline.
- **SubAgents in the web stream:** a SubAgent's finished turn is a line in the agent's stream and folds into
  the Orbit exchange; Orbit's delegated block is named Agent on web and Android, as on iOS and macOS; the
  Agents sheet on macOS and iOS shows no cost.
- **Smaller fixes:** a stepper and running count in the Max Concurrent dialog, the waiting capsule is a bare
  glyph, decision receipt cards and answered question cards are spaced like the others, and settings pages
  opened directly use an inline title.

## Upgrade impact

- **Database migrations.** One, additive: `0645_create_request_receipt` creates the table that holds create
  receipts per request id. The apiserver applies it on start.
- **Runners.** Runners on the beta channel move to 0.1.261-beta.9 (rollout 100%). The runner change is the
  delegate loading and wording above, and recovery reports carried in receipts.
- **Configuration.** No changes required.
- **Clients.** macOS users who enabled "Receive beta updates" get this build. iOS ships to TestFlight
  (marketing version 0.1.261, build number = commit count). Android offers the APK to every install via
  `android-update.json`.

## Security fixes

None in this release.

## Known limitations

- A SubAgent on another workspace runs on that workspace's last provider. If that provider is an engine
  signed out on the target runner, the SubAgent cannot start there.
- The known limitations of [0.1.261-beta.8](0.1.261-beta.8.md) still apply.

## Artifacts and verification

The release identity is `package.json` `0.1.261-beta.9` and tag `v0.1.261-beta.9`. This tag publishes the
macOS DMG and Sparkle payload (beta channel), the iOS TestFlight build, the runner binaries, and
`orbit-android-0.1.261-beta.9.apk` with its `.sha256` and `android-update.json` on the same GitHub Release.

The delegate change was checked with the full runner-go suite on HPC: every test passed except
`TestHostSetupWithoutRootExitsOne`, which fails on that host because a real
`/etc/systemd/system/orbit-runner@.service` is installed there. The other changes were checked in their own
landings.

## Rollback

Roll back to 0.1.261-beta.8. Migration `0645_create_request_receipt` only adds a table, which beta.8 does not
read, so an application-only rollback is schema-safe. Runners do not move back by themselves: roll them back
with the `/api/runner/release` pointer. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
