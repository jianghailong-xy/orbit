# Orbit 0.1.261-beta.38

## Summary

Scheduled runs stop stalling on approval cards: an OPEN_PR or LAND run on Claude Code now runs in Auto, and the
server's approval door enforces a run's access level on every engine before any workspace rule. The Update card now
keeps reading until the runner reports its restart on every client, the iPhone/iPad and Mac console shows a
still-running call from the second turn on, and a foreground delegate's session row names its work.

- **Scheduled runs (server).** An OPEN_PR or LAND run on Claude Code is now claimed in Auto, so the routine commands an
  unattended run needs (`git fetch`, `npm view`, its tests, `git commit`) no longer each wait on a card: measured
  2026-11-17, a LAND run waited 278 minutes on them and timed out with nothing landed. The level's denials still hold
  through Claude's `--disallowedTools` and the server door, and a model with no Auto runs as Default. Claude only: no
  other engine's Auto has a classifier. Interim, until per-schedule grants.
- **The approval door (server).** It now refuses a tool or command the run's access level denies, before any workspace
  rule, on every engine; a Codex `/bin/bash -lc '...'` wrapper is unwrapped first, so a workspace rule such as
  `gh pr:*` can no longer answer ALLOW for `gh pr merge` on an editing run. Always allow on a scheduled run's card no
  longer retags an identical interactive rule to `fromScheduleRun`, which took it away from the person's own sessions;
  in that duplicate case the scheduled check still asks.
- **Update Now (macOS, iOS, web, Android).** The runner answers on its next heartbeat, after the one read the press
  made, so the Update card stayed on Available until a refresh or the page's 15-30 s poll. Each client now rereads
  every 2 s for up to 30 s until the release is no longer waiting, and Android's session page does the same through one
  helper shared with its machine page.
- **The steps line (iPhone/iPad and Mac).** From the second turn on, a folded steps line still read "Ran 2 shell
  commands" while one of them was running: the stream's statuses cover a conversation's first turn only, and an earlier
  turn's `turn_end` leaves the status at awaiting input. The console now reads `isGenerating` off the session row, as
  Stop and the "Working for…" header do, falling back to the stream status until the row loads, so a still-running
  call keeps its own row under the line in every turn, not just the first.
- **Rows and the Agents band (iPhone/iPad, Mac, web, Android).** A foreground delegate's row now reads
  `Agent: <description>` rather than "Running delegate…", as a background Agent's row does. With no Agent running, the
  iPhone/iPad and Mac composer's Agents band names the newest run and how it ended — a green check, or red for failed,
  interrupted or stopped — with its duration, and VoiceOver adds "done, 50s" or "failed, 4m 12s".
- **Chat about this (iPhone/iPad, Mac, web).** A request's or owner item's chat now sends a screenshot alone, behind
  the request, instead of lighting Send and dropping it (web) or keeping Send off (macOS/iOS). A plan change still
  needs words.
- **Also.** The runner heartbeat survives a handover read that answers nothing at all, read as "none kept" like one
  that throws, and the keep-data ledger records the applied `0990` pair (f1bcd9ca7a). The scheduled-run grants design
  and its boards, and a translated owner-card board, are docs only and not user-facing.

## Upgrade impact

- **Database migrations: none in this range.** The diff of `src/apiserver/prisma/migrations/` between
  v0.1.261-beta.37 and this release is empty, so no migration is added and no schema change must be applied. The two
  `0990` migrations, `0990_runner_keep_free_default` and `0990_schedule_land`, were applied before this release and
  stay as they are: both were already on production when their shared number was seen (`schedule_land` at 2026-11-17
  08:24Z, `keep_free_default` with the 15:39Z release), so neither can be renamed. The keep-data ledger now lists
  `0990_runner_keep_free_default` with what it changes — runner's default only, no preserved relation — and the
  duplicate check exempts exactly that applied pair; any other number shared after 0246 still fails.
- **Server:** the schedule Auto, the approval door and the heartbeat fix are apiserver changes, so the apiserver must
  be deployed from this commit or later. Until then, a scheduled OPEN_PR or LAND run on Claude Code waits on cards as
  before, and a workspace rule can still answer for a wrapped command. The web client ships with the same deploy.
- **Runner:** this range changes no `src/runner-go` source, and the runner served at `/dl` is built from this tag.
- **Configuration:** none. No new variables, and no one-time step for a runner, Mac, iPhone/iPad or Android device. No
  minimum runner or native client version above the previous release is set by this range.
- **Clients:** macOS beta users get the DMG on the beta channel, TestFlight gets marketing version 0.1.261 with the
  build number as the commit count, and Android gets `android-update.json` from this tag.

## Security fixes

One approval-enforcement issue is fixed, with no advisory or CVE named.

- **A workspace rule could allow a command the run's access level denies.** The approval door now refuses such a tool
  or command before any workspace rule is consulted, on every engine, and unwraps a Codex `/bin/bash -lc '...'`
  wrapper first; before this, a rule such as `gh pr:*` could answer ALLOW for `gh pr merge` on an editing run. A server
  older than this release enforces the level only through the engine's own denials, so the wrapped command could still
  be allowed there. Nothing else in this range is a security fix.

## Known limitations

- **Auto is Claude Code's alone.** No other engine's Auto has a classifier, so an OPEN_PR or LAND run on another engine
  still waits on approval cards. Per-schedule grants (`docs/scheduled-run-grants-design.md`) are designed but not in
  this release; the owner chose A on G1-G9 on 2026-11-18.
- **A duplicate rule still asks.** When a scheduled run's card offers Always allow and an identical interactive rule
  exists, the check asks instead of reusing the rule; this release leaves the person's rule untouched rather than
  retagging it.
- **Update Now reads for up to 30 s.** A runner that reports the restart later is picked up by the page's usual poll
  (15-30 s) or a reload, as before.
- **The steps-line fix is in the Apple console.** The iPhone/iPad and Mac apps read the session row; web's and
  Android's session line are unchanged by this range.

## Rollback

rollback to it is schema-safe: no SQL needs undoing and no data is affected. Rolling back restores the old behaviour:

level ahead of a workspace rule, Update Now's card waits for the next poll, and the iPhone/iPad and Mac console hides a
