# Orbit 0.1.261-beta.56

## Summary

This release makes **Optimize For one account-wide preference, Balance by default**: it is set once in
Settings → General → New sessions, right under Smart model selection, and read for every Agent — SubAgents, remote
ones too, and smart-selected task runs — while the per-Agent controls are gone on web, macOS/iOS and Android.
**SubAgents now spend the quota that expires first**, ranked the way the runner already ranks accounts. **Kimi
approval cards carry the command they ask about**: the runner records each Kimi tool call's streamed arguments and
files the card with them, instead of the raw tool call that rendered an empty `$` box. The clients are named
**Orbitd**: macOS builds `Orbitd.app` with `Orbitd-v*.dmg`/`.zip` release files, iOS's app and share extension show
Orbitd, and Android's launcher label and icon follow iOS's. One database migration, an index: no table changes.

- **One account-wide Optimize For, Balance by default (server; web, macOS/iOS, Android).** Owner, 2026-11-19,
  board `docs/mocks/routing-mode-account` approved as drawn (`97a501c468`): Optimize For is the account preference
  `preferences.optimizeFor` (`cost`, `balance`, `intelligence`; absent, or a value a build cannot read, means
  Balance), set in Settings → General → New sessions as a segmented control right under Smart model selection, and
  read by `optimizeForOf` in `common/model-routing-switch.ts` for every Agent: SubAgents (remote ones too) and
  smart-selected task runs. `UpdatePreferencesDto` accepts the three values only. The per-Agent controls are
  removed from web's Agent settings, macOS/iOS's Subagent settings and Android's; the workspace column
  `model_routing_optimize_for` stays but is no longer read, and agents still cannot set the mode.
  `docs/model-routing-design.md` marks the Agent-scoped setting superseded. Specs whose expectations were written
  against the old default pin Cost on their accounts.
- **SubAgents spend the quota that expires first (server).** Owner, 2026-11-19 (`66d83728c2`): SubAgent routing
  ranks subscriptions the way runner account selection already does (`rankAccounts` in `planUsage.ts`): one nearly
  spent last, then the soonest expiry of its longest window, then headroom. Cost and Balance use it; Intelligence
  keeps the strongest model first and uses it between equals. A key, and a subscription with no reset known, never
  expire. An account pool runs on its member whose quota goes first. Kimi Code's monthly windows are read. The pick
  line names when the quota resets. Policy version `p5-expiry-first-1`.
- **Kimi approval cards carry the command they ask about (runner).** `a67d3263aa`: Kimi's
  `session/request_permission` toolCall has no `rawInput` — the engine builds it from the approval's title and a
  truncated action line, and sends the update carrying `rawInput` only after the answer — so the bridge fell back
  to filing the raw toolCall map, and every Kimi card (session or SubAgent) rendered an empty `$` command box and
  could not be told apart. The ACP client now records each tool call's streamed arguments in `readLoop`, in wire
  order (`kimi_acp.go`), and the permission bridge files the card with them; failing that, with a diff's file
  fields or the engine's action line, never the raw toolCall map. Allow rules now match on the real input too.
- **The macOS app and its release files are Orbitd (macOS).** `67132aaf93`: `build-dmg.sh` names the bundle, its
  executable, `CFBundleName`/`CFBundleDisplayName`, the share extension's display name, the DMG volume and the
  release files Orbitd, so Dock, Finder and Launchpad show Orbitd like iOS and Android. `release.yml`,
  `release-identity` and the supply-chain check and dry run look for `Orbitd-v*.dmg`/`.zip` and
  `Orbitd.app/Contents/Info.plist`.
- **iOS is named Orbitd (iOS).** `9982390753`: the app's and the share extension's `CFBundleDisplayName` is Orbitd,
  matching the Android launcher label.
- **Android: Orbitd's label and the iOS icon (Android).** `bafce8bac0`: the adaptive icon now uses the iOS tile's
  blue gradient as its background and the white orbit-and-terminal mark as its foreground, ported from the iOS icon
  source at the same proportions, and the launcher label is Orbitd.
- **Android's drawer loses its admin-only row (Android).** `4d7a74b6cc`: the admin-only drawer entry, its role
  lookup via `users/me` and the now-unused `ic_admin` vector drawable are removed.
- **Server: two database hot spots cooled (server).** `1e9988872b`: the open-list version's runners CTE read every
  one of the owner's sessions to find the owner's runners; it now asks per runner with EXISTS over
  `session_open_list_runner_idx` (production, 2026-11-19: 26 ms / 3,997 buffers → 14 ms / 1,922, the same 8
  runners, and it runs about twice a second). Migration `1240` adds a plain index on
  `project_coordinator_wake (idempotency_key)` for the evidence queue, which reads refused attempts too and so
  could not use `0174`'s partial unique index: ~600 sequential scans of the 7.6 MB table per 5 minutes, measured in
  a rolled-back transaction as 958 → 108 buffers and 6.2 → 0.5 ms for the same 125 rows.
- **A deployment can stop the "Run stopped" wake (server, deployment).** `ce80000db8`: `ORBIT_RUN_STOPPED_WAKE`
  switches off the `TASK_RUN_STOPPED` facts (the wake that tells a project's lead session a task's run parked with
  nothing to wake it). On by default, read per stop, set on the host as `ORBIT_RUN_STOPPED_WAKE_MODE`. `36fbd172de`
  brings the compose guards in line: the comment's wording and `APPROVED_APISERVER_BLOCKS`.
- **Docs and boards.** The `routing-mode-account` board (`97a501c468`), and the background-processes-row board in
  two passes (`b564db72a1`, `d668349dbe`): a row drawn only while something runs, naming a lone process, from real
  data (the coordinator session and 7 days of this runner's background launches, 565 sessions); then the owner's
  11-17 calls — keep ended rows until the next message, use the word Background, count `bg_run` jobs, and rotate
  names when several run — with rotation timing, failure pinning and the all-ended case left open.

## Upgrade impact

- **Database migrations: one, additive.** `1240_project_coordinator_wake_key_idx` adds a non-unique index,
  `project_coordinator_wake_key_idx`, on `project_coordinator_wake (idempotency_key)`. It changes no table shape:
  no column is added, dropped or renamed and no row is written, so an older apiserver neither reads nor needs it.
  It is not `CONCURRENTLY` (Prisma runs the migration in a transaction), so the first boot takes one pass over
  ~9,600 rows; the statement is `IF NOT EXISTS` and can run twice. The apiserver applies it on boot.
- **Configuration: one new optional setting.** `ORBIT_RUN_STOPPED_WAKE` (set on the host as
  `ORBIT_RUN_STOPPED_WAKE_MODE`) is new in `docker-compose.yml`, defaults to on, and takes effect on
  `docker compose up -d apiserver`. Nothing else in `.env` or Compose changes.
- **Runner:** `src/runner-go/` changes in this range — `kimi_acp.go` and its tests (`a67d3263aa`), the Kimi
  approval-card fix above. The other runner-facing change, `66d83728c2` (quota that expires first), is apiserver
  source (`model-routing.ts`, `subagent-route.ts`, `task-route-decision.ts`), not runner source. **The runner
  served at `/dl` is built from this tag**, so a runner fetched from it files Kimi cards with the command; a
  runner from beta.55 shows the empty `$` box. No managed-runner image or engine version changes in this range.
- **Operator decision: accounts that never chose a mode now run Balance.** The per-Agent default was Cost; the
  account preference's absent value is Balance. An operator who wants cost-first routing sets Cost in
  Settings → General → New sessions; nothing else is required.
- **Server:** the Optimize For preference, the expiry-first SubAgent routing, the coordinator-wake index, the
  open-list query and `ORBIT_RUN_STOPPED_WAKE` are apiserver changes, and each reaches an instance only when it is
  upgraded from this source; tagging does not deploy the server. The web changes (the Optimize For row, and the
  per-Agent controls' removal) reach browser users when the deployment's web is rebuilt from this source.
- **Clients:** macOS beta users get `Orbitd-v0.1.261-beta.56.dmg` on the beta channel; the app in it is
  `Orbitd.app`, and the zip the appcast points at is `Orbitd-v0.1.261-beta.56-arm64.zip`. TestFlight gets marketing
  version 0.1.261, with the build number as the commit count, and shows Orbitd as the app's display name. Android
  gets `versionName` 0.1.261-beta.56, the launcher label Orbitd and the iOS-matching icon, and `android-update.json`
  from this tag. No one-time step is required on a Mac, iPhone or Android device.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE, and the root
`package.json` and `package-lock.json` do not change in this range at all — the release commit writes only their
version lines. The Kimi change makes approval cards show the real streamed input and makes allow rules match that
input rather than the raw toolCall map; the commit records it as a card fix and does not describe it as a security
fix.

## Known limitations

- **Optimize For is one value for the whole account.** The per-Agent controls are gone, the workspace column stays
  but is no longer read, and agents cannot set the mode, so an Agent that used to carry its own mode now follows
  the account — and an account with no value reads Balance, where the per-Agent default was Cost.
- **A Kimi card can show the engine's action line instead of the full command.** The bridge files the card with
  the tool call's streamed arguments, and failing that with a diff's file fields or the engine's action line; when
  the engine streamed no arguments and the call has no diff, the action line is what the card has.
- **Android's drawer no longer has the admin-only Admin row.** The commit that removes it names no replacement
  entry.
- **The macOS DMG container is not codesigned.** It is notarised and stapled, so Gatekeeper accepts the app, but
  `spctl` reports the `.dmg` itself as having no usable signature. This predates this release and no commit in
  this range changes it; the DMG's name is now `Orbitd-v*`.

## Rollback

The previous tag is v0.1.261-beta.55, commit `0f80043f1a788e3c507006c34a059acfb8aa651e` (its tag object is
`41fd765c1a4d36b88c1e66bee735e3bf855e1b2c`), tagged on 2026-11-19. Rolling back removes the account-wide Optimize
For (the clients go back to per-Agent controls and the Cost default), the expiry-first SubAgent ranking, the Kimi
approval-card fix (a runner from beta.55 shows the empty `$` box again), the Orbitd naming on all three clients
and the Orbitd release-file names, and the `ORBIT_RUN_STOPPED_WAKE` setting; Android's Admin drawer row returns.

An application-only rollback to beta.55 is schema-safe: `1240` only adds a non-unique index and writes no row, and
beta.55 neither reads nor needs it, so it may stay or be dropped. The account preference is a value in the
existing preferences JSON, and no table shape changes. No backup or restore step is needed. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
