# Orbit 0.1.261-beta.60

## Summary

**This release supersedes 0.1.261-beta.57, 0.1.261-beta.58 and 0.1.261-beta.59.** All three were tagged, and each
failed only on its Android release APK job, with the supply-chain job failing as a knock-on, so none published a
GitHub Release, a Sparkle update or an Android update; their macOS DMG and iOS TestFlight jobs passed. beta.57
(run 44601692135) failed on `MachinesAndModelsCopyParityTest.noProductStringSaysProviders`, which died with
`StackOverflowError` matching `ProviderMark.kt`'s long SVG string literals. beta.58 (run 44605484923) failed first on a
Maven 429 and, on its rerun, on that test and on `SettingsOrderShotsTest.theGeneralPageHoldsTheSettings`, which still
expected Smart model selection off after `d4698bc5a9` turned it on by default. beta.59 (run 44615647285) carried
`3b60aa67d3`, the fix for the first, and failed on the second alone. `350ff1bc66` fixes the second, and this is the
first release after it — so this GitHub Release is the first to carry what beta.57, beta.58 and beta.59 contain,
including the commits made after beta.58 was tagged, which rename the managed runner and its infrastructure from
`orbit-managed` to Orbit Cloud.

## Upgrade impact

- **Database migrations: eight files, six new and two renumbered, every one additive.** No migration drops a column
  or table or alters one destructively; the only migration that writes a row is `1250`'s idempotent rename, and
  every statement can run twice.
  - `1000_claude_account_swap` adds six columns to `runner` (five nullable, `claude_account_swap_waiting` a
    `UUID[]` defaulting to `{}`); its header states an older apiserver neither reads nor writes them.
  - `1120_evidence_send_back_translation` adds two nullable `TEXT` columns to `task_evidence_decision`.
  - `1140_feishu_open_access` adds seven columns to `feishu_app` (one with a foreign key to `workspace`, SET NULL,
    plus three CHECKs), four to `feishu_chat_route` (with two CHECKs added or widened), and one to `feishu_thread`
    with a partial index. Column adds are catalog-only; each constraint is added NOT VALID and then validated,
    which scans a small table and writes nothing.
  - `1150_feishu_show_orbit` adds `feishu_app.show_orbit`, `NOT NULL DEFAULT true`.
  - `1213_session_branch_commits` adds nullable `session.branch_commits` (`JSONB`), null until a runner that reads
    commits reports.
  - `1250_managed_runner_name_orbit_cloud` is data-only: one idempotent `UPDATE` that sets a managed runner's
    stored name to `Orbit Cloud` when it is still `orbit-managed`. It changes no schema, leaves a self-managed
    runner of that name alone, and leaves the owner's `display_name` untouched.
  - `0511_project_done_task_epochs` and `0512_open_list_renewal_not_a_change` are **renumbered, not new**: beta.56
    carried the two files under the opposite numbers. The first adds nullable `project.done_task_epochs` with an
    `IF NOT EXISTS` guard; the second only replaces the `open_list_bump_owner` function with `CREATE OR REPLACE`.
    Each header says an environment that applied it under the earlier number replays it safely, so an instance
    upgraded from beta.56 applies both again as no-ops.
  - The apiserver applies all of them on boot, in order, in one Prisma transaction per migration; no
    `CONCURRENTLY` is used.
- **Configuration: nothing to fill in.** No new `ORBIT_*` variable is read. `docker-compose.yml` changes: the
  managed runners' directory is mounted for the apiserver and `docker-channel` at `/var/lib/orbit-cloud-runners`
  **and** at `/var/lib/orbit-managed-runners`, the path an earlier install's `channel.json` and `profile.json`
  name, and the firewall service is `orbit-cloud-runner-firewall`. An existing `.env` needs no edit; the
  remote-host kit's `compose.yml` does the same.
- **Managed-runner names: a host or cluster installed before 2026-11-20 keeps working unchanged.**
  - Docker: `docker-channel` creates a new managed runner named `Orbit Cloud` (`fdf07ba7ac`). The runners' network
    is whatever `channel.json` names, and `--enable-managed-runner-firewall`
    firewalls that network (a new install makes `orbit-cloud-runners`). The firewall finds its rules by the chain
    they jump to, so the next time it is recreated (a remote host's `upgrade`, or `--enable-managed-runner-firewall`)
    it replaces the earlier container's rules; `/upgrade` leaves the firewall as it is. The runner image is
    `orbit-cloud-runner:local`, and `channel.json` and `profile.json` name it by image ID, so the tag changes
    nothing that runs. A runner container made from an image built before the rename sends
    `X-Orbit-Managed-Runner-*` headers, which the apiserver reads as well as `X-Orbit-Cloud-Runner-*`.
  - Kubernetes: a webhook applied earlier as `orbit-managed-runner-pods` still guards the namespace and the
    manager accepts either admission refusal. To move to `orbit-cloud-runner-pods`, apply the template, check the
    two dry runs, then delete the old one. Earlier Pods and PVCs keep the `orbit-managed-runner` label; nothing in
    Orbit selects by it, but a `--pod-selector` of your own should name both. The hosted runner image is now
    `<registry>/orbit-cloud-runner`; the earlier `<registry>/orbit-managed-runner` digests stay in the registry for
    a rollback. An existing `orbit-managed` namespace needs no change.
- **Runner:** `src/runner-go/` changes in this range are the changed-file base (`7b6e305259`), the
  `claude-account-swap/v1` implementation and its macOS process scan and Keychain writes (`f9cdab7590`,
  `65d27d5c17`, `ffe4402a9d`), the `branchCommits` report and the Orbit-Saved trailer (`455945cff9`), primer 1.4.3
  (`90454daed6`), the read-only Kimi SubAgent's mode following (`22b6530657`) and the `X-Orbit-Cloud-Runner-*`
  headers it now sends (`ae798fefff`, which the apiserver reads alongside the earlier names). **The runner served
  at `/dl` is built from this tag**, so a runner fetched from it declares
  `claude-account-swap/v1`, reports its branch's commits and registers under the stored name `Orbit Cloud`; an older
  runner keeps its
  accounts without the Set as default menu item, keeps the file bar, and files a read-only Kimi SubAgent's shell
  card as before.
- **Server and web:** the Feishu open mode, the Show Orbit switch, the Claude account swap, the commit list, the
  background list's `job` kind, the card-free create preference, the coordinator recoveries and the Orbit Cloud
  naming are apiserver changes; each reaches an instance only when it is upgraded from this source — tagging does
  not deploy the server. The web changes reach browser users when the deployment's web is rebuilt from this source.
- **Clients:** macOS beta users get the DMG and Sparkle appcast from this tag on the beta channel; TestFlight gets
  marketing version 0.1.261, with the build number as the commit count; Android gets `versionName`
  `0.1.261-beta.60` and `android-update.json` from this tag. Because beta.57, beta.58 and beta.59 published no GitHub
  Release, Sparkle update or Android update, **this is the first published build to carry their changes**, and an
  Android phone still on beta.56 is offered it. No one-time step is required on a Mac, iPhone or Android device,
  and no account, workspace or Feishu app has to be reconfigured — an app that never opened the bot reads
  OWNER_ONLY and Show Orbit on, as before.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE, and the root
`package.json` and `package-lock.json` change only in their version lines. The Feishu availability check
(`6263885a9e`) and the Keychain write fix (`ffe4402a9d`) change access control and credential handling; their
commits record them as a feature and a correctness fix, not as security fixes.

## Known limitations

- **Under Auto or Bypass a read-only Kimi SubAgent's shell commands run without a card and without any check of the
  command.** In `22b6530657`'s own words the runner does not check the command, so under those two parent modes a
  read-only Kimi child is read-only by its plan-mode instructions alone. Edit tools stay with plan mode. Recorded
  in `docs/subagent-design.md` §5.3.
- **Only web gets the calmer open-item cards.** `a6949223eb` keeps the literals OrbitKit's parity tests pin exported
  until the native cards follow, so macOS/iOS and Android still draw the previous card.
- **An older runner keeps the file bar.** `455945cff9`: a runner that reports no `branchCommits` leaves the session
  on the previous "+/− files" bar.
- **A commit's file diff is the file's whole change on the branch.** Patches are per branch, so the drawer's view of
  one commit is not a per-commit patch; the drawer says so when that differs.
- **Feishu open mode answers some requests with one sentence and writes nothing.** External groups, switched-off
  implicit routes, requests over a limit, and every sender outside the app's availability scope get that answer
  (`880ba6cb22`, `0d3828ad50`).
- **A group session on a model that cannot run Auto opens in Default.** The confirm page preselects Auto, and
  dispatch narrows it when the model cannot run Auto (`3b7aa1eabf`).
