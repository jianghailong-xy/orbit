# Orbit 0.1.261-beta.74

## Summary

This release is the **first published build after v0.1.261-beta.73 failed to publish**, so it carries beta.73's changes as well as its own: a reader coming from beta.72 sees the whole change here. beta.73's release run ([45008425920](https://github.com/jianghailong-xy/orbit/actions/runs/45008425920)) ended with its Android job failing on a wrong expectation in `RunnerPageTest` — it expected the runner fixture's workspace (`orbit-develop`) on a Fixing view whose entry names `orbit-dev` — which `0d39c9380a` fixes (RunnerPageTest 30/30), after earlier attempts were stopped by Maven Central answering 429. Its macOS DMG job and iOS TestFlight job succeeded, but the Android job produced no APK for the supply-chain job to read, so the publish step was skipped: **no GitHub Release, Sparkle appcast or Android APK went out for beta.73**. This tag is the first build that publishes all of it.

**A session held by its GitHub workspace's clone now shows the clone's progress.** Where the waiting card said only "Waiting for the clone", web (`bf187953a9`) and the Apple apps (`014a82fb01`) name the repository and the machine and draw git's percentage once the realtime stream has relayed one, and the session's list row reads "Cloning · 42%"; a failed clone no longer points at a first line the session may not have. The Apple card draws its own bar rather than a native `ProgressView`, which does not render under `ImageRenderer` (`d180da0765`), and shots of it are added at a Mac and a phone width, plus one hosted in AppKit where the spinner is the real one (`5b2b9a959a`). On web the full-height card's own dots are the only waiting mark, so a spinner is drawn only before a percentage arrives, and the sentence stays on one line (`6e1c39c588`). Android does not draw the clone's percentage yet; its row for such a session still reads "Queued" (see Known limitations).

**A managed runner now shares the duplicate files on its own volume while it is idle.** A session checkout already shares its blocks with the checkout it was cloned from, but what a session writes itself — `node_modules` above all — does not, so every `npm ci` cost its full size. A managed runner now runs `duperemove` over its own volume once it has been idle for 25 s, counts the pass as an operation so the manager does not put it to sleep under it, and stops it as soon as work comes back; a failed pass is tried again after six hours, and a pass may hold off sleep for at most 20 minutes (`68c6cc5d18`). It runs in the Pod rather than from the host, so nothing outside the Pod ever holds the volume open, and each user's volume is a filesystem of its own, so nothing is ever shared between two users. Its hashes live in a file on the volume, so the next pass re-reads only what changed since and one cut short resumes. It works in 4 KB blocks: at the default 128 KB it skipped every file under 128 KB — most of `node_modules` — and shared only whole matching extents, as measured on ws01 (`de0c80f004`). The managed-runner image now installs `duperemove` and names its version in the image's tool list (`68c6cc5d18`). Self-managed runners do not run it.

**Model routing is one click from the account menu on web.** The row sits above Settings, opens Settings → Providers → Model routing, and says on its right how routing runs now: "Off" while Route by tier is off, else the Optimize For it routes by — "Balance" for an account that never chose (`c6206b596a`).

**The web Following page and session page read less.** Following's four lists are one request now: `GET /watches?following=true` answers the union the page draws — the newest 100 watches, then any ACTIVE, PAUSED or needs-attention watch not among them, each watch once — with the same ETag and 304 behaviour, while the three older shapes are unchanged for the Mac and Android apps (`f53616e1a2`). The session page reads a created-task strip on its own rows' task changes and runs, schedule cards on the new `schedule_cards.changed` event, and the integration line once per page on its project's task changes, with `task.changed` naming its rows' projects and creators additively (`837baf3332`, `4faeb2d431`); it reads approvals once when the stream opens, keeps question translations in one session-keyed query fed by live approvals, reads `/turns` only when a queued successor or an uncleared accepted placeholder can move, holds the background inventory in a stream-aware query patched from job ends, and leaves the turn-end detail to the control plane's coalesced refresh while it is live (`da30ace8c8`). A stream that hangs before opening no longer leaves pending approvals off the page: a 3 s grace timer reads them once when no open came (`558a4c2852`), which matters for the approval panel and the prompt optimizer's question reply. The delegate and workflow views share one subagents read (`8f2b5c4526`), and the favicon and touch icons are served cacheable for a day instead of revalidating with the shell (`7db43f87ff`).

**A long reply folds on the Apple apps.** A reply card drew the whole reply, so a long one filled the screen; its body now folds by rendered height through the fold the "From …" message card already draws, showing its first four lines of more than six with "Show more" / "Show less", while the head, what was asked, the chosen option, the excerpt and the foot stay whole, and a record or search reveal opens it — web parity `94c8a172be` (`eb462220a3`).

**The server builds again.** `5e57dcc4a3` left `attention-fix.ts` naming `OVER_STATUSES`, which `8d516a3eca` had removed, so beta.73's apiserver tree did not compile; `6959a6fa47` asks `isReleased` on `finished_at` instead, as an open fix session's filter does. `321fede22d` brings the reds that followed `d5092af4df` back to green, regenerating `docs/api-reference.md` and updating the tenant-isolation, session-kind, task-completion-evidence, db-write-inventory, host-setup, BgJobCard and AcceptedTurnWiring pins, and records the verification on `674a67596a`. `2d932e3916` gives the project row's Pause/Resume sentences and the machine page's sign-in sentence one name on both ends, with the same English (no visible change).

From beta.73, published here for the first time: **every model in Model tiers shows how well it completes work**, on web, macOS, iOS and Android. A parent session can rate a SubAgent run it started, 1 to 5 with an optional note, with the `subagent_rate` tool or `orbit subagent rate` on the runner (`c4148065b8`); the rating records the rater's own engine, provider and model, a later rating replaces the earlier one, and a foreground delegate's result carries one line asking for it. Model tiers draws a SubAgents line (the rating with rated/total) and a Tasks line (first-pass rate over done tasks), each reading "Not enough …" below its minimum and "No runs yet" with neither, and who rated sits in a tooltip (`3017117289`); the Mac gets a column and the iPhone the lines under the model (`967174e707`); Android follows iOS, with lines under the model on a phone, a column on a tablet, a tap on the SubAgents line showing who rated, and the tablet columns rebalanced so the figures, the model id and an "Older · uses …" tier all fit (`cf78eb5217`). The display only: routing reads none of it.

From beta.73: **the Android reader holds a card where it was put**, and **the Apple apps read a task's exemption from its record**. A WAITING request that found no card now lapses after 10 s and when the reader touches the list (`5979c61339`); the opened card, and a record jumped to, are put back whenever the cards item or the window's rows change, until the reader touches the list or 5 s pass with nothing moving it, and the quiet restarts only when a put-back actually moved the view (`52789f2f15`); a reader resting on the cards with no event row in view tells the model it is not following. A task page's origin badge reads the newest unreverted exemption record that set it, as web does — Coordinator, Approved on a card, or You, with its time — the landing's check list orders a step's status as web does, failed before skipped, and a TASK_EXEMPT line reads no inline output (`3ca2e6e132`, `60963ce4f5`); the Agents line and its sheet draw their running mark with the app spinner (`1a5e48ec25`).

## Upgrade impact

- **Database migrations:** none between v0.1.261-beta.73 and this tag — no migration file is added, changed or removed. The one migration since beta.72, and the one this release is the first published build to apply, is beta.73's `1429_subagent_run_rating`. It is **additive only**: it adds six nullable columns to `subagent_run` — `rating_score`, `rating_note`, `rated_at`, `rater_engine`, `rater_provider`, `rater_model` — a check that `rating_score` is NULL or between 1 and 5, and an index on `("owner_id", "created_at")` for the Model tiers view's 90-day read. It has no UPDATE or DELETE, existing rows keep NULL in all six, no table is altered beyond those additions, and every statement can run twice, so a server that already booted it (or boots it again) is unchanged. The commits that add it call it "migration 1420" in their messages; the file in this tag's tree is `1429_subagent_run_rating` and it is unchanged here.
- **Ordering:** beta.72's requirement stands unchanged. **Every replica must already run v0.1.261-beta.70 or later before this tag's apiserver boots migrations 1401+.** A server older than beta.70 writes a terminal session status with no `finished_at` and is refused by 1401. `1429` sits after `1428` and needs no particular order around the rest.
- **Release cause:** unchanged from beta.71. `session.release_cause` is no longer written and is gone from the Prisma model, but the column and `session_release_cause_chk` remain in the database until a later deploy (step R8). A beta.70 server still writing them during a hand-over harms nothing. No commit in this range changes it.
- **Configuration:** nothing new to fill in. A **managed-runner** image now carries `duperemove`; the dedupe pass is on automatically where the tool is installed and the volume's filesystem can share blocks (XFS with reflink, btrfs). Elsewhere the runner logs `dedupe: off` and changes nothing. There is no setting to turn it on or off.
- **Runner** (`src/runner-go`, built from this tag and served at `/dl`): the binary carries the managed volume's idle dedupe. The runner served at `/dl` is built from this tag; a production deployment is what puts it there, so the runner at `/dl` shows this tag after the next production deploy. A managed-runner deployment picks the dedupe up by updating the runner image; older runners keep working, and a runner without `duperemove` simply skips the pass.
- **Clients:**
  - *macOS:* the Model tiers Quality column, the Apple exemption, spinner, clone-card and reply-fold changes, and the hand-over copy — the first macOS build offered on the beta channel since beta.73's DMG was built but never published, so this is the first DMG and Sparkle appcast carrying beta.73's changes.
  - *iOS:* TestFlight marketing version 0.1.261, build number the commit count, with beta.73's Quality lines and Apple fixes plus the clone progress and the reply fold; beta.73's TestFlight build was uploaded even though its GitHub Release was not.
  - *Android:* `versionName` `0.1.261-beta.74`, the next `versionCode`, and `android-update.json`, with the Quality display and the reader card hold — beta.73's Android app changes reach users here for the first time, since beta.73's APK never shipped; the app code in this tag is beta.73's.
  - *Web:* the clone progress, the Model routing row, the Following and session-page read fixes, the approvals fallback and the favicon caching, with the next server/web deployment, not from this tag's client artifacts.
  - The server-side additions — the watches union read, `task.changed`'s `creatorSessionIds` and `rowProjectIds`, and `schedule_cards.changed` — are additive; older clients keep their existing reads and ignore the new event, and Android and the Mac keep the three older watch shapes. No minimum client version is enforced, and no one-time step is needed beyond the upgrade ordering above.

## Known limitations

## Rollback

The previous tag is v0.1.261-beta.73, commit `6781a226da63a761122ff39265e4e5df33a004b3`, and it published nothing: the last release published for macOS and Android is v0.1.261-beta.72, commit `1de50bb03b26f9b4c1c4c4ee3236be1da74f5f94`. beta.73's server tree does not compile (`6959a6fa47`: `attention-fix.ts` named `OVER_STATUSES`, which `8d516a3eca` had removed), so a server deployed from this tag rolls back to beta.72's commit, not to beta.73's.

An application-only rollback to beta.72 is schema-safe. `1429_subagent_run_rating` only adds nullable columns, a check every stored NULL row satisfies, and an index beta.72 never uses; beta.72 writes no rating, reads no rating, and the triggers and functions it runs are the ones it shipped with. A release before beta.70 cannot be the rollback target: 1401 refuses its terminal writes. Rolling back to beta.73's commit keeps the same schema but swaps in a server tree that does not build.

The client changes do not roll back with the code. Rolling macOS or Android back from this release means installing beta.72's build, which loses the Model tiers Quality display, the Android reader card hold and the Apple fixes — and the macOS clone card and reply fold that beta.72 never had. An iOS device can also go back to the beta.73 or beta.72 TestFlight build.
