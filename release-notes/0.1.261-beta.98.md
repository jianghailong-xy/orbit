# Orbit 0.1.261-beta.98

## Summary

This release finishes the move beta.97 began: the apiserver's claim, runner slots, dispatch and the other readers now read the session's derived turn state instead of `session.status`, and the database holds every session's `turn_state` and `phase` to its stored word — the migration fills the rows that were never filled, refuses to install its CHECKs if an existing filled row disagrees, and refuses a later write that disagrees. Codex sessions on Orbit Cloud no longer show the yellow "sandbox unavailable" notice in the transcript, and their permission note now says the Cloud runner's container isolates commands. The Android composer test that failed the v0.1.261-beta.97 release build now expects Queued, the header's word.

- **Server: the claim, slots and dispatch read the turn state.** Task T7 of docs/session-status-retirement-plan.md: in `queue/`, `common/`, `managed-runners/`, `runners/` and `metrics/` every read of `session.status` becomes its turn state one for one (PENDING = QUEUED, RUNNING = IN_FLIGHT, INTERRUPTED = ABANDONED, a held set = `finished_at IS NULL`), read through `sessions/session-turn-state.ts` so a row not yet backfilled answers from its stored word. The claim, its undo, the out-of-memory stop and the return-slot path write `turn_state` beside the word; released words on payloads (abandoned checkouts, removal and swap lists, handled fixes) are the projector's, and the partial indexes on `finished_at IS NULL` (1628, 1633) are the held rows' access path.

- **Server: two SQL facts that used to be NULL.** `turnStateFilter` is now never NULL in SQL: `turn_state IN (…)` is NULL on a held row the backfill has not reached, so `NOT` of a filter built on it dropped those rows from both sides, and an unfilled queued session with a resume watch read as not waking; the IN is now asked beside `turn_state IS NOT NULL`, which selects the same rows and is never NULL (7a23337e19, found by session-working.pg.spec.ts once it ran every shape unfilled). The dispatched-turn fact is `false`, not NULL, on a parked or released row, where `= 'IN_FLIGHT'` made it NULL and `NOT` of it dropped the row; `IS NOT DISTINCT FROM` keeps it boolean (2821e51a30, found by the same spec on every shape).

- **Server: return-slot and the draining Stop write the turn state.** The return-slot route and the Stop that idles a session on a draining runner read the slot as the turn state IN_FLIGHT and answer the projector's word, and both write `turnState` beside the word as deploy 2 does (4397a16a87).

- **Server: the database refuses a session whose state disagrees.** Migrations 1651–1655, deploy D2 of the retirement plan: 1651 fills every row that was never filled from its `status`, asserts that no filled row disagrees, and then adds two strict CHECKs; 1652–1654 validate them and 1622's released CHECK; 1655 makes `session.phase` NOT NULL. A database whose filled rows disagree stops at 1651, which names one row; details under Upgrade impact.

- **Runner: Codex on Orbit Cloud no longer warns that its sandbox is off.** The Cloud runner's container is already the boundary, so the yellow notice on every Codex session read as an alarm about nothing. The runner still reports `sandboxUnavailable` to the server, but carries no notice text or diagnostic, and the session's permission note reads "Codex's own sandbox cannot start on Orbit Cloud, so it is off: your Cloud runner's container isolates its commands instead." (short note "Codex sandbox off, the Cloud runner's container isolates commands"). The approval policy and reviewer stay as Auto has them, and a self-registered runner never probes and keeps its behaviour (9b69ea5553, owner 2026-11-26).

- **Android: the composer test reads Queued.** 707f20d14b took the header's word from the phase, and web's test of the same fixture was updated in 8c171127e9; Android's still expected "Runner updating" and "On hold", which failed the v0.1.261-beta.97 release build. The fixture now expects the header's word to be "Queued" for both the list and the detail payloads; the list row's own mark stays "Runner updating" (156b025245).

- **Documentation and the rehearsal kit.** The retirement plan's list row kind C8 is listed after the owner accepted it on 2026-11-26: old SUCCEEDED rows ended "completed" with no turn outcome read Ended, and the census counts them as listed instead of unlisted, with no projector change (905dfecfb0). The range also records the T3 production backfill and its census (1efae1ee48), the T16 rehearsal on a production-shaped copy with its reports (29f3ebaa9b, 232b6252b1, 913a04a6d7, ffe14ccbf1), the T16b and T16c censuses on restored backups (db1bc9eb99, d1b8babaab) and a fix to the query-plans script so a missing batch, tree, task or list target reads as the nil uuid instead of aborting the whole EXECUTE string (1e303d9970).

## Upgrade impact

- **Migrations:** five, applied by the apiserver on boot. Three are additive; one swaps a constraint and fills empty rows, and one makes a column NOT NULL.
  - `1651_session_turn_state_strict_checks` — **not additive:** it writes rows. It fills every session row that was never filled (`turn_state` from `session_turn_state_of_status`, where `phase` is NULL or `turn_state` is NULL under a word that means one), in a statement naming the function so 1611's trigger derives `phase` too, and commits that fill before it asks for a table lock; on a database the backfill has already filled it writes no row. It then asserts that no filled row disagrees with its derivation and, if one does, refuses the migration and names it. Then, both NOT VALID, it adds `session_turn_state_agrees_chk` (`turn_state IS NOT DISTINCT FROM` the word's) and `session_phase_not_null_chk`, and drops 1622's NULL-tolerant `session_turn_state_agrees_unless_null_chk` in the same transaction. It drops no column or table and rewrites no filled value.
  - `1652_session_turn_state_agrees_validate` — **additive in what it changes:** it only makes that CHECK enforced, scanning `session` under SHARE UPDATE EXCLUSIVE so it blocks no reader or writer; it writes no row and drops nothing.
  - `1653_session_turn_state_released_validate` — **additive in what it changes:** it validates 1622's `session_turn_state_released_chk` with the same scan, writes no row and drops nothing.
  - `1654_session_phase_not_null_validate` — **additive in what it changes:** it validates `session_phase_not_null_chk` with the same scan, writes no row and drops nothing.
  - `1655_session_phase_set_not_null` — **not additive:** it makes `session.phase` NOT NULL. It performs no validation scan and rewrites no row: SET NOT NULL scans nothing here because the validated `session_phase_not_null_chk` (1651, 1654) already proves no row is null, and it drops that helper CHECK in the same statement list. Both are catalog changes under ACCESS EXCLUSIVE, asked for 2 s at a time, 1 s apart, up to 45 tries.

- **Backfill:** not a separate step. 1651 does it on boot, so a self-hosted database going straight from before 1611 to this release is filled without a manual run; on production, where the batched backfill ran on 2026-11-26 (1efae1ee48), the UPDATE writes no row. A database with a filled row that disagrees stops at 1651 with a hint: fix or rewrite the rows from the status (the census and backfill scripts count and rewrite them), then mark the migration rolled back (`prisma migrate resolve --rolled-back 1651_session_turn_state_strict_checks`) and deploy again.

- **Configuration:** none. No environment variable or setting changes in this release.

- **Server:** the claim, its undo, the out-of-memory stop and the return-slot path write `turn_state` beside `session.status`, and `queue/`, `common/`, `managed-runners/`, `runners/` and `metrics/` read the turn state, NULL-safe so a row not yet backfilled reads its stored word. `session.status` is still written and still served; removing it is a later deploy, and the strict CHECK keeps the two spellings equal until then. No payload field changes shape or name.

- **Runners:** the runner served at `/dl` is built from this tag. It still reports `sandboxUnavailable` to the server, without notice text or a diagnostic, and its Codex permission semantics carry the new note. A runner older than this release keeps sending the old notice, so its Codex sessions keep the yellow transcript warning until the runner updates; nothing else a runner sends changes.

- **Clients:** web arrives with the deploy of this commit; macOS (beta channel DMG), iOS (TestFlight) and Android (APK) come from this tag. Web shows the new Codex Cloud permission note (shared `permissionSemantics.ts`); no Mac or iPhone source changes in this range, and Android's only change is the composer test fixture. No one-time step on a Mac, iPhone or Android device.

## Security fixes

None in this release.

## Known limitations

- A database with a filled `turn_state` or `phase` that disagrees with its `status` stops the upgrade at 1651, which names one row and refuses rather than repairs; the way through is to fix or rewrite those rows from the status and deploy again (see Upgrade impact).
- The fill 1651 performs writes only empty rows; a row that is filled and wrong is refused, not rewritten.
- `session.status` is still written and served; until a later deploy removes it, the strict CHECK holds the two spellings equal.
- A runner older than this release still sends the Codex Cloud sandbox notice, so its Codex sessions keep the yellow transcript warning.

## Rollback

Previous tag v0.1.261-beta.97 (`000a8f7eed`). Application-only rollback is **schema-safe for this release**: 1652–1654 only validate constraints and write no row; 1651 has already committed its fill of empty rows, which a beta.97 server does not read; and 1655's header records that a server one release older never writes `phase` itself — it writes `status`, and 1611's BEFORE triggers derive `turn_state` and `phase` in the same row, so every write it makes satisfies the strict CHECK and the NOT NULL. Leave the constraints in place: the release records no down-migration for 1651–1655.

Client rollback is to the last published builds, v0.1.261-beta.97's DMG, TestFlight build and `orbit-android-0.1.261-beta.97.apk`. A beta.97 client keeps working against this release's server: no Mac, iPhone or Android behaviour changed in this range, so a beta.97 build behaves as before, and it keeps the older Codex sandbox warning until a runner from this release serves it.
