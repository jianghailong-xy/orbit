# Orbit 0.1.261-beta.103

## Summary

The web session column is windowed and read from a new server listing instead of the whole Open list, so a workspace with folders or projects mounts about two screens of rows and a frame redraws only the row it is about. Apple and Android draw a scheduled run's status card on its session page, a filed session opened from a link lands over its folder's page, and the web composer's translation tag moves into the box as the Apple clients draw it.

- **Web and server: the session column reads `GET /sessions/listing` a page at a time (2fe3659bdf, 6c0e5968b6, d9d68ef86a, f6a46c925a, 896fd1d629, 985991d6c4, be949a0493, bb2d3c0e34, a1a0dbce59, 0522c25db8, 4068cbc599, 08f0b054c2, 05d90ea0e9, 4a73bd8334; no migration).** A workspace with folders or projects used to read its whole Open list so the client could group it. The new route pages one page of top-level entries with folder tallies, a version ETag answered 304, and project entries that carry `running` and `jobs` by the same predicates the folder rows count by, so a project row keeps its member's spinner and background-job pulse without holding the members. A read under a different order's cursor is answered from the first page and says `restarted: true` instead of looking like an ordinary next page. Open pages by the sections the web draws — Pinned, Needs you, Working, then `listedAt` — so a Working or Needs-you row listed long ago no longer sits on a later page; Completed keeps `GET /sessions?view=completed`'s order unless a project is held, and a cursor carries which order wrote it. The route is registered in the route censuses and the API reference, and a cursor written under a stale order restarts rather than duplicating rows.

- **Web: the column is windowed and redraws only the row a frame is about (a8135c1c84, 26252db13c, e8ad26c781, 146233f8ff, b82ec50737, 3716c7484c, df2523df25).** Folder rows, headings, session rows and project rows are one item list drawn by `@tanstack/react-virtual`, so 1,500 Open sessions mount about two screens of rows. Rows are memoized with props stable by id, and a listing re-read reuses an entry per session object and mark and shares pages by entry identity, so a watch or clone frame commits only the row it is about. A runner heartbeat alone no longer redraws the rows it re-stamps, and ↑ / ↓ step from the row the previous key chose rather than the last render's selection. WorkspaceView and BootGate now read the listing, folder pages read with `folderId`, folder rows draw the server's tallies, and the next page loads from the windowed list's last visible row; Trash, tag lists and Scheduled runs keep paging `GET /sessions`, and pin, rename, tags, settings, complete, delete and a move into a folder patch the loaded pages.

- **Web: the composer's translation tag sits in the box (ada5ba1599).** The "<Language> → English" tag lived in the toolbar, where on a phone it fought the model and account names for width. It is now the small capsule the Apple clients draw at the composer's top-right, on the empty draft's first line, its width reserved out of that line so neither a suggestion nor a placeholder runs under it; it leaves the moment the reader types, and a suggestion takes the line instead. The toolbar keeps +, the mode, the model, the gauges, ✦ and Send, and the phone rule that let the tag shrink there goes with it.

- **Web: the session title looks the same hovered as at rest (d13d972696), and one browser-notification offer is on screen (6e3bf06c91).** On hover the title grew a ground and a ›, which pushed the Task badge 17px right on a short title, and a Session settings tooltip opened; all three go, and the title still opens session settings, keeps the pointer, names itself to screen readers and shows the focus ring to the keyboard. The desktop browser-notification offer showed twice (top bar and rail card), and answering one left the other up until a reload; the bar now shows only at the drawer width and the rail card only on desktop, and answering — or turning it on in Settings — clears the cached offer for every mount.

- **Apple: a scheduled run's status card, a filed session opens its folder's page, and the run card takes the neutral stroke (588f1cb113, d7eeefd541, e922c35d2f, 957a74671c).** A run's session page now draws the web run status card's three states (Didn't run, Queued, Started on try N), with the shared copy pinned in `contracts/schedule.contract.json` `runStatusCopy`, the schedule card's `runStatus` field decoded, and the composer and never-started notes hidden for those sessions. The card takes the neutral secondary stroke in all three states, its time chips the normal label font, and Run now opens the session of the run it started, as web does. Opening a session filed in a folder from a link, notification or search now opens that folder's page once per open, so the conversation has a row and a pointer to its folder; a conversation link had the same gap.

- **Apple: a reopened cached session catches up in one read (1ad56d0e10).** A reopen drew the restored transcript first, then fetched the missed events in pages of 200, each its own publish, so the reader watched the conversation fast-forward before it settled. The reopen path now reads the gap after the cached max seq with one page: a gap that fits lands in a single publish and the stream opens from the new max seq, and a wider gap drops the kept window and re-seeds from a tail page, exactly as a cold open seeds. A reader up in the history keeps the paged catch-up, and a failed read resumes the stream from the kept seq. Web parity 4e53172f02.

- **Android: a scheduled run's status card, and a filed session opens its folder's page (289e6d4e2f, 19adfd2536, 0ee2847efe, 0066bcad5c, 0ee38f4eaa).** Android decodes the server's per-session run status and derives the same three card states, keeping the legacy path for sessions without the field; undelivered tries show the run's status and actions in place of the attempt's error and composer, laid out as the iOS card is (12 corner, 14 padding, 10 spacing, capsule time chips). A link, push or share to a session filed in a folder now lands as `[workspace, folder, session]` over the folder's page instead of the workspace root, once per open; in-app links still open over the page they were on.

- **Server: the Run now gate reads the turn state (936b8ea487, no migration).** D3.1 ships `6d017c045f` without deploy D4: `queued-gate.ts` filtered its lateral on `s.status = 'PENDING'`, which would make every session list answer 500 once D4 drops the column, and now asks `sessionTurnStateSql('s') = 'QUEUED'`; the text guard treats an alias as a session when the same fragment names a column only `session` has. It runs on the D3 schema with the column present.

- **Server: deploy D4 drops `session.status` and `run_status` (b1e750813f, 5b02d7f41b, 6d017c045f, 070f9f4b0c, f009672f05, e55ca68525, 57ed796264; migration 1711_session_status_drop).** Deploy D3 already reads and writes only the facts, so migration 1711 drops the column, its `run_status` type, 1671's rollback trigger and function, the two word CHECKs, six indexes and the word-based functions, and takes `status` out of 13 trigger column lists; its DO block refuses to run if anything else still names them. The legacy wire words (`status`, `runStatus`, `runState`, `sessionState`) are unchanged: they come from the projector, not the column. The PG specs run on the column-less schema, and `scripts/session-status-drop-down.sql` restores the D3 database, filled from the facts. The T17 rehearsal of D3.1 → D4 is recorded (02a19f8a2b, with its kit 27bd15d68a and 286741de58): 1711 ran in 69 ms with no lock waiters, and the D3.1 server answered every call after the drop with no 5xx.

- **Clients: Orbit Cloud workspaces wear the cloud on Android, iOS and macOS (2818271337), and the web task column docks without sliding in (eba3220242).** The Android drawer and the Apple clients' shared workspace icon draw Orbit Cloud's cloud and the folder for every other workspace, as the web sidebar already did. On web, the task column docked beside a conversation by Task › now appears in the same frame the conversation narrows, instead of a 220 ms slide that read as the page flickering.

- **Engines: the managed-runner image carries Kimi Code 2.8.1 and Antigravity CLI 1.5.18 (ad1d6560b7).** Upstream released new stable builds, so the managed-runner image is bumped in step: Kimi Code 2.8.0 → 2.8.1 and Antigravity CLI 1.5.17 → 1.5.18, both confirmed by download against their manifests.

- **Docs and tests.** The session-list scale design and the API reference now name the listings' Open sections and order (af502f343b), the API reference is regenerated after main added `accountFingerprint` to the Codex reset list route (e1731a398a), and the session-list measurement scripts can wait for a quiet host, re-send a rolled-back watch write, and name the commits they ran on (f28834fed6, 05d90ea0e9, 08f0b054c2, 4068cbc599, b7bde94353). The session title design is recorded in `docs/mocks` (fe088e3eea). Main's reds on the schedule-run header pin, the Secrets page clock and the `db-write-inventory` inventory are corrected (55a0b72478, 7474f16158, e349745e74), and the listing fixtures are realigned (146233f8ff, 99262be234, 400bd34e3e).

## Upgrade impact

- **Migrations:** one, `1711_session_status_drop` (deploy D4). It is **destructive**: it drops `session.status`, the `run_status` type, 1671's rollback trigger and function, two CHECKs, six indexes and the word-based functions, and rewrites 13 trigger column lists. It may run only once D3.1 (936b8ea487) is serving on every apiserver replica. Production has run 7474f16158, which contains D3.1, since 2026-11-27T00:35Z, so a normal two-stage hand-over is enough: no `--stop-then-start`. The T17 rehearsal ran 1711 in 69 ms with no lock waiters. The D3.1 commit itself adds no migration.
- **Backfill:** none.
- **Configuration:** none added or changed. The listing uses the workspace's existing folders, projects and sessions; no new environment variable is recorded.
- **Server:** `GET /sessions/listing` is a **new, additive route** — no existing route, field or payload changes shape or name. It pages top-level entries with folder tallies, answers a version ETag with 304, and says `restarted: true` when a cursor written under another order restarts the page. Open now pages by the sections the web draws (Pinned, Needs you, Working, then `listedAt`); Completed keeps `GET /sessions?view=completed`'s order unless a project is held. The D3.1 change is internal to the Run now gate and the text guard and does not change a route. D4 removes the stored column only; every payload's status words are unchanged.
- **Runners:** the runner served at `/dl` is built from this tag. This range changes no runner-go code; the managed-runner image's Kimi Code and Antigravity CLI engines are bumped to 2.8.1 and 1.5.18 (ad1d6560b7).
- **Clients:** web arrives with the deploy of this commit; macOS (beta-channel DMG), iOS (TestFlight) and Android (APK) come from this tag. An older client than this release keeps reading the whole Open list and does not draw the windowed column or the server's sectioned Open order, keeps the translation tag in the composer's toolbar and the session title's hover ground and ›, keeps the duplicate browser-notification offer, and lacks the scheduled run status card and the folder-page landing for a filed session.

## Security fixes

None in this release.

## Known limitations

- The windowed session column and the sectioned Open order are web-only; macOS, iOS and Android keep their own list reading and order.
- Trash, tag lists and Scheduled runs keep paging `GET /sessions` in the web client; only the folder/project session column reads `/sessions/listing`.

## Rollback

Previous tag v0.1.261-beta.102 (`9b89aefcda8dea70d6889d3b1b0bb5dfed8a5acf`). Application-only rollback is **not** schema-safe once 1711 has run. A v0.1.261-beta.102 server (or any release at or before 7474f16158) still expects `session.status`. Roll back in this order: first run `scripts/session-status-drop-down.sql` against the database, which re-adds the column filled from the facts and restores 1671's trigger (allow about a 2 s pause of session writes on production); only then deploy the previous commit for the server and web together. Never roll back by redeploying alone. `GET /sessions/listing` then disappears with the web that called it.

Client rollback is to v0.1.261-beta.102's DMG, TestFlight build and `orbit-android-0.1.261-beta.102.apk`. A beta.102 client keeps working against this release's server, since no payload it reads changes shape and it never calls the new listing route; it lacks the scheduled run status card, the folder-page landing and the web column and copy changes.
