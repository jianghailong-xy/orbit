# Orbit 0.1.261-beta.108

## Summary

This release is how iOS, macOS and Android show a message that is on its way. A new session's first message and every message into an existing session now waits as a dimmed "Sending…" bubble in the transcript; a server refusal or 20 s without an answer turns it into "⚠ Not sent · Retry · Put back in the composer" with the reason under it, instead of the message vanishing behind a "Couldn't send" line or a "Delivery unconfirmed / Retry saved send" strip. Retry resends the same persisted id — `clientRequestId` for a create, `clientTurnId` for a turn — so a repeat opens no second session and posts no second turn; the server in beta.107 already answers such a repeat with the session the first made. The commits also fix two ways the new bubble failed: a new-session Send that trapped because the bubble's required environment object is not under a console, and a create whose 20 s deadline was not cancelled, so "Not sent" arrived at the 60 s request timeout instead. No web, apiserver, gateway or runner-go source file differs from beta.107; the rest of the range is design boards, iPhone and Android frames and their capture kits under `docs/mocks`, which ship no code.

## Upgrade impact

- **Migrations:** none in this range. `git diff --stat v0.1.261-beta.107 origin/main -- src/apiserver/prisma/migrations/` is empty, so the schema is exactly beta.107's. That includes `1730_session_client_request_id`, which landed in beta.107's tree; this release adds no migration.
- **Backfill:** none.
- **Configuration:** none added or changed. The 20 s answer deadline is fixed, in web's `answerDeadline` manner; no commit in this range adds a setting for it.
- **Server and web:** no change. No file under `src/apiserver`, `src/web` or `src/gateway` differs from beta.107, so deploying this commit boots the same server and web code beta.107 already ran, and the server already answers a repeated `clientRequestId` with the session the first made.
- **Runners:** the runner served at `/dl` is built from this tag. No file under `src/runner-go` differs from beta.107, so its behavior is beta.107's; the binary differs only in the version it reports.
- **Clients:** iOS and macOS (shared code under `src/macos`) and Android change as described above. A beta.107 build keeps the old behavior — queued card in the tray, "Delivery unconfirmed / Retry saved send" strip for turns — against the same server.

## Security fixes

None in this release. No commit in this range names a security issue or a fix for one.

## Known limitations

- The new-session Sending… bubble is the new-session page's. The Apple commit says shell and wiki-chat first messages keep today's behavior; Android's first-message bubble draws in the engine picker's place.
- Send stays off while a message reads "Not sent" — Apple's new-session page says so explicitly, and Android makes Send a plain disabled arrow while a message is out — so Retry or Put back comes first.
- A message saved as "Not sent" reloads as "Not sent" after a restart and is never replayed by itself.
- Android removes the "Delivery unconfirmed / Retry saved send" strip for turns but keeps it for creates; on iOS and macOS a conflict refusal still keeps its card rather than the Not sent bubble.

## Rollback

The previous tag is v0.1.261-beta.107 (commit `675b5a868049af5f523eb0c737dabcb02ef7213a`). Its `release.yml` run finished green, and the GitHub Release lists its macOS DMG, APK, runner binaries, appcast, SBOM, provenance and SHA256SUMS.

Application-only rollback is **schema-safe**: this range adds no migration, so an earlier server reads and writes exactly the columns beta.107's schema has. No down-migration or backup/restore step is needed; deploy the previous commit for the server, web and gateway together. beta.107's server already answers a repeated `clientRequestId` with the session the first made, so it needs no change for these clients either way.

Rolling the runner back to beta.107's binary loses nothing: no runner source differs in this range, so what the runner sends the control plane is unchanged. Rolling iOS, macOS or Android back to a beta.107 build returns those screens to the queued card and the "Delivery unconfirmed / Retry saved send" strip.
