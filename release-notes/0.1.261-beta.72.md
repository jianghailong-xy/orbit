# Orbit 0.1.261-beta.72

## Summary

This release **carries v0.1.261-beta.71 to macOS and Android users**, adds **revision 42 part two on the Apple and Android apps**, and lands **the landing measurement fix with its start-time repair** plus a run of runner, Open-list and web reading fixes. The range is `v0.1.261-beta.71..origin/main` (`fe512f4f5a`).

**beta.71 was tagged but never published.** Its Android build failed its unit suite on `SessionProjectCopyParityTest.everyWebWordIsHeldHereOrNamed`: the web's twelve Pause/Resume words (`07478dc1d9`) were missing from that Android test. So the GitHub Release, the macOS DMG and Sparkle update, and the Android APK were never published; only its iOS TestFlight build went out. `c83d2c9e18` fixes the test — it names those words in `ProjectPauseCopy` and adds a case holding that class's fixed words to the web's. For macOS and Android users, this release therefore also carries everything listed in `release-notes/0.1.261-beta.71.md` — the project-row Pause and Resume, closing a failed merge with ✕, the session release fact, the shared row shell, and the quieter Agents and background rows. That file describes it and it is not repeated here.

**Revision 42 part two reaches the Apple apps and is completed on Android.** A start request that names no line draws one sentence, names no branch in its Automatic or comes-to-you copy, and sends no line; the merge check the owner set on the start card is kept until the line starts (`d485bc87fb`, `af0be12465`, `d8065f5b64`, `8f912f8bf4`, `b3b6a3c32a`, `7485aa32cb`). A project with no line draws no landing card, Landings row, task-row landing tag or landing lanes. How it runs shows the landing check's three values with who set it and when, and opens the coordinator's cardless changes, which the owner reverts after a confirmation (`af0be12465`, `d8065f5b64`, `e65e67f98b`). A task's exemption shows on its page with Remove exemption, and its landing check reads Skipped with the reason on its own line rather than failed, with the merge check before main still shown as running under it (`e896e8ed24`, `87827952b7`). Every new server field decodes as optional, so an older server still reads. The follow-ups that finish it: "Who can set it" now sits under the landing check's own origin, as on web (`c226af0ab4`); Remove exemption redraws a task page opened outside Tasks (`e503a6ff9e`); the Coordinator and Exempt badges read in dark mode (`82843b54bc`); the landing check's command box carries its own accessibility tag (`e195b935bf`); and Android's change rows say nothing to revert for a row the coordinator did not write, as web and OrbitKit do (`bf80ccd90c`).

**The landing measurement reads a task's own work.** P-M1 read the runner's `changed_files`, the diff from the base to wherever HEAD is, so a verification run that checked the project line out detached and committed nothing read as work elsewhere — and settled projects flipped to OPEN on 2026-11-20 (`cad7deec05`). A task now has nothing of its own unless one of its work sessions has a branch past its own base or a dirty checkout; the delivery review for files outside a declaration asks about those own commits instead of the checked-out commit's diff (`feb573edff`); and the deploy-time pass queues an observation only when a task actually waits to be observed (`c8b7d74a28`). A start repairs what the first reading wrote: it supersedes the open scope reviews and LANDING_UNOBSERVED items for tasks that measure nothing of their own and re-projects their projects — DONE over OPEN only, never out of DONE — and a dry run prints, in a READ ONLY transaction, exactly what the next start will do (`052ad2543d`, `70ac2d1154`, `7d7656e516`, `d76499ec5c`, `b6703ca575`). The production dry run of 2026-11-20 showed the first repair would have stored OPEN over four projects DONE since September and October.

**A DONE no longer waits for the reaper.** A DONE now asks its task's idle work session to end at once (`98c3e3b200`), so the landing it decides and the dependents it releases are handled at that finish instead of after the reaper's ~30 s sweep; the contract records about 29 s per dependency layer before and under 1 s after (`39316168eb`). A session with a queued turn, an open request or a wake source is still left to the reaper, which stays the backstop. The promotion candidate is now held while a DONE task's landing is deferred, so a partial tip is no longer offered to main where one merge was due (`2b7edea63c`).

**The Open list stops waking on heartbeats.** Every runner heartbeat rewrote all of its workspace rows — the directory and disk probe — and moved the account's Open-list version, so every web tab read an empty delta; the new migration's own comment records 2026-11-22 sampling with eight runners beating where the workspace counter moved in 184 of 900 seconds. `1428_open_list_workspace_probes` replaces `open_list_bump_owner` so a workspace UPDATE bumps only when a column a list draws changed, or when `work_dir_free_bytes` crosses the disk floor of a never-started PENDING session's runner (`b08fe52dbe`), and the poller now compares a heartbeat-free token — counter sums plus a clock part — instead of the whole list version (`5da9bf0a43`, `0eed55a22e`, `8b1198b028`). The list version and ETag are unchanged.

**A dormant retry arm no longer keeps a runner awake.** The runner's event ingestion, turn-complete and finalize, and the reaper's offline end wrote `retry_at` without asking whether the owner had already completed or trashed the session, so a late report armed a retry the sweep can never fire, and a due arm kept its managed runner awake (`391657ec72`, `2b41655592`). Each writer now refuses; `DUE_RETRY` counts only arms the sweep can fire; completing or trashing a session clears its arm; and `1427_clear_dormant_session_retry_arms` clears the ones already stored.

**Smaller changes.** A remote SubAgent can now hand files back with `file_upload`: the runner carries the mode it was claimed in so its Plan gate can answer, its file calls name the run, and the upload, folder-bundle and pin routes accept that runner (`96d1f71ca2`, `5bc9c25f00`). Writing in a session's uploads directory no longer asks for an approval card under DSH's Auto, Antigravity's Accept Edits, Cursor's Auto and Accept Edits, or a DSH session's `bg_run` in Auto — the same working directory Claude Code and Codex get with `--add-dir` — while links out of it and every other mode still ask (`0238c1fee8`, `c27755ae8d`, `b08aa1dc44`, `e0fd95a469`). `install.sh` now draws its own download bar with size, speed and time left (`7d81c17924`, `a0d6d7ee8b`, `09b902d5d8`). A promotion check no longer holds its target's integration lock, so one project's hung check no longer parks every other project's check and landing into main for its whole time limit (`f5cb448a1d`). The runner's re-register prompt names the OS user instead of "this machine" (`02e167409b`). On web, a fully loaded session offers Jump to the beginning too (`b3a331e0e8`); a session opened at a waiting card, a chat's card or a linked record keeps that card in place while the conversation lands (`0138628478`); a scrolled-up reader keeps their window when the stream has to re-seed (`efa1ae09cd`); a reopen draws one page and catches up its gap in one read (`4e53172f02`); a folded translation survives a reload (`b1b4b3784e`); a waiting coordinator opens at its open question, not an answered record above it (`beecbaca35`); and a non-code project draws its integration rows while the owner's own revert rows say nothing to revert (`e65e67f98b`).

## Upgrade impact

- **Database migrations:** two new files under `src/apiserver/prisma/migrations/`, 114 lines, both new — no migration file is changed or removed.
  - `1427_clear_dormant_session_retry_arms` is one `UPDATE "session"` clearing `retry_at` and `retry_claimed_at` on a session that is completed or deleted. It adds no table, column or index and drops nothing, but it does change stored data: it clears only arms the auto-retry sweep could never fire.
  - `1428_open_list_workspace_probes` is `CREATE OR REPLACE FUNCTION open_list_bump_owner()` and nothing else — no DDL, and no table locked. Its name, arguments and every trigger stay, and a statement already inside the old function finishes on it. Additive: no table, column or row is touched.
- **Ordering:** beta.71's requirement stands unchanged, because beta.71 never shipped. **Every replica must already run v0.1.261-beta.70 or later before this tag's apiserver boots migrations 1401+.** A server older than beta.70 writes a terminal session status with no `finished_at` and is refused by 1401. An operator on beta.70 upgrades straight to this tag, and its apiserver boots all ten migrations, 1401 to 1428, in that one start. Nothing requires `1427` or `1428` to come before or after the rest: 1427 is a cleanup of rows no sweep can fire, and 1428 replaces one function in place.
- **Release cause:** unchanged from beta.71. `session.release_cause` is no longer written and is gone from the Prisma model, but the column and `session_release_cause_chk` remain in the database until a later deploy (step R8). A beta.70 server still writing them during a hand-over harms nothing.
- **Configuration:** nothing new to fill in.
- **Runner** (`src/runner-go`, built from this tag and served at `/dl`): no image definition changed in this range. The binary carries the promotion check's own lock key, the remote SubAgent's claimed mode and run id for its file calls, the uploads-directory writes for DSH, Antigravity and Cursor, the DSH `bg_run` Auto gate, and the re-register wording. A managed-runner deployment picks these up by updating the runner; older runners keep working, and a remote SubAgent's `file_upload` needs both this server and this runner. The `install.sh` download bar ships with the next server/web deployment, not with the runner.
- **Clients:**
  - *macOS:* revision 42 part two (no-line start, the landing check with who set it, exemptions, the coordinator's changes with Revert) plus everything beta.71 carried, on the beta channel (DMG and Sparkle appcast). This is the first published DMG since beta.70.
  - *iOS:* TestFlight marketing version 0.1.261, build number the commit count, with revision 42 part two on the phone, on top of beta.71's TestFlight build.
  - *Android:* `versionName` `0.1.261-beta.72`, the next `versionCode`, and `android-update.json`, with revision 42 part two complete plus everything beta.71 carried. This is the first published APK since beta.70.
  - *Web:* the revision 42 part two leftovers, the session-reading fixes, the Open-list hint change and the new `install.sh`, with the next server/web deployment, not from this tag's client artifacts.
  - No minimum client version is enforced, and no one-time step is needed beyond the upgrade ordering above.

## Rollback

The previous tag is v0.1.261-beta.71, commit `e57d339a411302485f6845155b89c14adfa2d25d`, but it was never published: it produced only an iOS TestFlight build. **v0.1.261-beta.70 (`46d94bd7899e2ccb49cae1c5fe3af8144bae5fa1`) is the last release published for macOS and Android**, and beta.71 is the last TestFlight build. A server deployed from this tag rolls back to beta.70's commit.

An application-only rollback to beta.70 is schema-safe, and to no release older than it. Beta.70 carries the release-fact writers (1261/1262), so its terminal writes set `finished_at` and satisfy 1401's CHECK; the replaced functions and triggers keep answering as beta.70 expects; 1426 adds its index beside 0130's, which stays in force; nothing depends on 1427's cleanup; 1428 replaces one function and answers as before for every stored row except the heartbeat-only case it stops bumping; and `release_cause` is still in the database, so beta.70 keeps writing it. A release before beta.70 cannot be the rollback target: 1401 refuses its terminal writes.

The client changes do not roll back with the code. Rolling macOS or Android back from this release means installing beta.70's build, which loses everything beta.71 and this release carry: the project-row Pause/Resume, the merge-failure ✕, and revision 42 part two. An iOS device can also go back to the beta.71 TestFlight build.
