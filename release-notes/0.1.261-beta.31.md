# Orbit 0.1.261-beta.31

## Summary

The help center on web and a scheduled-run access level that lands a run on main, on top of v0.1.261-beta.30.

- **Help center on web.** A `/help` window and a help drawer over the app, Settings and Admin, built on 38 English
  articles in nine categories. The apiserver serves the library at `/api/help`, `/api/help/articles/:slug` and
  `/api/help/search`; the doors are open signed out, and the Admin & self-hosting category is shown to administrators
  only. `/help` has search with Ask, a Get started checklist ticked from the account, Browse by topic with counts, and
  Common problems; an article has its body with other platforms' passages hidden, resolved `orbit:/` buttons, On this
  page, and Did this help? The drawer opens from a `?` button beside the avatar, a Help center row in the account
  menu, and the `?` key (ignored while typing, Esc closes), and shows For this page (articles whose routes match),
  an error card's Learn more, reading, search as you type, and Ask instead. It shares the right dock with the wiki
  chat: opening one closes the other.
- **Ask.** A question answered by an ordinary session that starts read-only on one of the person's machines, on
  Claude: it reads the article library and the account's machines, sessions, tasks and quota, cites articles as
  `[1]`/`[2]`, writes nothing, and offers changes only as `orbit:/` buttons. The machine and engine are remembered per
  person, and `/help` → Your questions lists every Ask the person started with its page, outcome and cost.
- **Still stuck.** Under an Ask answer marked No: Tell it what's still wrong puts the cursor in the Ask's own
  composer, Ask your admin makes an ordinary task in that admin's task list (`/help` → Your questions then says
  "With your admin" and who it went to, recorded once per Ask), and Report on GitHub shows the exact issue body —
  with code blocks, paths, repository addresses, workspace and folder names and keys taken out — then opens a
  new-issue URL on the release repository.
- **Help feedback.** Yes/No on an article or an Ask answer, one vote per person per item with the last one winning;
  counts only, with no text column. Admin → Help feedback (under Server in the Admin nav) shows per-article Yes / No,
  most No first, and the Ask answers as two totals.
- **Schedules: a LAND access level, "Edit and land on main".** A LAND run edits and commits in its own worktree under
  OPEN_PR's modes and denied tools; once its turn has settled and it reported, the server lands its session through
  the ordinary merge-to-main path and merge check. A refused merge fails the run into Waiting on you; no commits or a
  failed run land nothing, and widening to LAND needs the owner's Allow card ("Let {title} land on main?"). Rows and
  cards name the level, a failed landing reads "Could not land on main", and a workspace with worktrees disabled
  holds the schedule. `schedule_update` now accepts `readBack`, and asks for a fresh one on a prompt or access change
  too.
- **Smaller fixes.** Help search snippets read as plain text (table pipes, separator rows and single-star emphasis
  dropped); an Ask's answer renders in Chromium, and an Ask keeps its first question as its title; `[1][2]` are two
  citation chips; link-only lines in an answer are buttons alone and the verdict scrolls into view; the help drawer is
  docked beside `/help` as in Settings.

## Upgrade impact

- **Database migrations:** four, all additive, applied by the apiserver on start. The three help migrations take their
  locks in short tries (2 s at a time, at most 45) rather than waiting on a busy table, and each of them says it is
  safe to run twice.
  - `0850_help_ask_session` adds the nullable `session.help_ask` column and a trigger that refuses an UPDATE changing
    it, so a session is an Ask for its whole life or never.
  - `0890_help_ask_admin_request` creates the `help_ask_admin_request` table (one row per Ask sent to an admin).
  - `0900_help_feedback` creates the `help_feedback` table, keyed (user, kind, item) with no text column.
  - `0990_schedule_land` adds the `LAND` value to the `schedule_access_level` enum and the nullable
    `landing_status` and `landed_sha` columns to `schedule_run`.
- **Configuration:** one new optional variable, `ORBIT_RELEASE_REPOSITORY` (`owner/repo` or its GitHub URL; absent or
  empty is Orbit's own repository): the repository Help → Still stuck → Report on GitHub opens a new issue on. A fork
  that ships its own builds names its own. It needs the API recreated. Nothing else is required.
- **Runner:** the runner served at `/dl` is built from this tag. An Ask needs it — the runner starts the Ask
  read-only and declares `help-ask/v1`, and the web picker shows "Update runner" for a machine on an older one. The
  runner's own schedule tools also gain the LAND access level and the wider `schedule_update` read-back wording.
- **Managed runner image:** its pins move to Codex 0.169.0, Claude Code 2.1.326 and Antigravity CLI 1.5.10. The
  Antigravity digests were taken from its publisher manifests and confirmed by downloading both artifacts.
- **Clients:** web carries the help center and the schedule changes; macOS/iOS (OrbitKit) and Android carry the new
  access level's label, detail, brief, history field, failure and held reasons and the phone row. Each builds from
  this tag: macOS beta users, TestFlight (marketing version 0.1.261, build number = commit count) and Android via
  `android-update.json` are offered it.

## Security fixes

None in this release.

## Known limitations

- An Ask runs on Claude only, and only on a machine whose runner is at least this version (`help-ask/v1`); the picker
  shows "Update runner" for an older runner and "No engine" for a machine with no Ask-capable engine signed in.
- The help center is web-only in this release; the Apple and Android clients carry the schedule changes only.
- The two red tests [0.1.261-beta.30](0.1.261-beta.30.md) named — Android `ProjectMergeShellTest` and the Swift
  `SessionProjectPageWiringTests` waiting-card case — are fixed by this release's test commits. The Codex-account-slot
  and read-back-sentence limitations of those notes still apply.

## Rollback

The previous tag is v0.1.261-beta.30, commit f58743c19. All four migrations are additive — three add a new table or a
nullable column with its trigger, and one adds an enum value and two nullable columns — so an application-only
rollback to v0.1.261-beta.30 is schema-safe: the new tables stay in place, unread, and the column and trigger stay in
place. Two things need care: a schedule set to LAND under this tag is not readable by v0.1.261-beta.30's server or
clients, whose copy knows only CHECK_ONLY and OPEN_PR and reads the label without a fallback, so pause or end a LAND
schedule, or have an agent set it back to OPEN_PR or CHECK_ONLY, before rolling the application back; and runners do
not move back by themselves, so roll them back with the `/api/runner/release` pointer, after which they no longer
answer an Ask. See
[Release process](../docs/release-process.md#rollback-decision-and-procedure).
