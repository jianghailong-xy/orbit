# Orbit 0.1.261-beta.45

## Summary

This release is about the project board saying what is actually true. A task's latest evidence revision that its coordinator has not decided no longer sits silently OPEN: after the project's window the owner gets one item, "Evidence waiting for a decision", whose Review opens the evidence, and the clock honours the owner's rule that a live coordinator holding the work is never handed a timer. A landing that stopped at a MAIN_SYNC conflict can now be landed again from Retry once the task's branch carries both the project line and main, decided from SHAs the server already records, because the apiserver image has no git. A task the auto-run sweep holds because its engine is signed out now says so on its row, with a Sign in, instead of reading "Ready". Every client pins the account's managed runner first in its machine lists, the done question is a preview that opens the whole card, and "Hide original" works on your own messages too. It adds one database migration (1110, additive).

- **Undecided evidence reaches the owner (server, web).** A project task's latest evidence revision that its coordinator has not decided stayed OPEN with nobody told (production: 8 days for one revision submitted on 2026-11-10). The escalation tick now opens one `EVIDENCE_UNDECIDED` item per waiting revision once the project's `exceptionEscalationSeconds` have passed since it was submitted, in projects whose coordinator switch is on, keyed `EV:<evidenceId>` so ticks never open a duplicate and a settled revision is never reopened. It is OWNER / ESCALATED from birth, titled "Evidence waiting for a decision: <task>", its detail line says how long ago the revision was submitted and that the coordinator has not decided it, and its Review opens the task's evidence (the web project page words the Review press accordingly). The decision door ends it (DECIDED, CONFIRM or SEND_BACK), a newer revision supersedes it (REVISED), and `openItemOwed` plus the backstop close one an edge missed (TASK_CLOSED when the task settles). The clock keeps the owner's taken-up rule: it opens the item only when the project's coordinator cannot take a turn, and only once the window has passed since the last delivery of the revision a coordinator took up — so while a live coordinator can still take the work, no timer hands it to the owner. A project that was never Automatic still raises nothing; one switched off after the revision was put to its coordinator does. Migration 1110.
- **Retry lands a MAIN_SYNC conflict once the branch carries both tips (server).** `integration_retry` refused every CONFLICT that stopped at MAIN_SYNC, even after the task's branch had absorbed the project line and main, so coordinators had to reopen finished work. The door now queues the rerun when the branch carries both tips (and the branch is not main itself), records CONFLICT as what it reruns and answers "Landing again: the branch now contains the project line and main, so it lands by a merge." The first revision probed ancestry with git in a scratch repository; the apiserver image ships no git, so it answered UNKNOWN in production and Retry kept refusing. The door now decides from facts the server already records — the conflicted landing's `source_sha` against the `session.branch_sha` the runner last reported for the branch a rerun would land: moved queues the next generation and says so, and the runner decides whether the branch now carries both tips (lands by MERGE) or stops at MAIN_SYNC again and brings the conflict item back; unmoved, or either SHA unknown, keeps the refusal word for word. An intermediate migration 1090 was added for the first revision and removed with it, so it never reaches this tag.
- **A held task says why it is held, with a Sign in (server, web).** The auto-run sweep held a task whose engine is signed out on its runner, but the row still read "Ready · automatic dispatch" and the reason was only in the apiserver log. The task read, the paged task list rows and the project task page rows now carry a `hold` (engine, label, runner), computed by the sweep's own candidate scans, quota and signed-out gates, in the sweep's order; the project open-items read gains `signIns`, one "N tasks wait for a sign-in" row per runner and engine, derived on every read so it is gone once the engine is signed in. The web draws a Held pill, "Held: Claude Code is signed out on <runner>" and Sign in on the project task row and the Tasks list row, and a Needs you row per sign-in wait on the project page.
- **An answered question is listed once in a coordinator's opening digest (server).** Every owner answer also writes an automatic ruling, and the successor's digest listed both. "Owner answers in force" now leaves out any answer a ruling records (live or superseded); an ASK_OWNER ruling whose text lacks the owner's typed words shows them after the ruling as "→ <quote>". Contract revision 41. No migration.
- **Landing timeline wording (server).** A skipped attempt's line reads "Landing check skipped" rather than "Merge check skipped", and the attempt queued by the owner's skip of a running landing reads as a rerun the owner asked for, with the skip's reason, so every client words it without a change of its own.
- **A bulk Run's stale item is re-planned (server).** A press that bound its plan, whose item's create was refused, no longer replays the same refused create whatever the task has been re-pinned to: a repeat re-plans an item only when a dispatch-relevant pin changed since it was bound and the Session it names provably does not exist, under the press's lease; items whose run exists or whose create is in flight are taken over, never replaced.
- **Orbit Cloud is pinned first in every machine list (web, macOS/iOS, Android).** The account's managed runner now draws first in Settings > Machines and the account menu's Machines submenu (web), Machines & models and the sidebar's and drawer's Set up rows (macOS/iOS), and Settings > Machines / Machines & models and the drawer's Set up rows (Android), with a brand-coloured cloud and a semibold name and a line before the owner's own machines (board `docs/mocks/orbit-cloud-pinned`, option A). It cannot be dragged or moved past, and a reorder sends it first. With no managed runner every list is as it was.
- **The done question is a preview in the conversation (iOS, macOS, Android).** The done card is a small preview (heading, project and tally, "View details & act") that opens the whole card in the review sheet with Record as done / Not yet… pinned at its foot; the open-question capsule opens the same sheet. Each Done when row puts its state on a line under the words (glyph + "Met · …"), and the words show three lines until pressed. Android follows iOS. Board: `docs/mocks/project-done-card-criteria-ios`.
- **Hide original on your own messages (web, iOS, macOS, Android).** With Show both languages on, a reply's foot reads "Translated · Hide original" on the web, and your own message's foot reads "Sent to the agent in English · Hide original" ↔ "· Show both" on every client, per message and never kept. "Show both" rather than "Show original", which already means swapping the translation for the original. Board: `docs/mocks/translation-hide-original`.
- **A failed press says what went wrong (iOS, Android).** A schedule card press that failed without a server sentence read "Couldn't reach Orbit. Try again." even when Orbit answered. Only a dropped connection says that now: an unreadable reply asks to update the app, an HTTP error names its status, and a lapsed sign-in says so. An Android owner-request card no longer calls an unreadable reply or a bare HTTP error unreachable either.
- **An Agent block reads the run's text, not the `{` of a clipped result (web, macOS/iOS, Android).** The server clips a long tool result to a 2 KB preview, so the pretty-printed JSON no longer parses and the closed macOS block's outcome line read `{`. When the result does not parse and starts with `{`, the block uses the ended run's resultSummary, or shows nothing until the run is read; the macOS outcome line also skips lines that are only brackets or a code fence. The web now reads OpenCode's no-provider-key sentence from `runnerCopy.ts`, matching the native copy table.
- **Also.** The rest of the range is test and design material: `evidence-undecided.pg.spec.ts` (475 lines), `task-auto-run-stale-batch-plan.pg.spec.ts`, `task-sign-in-hold-read.pg.spec.ts`, `integration-retry.pg.spec.ts`, the two test-only commits that adjust `task-run-winner-recovery.pg.spec.ts` and `provider-engine-api.pg.spec.ts` to rules from earlier releases, and the design documents and boards for Orbit Cloud's "new version available" / Update Now (`docs/managed-runner-update-now-design.md`) and the updated hand-off and integration-line documents. No user-facing change comes from those files.

## Upgrade impact

- **Database migrations: one, additive.** `1110_evidence_undecided_item` widens three CHECK constraints on `project_open_item` — `project_open_item_kind_chk` admits `EVIDENCE_UNDECIDED`, `project_open_item_resolution_chk` admits `DECIDED` and `REVISED`, and `project_open_item_owner_only_chk` lists the new kind among the owner-only kinds. It is catalog-only: every stored row already satisfies the widened sets, no row is written, and every statement can run twice. The apiserver applies it on boot; there is no manual step. Nothing is destructive. A migration 1090 was added and removed inside this range, so it does not exist at this tag; the newest migrations before this one remain 1070 and 1080 from v0.1.261-beta.41.
- **Server:** the evidence clock, the Retry door, the sign-in hold read, the digest fix and the landing-timeline wording are apiserver changes, so the apiserver must be deployed from this commit or later for them. The web client ships with the same deploy. Because the Retry door reads `source_sha` and the runner-reported `branch_sha` rather than running git, it needs no git in the apiserver image.
- **Runner:** no runner change in this range; the runner served at `/dl` is built from this tag. No commit names an engine version change and no minimum runner version is set.
- **Configuration:** no variable, compose file or deploy script changes in this range; nothing must be set before or during the upgrade.
- **Clients:** macOS beta users get the DMG on the beta channel, TestFlight gets marketing version 0.1.261 with the build number as the commit count, and Android gets `android-update.json` from this tag with `versionName` 0.1.261-beta.45. The web surfaces that read the new fields — the Held pill and Sign in wait rows, and the evidence item's Review wording — need the server from this commit; the sign-in wait rows are absent from a server that predates them, and every other client change in this range works against the previous server. No minimum native client version above the previous release is set by this range.

## Security fixes

None in this release. No commit in this range names a security fix, an advisory or a CVE, and no dependency is added, removed or moved: the lockfile is unchanged between v0.1.261-beta.44 and this tag's base, and the release commit itself changes only its package version lines.

## Known limitations

None known. The evidence item appears only in projects whose coordinator switch is on, by the owner's escalation rule rather than as a limit of this release.

## Rollback

The previous tag is v0.1.261-beta.44, commit a9e5be38ca43aac9b5b7f612006f27802011ab00 (its tag object is f549496e78554d8e8864647f7a18e77743674a44), on origin. This range adds one catalog-only migration that widens three CHECK constraints and writes no row, so an application-only rollback to that tag is schema-safe: the older apiserver ignores the widened sets, nothing is left to undo, no backup or restore step is needed, and no data is affected. Rolling back restores the older behaviour: an undecided evidence revision again waits with nobody told, Retry again refuses every MAIN_SYNC conflict, a held task again reads "Ready" with no sign-in action, and the landing timeline again says "Merge check skipped". A client from this tag against a server older than this commit keeps working: the sign-in hold and sign-in wait fields are absent, so those rows simply do not draw, and every other change in this range is client-side. See [Release process](../docs/release-process.md#rollback-decision-and-procedure).
