# Orbit Android engineering shell

A02 establishes the native Android build, module boundary and verification entry points.
It contains a Compose launcher and build/device information screen only. Login, protocol,
business navigation, iOS visual alignment, notifications and release signing belong to later
tasks. The iOS installed version is still being established by A01; no repository revision or
"latest beta" is treated as that frozen baseline.

## Modules and supported range

- `:app`: Android activity, Compose/navigation, platform information and local UI tests.
- `:core`: pure Kotlin/JVM code used by the shell, initially traceable build identity; later
  protocol/state code can live here without depending on Android.
- S1: Android 10–16 (API29–36), GMS phones in Hong Kong/Singapore, APK installation.
  `minSdk=29`, `compileSdk=36`, `targetSdk=36`; no fixed orientation or phone screen size.
  Debug package is `io.orbitd.android.debug`, separate from the provisional production
  package `io.orbitd.android`. A14 owns final distribution/signing decisions.

## Build and verify

Install Java 21, Android command-line tools, `platforms;android-36` and `build-tools;36.0.0`.
Accept Android SDK licenses in your environment; dependency resolution needs network access.
The first run downloads Gradle and Maven dependencies, including Robolectric's Android runtime.
Git and Python 3 are needed by the build identity and verification scripts. No production
signing, service account, FCM config or backend credentials are required.

From the repository root, the project merge gate is exactly:

```sh
env JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ANDROID_HOME=/opt/android-sdk ANDROID_SDK_ROOT=/opt/android-sdk bash src/android/gradlew -p src/android --no-daemon --max-workers=2 test lintDebug assembleDebug
```

The reusable clean verification entry also checks the task graph, rejects empty/skipped JUnit
results, and saves raw logs, XML/HTML reports, APK, signing certificate and SHA256:

```sh
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export ANDROID_HOME=/opt/android-sdk ANDROID_SDK_ROOT=/opt/android-sdk
bash src/android/scripts/verify.sh
```

`test` selects `:core:test`, `:app:testDebugUnitTest` and `:app:testReleaseUnitTest`.
`:core` verifies build identity validation; `:app` launches real Compose content under
Robolectric API29 and verifies navigation/recreation. These local tests do not replace AVD
or physical-device evidence. Results are under `.artifacts/verify-<UTC>/` (ignored by Git).
The workflow `.github/workflows/android.yml` runs the same entry on PRs and manual dispatch,
and Android branch changes trigger it on push. It uploads the evidence even on failure.

The engineering screen and generated `BuildConfig` record the source SHA and dirty state.
Make a source commit before generating handoff APKs. The debug key is generated locally and
is unsuitable for production; do not assume APKs from different machines share that key.
Use the same handoff APK for device evidence and compare its SHA256.

## Device checks

See [device-testing.md](docs/device-testing.md) for API29–36 preparation, serialized smoke
runs, raw evidence format, and the shell checklist. The shared API36 AVD is a Pixel 7
emulator, not the owner's phone. A02 requires real target-phone launch evidence separately.
Final business/quality matrix execution belongs to A15; feature tasks add their own cases.
